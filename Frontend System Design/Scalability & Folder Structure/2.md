Setting up a Turborepo monorepo with a shared design system and API client requires a clean separation between **applications** (`/apps`) and **shared workspace packages** (`/packages`).

This architecture allows multiple apps (e.g., a Next.js marketing site and a Vite client app) to consume shared Tailwind CSS styles and typed API calls without publishing to npm.

---

## 1. Monorepo Directory Architecture

```text
my-monorepo/
├── apps/
│   ├── web/                    --> Main Next.js application
│   └── admin/                  --> Internal Vite/React admin portal
├── packages/
│   ├── ui/                     --> Shared React Design System + Tailwind CSS
│   │   ├── src/                --> Shared UI components (Button, Modal, etc.)
│   │   ├── styles/             --> Global Tailwind CSS entry point
│   │   ├── package.json
│   │   └── tsup.config.ts
│   ├── api-client/             --> Shared TypeScript API Client
│   │   ├── src/                --> API methods & TypeScript interfaces
│   │   ├── package.json
│   │   └── tsup.config.ts
│   ├── config-tailwind/        --> Shared Tailwind CSS configuration preset
│   └── config-typescript/      --> Shared tsconfig base files
├── package.json                --> Root workspace package.json
└── turbo.json                  --> Turborepo pipeline configuration

```

---

## 2. Root Workspace & Turborepo Setup

### Root `package.json`

Define the workspaces using your package manager (pnpm recommended for monorepos):

```json
{
  "name": "my-monorepo",
  "private": true,
  "scripts": {
    "build": "turbo run build",
    "dev": "turbo run dev",
    "lint": "turbo run lint"
  },
  "devDependencies": {
    "turbo": "^2.0.0"
  },
  "packageManager": "pnpm@9.0.0"
}

```

### `turbo.json`

Configure the execution graph so dependencies build in the correct topological order:

```json
{
  "$schema": "https://turbo.build/schema.json",
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**"]
    },
    "dev": {
      "cache": false,
      "persistent": true
    },
    "lint": {
      "dependsOn": ["^build"]
    }
  }
}

```

## 3. Setting Up Package 1: Shared Tailwind CSS Design System (`/packages/ui`)

Instead of duplicating Tailwind configs across apps, centralize your design tokens and UI components inside `@repo/ui`.

### A. Tailwind Shared Preset (`/packages/config-tailwind/tailwind.config.ts`)

```typescript
import type { Config } from 'tailwindcss';

const config: Omit<Config, 'content'> = {
  theme: {
    extend: {
      colors: {
        brand: {
          50: '#f0fdf4',
          500: '#22c55e',
          900: '#14532d',
        },
      },
    },
  },
  plugins: [],
};

export default config;

```

### B. UI Package Configuration (`/packages/ui/package.json`)

```json
{
  "name": "@repo/ui",
  "version": "0.0.0",
  "private": true,
  "exports": {
    ".": "./src/index.ts",
    "./styles.css": "./dist/styles.css"
  },
  "scripts": {
    "build": "tsup src/index.ts --format cjs,esm --dts && tailwindcss -i ./src/styles.css -o ./dist/styles.css",
    "dev": "tsup src/index.ts --format cjs,esm --watch"
  },
  "devDependencies": {
    "@repo/config-tailwind": "workspace:*",
    "autoprefixer": "^10.4.0",
    "postcss": "^8.4.0",
    "tailwindcss": "^3.4.0",
    "tsup": "^8.0.0",
    "typescript": "^5.0.0"
  },
  "peerDependencies": {
    "react": "^18.0.0"
  }
}

```

### C. Shared Component (`/packages/ui/src/Button.tsx`)

```tsx
import React from 'react';

interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: 'primary' | 'secondary';
  children: React.ReactNode;
}

export const Button: React.FC<ButtonProps> = ({ 
  variant = 'primary', 
  children, 
  className = '', 
  ...props 
}) => {
  const baseStyles = 'px-4 py-2 rounded-lg font-medium transition-colors focus:outline-none';
  const variants = {
    primary: 'bg-brand-500 text-white hover:bg-brand-900',
    secondary: 'bg-gray-200 text-gray-800 hover:bg-gray-300',
  };

  return (
    <button className={`${baseStyles} ${variants[variant]} ${className}`} {...props}>
      {children}
    </button>
  );
};

```

## 4. Setting Up Package 2: Shared TypeScript API Client (`/packages/api-client`)

Encapsulate HTTP logic, endpoints, and response types into a headless SDK package.

### A. API Package Configuration (`/packages/api-client/package.json`)

```json
{
  "name": "@repo/api-client",
  "version": "0.0.0",
  "private": true,
  "main": "./dist/index.js",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "scripts": {
    "build": "tsup src/index.ts --format cjs,esm --dts",
    "dev": "tsup src/index.ts --format cjs,esm --watch"
  },
  "devDependencies": {
    "tsup": "^8.0.0",
    "typescript": "^5.0.0"
  }
}

```

### B. API Client Source (`/packages/api-client/src/index.ts`)

```typescript
export interface User {
  id: string;
  name: string;
  email: string;
}

export interface ApiClientConfig {
  baseUrl: string;
  getToken?: () => Promise<string | null>;
}

export class ApiClient {
  private baseUrl: string;
  private getToken?: () => Promise<string | null>;

  constructor(config: ApiClientConfig) {
    this.baseUrl = config.baseUrl;
    this.getToken = config.getToken;
  }

  private async request<T>(endpoint: string, options: RequestInit = {}): Promise<T> {
    const token = this.getToken ? await this.getToken() : null;
    const headers: Record<string, string> = {
      'Content-Type': 'application/json',
      ...(options.headers as Record<string, string>),
    };

    if (token) {
      headers['Authorization'] = `Bearer ${token}`;
    }

    const response = await fetch(`${this.baseUrl}${endpoint}`, {
      ...options,
      headers,
    });

    if (!response.ok) {
      throw new Error(`API Error: ${response.status} ${response.statusText}`);
    }

    return response.json();
  }

  // Domain Endpoint Methods
  users = {
    getById: (id: string) => this.request<User>(`/users/${id}`),
    list: () => this.request<User[]>('/users'),
  };
}

```

## 5. Consuming Shared Packages in Applications (`/apps/web`)

### A. App Dependencies (`/apps/web/package.json`)

Link workspace dependencies using `workspace:*`:

```json
{
  "name": "web",
  "dependencies": {
    "@repo/api-client": "workspace:*",
    "@repo/ui": "workspace:*",
    "next": "^14.0.0",
    "react": "^18.0.0"
  },
  "devDependencies": {
    "@repo/config-tailwind": "workspace:*",
    "tailwindcss": "^3.4.0"
  }
}

```

### B. App Tailwind Config (`/apps/web/tailwind.config.ts`)

Import the shared Tailwind preset and add the `@repo/ui` package directory to `content` so Tailwind scans the shared component source files for class names:

```typescript
import type { Config } from 'tailwindcss';
import sharedConfig from '@repo/config-tailwind/tailwind.config';

const config: Config = {
  presets: [sharedConfig],
  content: [
    './src/**/*.{js,ts,jsx,tsx}',
    '../../packages/ui/src/**/*.{js,ts,jsx,tsx}', // Scan shared UI components!
  ],
};

export default config;

```

### C. Usage in Next.js / React View (`/apps/web/src/app/page.tsx`)

```tsx
import { useEffect, useState } from 'react';
import { Button } from '@repo/ui';
import { ApiClient, User } from '@repo/api-client';

// Initialize shared client
const api = new ApiClient({
  baseUrl: process.env.NEXT_PUBLIC_API_URL || 'https://api.example.com',
});

export default function HomePage() {
  const [users, setUsers] = useState<User[]>([]);

  useEffect(() => {
    api.users.list().then(setUsers).catch(console.error);
  }, []);

  return (
    <main className="p-8 space-y-4">
      <h1 className="text-2xl font-bold text-brand-900">Workspace Dashboard</h1>
      
      {/* Consuming shared Tailwind button */}
      <Button variant="primary" onClick={() => alert('Clicked!')}>
        Action Button
      </Button>

      <ul className="divide-y border rounded-lg p-4">
        {users.map((user) => (
          <li key={user.id} className="py-2">{user.name} ({user.email})</li>
        ))}
      </ul>
    </main>
  );
}

```

## 6. Monorepo Benefits Summary

1. **Zero Bundle Drift:** Modifying theme colors in `@repo/config-tailwind` updates every application instantly across the workspace.
2. **Type-Safe API Contracts:** Updating response interfaces in `@repo/api-client` immediately triggers TypeScript compiler errors across all consuming apps during `turbo run build`.
3. **Optimized Build Graph:** Turborepo caches output builds of `@repo/ui` and `@repo/api-client` so applications only re-compile packages that actually changed.
