## 1. Integrating Automated axe-core Contrast Checks in Playwright

Playwright integrates with `axe-core` via the official `@axe-core/playwright` package. This allows you to perform automated audits—including color contrast checks—directly in end-to-end tests.

### Step-by-Step Implementation

#### Step 1: Install `@axe-core/playwright`

```bash
npm install -D @axe-core/playwright

```

#### Step 2: Write a Contrast-Focused Playwright Test

You can run `axe-core` across the entire page or filter specifically for WCAG color contrast rules (`color-contrast` and `color-contrast-enhanced`).

```typescript
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

test.describe('Accessibility - Color Contrast Audit', () => {
  test('should pass WCAG AA color contrast standards', async ({ page }) => {
    // 1. Navigate to target URL
    await page.goto('https://your-app.com/login');

    // 2. Ensure dynamic themes or async components are loaded
    await page.waitForLoadState('networkidle');

    // 3. Run axe-core specifically targeting WCAG AA & contrast rules
    const contrastScanResults = await new AxeBuilder({ page })
      .withTags(['wcag2a', 'wcag2aa', 'wcag21aa', 'wcag22aa']) // WCAG AA standards
      .include('#main-content') // Optional: scope to specific UI region
      .analyze();

    // 4. Filter strictly for color contrast violations (optional)
    const contrastViolations = contrastScanResults.violations.filter(
      (v) => v.id === 'color-contrast' || v.id === 'color-contrast-enhanced'
    );

    // 5. Assert zero contrast failures
    expect(contrastViolations).toEqual([]);
  });

  test('should pass contrast check in Dark Mode', async ({ page }) => {
    await page.goto('https://your-app.com/login');

    // Toggle dark theme
    await page.emulateMedia({ colorScheme: 'dark' });

    const darkContrastResults = await new AxeBuilder({ page })
      .withRules(['color-contrast'])
      .analyze();

    expect(darkContrastResults.violations).toEqual([]);
  });
});

```

#### Step 3: Create a Reusable Playwright Fixture for CI/CD

To avoid repeating configuration across tests, export a custom fixture:

```typescript
// fixtures/a11y-fixture.ts
import { test as base } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

type A11yFixtures = {
  makeAxeBuilder: () => AxeBuilder;
};

export const test = base.extend<A11yFixtures>({
  makeAxeBuilder: async ({ page }, use) => {
    const makeAxeBuilder = () =>
      new AxeBuilder({ page })
        .withTags(['wcag2a', 'wcag2aa', 'wcag21aa'])
        .exclude('.third-party-widget'); // Skip unowned widgets

    await use(makeAxeBuilder);
  },
});

export { expect } from '@playwright/test';

```

## 2. Essential Accessibility Testing Tools

Automated testing catches roughly **30%–57% of WCAG violations** (e.g., missing labels, low contrast, missing alt text). Manual testing is required to verify logical focus order, dynamic announcements, keyboard interaction flow, and screen reader usability.

### Automated Testing Tools (CI/CD & Dev Time)

* **`@axe-core/playwright` / `@axe-core/cypress`:** E2E automated test runner assertions.
* **axe DevTools (Browser Extension):** Instant visual inspect audits directly inside Chrome/Firefox DevTools.
* **Lighthouse / Pa11y:** Synthetic web audits for basic contrast, landmark, and aria checks.
* **`eslint-plugin-jsx-a11y`:** Linter for flagging invalid ARIA, missing labels, or bad image tags during development.

### Manual & Assisted Assessment Tools

* **Accessibility Insights for Web:** Free tool by Microsoft that provides guided workflows (FastPass and full manual WCAG assessments).
* **Screen Readers:**
* **macOS / iOS:** VoiceOver (`Cmd + F5`)
* **Windows:** NVDA (Open Source) or JAWS
* **Android:** TalkBack

* **Colour Contrast Analyzer (CCA):** Desktop eyedropper tool for inspecting text rendered over complex image gradients or multi-layered canvas elements.

## 3. Combined Manual & Automated Strategy to Fix Accessibility

```
                       ┌───────────────────────────────┐
                       │   Development & CI Pipeline   │
                       └───────────────┬───────────────┘
                                       │
                      ┌────────────────┴────────────────┐
                      ▼                                 ▼
             [ Automated Tools ]               [ Manual Testing ]
             • eslint-jsx-a11y                 • Keyboard Navigation
             • Playwright + axe-core           • Screen Readers (NVDA/VoiceOver)
             • Lighthouse CI                   • Accessibility Insights
                      │                                 │
                      └────────────────┬────────────────┘
                                       │
                                       ▼
                       ┌───────────────────────────────┐
                       │    Remediation & Fix Phase    │
                       └───────────────────────────────┘

```

### Phase 1: Catch Surface-Level Bugs via Automation

1. **Gate PRs with Linting & E2E:** Run `eslint-plugin-jsx-a11y` and `@axe-core/playwright` in CI to prevent low-hanging accessibility regressions from merging.
2. **Fix Structural Semantics First:**

* Replace non-interactive elements (`<div onClick=.../>`) with native elements (`<button>`, `<a>`).
* Ensure explicit form inputs match `<label htmlFor="...">` attributes.
* Replace low-contrast tokens with contrast-validated CSS variables (targeting $4.5:1$ ratio minimum).

### Phase 2: Remediate Complex Flows via Manual Auditing

1. **Keyboard-Only Traversal (No Mouse):**

* Press `Tab` and `Shift + Tab` through user journeys (e.g., checkout, form submission).
* **Fix:** Ensure visible focus rings (`:focus-visible`) are present on all interactive controls.
* **Fix:** Ensure modals trap focus inside their container while active and restore focus to the trigger button upon closing.

1. **Screen Reader Walkthrough (VoiceOver / NVDA):**

* Turn off the monitor or close your eyes; complete key flows using screen reader controls.
* **Fix:** Add `aria-live="polite"` or `role="status"` to dynamic toast notifications and inline alert containers so screen readers announce dynamic UI changes without requiring full reloads.
* **Fix:** Verify screen reader announcements for complex widgets (accordions, comboboxes, dropdowns) accurately update `aria-expanded="true/false"` and `aria-selected` attributes.
