# rtk-counter-cart

A small, genuinely runnable multi-file Redux Toolkit + React app demonstrating the core RTK patterns covered in this topic: `configureStore` wiring two slices, `createSlice` with Immer-powered "mutating" reducers, and `useSelector`/`useDispatch` in real components.

## What it demonstrates

- **`src/app/store.js`** — `configureStore({ reducer: { counter, cart } })`. No manual middleware/devtools setup; both come free.
- **`src/features/counter/counterSlice.js`** — a simple slice with a configurable step size, showing basic `createSlice` reducers and co-located selectors.
- **`src/features/cart/cartSlice.js`** — a slightly more realistic slice: adding a duplicate item increments its quantity instead of pushing a duplicate row, `quantityChanged` removes the item entirely when quantity drops to zero, and derived totals (`selectCartItemCount`, `selectCartTotal`) are plain selector functions, not stored state.
- **`src/components/Counter.jsx` / `src/components/Cart.jsx`** — function components reading state with `useSelector` and dispatching plain action objects (produced by RTK's generated action creators) with `useDispatch`.
- **`src/main.jsx`** — `<Provider store={store}>` at the root, the one place the store is threaded into the React tree.

## Folder layout

```
rtk-counter-cart/
  package.json
  README.md
  src/
    app/
      store.js
    features/
      counter/
        counterSlice.js
      cart/
        cartSlice.js
    components/
      Counter.jsx
      Cart.jsx
    App.jsx
    main.jsx
```

This is the "feature folder" convention RTK's own documentation recommends: each slice lives next to the components that primarily use it, under `src/features/<feature>/`, rather than a single global `reducers/` and `actions/` split (the old classic-Redux convention this topic's `problems/01-convert-classic-reducer-to-slice.md` deliberately moves away from).

## Running it

```bash
npm install
npm run start
```

This uses Vite (see `package.json`) purely as a fast dev server — nothing here is Vite-specific; the same source would work unchanged with Create React App or Next.js's client components.

## Things worth trying once it's running

1. Add the same product to the cart twice and watch the quantity increment instead of a duplicate row appearing — that's `cartSlice.js`'s `itemAdded` reducer finding an existing entity by id.
2. Set a cart item's quantity input to `0` and watch it disappear — same reducer branch as clicking "Remove."
3. Open the Redux DevTools Extension while this is running: every dispatched action (`counter/increment`, `cart/itemAdded`, etc.) is inspectable, and the action type strings are exactly `${sliceName}/${reducerKey}`, generated by `createSlice`, matching what's covered in `../../theory/03-create-slice-and-immer.md`.
