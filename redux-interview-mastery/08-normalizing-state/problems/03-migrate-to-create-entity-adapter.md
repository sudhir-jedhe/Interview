# Problem 3: Convert a Hand-Normalized Slice to `createEntityAdapter`

## Task

Below is a hand-written normalized `todos` slice using a plain `createSlice` with manual `byId`/`allIds` management. Convert it to use `createEntityAdapter`, preserving all four behaviors: add a todo, toggle a todo's `completed` flag, remove a todo, and replace the whole list (e.g., after a fetch). Also expose `selectAllTodos` and `selectTodoById` selectors using the adapter's generated selectors instead of manual `Object.values`/lookup.

```javascript
// BEFORE: hand-rolled
import { createSlice } from '@reduxjs/toolkit';

const todosSlice = createSlice({
  name: 'todos',
  initialState: { byId: {}, allIds: [] },
  reducers: {
    todoAdded(state, action) {
      const todo = action.payload;
      state.byId[todo.id] = todo;
      state.allIds.push(todo.id);
    },
    todoToggled(state, action) {
      const todo = state.byId[action.payload.id];
      if (todo) todo.completed = !todo.completed;
    },
    todoRemoved(state, action) {
      delete state.byId[action.payload.id];
      state.allIds = state.allIds.filter((id) => id !== action.payload.id);
    },
    todosReplaced(state, action) {
      state.byId = {};
      state.allIds = [];
      for (const todo of action.payload) {
        state.byId[todo.id] = todo;
        state.allIds.push(todo.id);
      }
    },
  },
});

export const selectAllTodos = (state) => state.todos.allIds.map((id) => state.todos.byId[id]);
export const selectTodoById = (state, id) => state.todos.byId[id];
```

## Solution

```javascript
// AFTER: createEntityAdapter
import { createEntityAdapter, createSlice } from '@reduxjs/toolkit';

const todosAdapter = createEntityAdapter();

const todosSlice = createSlice({
  name: 'todos',
  initialState: todosAdapter.getInitialState(),
  reducers: {
    todoAdded: todosAdapter.addOne,
    todoToggled(state, action) {
      const todo = state.entities[action.payload.id];
      if (todo) {
        todosAdapter.updateOne(state, {
          id: action.payload.id,
          changes: { completed: !todo.completed },
        });
      }
    },
    todoRemoved: todosAdapter.removeOne,
    todosReplaced: todosAdapter.setAll,
  },
});

export const { todoAdded, todoToggled, todoRemoved, todosReplaced } = todosSlice.actions;
export default todosSlice.reducer;

export const { selectAll: selectAllTodos, selectById: selectTodoById } =
  todosAdapter.getSelectors((state) => state.todos);
```

## What changed, and why it's better

- `byId`/`allIds` becomes `entities`/`ids` automatically via `getInitialState()` — no manual shape maintenance.
- `todoAdded`, `todoRemoved`, `todosReplaced` become one-line delegations to `addOne`, `removeOne`, `setAll` — no more manually pushing into `allIds` or remembering to `delete` from `byId` (a common source of the two collections drifting out of sync, e.g., forgetting the `allIds.filter()` step when removing).
- `todoToggled` still needs custom logic (it's a computed toggle, not a plain field replacement) but now delegates the actual write to `updateOne`, which correctly no-ops if the ID doesn't exist rather than crashing on `undefined.completed`.
- `selectAllTodos`/`selectTodoById` are now generated by `getSelectors()` instead of hand-written, and are consistent with every other adapter-based slice in the codebase — a new engineer who's used `createEntityAdapter` elsewhere already knows this slice's API without reading it.
- Every `reducers` entry that maps directly to an adapter method (`addOne`, `removeOne`, `setAll`) is Immer-safe and battle-tested by RTK itself, removing an entire category of hand-rolled bugs (like the pre-migration `todoRemoved`, which relied on remembering to update both `byId` and `allIds` together, and would silently desync if someone edited one without the other in a future change).
