# Interview Q&A: `connect` vs Hooks

**Q: Can you use `useSelector`/`useDispatch` inside a class component?**
A: No — hooks can only be called inside function components (or custom hooks, which are themselves only callable from function components). A class component that needs Redux state or dispatch must use `connect`, which works via props rather than hooks and has no such restriction, since it's implemented as a higher-order component wrapping your class rather than calling hooks inside it.

**Q: Is `connect` deprecated? Should a team actively migrate away from it?**
A: `connect` is not deprecated — `react-redux` continues to support and maintain it, and it remains the only option for class components. Whether to actively migrate existing `connect`-based code is a judgment call based on cost/benefit: pure hook-based code is generally easier to read and has less indirection, but a large-scale migration purely for style, with no functional need (like adopting a hooks-only feature), is often not worth the risk/effort unless done incrementally and opportunistically (e.g., migrating a component when you're already touching it for an unrelated change).

**Q: `mapStateToProps` combines multiple fields into one props object, and `connect` shallow-compares that whole object to decide whether to re-render. How does that compare to using several separate `useSelector` calls?**
A: They achieve a similar goal through different mechanisms. `connect`'s shallow comparison of the combined props object means a change to *any* field in `mapStateToProps`'s return value triggers a re-render (but a change to `state` that doesn't affect any selected field does not) — effectively one combined check. Multiple `useSelector` calls perform independent reference-equality checks per call; a change in any one of them triggers a re-render, similarly, but each `useSelector` needs its own selector to return a stable reference internally (an object/array constructed by any one of them would defeat that call's own check) — the "many independent primitive selections" pattern (see `theory/05-avoiding-unnecessary-rerenders.md`) is closer in spirit to `connect`'s shallow comparison than to a single combined `useSelector` returning an object.

**Q: In `mapDispatchToProps`'s function form (not the object shorthand), what's the actual signature, and what's it for?**
A: `(dispatch, ownProps?) => ({ someActionName: (...args) => dispatch(actionCreator(...args)) })` — it receives `dispatch` (and optionally the component's own props, useful for building dispatch calls that need data from props, like an item's id) and returns an object of functions to attach as props. It exists to pre-bind action dispatching so the wrapped component never needs to import `dispatch` or action creators directly — it just calls `this.props.someActionName(...)` as if it were a plain callback prop.
