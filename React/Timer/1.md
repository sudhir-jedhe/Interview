In JavaScript, timers allow you to execute code asynchronously at a specified time or interval using **timing events**.

Here are the four core ways to handle timers in JavaScript:

---

### 1. `setTimeout` (Execute Once After Delay)

Executes a function **once** after a specified delay in milliseconds ($1\text{ second} = 1000\text{ ms}$).

```javascript
// Syntax: setTimeout(callback, delayInMs, param1, param2, ...)

console.log("Start");

const timerId = setTimeout(() => {
  console.log("This runs after 2 seconds");
}, 2000);

console.log("End");

```

#### Stopping a Timeout (`clearTimeout`)

To cancel a scheduled timeout before it runs, pass its ID to `clearTimeout()`:

```javascript
const timerId = setTimeout(() => {
  console.log("Will not run!");
}, 3000);

// Cancel the timer
clearTimeout(timerId);

```

---

### 2. `setInterval` (Execute Repeatedly at Fixed Intervals)

Executes a function **repeatedly** every time the specified delay passes.

```javascript
let count = 1;

const intervalId = setInterval(() => {
  console.log(`Tick ${count}`);
  count++;

  // Stop after 5 ticks
  if (count > 5) {
    clearInterval(intervalId);
    console.log("Timer stopped!");
  }
}, 1000); // Runs every 1 second

```

#### Stopping an Interval (`clearInterval`)

Always call `clearInterval()` when done to prevent **memory leaks** and infinite loops.

---

### 3. Practical Example: Building a Countdown Timer

```javascript
function startCountdown(seconds) {
  let counter = seconds;

  const intervalId = setInterval(() => {
    console.log(`Time left: ${counter}s`);
    counter--;

    if (counter < 0) {
      clearInterval(intervalId);
      console.log("Countdown Finished! 🎉");
    }
  }, 1000);
}

startCountdown(5);

```

---

### 4. Modern Promise-Based Timer (`async/await`)

Traditional `setTimeout` uses callbacks. If you prefer `async/await` syntax, wrap `setTimeout` in a Promise:

```javascript
// Helper function
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function runProcess() {
  console.log("Step 1");
  
  await delay(2000); // Pause execution for 2 seconds
  console.log("Step 2 (2 seconds later)");
  
  await delay(1000); // Pause for 1 second
  console.log("Step 3 (1 second later)");
}

runProcess();

```

---

### 5. High-Precision Timers (`requestAnimationFrame` & `performance.now`)

For **smooth animations** or **game loops** (60+ FPS), standard `setInterval` is imprecise. Use `requestAnimationFrame`:

```javascript
let startTime = performance.now();

function animate(currentTime) {
  let elapsedTime = currentTime - startTime;
  
  console.log(`Elapsed: ${Math.round(elapsedTime)}ms`);

  if (elapsedTime < 2000) { // Run animation for 2 seconds
    requestAnimationFrame(animate);
  }
}

requestAnimationFrame(animate);

```

### Summary Table

| Method                      | Execution Pattern                           | Use Case                            | Cancellation Method            |
| --------------------------- | ------------------------------------------- | ----------------------------------- | ------------------------------ |
| **`setTimeout`**            | Runs **once** after delay                   | Delayed actions, popups, debouncing | `clearTimeout(id)`             |
| **`setInterval`**           | Runs **repeatedly** at fixed rate           | Clocks, polling API endpoints       | `clearInterval(id)`            |
| **`Promise Delay`**         | Sequential pause in `async` functions       | Cleaner async workflows             | N/A (or via `AbortController`) |
| **`requestAnimationFrame`** | Runs **every screen repaint** (~60–120 FPS) | Smooth UI animations, games         | `cancelAnimationFrame(id)`     |

Here is how to build a production-grade custom `useTimer` hook in React using `useRef` and `useEffect`.

This implementation avoids common timer bugs (like stale closures or state drift), supports **Start**, **Pause**, **Resume**, and **Reset** controls, and cleans up after itself when unmounted to prevent memory leaks.

---

### 1. Custom Hook Implementation (`useTimer.ts`)

```typescript
import { useState, useRef, useEffect, useCallback } from 'react';

interface UseTimerOptions {
  initialTime?: number; // In seconds
  interval?: number;    // In milliseconds (default: 1000ms)
  onExpire?: () => void; // Callback when timer reaches 0
}

export function useTimer({
  initialTime = 60,
  interval = 1000,
  onExpire,
}: UseTimerOptions = {}) {
  const [timeLeft, setTimeLeft] = useState<number>(initialTime);
  const [isRunning, setIsRunning] = useState<boolean>(false);

  // 1. Ref for Timer ID (Persists across re-renders without triggering them)
  const timerIdRef = useRef<NodeJS.Timeout | null>(null);

  // 2. Ref for Callback (Prevents stale closure bugs in setInterval)
  const onExpireRef = useRef(onExpire);
  useEffect(() => {
    onExpireRef.current = onExpire;
  }, [onExpire]);

  // Clear timer helper
  const clearTimer = useCallback(() => {
    if (timerIdRef.current !== null) {
      clearInterval(timerIdRef.current);
      timerIdRef.current = null;
    }
  }, []);

  // Controls: Start / Pause / Resume / Reset
  const start = useCallback(() => {
    setIsRunning(true);
  }, []);

  const pause = useCallback(() => {
    setIsRunning(false);
  }, []);

  const reset = useCallback(
    (newTime = initialTime) => {
      clearTimer();
      setIsRunning(false);
      setTimeLeft(newTime);
    },
    [initialTime, clearTimer]
  );

  // 3. Core Timer Logic using useEffect
  useEffect(() => {
    if (!isRunning) {
      clearTimer();
      return;
    }

    timerIdRef.current = setInterval(() => {
      setTimeLeft((prevTime) => {
        if (prevTime <= 1) {
          clearTimer();
          setIsRunning(false);
          if (onExpireRef.current) {
            onExpireRef.current();
          }
          return 0;
        }
        return prevTime - 1;
      });
    }, interval);

    // 4. Cleanup on unmount or dependency change
    return () => clearTimer();
  }, [isRunning, interval, clearTimer]);

  // Format helper (e.g., 01:30)
  const formattedTime = `${String(Math.floor(timeLeft / 60)).padStart(2, '0')}:${String(
    timeLeft % 60
  ).padStart(2, '0')}`;

  return {
    timeLeft,
    formattedTime,
    isRunning,
    start,
    pause,
    reset,
  };
}

```

### Key React Patterns Used

1. **`useRef` for Interval Storage:** `timerIdRef` holds the `setInterval` identifier. Since mutating a `.current` value doesn't trigger a component re-render, it avoids unnecessary re-renders when managing timer lifecycle.
2. **`useRef` for Stale Closure Prevention:** `onExpireRef` guarantees that when `setInterval` executes after multiple renders, it always calls the latest version of `onExpire` passed by the parent component.
3. **`useEffect` Cleanup:** The `useEffect` cleanup return function (`return () => clearTimer()`) automatically clears the interval if the component unmounts or if `isRunning` changes, preventing memory leaks and orphaned background processes.

Both **debouncing** and **throttling** are techniques used to control how often a function executes over time. They are essential for optimizing performance when handling high-frequency events like scrolling, resizing, or typing.

---

### Comparison at a Glance

| Feature                | Debouncing                                                                                                                   | Throttling                                                                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Execution Strategy** | Waits for a **pause** in events. Resets the delay timer on every new event.                                                  | Guarantees execution at **fixed time intervals**, regardless of event frequency.                                                          |
| **Analogy**            | **Elevator Door:** The door stays open as long as new people keep entering. It only closes and moves after a pause in entry. | **Machine Gun Fire:** Holding down the trigger fires bullets at a steady rate (e.g., 1 bullet every 100ms), ignoring continuous pressure. |
| **Common Uses**        | Auto-complete search inputs, form auto-save, resize layout recalculations.                                                   | Infinite scroll triggers, window scroll position tracking, drag-and-drop mouse movements.                                                 |

### 1. Debouncing

Debouncing delays the execution of a function until a specified amount of time has elapsed since the last time it was called. If a new event fires before the timer finishes, the previous timer is canceled and restarted.

#### Implementation

```javascript
function debounce(func, delay = 300) {
  let timerId;

  return function (...args) {
    // 1. Clear any existing timer
    clearTimeout(timerId);

    // 2. Schedule a new timer
    timerId = setTimeout(() => {
      func.apply(this, args);
    }, delay);
  };
}

```

#### Practical Example: Search Input Auto-Complete

Without debouncing, making an API call on every keystroke sends 10 requests for a 10-character search string. With debouncing, only 1 request is sent after the user stops typing.

```javascript
// Simulated API Fetch function
function fetchSearchResults(query) {
  console.log(`📡 API Request sent for: "${query}" at ${new Date().toLocaleTimeString()}`);
}

// Wrap with a 500ms debounce
const debouncedSearch = debounce(fetchSearchResults, 500);

// Simulating typing "REACT" rapidly
debouncedSearch("R");     // Timer set
debouncedSearch("RE");    // Prev timer cleared, new timer set
debouncedSearch("REA");   // Prev timer cleared, new timer set
debouncedSearch("REACT"); // Prev timer cleared, new timer set

// Output after 500ms of inactivity:
// 📡 API Request sent for: "REACT" at 10:00:00 AM

```

### 2. Throttling

Throttling ensures that a function is executed at most once within a specified time window. Even if the user triggers the event 100 times in 1 second, a throttled function with a 200ms limit will execute only 5 times.

#### Implementation

```javascript
function throttle(func, limit = 300) {
  let inThrottle = false;

  return function (...args) {
    if (!inThrottle) {
      // 1. Execute the function immediately
      func.apply(this, args);
      inThrottle = true;

      // 2. Block execution for the specified limit duration
      setTimeout(() => {
        inThrottle = false;
      }, limit);
    }
  };
}

```

#### Practical Example: Window Scroll Listener

Checking the page scroll position on every pixel shift can severely lag the main UI thread. Throttling restricts the execution to a manageable rate (e.g., once every 200ms).

```javascript
function handleScroll() {
  console.log(`📜 Scroll position calculated at ${new Date().toLocaleTimeString()}`);
}

// Wrap with a 200ms throttle
const throttledScroll = throttle(handleScroll, 200);

// Attach to window scroll event
window.addEventListener('scroll', throttledScroll);

```

### React Custom Hooks Pattern

In React, use `useRef` to persist the debounced or throttled callback across re-renders without re-instantiating the timer wrapper.

```tsx
import { useEffect, useRef } from 'react';

export function useDebounce<T extends (...args: any[]) => void>(callback: T, delay: number) {
  const callbackRef = useRef(callback);
  
  // Keep latest reference to prevent stale closures
  useEffect(() => {
    callbackRef.current = callback;
  }, [callback]);

  const timerRef = useRef<NodeJS.Timeout | null>(null);

  return (...args: Parameters<T>) => {
    if (timerRef.current) clearTimeout(timerRef.current);
    timerRef.current = setTimeout(() => {
      callbackRef.current(...args);
    }, delay);
  };
}

```

### Scenario Breakdown

1. **Search Bar (Debounced - 500ms):**

* **The Problem:** When a user types `"wireless headphones"`, firing an API request on every keystroke causes 19 unnecessary API calls, leading to server overload, race conditions, and heavy network payload.
* **The Fix:** Wait until the user stops typing for 500ms before triggering the API search.

1. **Scroll Telemetry (Throttled - 300ms):**

* **The Problem:** Tracking how far down a user scrolls for analytics triggers hundreds of `scroll` events per second, causing layout thrashing and freezing the main thread (high INP penalty).
* **The Fix:** Execute the tracking calculation at most once every 300ms.

import React, { useState, useEffect, useRef, useCallback } from 'react';

// ==========================================
// 1. REUSABLE TIMING UTILITIES
// ==========================================

/**
 * Creates a debounced function that delays invocation until 'delay' ms 
 * have elapsed since the last time it was called.
 */
function debounce<T extends (...args: any[]) => void>(func: T, delay: number) {
  let timerId: NodeJS.Timeout;
  return function (this: any, ...args: Parameters<T>) {
    clearTimeout(timerId);
    timerId = setTimeout(() => func.apply(this, args), delay);
  };
}

/**
 * Creates a throttled function that only invokes 'func' at most once 
 * per 'limit' milliseconds.
 */
function throttle<T extends (...args: any[]) => void>(func: T, limit: number) {
  let inThrottle = false;
  return function (this: any, ...args: Parameters<T>) {
    if (!inThrottle) {
      func.apply(this, args);
      inThrottle = true;
      setTimeout(() => (inThrottle = false), limit);
    }
  };
}

// ==========================================
// 2. REAL-WORLD COMPONENT
// ==========================================

export default function ECommerceDashboard() {
  const [searchTerm, setSearchTerm] = useState('');
  const [searchResults, setSearchResults] = useState<string[]>([]);
  const [isSearching, setIsSearching] = useState(false);
  const [apiCallCount, setApiCallCount] = useState(0);

  const [scrollPercentage, setScrollPercentage] = useState(0);
  const [scrollEventCount, setScrollEventCount] = useState(0);

  // ----------------------------------------------------
  // USE CASE 1: DEBOUNCED API SEARCH
  // ----------------------------------------------------
  
  // Simulated Backend Search API
  const fetchSearchResultsFromAPI = (query: string) => {
    if (!query.trim()) {
      setSearchResults([]);
      setIsSearching(false);
      return;
    }

    // Increment API count to demonstrate savings
    setApiCallCount((prev) => prev + 1);

    // Mock response
    setTimeout(() => {
      setSearchResults([
        `${query} - Model Alpha`,
        `${query} - Pro Edition`,
        `${query} - Wireless Max`,
      ]);
      setIsSearching(false);
    }, 200);
  };

  // Persist debounced instance across re-renders using useRef
  const debouncedSearchRef = useRef(
    debounce((query: string) => {
      fetchSearchResultsFromAPI(query);
    }, 500)
  );

  const handleInputChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setSearchTerm(value);
    
    if (value.trim()) {
      setIsSearching(true);
    }
    
    // Trigger debounced function
    debouncedSearchRef.current(value);
  };

  // ----------------------------------------------------
  // USE CASE 2: THROTTLED SCROLL TELEMETRY
  // ----------------------------------------------------

  const handleScrollTelemetry = useCallback(() => {
    const scrollTop = window.scrollY;
    const docHeight = document.documentElement.scrollHeight - window.innerHeight;
    const scrollPercent = Math.round((scrollTop / docHeight) * 100);

    setScrollPercentage(isNaN(scrollPercent) ? 0 : scrollPercent);
    setScrollEventCount((prev) => prev + 1);
  }, []);

    // Throttle scroll listener to execute at most once every 300ms
    const throttledScrollHandler = throttle(handleScrollTelemetry, 300);

    window.addEventListener('scroll', throttledScrollHandler);
    return () => window.removeEventListener('scroll', throttledScrollHandler);
  }, [handleScrollTelemetry]);

  return (
    <div style={{ padding: '24px', fontFamily: 'sans-serif', minHeight: '200vh' }}>
      <h2>E-Commerce Dashboard Telemetry</h2>

      {/* SEARCH SECTION (DEBOUNCED) */}
      <section style={cardStyle}>
        <h3>1. Debounced Product Search (500ms Delay)</h3>
        <p style={{ color: '#666' }}>
          Type rapidly in the input below. Notice that API requests execute <strong>only after you pause typing for 500ms</strong>.
        </p>

        <input
          type="text"
          value={searchTerm}
          onChange={handleInputChange}
          placeholder="Search items (e.g. 'Laptop')..."
          style={inputStyle}
        />

        <div style={{ marginTop: '12px' }}>
          <p>Status: {isSearching ? '⏳ Waiting for typing pause...' : '✅ Ready'}</p>
          <p><strong>Actual API Calls Triggered:</strong> <span style={badgeStyle}>{apiCallCount}</span></p>
        </div>

        {searchResults.length > 0 && (
          <ul style={{ background: '#f8fafc', padding: '12px 24px', borderRadius: '4px' }}>
            {searchResults.map((item, idx) => (
              <li key={idx}>{item}</li>
            ))}
          </ul>
        )}
      </section>

      {/* SCROLL SECTION (THROTTLED) */}
      <section style={cardStyle}>
        <h3>2. Throttled Scroll Analytics (300ms Limit)</h3>
        <p style={{ color: '#666' }}>
          Scroll down the page. Native scroll triggers hundreds of times per second, but this throttled event executes <strong>at most once every 300ms</strong>.
        </p>

### What Happens Behind the Scenes?

1. **Search Input (Debounce):**

* If a user types `"HEADPHONES"` (10 keystrokes) in 1 second:
* Without Debounce $\rightarrow$ **10 API Requests**
* With Debounce ($500\text{ms}$) $\rightarrow$ **1 API Request**

1. **Page Scroll (Throttle):**

* If a user scrolls continuously for 3 seconds:
* Without Throttle $\rightarrow$ **$\approx 180\text{ to }300$ event calls** (causes UI micro-stutters)
* With Throttle ($300\text{ms}$) $\rightarrow$ **$\approx 10$ event calls** (smooth 60 FPS scrolling)
