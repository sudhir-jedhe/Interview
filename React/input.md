# The `<input>` Component

The built-in browser `<input>` component allows you to render various kinds of form fields (text, checkboxes, radios, etc.) to capture user data.

---

## Props Reference

The `<input>` component supports all standard HTML element props.

### Controlled Input Props

To make an input **controlled** (managed by React state), use these props. When using these, you **must** also provide an `onChange` handler.

* **`value`** *(string)*: Controls the text inside a text input, or specifies the submitted form data for a radio button.
* **`checked`** *(boolean)*: Controls whether a checkbox or radio button is currently selected.
* **`onChange`** *(function)*: Fires immediately on every user interaction (e.g., every keystroke) to synchronously update the state.

### Uncontrolled Input Props

To let the DOM manage the input's state, use these props to set the *initial* value only:

* **`defaultValue`** *(string)*: Specifies the initial value for a text input.
* **`defaultChecked`** *(boolean)*: Specifies the initial state for `type="checkbox"` or `type="radio"`.

### Form Action Overrides

If your input acts as a submit button (`type="submit"` or `type="image"`), these props override the parent `<form>` attributes:

* **`formAction`**: Overrides `<form action>`. Accepts a URL or a function (Server/Client Action).
* **`formEnctype`**, **`formMethod`**, **`formNoValidate`**, **`formTarget`**: Override their respective `<form>` counterparts.

---

## ⚠️ Important Caveats

1. **Checkboxes:** Use `checked` or `defaultChecked`, not `value` or `defaultValue`.
2. **Controlled State:** If an input receives a `value` (string) or `checked` (boolean) prop, React treats it as controlled.
3. **Consistency:** An input cannot be both controlled and uncontrolled simultaneously. It also cannot switch between the two over its lifetime.
4. **Synchronous Updates:** Every controlled input requires an `onChange` handler that *synchronously* updates the state to match `e.target.value`.

## Usage Guide

### 1. Displaying Inputs of Different Types

By default, an `<input>` renders as a text field. Pass the `type` prop to change its behavior.

```jsx
export default function MyForm() {
  return (
    <>
      <label>Text: <input name="username" /></label>
      <label>Checkbox: <input type="checkbox" name="subscribe" /></label>
      
      <p>Radio buttons:</p>
      <label><input type="radio" name="plan" value="free" /> Free</label>
      <label><input type="radio" name="plan" value="pro" /> Pro</label>
    </>
  );
}

```

### 2. Providing a Label

For accessibility and usability, always associate inputs with a `<label>`. You can either nest the input inside the label, or use `htmlFor` and an ID generated by `useId`.

```jsx
import { useId } from 'react';

export default function Form() {
  const ageInputId = useId();
  
  return (
    <>
      {/* Nested label (Preferred) */}
      <label>
        First name: <input name="firstName" />
      </label>

      {/* Linked via ID */}
      <label htmlFor={ageInputId}>Age:</label>
      <input id={ageInputId} name="age" type="number" />
    </>
  );
}

```

### 3. Reading Input Values on Form Submit (Uncontrolled)

If you wrap your inputs in a `<form>`, you can read all their values upon submission using the native `FormData` API. **Ensure every input has a `name` attribute.**

```jsx
export default function MyForm() {
  function handleSubmit(e) {
    e.preventDefault();

    const form = e.target;
    const formData = new FormData(form);
    
    // Convert to a plain object: { username: "...", subscribe: "on" }
    const formJson = Object.fromEntries(formData.entries());
    console.log(formJson);
  }

  return (
    <form onSubmit={handleSubmit}>
      <label>Username: <input name="username" defaultValue="Guest" /></label>
      <button type="submit">Submit</button>
    </form>
  );
}

```

### 4. Controlling an Input with State

If you need to update the UI on every keystroke, validate in real-time, or update the input programmatically, use a controlled input.

> **Note:** Initialize text states with an empty string `''`, never `null` or `undefined`.

```jsx
import { useState } from 'react';

export default function ControlledForm() {
  const [firstName, setFirstName] = useState('');
  
  return (
    <label>
      First name:
      <input
        value={firstName}
        onChange={e => setFirstName(e.target.value)}
      />
    </label>
  );
}

```

### 5. Optimizing Re-rendering

Typing into a controlled input updates state on every keystroke. If that state sits at the top of a massive component tree, typing will feel laggy.

**Solution:** Isolate the input state into its own small component so only the input re-renders, or use `useDeferredValue` if the rest of the page must react to the input.

## Troubleshooting

### "You provided a value prop... without an onChange handler"

If you provide `value={...}` but no `onChange`, React makes the field read-only.

* **Fix A (Uncontrolled):** If you just wanted an initial value, change `value` to `defaultValue`.
* **Fix B (Controlled):** Add an `onChange={e => setState(e.target.value)}` handler.
* **Fix C (Intentional):** If it's supposed to be read-only, add the `readOnly={true}` prop to silence the warning.

*(The same applies to `checked` vs `defaultChecked` for checkboxes).*

### My checkbox doesn't update when clicked

Ensure you are reading `e.target.checked` in your event handler, **not** `e.target.value`.

```jsx
// ✅ Correct for checkboxes
<input 
  type="checkbox" 
  checked={isSubscribed} 
  onChange={e => setIsSubscribed(e.target.checked)} 
/>

```

### My text input caret jumps to the beginning on every keystroke

This happens if you do not update the state *synchronously* to the exact value of `e.target.value`.

* **Do not** update it asynchronously (e.g., inside a `setTimeout`).
* **Do not** force format it inside the `onChange` (e.g., `setFirstName(e.target.value.toUpperCase())`).
* Ensure the component isn't losing its `key` or re-mounting on every render.

### "A component is changing an uncontrolled input to be controlled"

You cannot pass `value={undefined}` initially and later pass `value="hello"`. React needs to know immediately if the input is controlled or not.

* **Fix:** If your data comes from an API, initialize your state as `''` (empty string) instead of `null`/`undefined`, or fall back to an empty string in the JSX: `<input value={data ?? ''} />`.
