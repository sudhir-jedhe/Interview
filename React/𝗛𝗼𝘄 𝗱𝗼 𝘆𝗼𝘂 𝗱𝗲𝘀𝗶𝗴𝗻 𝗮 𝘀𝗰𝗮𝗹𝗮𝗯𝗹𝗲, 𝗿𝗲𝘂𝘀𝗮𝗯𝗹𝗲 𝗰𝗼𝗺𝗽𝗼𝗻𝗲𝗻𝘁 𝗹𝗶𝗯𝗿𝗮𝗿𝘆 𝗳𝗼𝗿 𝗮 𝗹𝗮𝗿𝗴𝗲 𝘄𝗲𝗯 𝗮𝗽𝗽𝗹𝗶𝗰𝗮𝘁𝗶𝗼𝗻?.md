Designing a scalable, reusable component library requires separating headless logic, design tokens, and visual presentation into a multi-tiered architecture that scales across teams and product domains.

---

### 1. Architectural Foundation: Atomic Design Hierarchy

Map UI elements to a strict hierarchy to prevent leaky abstractions and cyclical dependencies:

```
┌─────────────────────────────────────────────────────────────┐
│  Templates / Patterns (DashboardLayout, CheckoutFlow)       │
├─────────────────────────────────────────────────────────────┤
│  Organisms (DataTable, NavigationBar, FilterSidebar)        │
├─────────────────────────────────────────────────────────────┤
│  Molecules (SearchBar, FormField, PaginationControl)        │
├─────────────────────────────────────────────────────────────┤
│  Atoms (Button, Input, Badge, Icon, Spinner, Typography)    │
├─────────────────────────────────────────────────────────────┤
│  Design Tokens (Colors, Spacing, Radius, Elevations, Motion)│
└─────────────────────────────────────────────────────────────┘

```

* **Design Tokens (Base Layer):** Platform-agnostic JSON definitions compiling down to CSS variables and TypeScript constants via Style Dictionary.
* **Atoms:** Indivisible primitive UI elements that cannot be broken down further without losing practical utility.
* **Molecules:** Functional compositions of 2–3 atoms (e.g., `Input` + `Label` + `ErrorMessage` = `FormField`).
* **Organisms:** Complex, self-contained interactive widgets with internal layout coordination (e.g., `DataTable` with sorting, search, and pagination).
* **Templates / Patterns:** Reusable structural layouts providing slots for organisms and molecules without hardcoded domain data.

### 2. Core Component Design Patterns

To prevent "mega-props" (`<Modal hasSecondaryButton="{true}" isFooterFixed="{false}"/>`), leverage composable patterns:

#### A. Compound Components (Inversion of Control)

Expose sub-components sharing an implicit React Context. This hands composition and layout control over to the consumer:

```tsx
import React, { createContext, useContext, useState } from 'react';

const TabsContext = createContext<{ activeTab: string; setActiveTab: (id: string) => void } | null>(null);

export function Tabs({ defaultValue, children }: { defaultValue: string; children: React.ReactNode }) {
  const [activeTab, setActiveTab] = useState(defaultValue);
  return (
    <TabsContext.Provider value={{ activeTab, setActiveTab }}>
      <div className="tabs-root">{children}</div>
    </TabsContext.Provider>
  );
}

Tabs.List = function TabList({ children }: { children: React.ReactNode }) {
  return <div role="tablist" className="tabs-list">{children}</div>;
};

Tabs.Trigger = function TabTrigger({ value, children }: { value: string; children: React.ReactNode }) {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error('Tabs.Trigger must be inside Tabs');
  const isActive = ctx.activeTab === value;
  return (
    <button
      role="tab"
      aria-selected={isActive}
      onClick={() => ctx.setActiveTab(value)}
      className={`tab-trigger ${isActive ? 'active' : ''}`}
    >
      {children}
    </button>
  );
};

Tabs.Content = function TabContent({ value, children }: { value: string; children: React.ReactNode }) {
  const ctx = useContext(TabsContext);
  if (!ctx || ctx.activeTab !== value) return null;
  return <div role="tabpanel" className="tab-content">{children}</div>;
};

```

#### B. Polymorphism (`as` / `asChild`)

Allow components to render alternate HTML tags or third-party router links (`<Link>`, `<NavLink>`) while preserving the library's styling and ARIA attributes:

```tsx
import { Slot } from '@radix-ui/react-slot';

interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  asChild?: boolean;
}

export const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ asChild = false, className, ...props }, ref) => {
    const Component = asChild ? Slot : 'button';
    return <Component ref={ref} className={`btn ${className || ''}`} {...props} />;
  }
);

// Usage with Next.js or React Router:
// <Button asChild><Link to="/dashboard">Dashboard</Link></Button>

```

#### C. Type-Safe Variant-Driven Styling (CVA)

Use `class-variance-authority` (CVA) to manage visual states systematically:

```typescript
import { cva, type VariantProps } from 'class-variance-authority';

export const buttonVariants = cva(
  'inline-flex items-center justify-center font-medium transition-colors focus-visible:outline-none focus-visible:ring-2 disabled:pointer-events-none disabled:opacity-50',
  {
    variants: {
      intent: {
        primary: 'bg-blue-600 text-white hover:bg-blue-700 active:bg-blue-800',
        secondary: 'bg-slate-100 text-slate-900 hover:bg-slate-200',
        danger: 'bg-red-600 text-white hover:bg-red-700',
        outline: 'border border-slate-300 bg-transparent hover:bg-slate-100',
      },
      size: {
        sm: 'h-8 px-3 text-xs rounded-md',
        md: 'h-10 px-4 text-sm rounded-lg',
        lg: 'h-12 px-6 text-base rounded-lg',
      },
    },
    defaultVariants: {
      intent: 'primary',
      size: 'md',
    },
  }
);

export type ButtonVariantProps = VariantProps<typeof buttonVariants>;

```

### 3. Storybook for Isolated Development & Testing

Storybook serves as the component sandbox, living documentation, and automated test harness.

```
.storybook/
├── main.ts              # Framework config, addons (a11y, interactions, coverage)
└── preview.ts           # Global decorators (ThemeProviders, CSS imports, MSW loaders)

```

#### A. Interactive Stories with Controls & Documentation

```tsx
// src/components/Button.stories.tsx
import type { Meta, StoryObj } from '@storybook/react';
import { Button } from './Button';

const meta: Meta<typeof Button> = {
  title: 'Atoms/Button',
  component: Button,
  tags: ['autodocs'],
  argTypes: {
    intent: {
      control: { type: 'select' },
      options: ['primary', 'secondary', 'danger', 'outline'],
    },
    size: {
      control: { type: 'radio' },
      options: ['sm', 'md', 'lg'],
    },
    disabled: { control: 'boolean' },
  },
};

export default meta;
type Story = StoryObj<typeof Button>;

export const Primary: Story = {
  args: {
    intent: 'primary',
    size: 'md',
    children: 'Confirm Action',
  },
};

```

#### B. Component Interaction Testing (`play` function)

Automate user behavior simulations directly inside Storybook using `@storybook/test`:

```tsx
// src/components/FormField.stories.tsx
import type { Meta, StoryObj } from '@storybook/react';
import { expect, userEvent, within } from '@storybook/test';
import { FormField } from './FormField';

export const SubmitsValidEmail: StoryObj<typeof FormField> = {
  play: async ({ canvasElement, step }) => {
    const canvas = within(canvasElement);
    const input = canvas.getByLabelText(/email address/i);
    const submitBtn = canvas.getByRole('button', { name: /submit/i });

    await step('Type invalid email and verify error', async () => {
      await userEvent.type(input, 'invalid-email');
      await userEvent.click(submitBtn);
      await expect(canvas.getByText(/please enter a valid email/i)).toBeInTheDocument();
    });

    await step('Correct email and verify success', async () => {
      await userEvent.clear(input);
      await userEvent.type(input, 'alex@example.com');
      await userEvent.click(submitBtn);
      await expect(canvas.queryByText(/please enter a valid email/i)).not.toBeInTheDocument();
    });
  },
};

```

#### C. Automated Accessibility Auditing (`@storybook/addon-a11y`)

The accessibility addon runs `axe-core` against rendered components in every state (hover, open, focused), surfacing WCAG 2.1 AA violations (contrast ratio failures, missing ARIA labels, focus traps) directly in the Storybook UI and CI build pipeline.

### 4. Monorepo Distribution & Packaging

For enterprise scalability, manage the library via a Turborepo monorepo with explicit export maps:

| Package           | Purpose                                                           | Tooling                         |
| ----------------- | ----------------------------------------------------------------- | ------------------------------- |
| `@org/tokens`     | W3C Design Tokens JSON compiled to CSS/TS                         | Style Dictionary                |
| `@org/primitives` | Headless accessibility & state logic                              | Radix UI / React Aria           |
| `@org/ui`         | Styled, variant-driven components (Atoms $\rightarrow$ Organisms) | CVA, Vanilla Extract / Tailwind |
| `@org/icons`      | Optimized, tree-shakeable SVG icon components                     | SVGR                            |

* Configure `"sideEffects": false` in each `package.json` to enable dead-code elimination.
* Provide dual ESM/CJS exports via `tsup` or `vite build --mode lib`.
* Enforce versioning and release notes using **Changesets** on pull requests.
