- How would you prevent multiple API hits on rapid user interaction?
- Would you use lodash throttle, debounce, or custom logic?
Preventing multiple API hits during rapid user interactions (such as repeated button clicks) is a fundamental requirement for building resilient, user-friendly React interfaces.

Below is a complete System Design and Low-Level Design (LLD) breakdown, an architectural comparison, and a production-grade TypeScript implementation.

---

# 1. Architectural Strategy Comparison

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │                      Rate Limiting Strategies                          │
 ├───────────────────┬───────────────────┬────────────────────────────────┤
 │   1. Debounce     │    2. Throttle    │ 3. Disabled State / Abort      │
 └───────────────────┴───────────────────┴────────────────────────────────┘

```

| Technique                                | How It Works                                                                                                                                                       | Best Used For                                                | Drawbacks for Action Buttons                                                                                                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Debounce**                             | Delays function execution until $N\text{ ms}$ have passed **after the last interaction**.                                                                          | Search inputs, auto-save drafts, window resize handlers.     | **Poor UX for buttons:** The API call is delayed *after* the user stops clicking. If a user clicks a "Submit Order" button once, they must wait $N\text{ ms}$ before the request even starts. |
| **Throttle**                             | Guarantees execution **at most once every $N\text{ ms}$**, regardless of click frequency.                                                                          | Infinite scroll, window scroll/resize, like/upvote buttons.  | First click fires immediately, but subsequent rapid clicks during the cooldown window are silently ignored or queued.                                                                         |
| **Leading Edge + Disable (Recommended)** | **Fires immediately on the first click**, then instantly disables the button or ignores subsequent clicks until the async operation settles or a cooldown expires. | Form submissions, payment processing, transactional actions. | **Best Practice.** Gives immediate feedback while physically preventing duplicate network dispatches.                                                                                         |

# 2. Decision Framework: Lodash vs. Custom Logic

- **Lodash (`lodash.throttle` / `lodash.debounce`):** Easy to import, but tricky in React because functional components recreate function instances on every re-render. You must wrap `lodash.throttle` in `useCallback` or `useMemo` with proper ref-persisted cleanups to avoid memory leaks.
- **Custom React Hook (Recommended):** Writing a custom hook using `useRef` or tracking an `isLoading`/`isThrottled` state gives you **full control over async promises**, automatic cleanup on component unmount, zero third-party dependencies, and accurate button disabling states.

# 3. Complete Production Implementation (TypeScript + React)

Here are the two industry-standard patterns for button rate limiting.

---

### Pattern A: Leading-Edge Async Throttle Hook (`useThrottledCallback`)

Fires the click handler **immediately on the first click**, then blocks all further clicks until the specified cooldown period ($N\text{ ms}$) expires.

```typescript
import { useRef, useCallback, useEffect } from 'react';

/**
 * Custom hook that creates a leading-edge throttled click handler.
 * @param callback The function to execute on button click.
 * @param delay Cooldown window in milliseconds (default: 1000ms).
 */
export function useThrottledCallback<T extends (...args: any[]) => any>(
  callback: T,
  delay = 1000
) {
  const lastRunRef = useRef<number>(0);
  const callbackRef = useRef<T>(callback);

  // Keep latest callback reference without invalidating the throttled handler
  useEffect(() => {
    callbackRef.current = callback;
  }, [callback]);

  return useCallback(
    (...args: Parameters<T>) => {
      const now = Date.now();

      // Check if cooldown period has elapsed since the last execution
      if (now - lastRunRef.current >= delay) {
        lastRunRef.current = now;
        callbackRef.current(...args);
      } else {
        console.warn(`[Rate Limiter] Click ignored. Cooldown active (${delay}ms).`);
      }
    },
    [delay]
  );
}

```

---

### Pattern B: Promise-Aware Async Lock Button Hook (`useAsyncLock`)

For transactional buttons (e.g., "Submit Order" or "Pay Now"), rate-limiting via fixed timeouts isn't enough because network latency can exceed the timeout duration.

This pattern **locks the button for the entire duration of the async Promise execution** and unlocks it only when the API call resolves or fails.

```typescript
import { useState, useRef, useCallback } from 'react';

export function useAsyncLock<T extends (...args: any[]) => Promise<any>>(asyncFn: T) {
  const [isLoading, setIsLoading] = useState(false);
  const isExecutingRef = useRef(false);

  const execute = useCallback(
    async (...args: Parameters<T>) => {
      // Prevent execution if request is already in-flight
      if (isExecutingRef.current) {
        console.warn('[Rate Limiter] Operation already in progress. Ignoring click.');
        return;
      }

      isExecutingRef.current = true;
      setIsLoading(true);

      try {
        await asyncFn(...args);
      } finally {
        isExecutingRef.current = false;
        setIsLoading(false);
      }
    },
    [asyncFn]
  );

  return { execute, isLoading };
}

```

## 4. UI Usage Example

```tsx
import React from 'react';
import { useThrottledCallback } from './useThrottledCallback';
import { useAsyncLock } from './useAsyncLock';

export const RateLimitedButtonDemo: React.FC = () => {
  // Scenario 1: Like Button (Throttled Cooldown of 1500ms)
  const handleLikeClick = useThrottledCallback(() => {
    console.log('❤️ Like API Request Dispatched at:', new Date().toLocaleTimeString());
  }, 1500);

  // Scenario 2: Payment Button (Locked during API Request In-Flight)
  const processPayment = async () => {
    console.log('💳 Payment Processing Started...');
    await new Promise((resolve) => setTimeout(resolve, 2000)); // Simulate API latency
    console.log('✅ Payment Processed Successfully!');
  };

  const { execute: handlePaymentClick, isLoading } = useAsyncLock(processPayment);

  return (
    <div style={{ display: 'flex', flexDirection: 'column', gap: '20px', padding: '32px' }}>
      <div>
        <h3>1. Throttled Action Button (Cooldown: 1.5s)</h3>
        <button onClick={handleLikeClick} style={{ padding: '8px 16px', cursor: 'pointer' }}>
          ❤️ Like Post (Fast-click me!)
        </button>
      </div>

      <div>
        <h3>2. Promise-Locked Transactional Button (Auto-Disables)</h3>
        <button
          onClick={handlePaymentClick}
          disabled={isLoading}
          style={{
            padding: '10px 20px',
            cursor: isLoading ? 'not-allowed' : 'pointer',
            backgroundColor: isLoading ? '#cbd5e1' : '#3b82f6',
            color: '#fff',
            border: 'none',
            borderRadius: '6px',
          }}
        >
          {isLoading ? '⏳ Processing Payment...' : '💳 Pay Now ($99)'}
        </button>
      </div>
    </div>
  );
};

```

# Key LLD Takeaways

1. **Prefer "Leading-Edge" Execution for Buttons:** Unlike search inputs where trailing debounce makes sense, button clicks should respond on the **first tap** immediately.
2. **Combine Lock States with Visual Disabling:** Always reflect the locked or throttled state visually (`disabled={isLoading}` or `aria-disabled="true"`) so the user understands why subsequent clicks aren't registering.
3. **Use AbortController for In-Flight Cancellations:** For high-frequency action buttons (like toggling bookmark/favorite), combine custom throttling with `AbortController` to cancel stale in-flight HTTP requests.
