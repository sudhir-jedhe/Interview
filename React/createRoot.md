**`createRoot`** is the entry point for all modern React applications (React 18 and above). It tells React to take control of a specific HTML element and creates a root data structure to manage rendering your components inside it.

Here is a detailed breakdown of its API, practical usage scenarios, and solutions to common troubleshooting errors.

---

## 1. Reference

### `createRoot(domNode, options?)`

Call this method to create a React root.

| Parameter                        | Description                                                                                                                                              |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`domNode`**                    | The actual HTML element from your document (e.g., `document.getElementById('root')`). React will take complete control of this element and its children. |
| **`options` (Optional)**         | An object containing configuration for the root.                                                                                                         |
| **`options.onRecoverableError`** | A callback function called when React automatically recovers from errors.                                                                                |
| **`options.identifierPrefix`**   | A string prefix React uses for IDs generated by `useId` (useful to avoid conflicts if multiple React roots exist on one page).                           |

**Returns:** A `root` object with two methods: `render` and `unmount`.

### `root.render(reactNode)`

This method tells React to display a specific piece of JSX (a React node) inside the root DOM node. On the first call, it clears any existing HTML inside the container and renders your React component. If called again, React will calculate the differences (diffing) and update the DOM efficiently.

### `root.unmount()`

This destroys the React tree inside the root. It unmounts all components, runs all `useEffect` cleanup functions, and removes event listeners from the DOM node. This is primarily used when React is embedded inside another framework (like Angular or jQuery) and the container is being removed from the screen.

---

## 2. Usage Scenarios

### Rendering an app fully built with React

If you are building a Single Page Application (SPA), you will typically call `createRoot` exactly once when your application starts.

```jsx
import { createRoot } from 'react-dom/client';
import App from './App.js';

const root = createRoot(document.getElementById('root'));
root.render(<App />);

```

### Rendering a page partially built with React

If you are adding React to an existing HTML page (like a PHP, Ruby on Rails, or WordPress site), you don't need a single root. You can call `createRoot` multiple times to create isolated React "islands" or widgets anywhere on the page.

```jsx
import { createRoot } from 'react-dom/client';
import NavigationBar from './NavigationBar.js';
import ShoppingCart from './ShoppingCart.js';

const navRoot = createRoot(document.getElementById('nav-container'));
navRoot.render(<NavigationBar />);

const cartRoot = createRoot(document.getElementById('cart-container'));
cartRoot.render(<ShoppingCart />);

```

### Updating a root component

You can call `root.render()` multiple times on the same root. React will not destroy and recreate the DOM; instead, it will compare the new JSX with the old JSX and apply only the necessary targeted updates to the browser.

### Error logging in production

By default, React logs errors to the console. In production, you might want to send these errors to an external logging service (like Sentry or Datadog) using the `onRecoverableError` option.

```jsx
const root = createRoot(document.getElementById('root'), {
  onRecoverableError: (error, errorInfo) => {
    myCustomErrorLogger(error, errorInfo.componentStack);
  }
});

```

## 3. Troubleshooting Guide

### I’ve created a root, but nothing is displayed

Calling `createRoot` only initializes the data structure; it doesn't draw anything to the screen. You must explicitly call the render method afterward.

* **Fix:** Ensure you are executing `root.render(<App/>)` immediately after creating the root.

### I’m getting an error: “You passed a second argument to root.render”

This happens when you accidentally mix React 17 syntax with React 18 syntax. In React 17, the API was `ReactDOM.render(component, container)`. In React 18, the container is passed to `createRoot`, and only the component is passed to `render`.

* **Fix:** Change `root.render(<App/>, document.getElementById('root'))` to `root.render(<App/>)`.

### I’m getting an error: “Target container is not a DOM element”

React cannot find the HTML element you are trying to attach to. This usually means `document.getElementById` returned `null`.

* **Fix:** Check that your `index.html` file actually contains an element with that exact ID. Also, ensure your `<script>` tag is placed *after* the HTML element, or use the `defer` attribute on your script so it waits for the DOM to load before running.

### I’m getting an error: “Functions are not valid as a React child.”

This occurs when you pass a component *definition* (the function itself) into the render method, rather than a React *element* (JSX).

* **Fix:** Change `root.render(App)` to `root.render(<App/>)`.

### My server-rendered HTML gets re-created from scratch

If you are using Server-Side Rendering (SSR) via Next.js, Remix, or a custom Node server, the server has already generated the HTML. If you use `createRoot`, React will blow away that HTML and redraw it, causing a visual flash and ruining the performance benefits of SSR.

* **Fix:** Use `hydrateRoot` instead of `createRoot`. This tells React to silently attach event listeners to the existing HTML without destroying it.
