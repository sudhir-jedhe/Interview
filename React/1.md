React Interview Trap: Does React.memo() Stop Re-renders?
This is one of the most misunderstood React interview questions.
Many developers answer it incorrectly.

❌ Wrong Answer
"React.memo() prevents a component from re-rendering."
=> Right Answer
"React.memo() only skips a re-render when the component receives the same props (based on a shallow comparison). It does not stop re-renders caused by state updates or context changes."

Here's what interviewers are actually testing:
• What is React.memo()?
• How does shallow comparison work?
• What types of values are compared?
• Why do functions and objects often cause unnecessary re-renders?
• Why does an inline function break memoization?
• Why does an inline object break memoization?
• When should React.memo() be used?
• When should you avoid React.memo()?
• What is the difference between React.memo(), useMemo(), and useCallback()?
• Does React.memo() improve performance in every application?
• Can a memoized component still re-render?
• What happens when Context changes?
• What happens when the component's own state changes?
• Why can React.memo() sometimes make an application slower?

Key Points
• React.memo() performs a shallow comparison of props.
• Primitive values are compared by value.
• Objects, arrays, and functions are compared by reference.
• New object = New reference = Re-render.
• New array = New reference = Re-render.
• New function = New reference = Re-render.
• Parent re-render does not always mean child re-render.
• React.memo() cannot stop re-renders caused by state updates.
• React.memo() cannot stop re-renders caused by Context updates.
• useCallback() helps keep function references stable.
• useMemo() helps keep object and array references stable.
• React.memo() is an optimization, not a guarantee.
• Measure performance before optimizing.

Interview Question:-
Will Child re-render every time the button is clicked at this block of code.

**Yes, `Child` will re-render EVERY single time the button is clicked.**

Even though `Child` is wrapped in `React.memo()`, it will still re-render on every state update of `Parent`.

---

# Recreated Code Example

```jsx
import React, { useState } from 'react';

const Child = React.memo(({ user }) => {
  console.log("Rendered");
  return <h1>{user.name}</h1>;
});

function Parent() {
  const [count, setCount] = useState(0);

  return (
    <>
      <Child user={{ name: "Priya" }} />
      <button onClick={() => setCount(count + 1)}>+</button>
    </>
  );
}

```

---

# Detailed Step-by-Step Breakdown

### 1. What Happens When the Button is Clicked?

1. The user clicks the button, triggering `setCount(count + 1)`.
2. State changes in `Parent`, forcing `Parent` to re-render.
3. As `Parent` executes its render function again, it encounters:

```jsx
<Child user={{ name: "Priya" }} />

```

1. `Parent` creates a **brand-new inline object literal** in memory: `{ name: "Priya" }`.

---

### 2. Why Does `React.memo()` Fail Here?

`React.memo()` performs a **shallow comparison** (`Object.is`) of the incoming props against the previous props:

```javascript
// Shallow comparison executed internally by React.memo:
prevProps.user === nextProps.user

```

* In JavaScript, **objects are compared by reference, not by value**.
* Every time `Parent` renders, the expression `user={{ name: "Priya" }}` evaluates to a **new object in memory with a brand-new reference address**.
* Because `prevProps.user !== nextProps.user` evaluates to `false`, `React.memo()` concludes that the props have changed and allows `Child` to re-render.

---

# How to Fix It

To make `React.memo()` actually work in this scenario, you must keep the reference of the `user` object stable across re-renders. Here are the three standard solutions:

### Solution 1: Move the Static Object Outside the Component (Best for Constant Data)

If the object is static and does not rely on component props/state, define it outside the render function so it shares a single memory reference:

```jsx
// Object reference is initialized once and stays identical across all renders
const USER_DATA = { name: "Priya" };

function Parent() {
  const [count, setCount] = useState(0);

  return (
    <>
      <Child user={USER_DATA} />
      <button onClick={() => setCount(count + 1)}>+</button>
    </>
  );
}

```

---

### Solution 2: Memoize the Object with `useMemo` (Best for Dynamic Data)

If the object depends on internal state or props, stabilize its reference using `useMemo`:

```jsx
function Parent() {
  const [count, setCount] = useState(0);

  // useMemo ensures user object reference remains stable unless dependencies change
  const user = useMemo(() => ({ name: "Priya" }), []);

  return (
    <>
      <Child user={user} />
      <button onClick={() => setCount(count + 1)}>+</button>
    </>
  );
}

```

---

### Solution 3: Provide a Custom Comparator to `React.memo`

Pass a custom comparison function as the second argument to `React.memo` to perform deep/custom property checks:

```jsx
const Child = React.memo(
  ({ user }) => {
    console.log("Rendered");
    return <h1>{user.name}</h1>;
  },
  (prevProps, nextProps) => {
    // Custom comparison logic: compare values instead of object references
    return prevProps.user.name === nextProps.user.name;
  }
);

```

# Summary Checklist for Interviews

| Prop Type Passed to Memoized Child            | How React Compares It      | Re-renders on Parent State Change?               |
| --------------------------------------------- | -------------------------- | ------------------------------------------------ |
| **Primitive (`string`, `number`, `boolean`)** | Value Comparison           | ❌ **No** (Skipped)                               |
| **Inline Object (`{{ name: "Priya" }}`)**     | New Reference Created      | ✅ **Yes** (Memo broken)                          |
| **Inline Function (`() => doSomething()`)**   | New Reference Created      | ✅ **Yes** (Memo broken - fix with `useCallback`) |
| **`useMemo()` / `useCallback()` Value**       | Stable Reference Preserved | ❌ **No** (Skipped)                               |
