A resilient error-handling architecture prevents a single component failure from crashing the entire application (the "white screen of death"), reports contextual telemetry to monitoring systems like Sentry, and presents actionable, localized recovery paths to the user.

---

### 1. Error Boundary Architecture & Granular Placement

Error boundaries are React class components that catch JavaScript errors anywhere in their child component tree during **rendering, lifecycle methods, and constructors**.

#### What Error Boundaries Catch vs. Miss

* **Caught:** Render errors, JSX runtime failures, lifecycle method crashes (`useEffect` throws inside React reconciliation).
* **Missed:** Asynchronous callbacks (`setTimeout`), event handlers (`onClick`), server-side rendering (SSR), and unhandled Promise rejections. (These must be routed into React or Sentry manually via `try/catch` or `useErrorBoundary()`).

#### Multi-Tiered Placement Strategy

```
┌────────────────────────────────────────────────────────┐
│  Tier 1: Global Root Boundary (Catch-all fallback)     │
│  ┌──────────────────────────────────────────────────┐  │
│  │  Tier 2: Layout / Route Boundary (Page-level)    │  │
│  │  ┌────────────────────────────────────────────┐  │  │
│  │  │  Tier 3: Widget / Component Boundary       │  │  │
│  │  │  (Data tables, charts, comments feeds)     │  │  │
│  │  └────────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘

```

* **Tier 1 (Root Boundary):** Prevents total screen crash; renders a full-page "System Unavailable" view with a reload option.
* **Tier 2 (Route / Layout Boundary):** Wraps page routes. If `/dashboard/analytics` crashes, the navigation sidebar and header remain functional, allowing users to navigate elsewhere.
* **Tier 3 (Widget Boundary):** Isolates unstable third-party widgets (e.g., charts, rich text editors). If the chart component crashes, only that card displays an inline "Failed to load chart" widget with a retry button, leaving the rest of the page intact.

### 2. Modern Reusable Error Boundary with Sentry & Reset Support

```tsx
// src/components/ErrorBoundary.tsx
import React, { Component, ErrorInfo, ReactNode } from 'react';
import * as Sentry from '@sentry/react';

interface Props {
  children: ReactNode;
  fallbackRender?: (props: { error: Error; resetErrorBoundary: () => void }) => ReactNode;
  onReset?: () => void;
  name?: string; // Identifier for Sentry tags
}

interface State {
  hasError: boolean;
  error: Error | null;
}

export class ErrorBoundary extends Component<Props, State> {
  public state: State = {
    hasError: false,
    error: null,
  };

  // 1. Update state so the next render shows the fallback UI
  public static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }

  // 2. Telemetry and Error Logging
  public componentDidCatch(error: Error, errorInfo: ErrorInfo) {
    console.error(`Uncaught error in ${this.props.name || 'Component'}:`, error, errorInfo);

    Sentry.withScope((scope) => {
      scope.setTag('boundary_name', this.props.name || 'anonymous_boundary');
      scope.setExtra('componentStack', errorInfo.componentStack);
      Sentry.captureException(error);
    });
  }

  // 3. Reset the boundary state (Retry capability)
  public resetErrorBoundary = () => {
    if (this.props.onReset) {
      this.props.onReset();
    }
    this.setState({ hasError: false, error: null });
  };

  public render() {
    if (this.state.hasError && this.state.error) {
      if (this.props.fallbackRender) {
        return this.props.fallbackRender({
          error: this.state.error,
          resetErrorBoundary: this.resetErrorBoundary,
        });
      }

      // Default inline graceful fallback UI
      return (
        <div
          role="alert"
          style={{
            padding: '16px',
            border: '1px solid #fee2e2',
            borderRadius: '8px',
            backgroundColor: '#fff5f5',
            color: '#991b1b',
            fontFamily: 'sans-serif',
          }}
        >
          <h4 style={{ margin: '0 0 8px' }}>Something went wrong</h4>
          <p style={{ margin: '0 0 12px', fontSize: '13px' }}>
            {this.state.error.message || 'An unexpected error occurred.'}
          </p>
          <button
            type="button"
            onClick={this.resetErrorBoundary}
            style={{
              padding: '6px 12px',
              backgroundColor: '#dc2626',
              color: '#ffffff',
              border: 'none',
              borderRadius: '4px',
              cursor: 'pointer',
              fontSize: '12px',
            }}
          >
            Try Again
          </button>
        </div>
      );
    }

    return this.props.children;
  }
}

```

### 3. Bridging Async & Event-Handler Errors to Error Boundaries

Because Error Boundaries do not catch errors inside `onClick` handlers or async `fetch()` calls, use a state-dispatching trick or custom hook to re-throw them into the React render lifecycle:

```typescript
// src/hooks/useAsyncError.ts
import { useState, useCallback } from 'react';

/**
 * Throws asynchronous errors into the nearest Error Boundary
 */
export function useAsyncError() {
  const [, setError] = useState();

  return useCallback((error: unknown) => {
    setError(() => {
      throw error;
    });
  }, []);
}

```

#### Usage in Async Event Handlers

```tsx
import React from 'react';
import { useAsyncError } from './hooks/useAsyncError';

export function CheckoutButton() {
  const throwToBoundary = useAsyncError();

  const handleCheckout = async () => {
    try {
      const res = await fetch('/api/checkout', { method: 'POST' });
      if (!res.ok) throw new Error('Checkout service failed');
    } catch (err) {
      // Re-throws directly into the nearest Error Boundary
      throwToBoundary(err);
    }
  };

  return <button onClick={handleCheckout}>Pay Now</button>;
}

```

### 4. Sentry Configuration with User Context and Breadcrumbs

Initialize Sentry with source maps, release tracking, and automated breadcrumbs:

```typescript
// src/main.tsx
import * as Sentry from '@sentry/react';

Sentry.init({
  dsn: 'https://examplePublicKey@o0.ingest.sentry.io/0',
  environment: process.env.NODE_ENV,
  release: 'my-app@1.4.2',
  integrations: [
    Sentry.browserTracingIntegration(),
    Sentry.replayIntegration(),
  ],
  // Capture 100% of errors in production, sample performance traces
  tracesSampleRate: 0.2,
  replaysOnErrorSampleRate: 1.0, // Record 1-minute visual session replay on crashes
});

// Set user identity once authenticated
export function setUserContext(user: { id: string; email: string; organizationId: string }) {
  Sentry.setUser({
    id: user.id,
    email: user.email,
    org: user.organizationId,
  });
}

```

### 5. Graceful UI Design Guidelines

When an error boundary renders:

* **Preserve Unaffected State:** A crashed comments section must not reset the article the user is currently reading.
* **Provide Instant Recovery (`onReset`):** Always give users a self-serve recovery button (`Try Again` or `Reload Section`) that clears local query caches (e.g., TanStack Query `queryClient.resetQueries()`).
* **Display User-Friendly Diagnostics:** Display a sanitized trace/reference code that users can provide to customer support, rather than exposing raw stack traces or internal backend endpoints.
