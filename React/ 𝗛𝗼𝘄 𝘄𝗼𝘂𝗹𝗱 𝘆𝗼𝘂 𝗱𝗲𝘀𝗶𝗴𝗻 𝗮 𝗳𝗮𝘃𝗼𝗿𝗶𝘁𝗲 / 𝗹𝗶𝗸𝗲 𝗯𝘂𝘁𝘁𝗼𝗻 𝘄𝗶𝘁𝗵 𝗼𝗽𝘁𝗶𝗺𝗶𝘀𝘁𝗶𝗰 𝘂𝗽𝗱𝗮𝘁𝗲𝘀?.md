- How would you update the UI immediately before the server responds?
- How would you roll back the UI if the API call fails?

Designing a favorite/like button with **optimistic updates** is a classic Frontend Low-Level Design (LLD) scenario. It tests your ability to deliver instant UI feedback ($< 16\text{ms}$) while maintaining strict consistency with backend servers, gracefully handling network failures, and preventing race conditions caused by rapid double-clicking.

Below is the architectural flow and a complete production React implementation.

---

### System Architecture & State Flow

```text
 User Clicks "Like"
        │
        ▼
 1. Immediate UI Mutate (Optimistic Update)
    ├── count = count + 1
    └── isLiked = true
        │
        ├──► 2. Dispatch Async API Request to Server
        │
        ├─── IF API Success ──────────────────────────────────────────┐
        │    └─► Confirm state (or sync with server response)          │
        │                                                             │
        └─── IF API Fails (or Network Error) ─────────────────────────┤
             ├─► Rollback UI state (count = count - 1, isLiked = false)│
             └─► Display Error Toast / Notification                   │

```

---

### Key LLD Challenges & Solutions

| Challenge                          | Solution Strategy                                                                                                                                     |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Race Conditions (Rapid Clicks)** | Cancel ongoing/previous API requests using `AbortController` or debounce network dispatches so out-of-order network responses don't corrupt UI state. |
| **Failure Rollback**               | Store the **previous state snapshot** in a React `ref` or state variable before applying optimistic changes. If the API fails, restore the snapshot.  |
| **Debouncing Network Requests**    | For frequent toggles (like clicking like/unlike repeatedly), queue local state immediately while debouncing the network call to reduce API load.      |

### Complete Production Implementation (TypeScript + React)

Here is a robust implementation using native React hooks (`useState`, `useRef`, `useCallback`) that handles immediate updates, server rollback, and request cancellation.

#### 1. Custom Hook: `useOptimisticLike`

```typescript
import { useState, useRef, useCallback } from 'react';

interface LikeState {
  isLiked: boolean;
  likeCount: number;
}

interface UseOptimisticLikeOptions {
  initialIsLiked: boolean;
  initialLikeCount: number;
  onApiToggle: (nextIsLiked: boolean, signal: AbortSignal) => Promise<void>;
  onError?: (error: Error) => void;
}

export function useOptimisticLike({
  initialIsLiked,
  initialLikeCount,
  onApiToggle,
  onError,
}: UseOptimisticLikeOptions) {
  const [state, setState] = useState<LikeState>({
    isLiked: initialIsLiked,
    likeCount: initialLikeCount,
  });

  const [isLoading, setIsLoading] = useState(false);

  // Store active AbortController to cancel pending requests if user clicks again rapidly
  const abortControllerRef = useRef<AbortController | null>(null);

  const toggleLike = useCallback(async () => {
    // 1. Cancel previous in-flight request if user rapidly clicks
    if (abortControllerRef.current) {
      abortControllerRef.current.abort();
    }

    const controller = new AbortController();
    abortControllerRef.current = controller;

    // 2. Snapshot current state BEFORE optimistic mutation (for rollback)
    let previousState: LikeState = { ...state };

    setState((prev) => {
      previousState = prev; // Keep reference to exact current state
      const nextIsLiked = !prev.isLiked;
      return {
        isLiked: nextIsLiked,
        likeCount: nextIsLiked ? prev.likeCount + 1 : Math.max(0, prev.likeCount - 1),
      };
    });

    const targetIsLiked = !previousState.isLiked;
    setIsLoading(true);

    try {
      // 3. Dispatch Network Request
      await onApiToggle(targetIsLiked, controller.signal);
      setIsLoading(false);
    } catch (error: any) {
      // Ignore errors caused by manual request cancellation on rapid clicks
      if (error.name === 'AbortError') {
        return;
      }

      console.error('Like API failed. Rolling back UI state...', error);

      // 4. ROLLBACK UI STATE ON FAILURE
      setState(previousState);
      setIsLoading(false);

      if (onError) {
        onError(error);
      }
    }
  }, [state, onApiToggle, onError]);

  return {
    isLiked: state.isLiked,
    likeCount: state.likeCount,
    isLoading,
    toggleLike,
  };
}

```

#### 2. Like Button UI Component (`LikeButton.tsx`)

```tsx
import React from 'react';
import { useOptimisticLike } from './useOptimisticLike';

interface LikeButtonProps {
  itemId: string;
  initialIsLiked: boolean;
  initialLikeCount: number;
  onNotifyError?: (message: string) => void;
}

export const LikeButton: React.FC<LikeButtonProps> = ({
  itemId,
  initialIsLiked,
  initialLikeCount,
  onNotifyError,
}) => {
  // Simulated Async API Call
  const handleApiToggle = async (nextIsLiked: boolean, signal: AbortSignal) => {
    const response = await fetch(`/api/v1/items/${itemId}/like`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ isLiked: nextIsLiked }),
      signal, // Attach AbortSignal to cancel HTTP request if needed
    });

    if (!response.ok) {
      throw new Error('Failed to update like status on server');
    }
  };

  const { isLiked, likeCount, toggleLike } = useOptimisticLike({
    initialIsLiked,
    initialLikeCount,
    onApiToggle: handleApiToggle,
    onError: (err) => {
      onNotifyError?.(err.message || 'Network error. Please try again.');
    },
  });

  return (
    <button
      onClick={toggleLike}
      className={`like-button ${isLiked ? 'liked' : ''}`}
      aria-label={isLiked ? 'Unlike item' : 'Like item'}
      style={{
        display: 'inline-flex',
        alignItems: 'center',
        gap: '8px',
        padding: '8px 16px',
        borderRadius: '20px',
        border: '1px solid #cbd5e1',
        backgroundColor: isLiked ? '#fef2f2' : '#ffffff',
        color: isLiked ? '#ef4444' : '#64748b',
        cursor: 'pointer',
        fontSize: '14px',
        fontWeight: 600,
        transition: 'all 0.15s ease-in-out',
      }}
    >
      <span
        style={{
          transform: isLiked ? 'scale(1.2)' : 'scale(1)',
          transition: 'transform 0.15s ease-in-out',
        }}
      >
        {isLiked ? '❤️' : '🤍'}
      </span>
      <span>{likeCount}</span>
    </button>
  );
};

```

### Alternative: TanStack Query (React Query) Optimistic Updates

If your application uses **TanStack Query**, optimistic updates and automatic rollbacks can be implemented declaratively using `useMutation`:

```typescript
import { useMutation, useQueryClient } from '@tanstack/react-query';

export function useOptimisticLikeMutation(itemId: string) {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: async (nextIsLiked: boolean) => {
      await fetch(`/api/v1/items/${itemId}/like`, {
        method: 'POST',
        body: JSON.stringify({ isLiked: nextIsLiked }),
      });
    },

    // 1. Before API call executes, run optimistic update
    onMutate: async (nextIsLiked) => {
      // Cancel outgoing refetches so they don't overwrite optimistic update
      await queryClient.cancelQueries({ queryKey: ['item', itemId] });

      // Snapshot previous state
      const previousItem = queryClient.getQueryData(['item', itemId]);

      // Optimistically update cache
      queryClient.setQueryData(['item', itemId], (old: any) => ({
        ...old,
        isLiked: nextIsLiked,
        likeCount: nextIsLiked ? old.likeCount + 1 : old.likeCount - 1,
      }));

      // Return context object containing snapshot
      return { previousItem };
    },

    // 2. IF API FAILS: Roll back to previous snapshot context
    onError: (err, newTodo, context) => {
      if (context?.previousItem) {
        queryClient.setQueryData(['item', itemId], context.previousItem);
      }
    },

    // 3. Always refetch after error or success to sync with ground truth
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ['item', itemId] });
    },
  });
}

```

### Key Takeaways for LLD Interviews

1. **Immediate Execution:** Mutate local component state before making the network call.
2. **Snapshotting:** Save a snapshot of state before the mutation to allow precise rollbacks on HTTP 4xx/5xx or timeout errors.
3. **Concurrency Control:** Use `AbortController` or debouncing to manage rapid clicks and prevent out-of-order network responses.
