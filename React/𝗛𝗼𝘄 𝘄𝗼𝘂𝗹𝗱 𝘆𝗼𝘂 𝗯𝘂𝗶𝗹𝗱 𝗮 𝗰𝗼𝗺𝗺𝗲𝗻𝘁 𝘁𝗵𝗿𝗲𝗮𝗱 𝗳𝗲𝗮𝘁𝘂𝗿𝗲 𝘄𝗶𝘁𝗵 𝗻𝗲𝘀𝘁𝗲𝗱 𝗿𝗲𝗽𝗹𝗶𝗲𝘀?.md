# 3. State Management & Immutable Tree Updates

Adding, deleting, or updating a reply deep inside a nested tree requires updating the state immutably without mutating original objects.

### Recursive Immutable Helper

```typescript
// Helper to immutably insert a new reply node into a nested comment tree
export const addReplyToTree = (
  comments: CommentNode[],
  parentId: string,
  newComment: CommentNode
): CommentNode[] => {
  return comments.map((comment) => {
    if (comment.id === parentId) {
      return {
        ...comment,
        replies: [newComment, ...comment.replies], // Prepend new reply
      };
    }

    if (comment.replies && comment.replies.length > 0) {
      return {
        ...comment,
        replies: addReplyToTree(comment.replies, parentId, newComment),
      };
    }

    return comment;
  });
};

// Helper to immutably remove a comment node from a nested tree
export const deleteCommentFromTree = (
  comments: CommentNode[],
  commentId: string
): CommentNode[] => {
  return comments
    .filter((comment) => comment.id !== commentId)
    .map((comment) => {
      if (comment.replies && comment.replies.length > 0) {
        return {
          ...comment,
          replies: deleteCommentFromTree(comment.replies, commentId),
        };
      }
      return comment;
    });
};

```

# 4. Key Performance Optimizations

### 1. Unique & Stable Keys

- **Rule:** Never use array indices (`key={index}`) for keys in nested trees!
- **Why:** Inserting a new reply at the top of a child list shifts array indices, causing React to re-mount DOM nodes and lose local states (e.g., active input fields or collapsed state).
- **Fix:** Assign a globally unique server ID (UUID or Snowflake ID) for every comment node (`key={comment.id}`).

### 2. Component Memoization (`React.memo` + `useCallback`)

Wrap `<CommentItem/>` in `React.memo` and pass callback functions wrapped in `useCallback`. When a user replies to Comment A, `React.memo` skips re-rendering sibling Comment B and its entire subtree.

### 3. Max Indentation Clamping (`maxDepth`)

Unbounded nested margins (`marginLeft: depth * 24px`) break mobile viewports after 5–6 nesting levels. Clamp visual indentation using a `MAX_DEPTH` boundary, while continuing to render deeper replies flat under the same margin.

### 4. Normalized State vs. Tree State (Advanced Scaling Strategy)

| Pattern                     | Data Shape                                         | Best For                                                             |
| --------------------------- | -------------------------------------------------- | -------------------------------------------------------------------- |
| **Nested Tree (Recursive)** | `{ id: '1', replies: [{ id: '2', replies: [] }] }` | Low-to-medium volume ($< 500$ comments). Simple recursive rendering. |
| **Normalized Hash Map**     | `byId: { '1': {...}, '2': {...} }`<br>             |

<br>`allIds: ['1', '2']` | **High-volume platforms (Reddit scale)**. $O(1)$ lookups, instant updates without recursive traversal. |

#### Example Normalized Schema

```typescript
interface NormalizedCommentsState {
  byId: {
    [id: string]: {
      id: string;
      content: string;
      childIds: string[]; // Pointer IDs to child replies
      parentId: string | null;
    };
  };
  rootIds: string[]; // Pointer IDs to top-level comments

```

In a normalized store, updating or deleting a reply only requires modifying two items in a hash map without traversing nested arrays.

For threads with 5,000+ comments (like viral posts), rendering thousands of DOM elements will cause frame drops. Flatten the nested structure into a single list with `depth` metadata and render it using a virtualized list windowing library like `react-window` or `react-virtualized`.

### B. Zustand Store (`useCommentStore.ts`)

```typescript
import { create } from 'zustand';
import { immer } from 'zustand/middleware/immer';
import { NormalizedCommentsState } from './types';

export const useCommentStore = create<NormalizedCommentsState>()(
  immer((set) => ({
    byId: {
      'comment-1': {
        id: 'comment-1',
        author: 'Sudhir',
        content: 'This is a top-level comment!',
        createdAt: '10m ago',
        parentId: null,
        childIds: ['comment-2'],
      },
      'comment-2': {
        id: 'comment-2',
        author: 'Kishori',
        content: 'Replying to Sudhir!',
        createdAt: '5m ago',
        parentId: 'comment-1',
        childIds: [],
      },
    },
    rootIds: ['comment-1'],

    // 1. ADD COMMENT OR REPLY
    addComment: (content, parentId = null) =>
      set((state) => {
        const newId = `comment-${Date.now()}`;
        
        const newComment = {
          id: newId,
          author: 'You',
          content,
          createdAt: 'Just now',
          parentId,
          childIds: [],
        };

        // Add new node to hash map
        state.byId[newId] = newComment;

        if (parentId && state.byId[parentId]) {
          // If it's a reply, push ID to parent's childIds array
          state.byId[parentId].childIds.unshift(newId);
        } else {
          // If top-level, push ID to rootIds
          state.rootIds.unshift(newId);
        }
      }),

    // 2. DELETE COMMENT & RECURSIVELY CLEAN UP CHILDREN
    deleteComment: (commentId) =>
      set((state) => {
        const commentToDelete = state.byId[commentId];
        if (!commentToDelete) return;

        // Recursive helper to collect all descendant IDs to prune
        const getDescendantIds = (id: string): string[] => {
          const node = state.byId[id];
          if (!node) return [];
          return [id, ...node.childIds.flatMap(getDescendantIds)];
        };

        const idsToRemove = getDescendantIds(commentId);

        // Remove pointer reference from parent
        if (commentToDelete.parentId && state.byId[commentToDelete.parentId]) {
          state.byId[commentToDelete.parentId].childIds = state.byId[
            commentToDelete.parentId
          ].childIds.filter((id) => id !== commentId);
        } else {
          state.rootIds = state.rootIds.filter((id) => id !== commentId);
        }

        // Delete all pruned nodes from byId map
        idsToRemove.forEach((id) => {
          delete state.byId[id];
        });
      }),

    // 3. TOGGLE COLLAPSE STATE
    toggleCollapse: (commentId) =>
      set((state) => {
        if (state.byId[commentId]) {
          state.byId[commentId].isCollapsed = !state.byId[commentId].isCollapsed;
        }
      }),
  }))
);

```

## Performance Comparison: Nested Tree vs. Normalized State

| Metric                     | Nested Tree State                                                 | Normalized State (`byId` + `childIds`)           |
| -------------------------- | ----------------------------------------------------------------- | ------------------------------------------------ |
| **Lookup Time ($O$)**      | $O(N)$ (Requires recursive tree search)                           | **$O(1)$** (Direct key lookup)                   |
| **Add Reply Complexity**   | Deep array cloning across tree depth                              | **$O(1)$** (Push ID to array & set key)          |
| **Delete Node Complexity** | $O(N)$ filter & map pass                                          | **$O(1)$** (Delete key from map)                 |
| **React Re-render Impact** | **High:** Updating a nested child re-renders all parent ancestors | **Zero:** Only the modified component re-renders |

### Step 2: Types & Flattening Algorithm (`commentUtils.ts`)

The key to flattening a tree for a virtualized list is converting nested `replies` into a linear array where each item keeps track of its depth and parent node.

```typescript
export interface CommentNode {
  id: string;
  author: string;
  content: string;
  createdAt: string;
  replies: CommentNode[];
  isCollapsed?: boolean;
}

export interface FlattenedCommentItem {
  id: string;
  author: string;
  content: string;
  createdAt: string;
  depth: number; // Used for left-padding/indentation
  hasReplies: boolean;
  isCollapsed: boolean;
}

/**
 * Traverses a nested comment tree and flattens it into a 1D array.
 * Skips children if a parent node is collapsed.
 */
export function flattenCommentTree(
  nodes: CommentNode[],
  depth = 0
): FlattenedCommentItem[] {
  const result: FlattenedCommentItem[] = [];

  for (const node of nodes) {
    const hasReplies = node.replies && node.replies.length > 0;
    const isCollapsed = Boolean(node.isCollapsed);

    // 1. Add current node to flat list
    result.push({
      id: node.id,
      author: node.author,
      content: node.content,
      createdAt: node.createdAt,
      depth,
      hasReplies,
      isCollapsed,
    });

    // 2. Recursively process children ONLY if NOT collapsed
    if (hasReplies && !isCollapsed) {
      result.push(...flattenCommentTree(node.replies, depth + 1));
    }
  }

  return result;
}

```

Show me how to support variable-height comments in react-window using VariableSizeList.

Supporting variable-height comments (where comments vary in length, have optional images, or expand when opened) in `react-window` requires using **`VariableSizeList`** instead of `FixedSizeList`.

Because `VariableSizeList` needs to know the exact height of an item *before* rendering it, we dynamically measure each comment row DOM element after it renders and cache its height using a `ref`.

### Complete Implementation

#### 1. Dynamic Height Comment Thread (`VariableHeightCommentThread.tsx`)

Here is the complete solution using `VariableSizeList`, `useCallback`, and a custom measurement `ref`.

```tsx
import React, { useRef, useCallback, useEffect, useState, useMemo } from 'react';
import { VariableSizeList as List, ListChildComponentProps } from 'react-window';
import { CommentNode, FlattenedCommentItem, flattenCommentTree } from './commentUtils';

interface Props {
  initialComments: CommentNode[];
}

const DEFAULT_ESTIMATED_ROW_HEIGHT = 90;
const CONTAINER_HEIGHT = 600;

export const VariableHeightCommentThread: React.FC<Props> = ({ initialComments }) => {
  const [treeData, setTreeData] = useState<CommentNode[]>(initialComments);

  // 1. Flatten the nested tree structure
  const flatComments = useMemo(() => flattenCommentTree(treeData), [treeData]);

  // 2. Ref to the react-window List instance (used to reset cached heights)
  const listRef = useRef<List | null>(null);

  // 3. Cache map to store dynamically measured row heights: { [index]: heightInPixels }
  const rowHeightsRef = useRef<Record<number, number>>({});

  // Function called by react-window to get the height of a row at a specific index
  const getItemSize = useCallback((index: number) => {
    return rowHeightsRef.current[index] || DEFAULT_ESTIMATED_ROW_HEIGHT;
  }, []);

  // Callback passed to individual row items to register their measured DOM height
  const setRowHeight = useCallback((index: number, size: number) => {
    // Only update and re-measure if the height actually changed
    if (rowHeightsRef.current[index] !== size) {
      rowHeightsRef.current[index] = size;
      
      // CRITICAL: Notify react-window that item heights from this index onward have changed
      if (listRef.current) {
        listRef.current.resetAfterIndex(index, true);
      }
    }
  }, []);

  // Reset row height cache whenever flatComments list structure or length changes
  useEffect(() => {
    rowHeightsRef.current = {};
    if (listRef.current) {
      listRef.current.resetAfterIndex(0, true);
    }
  }, [flatComments]);

  // Toggle collapse state in the nested tree
  const toggleCollapse = useCallback((targetId: string) => {
    const updateTree = (nodes: CommentNode[]): CommentNode[] => {
      return nodes.map((node) => {
        if (node.id === targetId) {
          return { ...node, isCollapsed: !node.isCollapsed };
        }
        if (node.replies && node.replies.length > 0) {
          return { ...node, replies: updateTree(node.replies) };
        }
        return node;
      });
    };

    setTreeData((prev) => updateTree(prev));
  }, []);

  // 4. Individual Row Item Container with ResizeObserver
  const Row = useCallback(
    ({ index, style }: ListChildComponentProps) => {
      const item: FlattenedCommentItem = flatComments[index];
      const rowRef = useRef<HTMLDivElement | null>(null);

      // Measure row height using ResizeObserver to handle dynamic content expansions
      useEffect(() => {
        if (!rowRef.current) return;

        const observer = new ResizeObserver((entries) => {
          for (let entry of entries) {
            // Measure actual border-box height of the content wrapper
            const height = entry.borderBoxSize[0]?.blockSize || entry.contentRect.height;
            if (height > 0) {
              setRowHeight(index, Math.ceil(height));
            }
          }
        });

        observer.observe(rowRef.current);

        return () => {
          observer.disconnect();
        };
      }, [index, setRowHeight]);

      const clampedDepth = Math.min(item.depth, 6);

      return (
        <div style={style}>
          {/* Inner content wrapper measured by ResizeObserver */}
          <div
            ref={rowRef}
            style={{
              paddingLeft: `${clampedDepth * 24 + 12}px`,
              paddingRight: '16px',
              paddingTop: '12px',
              paddingBottom: '12px',
              boxSizing: 'border-box',
              borderBottom: '1px solid #e5e7eb',
              borderLeft: clampedDepth > 0 ? '2px solid #cbd5e1' : 'none',
              backgroundColor: '#ffffff',
            }}
          >
            {/* Header */}
            <div style={{ display: 'flex', alignItems: 'center', gap: '8px' }}>
              <strong>{item.author}</strong>
              <span style={{ fontSize: '12px', color: '#6b7280' }}>{item.createdAt}</span>

              {item.hasReplies && (
                <button
                  onClick={() => toggleCollapse(item.id)}
                  style={{
                    fontSize: '11px',
                    cursor: 'pointer',
                    background: '#f3f4f6',
                    border: '1px solid #d1d5db',
                    borderRadius: '4px',
                    padding: '2px 6px',
                  }}
                >
                  {item.isCollapsed ? '▶ Expand' : '▼ Collapse'}
                </button>
              )}
            </div>

            {/* Variable Length Body Content */}
            <div
              style={{
                marginTop: '6px',
                fontSize: '14px',
                color: '#334155',
                lineHeight: '1.5',
                wordBreak: 'break-word',
              }}
            >
              {item.content}
            </div>
          </div>
        </div>
      );
    },
    [flatComments, setRowHeight, toggleCollapse]
  );

  return (
    <div style={{ maxWidth: '650px', margin: '0 auto', border: '1px solid #cbd5e1' }}>
      <div style={{ padding: '12px', borderBottom: '1px solid #cbd5e1', background: '#f8fafc' }}>
        <h3>Variable Height Virtualized Comments ({flatComments.length} items)</h3>
      </div>

      {/* REACT-WINDOW VARIABLE SIZE LIST */}
      <List
        ref={listRef}
        height={CONTAINER_HEIGHT}
        itemCount={flatComments.length}
        itemSize={getItemSize} // Dynamic height calculator function
        estimatedItemSize={DEFAULT_ESTIMATED_ROW_HEIGHT}
        width="100%"
      >
        {Row}
      </List>
    </div>
  );
};

```

### Key Mechanics Explained

1. **`itemSize={getItemSize}`:** Instead of a static number (e.g., `itemSize={80}`), `VariableSizeList` calls `getItemSize(index)` for every row. It reads from our `rowHeightsRef.current` cache map.
2. **`ResizeObserver` inside Row:** Every row element attaches a `ResizeObserver` to its inner DOM node (`rowRef`). When a comment renders or resizes (e.g., image loads, user expands inline text), `ResizeObserver` detects the new pixel height instantly.
3. **`listRef.current.resetAfterIndex(index, true)`:** This is the most crucial API call in `react-window`. When row #5 changes height from $100\text{px}$ to $250\text{px}$, calling `resetAfterIndex(5, true)` forces `react-window` to invalidate its cached cumulative offset calculations for all subsequent rows (#6, #7, #8...), recalculating layout positions without rendering bugs or overlapping rows.

### Step 1: Types & Utility Helpers (`commentUtils.ts`)

We flatten the comment tree into a 1D array while preserving indentation levels.

```typescript
export interface CommentNode {
  id: string;
  author: string;
  content: string;
  createdAt: string;
  replies: CommentNode[];
  isCollapsed?: boolean;
}

export interface FlattenedCommentItem {
  id: string;
  author: string;
  content: string;
  createdAt: string;
  depth: number;
  hasReplies: boolean;
  isCollapsed: boolean;
}

export function flattenCommentTree(
  nodes: CommentNode[],
  depth = 0
): FlattenedCommentItem[] {
  const result: FlattenedCommentItem[] = [];

  for (const node of nodes) {
    const hasReplies = node.replies && node.replies.length > 0;
    const isCollapsed = Boolean(node.isCollapsed);

    result.push({
      id: node.id,
      author: node.author,
      content: node.content,
      createdAt: node.createdAt,
      depth,
      hasReplies,
      isCollapsed,
    });

    if (hasReplies && !isCollapsed) {
      result.push(...flattenCommentTree(node.replies, depth + 1));
    }
  }

  return result;
}
```

### How It Works Under the Hood

1. **`itemCount = flatComments.length + 1`:** When more pages exist (`hasNextPage = true`), we tell `react-window` that there is 1 extra item at the end of the array.
2. **`isItemLoaded(index)`:** Returns `true` for items already in state, and `false` for the extra item at index `flatComments.length`. When `react-window` renders that unrendered index, it displays the `"Loading more comments..."` placeholder.
3. **`InfiniteLoader` Callback Hookup:** Passing `onItemsRendered` and `ref` from `InfiniteLoader` to `List` allows `InfiniteLoader` to monitor the user's scroll position and trigger `loadMoreItems()` automatically when scrolling within 3 items of the bottom.
