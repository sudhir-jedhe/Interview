Updating deeply nested state in React requires maintaining **immutability** at every level of the state tree. If you mutate a nested property directly, React’s shallow comparison (`Object.is`) won't detect the change, leading to missed re-renders and subtle UI bugs.

Here is a breakdown of best practices, ranging from native JavaScript techniques (including ES2023 methods) to specialized libraries like Immer.

---

### The Fundamental Rule: Copy Every Level Being Changed

When modifying a deeply nested property, every parent container (objects and arrays) leading down to that property must be copied. Unchanged siblings should keep their original references.

#### Example State Structure

```javascript
const [userProfile, setUserProfile] = useState({
  id: 101,
  personal: {
    name: 'Alice',
    contacts: [
      { type: 'email', value: 'alice@example.com' },
      { type: 'phone', value: '555-0199' }
    ]
  },
  preferences: { theme: 'dark' }
});

```

---

### 1. Updating Nested Objects (Native Spread Syntax)

To update `personal.name` without losing `id`, `contacts`, or `preferences`:

```jsx
const updateName = (newName) => {
  setUserProfile(prev => ({
    ...prev, // Copy top-level object
    personal: {
      ...prev.personal, // Copy nested 'personal' object
      name: newName     // Override target property
    }
  }));
};

```

---

### 2. Updating Deeply Nested Arrays (`map` + Spread / `with`)

To update the `value` of the contact at index `0`:

#### Option A: Native `map()`

```jsx
const updateEmail = (newEmail) => {
  setUserProfile(prev => ({
    ...prev,
    personal: {
      ...prev.personal,
      contacts: prev.personal.contacts.map((contact, index) => 
        index === 0 ? { ...contact, value: newEmail } : contact
      )
    }
  }));
};

```

#### Option B: ES2023 `with()`

ES2023’s `with()` cleanly updates a specific array index immutably:

```jsx
const updateEmailWith = (newEmail) => {
  setUserProfile(prev => {
    const updatedContacts = prev.personal.contacts.with(0, {
      ...prev.personal.contacts[0],
      value: newEmail
    });

    return {
      ...prev,
      personal: {
        ...prev.personal,
        contacts: updatedContacts
      }
    };
  });
};

```

---

### 3. Adding or Removing Items from Nested Arrays (`toSpliced` / `filter`)

#### Adding an item

```jsx
const addContact = (newContact) => {
  setUserProfile(prev => ({
    ...prev,
    personal: {
      ...prev.personal,
      contacts: [...prev.personal.contacts, newContact]
    }
  }));
};

```

#### Removing an item at index `targetIndex`

```jsx
const removeContact = (targetIndex) => {
  setUserProfile(prev => ({
    ...prev,
    personal: {
      ...prev.personal,
      // Using ES2023 toSpliced() instead of filter()
      contacts: prev.personal.contacts.toSpliced(targetIndex, 1)
    }
  }));
};

```

### 4. The Recommended Solution for Deep Nesting: Immer (`useImmer`)

When state nesting goes beyond 2 levels, manual spreading becomes verbose and prone to missed copies. **Immer** allows you to write mutating code inside a draft proxy while handling immutability under the hood.

#### Installation

```bash
npm install use-immer

```

#### Code Comparison: Native vs. `useImmer`

```jsx
import { useImmer } from 'use-immer';

export function UserProfileEditor() {
  const [profile, updateProfile] = useImmer({
    id: 101,
    personal: {
      name: 'Alice',
      contacts: [
        { type: 'email', value: 'alice@example.com' },
        { type: 'phone', value: '555-0199' }
      ]
    }
  });

  // Mutate draft directly! Immer creates a fresh immutable copy behind the scenes.
  const updateEmail = (newEmail) => {
    updateProfile(draft => {
      draft.personal.contacts[0].value = newEmail;
    });
  };

  const addContact = () => {
    updateProfile(draft => {
      draft.personal.contacts.push({ type: 'address', value: '123 Main St' });
    });
  };

  return (
    <div>
      <button onClick={() => updateEmail('new@example.com')}>Update Email</button>
      <button onClick={addContact}>Add Contact</button>
    </div>
  );
}

```

### 5. Alternative Architectural Pattern: Flatten / Normalize State

If state updates feel too complex, the best long-term architectural solution is often **normalizing** the state structure (flattening nested relationships into ID-based dictionaries), similar to how a database stores records.

#### Deeply Nested (Hard to update)

```javascript
const state = {
  posts: [
    {
      id: 1,
      comments: [{ id: 10, text: 'Great post!' }]
    }
  ]
};

```

#### Normalized (Easy $O(1)$ updates)

```javascript
const state = {
  posts: {
    1: { id: 1, commentIds: [10] }
  },
  comments: {
    10: { id: 10, postId: 1, text: 'Great post!' }
  }
};

// Updating comment 10 is direct and independent of the post:
setComments(prev => ({
  ...prev,
  10: { ...prev[10], text: 'Updated comment text!' }
}));

```

---

### Summary Checklist for Nested State in React

1. **Keep state shallow:** Re-architect state into flat structures or multiple independent `useState` hooks whenever possible.
2. **Never mutate `prev` directly:** Always create copies of changed objects/arrays at every nesting tier.
3. **Use ES2023 methods (`with`, `toSpliced`):** For clean single-index array updates in native React.
4. **Reach for `useImmer`:** If nesting exceeds 2 levels and flattening state isn't an option.
