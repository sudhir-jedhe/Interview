URL navigation pipeline

Here is a breakdown of the entire URL navigation pipeline, step-by-step:

---

### Stage 1: DNS Resolution

Before a browser can connect to a server, it must translate the domain name (`example.com`) into an IP address. The browser checks local caches from top to bottom before sending network queries:

1. **Browser Cache:** Checks if the domain IP is already stored in memory (TTL ~60s). **Hit = instant skip.**
2. **OS Cache:** If missed, checks the operating system's DNS resolver cache (TTL ~300s).
3. **Router Cache:** Checks local router memory (TTL ~600s).
4. **ISP Resolver:** If all local caches miss, the request goes to your ISP or configured DNS resolver (e.g., 1.1.1.1 or 8.8.8.8) which recurses to root DNS servers.

- _Note:_ Modern browsers use **DNS-over-HTTPS (DoH)** to encrypt this lookup step.

**Round Trip Time (RTT):** $+1\text{ RTT}$ on cache miss, $+0$ on cache hit.

---

### Stage 2: Connection Handshake

Once the IP is known, the browser establishes a secure network connection. There are two main pathways:

- **HTTP/2 (TCP + TLS 1.3):**
- **TCP SYN-ACK:** Opens TCP socket connection ($+1\text{ RTT}$).
- **TLS 1.3:** Negotiates encryption keys ($+1\text{ RTT}$).

- **HTTP/3 (QUIC over UDP):**
- **QUIC Handshake:** Combines connection setup and TLS encryption into a single exchange ($+1\text{ RTT}$).
- **0-RTT Resume:** Re-connecting to a previously visited server allows immediate encrypted data transmission ($+0\text{ RTT}$).

**Round Trip Time (RTT):** $+1 \text{ to } 2\text{ RTT}$.

---

### Stage 3: HTTP Request / Response

The request is sent to fetch the webpage payload:

1. **Browser Request:** Sends `GET /` with HTTP headers, cookies, and `Accept-Encoding`.
2. **CDN Edge Node:** Geographically close servers (Cloudflare, Fastly, Akamai) intercept the request. If cached (**Edge Hit**), the response is returned immediately without contacting the origin.
3. **Origin Server:** Reached **only on cache miss** to run backend application logic and DB queries.
4. **Streaming Response:** The browser renders incrementally as bytes arrive instead of waiting for the full download.

---

### Stage 4: Rendering Pipeline

The browser engine converts raw HTML bytes into pixels on screen:

```
HTML Bytes ──► DOM Tree ─────────┐
                                 ├──► Render Tree ──► Layout ──► Paint ──► Composite ──► Pixels
CSS Bytes  ──► CSSOM (Blocking) ─┘     (Visible only)  (Sizes)   (Pixels)  (GPU Layers)

```

- **DOM & CSSOM:** Parses HTML tokens into DOM tree; CSSOM blocks render until parsed.
- **JavaScript:** Blocks HTML parsing unless marked with `async` or `defer` attributes.
- **Preload Scanner:** Runs ahead of the main parser in parallel to pre-discover fonts, CSS, and critical scripts.
- **Layout, Paint, Composite:** Calculates geometry, draws elements to layers, and GPU-composites the final image to the screen.

---

### Stage 5: What Modern Browsers Skip (Green Fast-Paths)

Modern web engines optimize navigation by skipping entire stages of the pipeline:

- **Service Workers:** Intercepts requests locally. Bypasses DNS, Connection, and HTTP network requests entirely by serving cached assets.
- **QUIC 0-RTT Resumption:** Uses stored cryptographic session tickets to skip the TCP/TLS connection setup on repeat visits ($0\text{ RTT}$).
- **Speculative DNS:** As you type in the address bar, the browser starts DNS resolution _before_ you press Enter.
- **Speculative Rules API:** Pre-renders next likely pages in an invisible background tab. Clicking the link results in an **instant page transition**.

---

### Total Load Latency Breakdown

| Navigation State                    | Round Trips (RTT)   | Speed Experience   |
| ----------------------------------- | ------------------- | ------------------ |
| **Cold Visit (HTTP/2)**             | **$4+\text{ RTT}$** | Baseline / Slowest |
| **Warm Visit (HTTP/3)**             | **$1\text{ RTT}$**  | Fast               |
| **Resumed Session (0-RTT)**         | **$0\text{ RTT}$**  | Near-Instant       |
| **Prerendered (Speculation Rules)** | **$0\text{ RTT}$**  | Instant            |

The **rendering pipeline** is the step-by-step process a web browser engine (like Chrome's Blink, Firefox's Gecko, or Safari's WebKit) follows to transform raw HTML, CSS, and JavaScript bytes fetched over the network into interactive pixels on a user's screen.

Here is the complete rendering pipeline broken down in detail, from network response to screen compositing.

---

## Stage 1: Parsing & Tree Construction

When the browser receives raw HTML bytes from the network, it starts converting them into structured object models in real time as data streams in.

### 1. Document Object Model (DOM) Construction

- **Bytes to Characters:** Raw bytes are converted into text characters based on character encoding (e.g., UTF-8).
- **Tokenization:** HTML text is converted into distinct tokens (`<html>`, `<body>`, `<div>`, etc.).
- **Node Generation & Tree Building:** Tokens are converted into DOM Nodes and linked into a tree structure representing the parent-child relationships of the HTML document.
- _Note:_ The DOM construction process is **incremental**—the browser doesn't wait for the whole HTML document to download before building the DOM.

### 2. CSS Object Model (CSSOM) Construction

When the parser encounters external CSS `<link>` stylesheets or inline `<style>` tags:

- It parses the CSS rules into a tree structure called the **CSSOM**.
- Unlike the DOM, CSSOM construction is **not incremental**. CSS is **render-blocking**—the browser must process all CSS before it can render the page to avoid FOUC (Flash of Unstyled Content).
- CSS rules are resolved using cascade rules and selector specificity to compute final styles for each node.

### 3. JavaScript Execution & Parser Blocking

When the HTML parser encounters a `<script>` tag without `async` or `defer`:

- HTML parsing **stops immediately**.
- JavaScript can read and modify the DOM (`document.createElement`) and CSSOM (`element.style`), so the browser must download, parse, and execute the script before resuming DOM construction.
- _Optimization:_ Script tags with `defer` execute after HTML parsing finishes; `async` downloads in parallel and executes as soon as it is ready without blocking DOM construction.

---

## Stage 2: Combining DOM + CSSOM into the Render Tree

Once the DOM and CSSOM trees are ready, the browser combines them into the **Render Tree**.

- The Render Tree contains only **visible nodes** that will actually be painted on the screen.
- **Nodes Excluded from Render Tree:**
- Non-visual elements (`<head>`, `<meta>`, `<script>`, `<title>`).
- Elements with CSS `display: none` (and their children).

- **Nodes Included in Render Tree:**
- Elements with `visibility: hidden` or `opacity: 0` **are included** because they still occupy layout space on the screen.

- Each node in the Render Tree contains both its DOM structure and its computed CSS styles.

---

## Stage 3: Layout (Reflow)

With the Render Tree constructed, the browser calculates the precise geometry of every visible element on the page.

- **Viewport Dimensions:** Layout depends directly on the screen/viewport size (`<meta name="viewport" content="width=device-width">`).
- **Geometry Calculation:** The browser computes exact pixel values for:
- Width and Height
- Margin, Padding, and Border
- Position (`top`, `left`, `right`, `bottom`, flexbox, grid alignment)

- **Reflow:** A "Reflow" occurs whenever an element's geometric properties change (e.g., resizing the window, modifying font sizes, or changing element dimensions via JS). Reflow is CPU-intensive as it forces recalculations for parent and child nodes down the tree.

---

## Stage 4: Paint (Rasterization)

Now that element sizes and positions are known, the browser determines what visual pixels need to be drawn.

- **Paint Records:** The browser creates a list of draw calls (e.g., "draw background color #fff", "draw text at x, y", "draw border").
- **Stacking Contexts & Layers:** Elements are organized into multiple z-index stacking layers based on overlapping, `position: fixed`, `transform`, `will-change`, or `opacity`.
- **Rasterization:** The vector instructions are converted into actual color pixel arrays stored in memory.

> **Paint vs. Reflow:** Changing visual properties like `color` or `background-color` skips the Layout phase and triggers only a **Repaint**. Changing layout properties like `width` triggers both **Reflow and Repaint**.

---

## Stage 5: Compositing (GPU Acceleration)

Modern browser engines break pages into separate layers and draw them on the GPU for maximum frame rates (60 FPS / 120 FPS).

1. **Layer Creation:** The browser promotes specific DOM elements into independent **Compositor Layers** if they have CSS properties like:

- `transform: translate3d()` or `translateZ()`
- `will-change: transform / opacity`
- `<video>`, `<canvas>`, or CSS animations

2. **Rastering Layers:** Each layer is painted independently into bitmapped tiles.
3. **GPU Compositing:** The **Compositor Thread** sends these separate layer textures directly to the GPU. The GPU merges and transforms the layers onto the screen.

### Why Compositor Animations are Extremely Fast

Animating properties like `transform` or `opacity` skips **Layout** and **Paint** entirely. The browser simply moves or fades pre-rendered GPU layers around, preventing main-thread UI jank.

---

## Summary Pipeline Cheat Sheet

```
[ HTML Bytes ] ──► DOM Tree ────────┐
                                     ├──► [ Render Tree ] ──► [ Layout ] ──► [ Paint ] ──► [ Composite ] ──► Screen
[ CSS Bytes  ] ──► CSSOM Tree ──────┘

```

| Pipeline Step                    | Triggered By                                                       | Performance Cost         |
| -------------------------------- | ------------------------------------------------------------------ | ------------------------ |
| **Reflow + Repaint + Composite** | Changing geometry (`width`, `height`, `margin`, `top`, `fontSize`) | 🔴 High (CPU Heavy)      |
| **Repaint + Composite**          | Changing appearance (`color`, `background-color`, `box-shadow`)    | 🟡 Medium                |
| **Composite Only**               | Changing GPU-accelerated layers (`transform`, `opacity`)           | 🟢 Low (GPU Accelerated) |
