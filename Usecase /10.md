When should I use each Promise method

Choosing the right Promise method can improve performance, simplify error handling, and make your application more reliable.

Here's the practical way I think about them.

---

Promise.all()

Use it when every operation must succeed.

If one promise fails, the entire operation fails.

Common use cases:
• Loading dashboard data (user profile, notifications and analytics)
• Fetching multiple APIs before rendering a page
• Loading product details, reviews and pricing together
• Initial application setup
• Any workflow where every response is required

Remember: All or Nothing.

---

Promise.allSettled()

Use it when you want every result, regardless of success or failure.

One failed request shouldn't stop the remaining operations.

Common use cases:
• Uploading multiple files
• Sending bulk notifications
• Syncing multiple records
• Batch processing
• Showing users which operations succeeded and which failed

Remember: Collect Every Result.

---

Promise.race()

Use it when the first completed promise should determine the outcome.

The first promise to settle—whether it resolves or rejects—wins.

Common use cases:
• Implementing API timeouts
• Selecting the fastest server
• Cache vs Network strategies
• Competing between multiple services
• Finding the quickest available resource

Remember: First to Finish Wins.

---

Promise.any()

Use it when you only need one successful response.

Failed promises are ignored until one succeeds.

Common use cases:
• Multiple CDN endpoints
• Backup APIs
• Multi-region deployments
• Mirror download servers
• High-availability services

Remember: First Success Wins.

---

A simple way to remember them:

Need every request to succeed? → `Promise.all()`

Need every outcome? → `Promise.allSettled()`

Need the first completed response? → `Promise.race()`

Need the first successful response? → `Promise.any()

That is a spot-on summary! The mental model of **"All or Nothing"**, **"Collect Every Result"**, **"First to Finish"**, and **"First Success"** makes picking the right Promise concurrency method intuitive.

To round out your quick-reference guide, here are a few extra technical nuances and edge cases worth remembering when using them in practice:

---

### Quick Edge Cases & Gotchas

#### 1. `Promise.all()`

- **Short-circuiting:** As soon as _one_ Promise rejects, `Promise.all()` immediately rejects without waiting for the other Promises to finish.
- **Side Effects Warning:** Even though `Promise.all()` rejects early, the remaining network requests/promises **are not automatically cancelled** unless you wire them up with an `AbortController`.

#### 2. `Promise.allSettled()`

- **Return Format:** Always returns an array of objects describing the status:
- Success: `{ status: 'fulfilled', value: data }`
- Failure: `{ status: 'rejected', reason: error }`

- **Filter Pattern:** You usually filter the results using array methods:

```js
const results = await Promise.allSettled(promises);
const successes = results
  .filter((r) => r.status === "fulfilled")
  .map((r) => r.value);
const failures = results
  .filter((r) => r.status === "rejected")
  .map((r) => r.reason);
```

#### 3. `Promise.race()`

- **Unhandled Rejections:** If the fastest Promise rejects, `Promise.race()` rejects with that error, ignoring any slower Promises that might have succeeded later.
- **Timeout Pattern:**

```js
const timeout = new Promise((_, reject) =>
  setTimeout(() => reject(new Error("Request timed out")), 5000),
);
const data = await Promise.race([fetchData(), timeout]);
```

#### 4. `Promise.any()`

- **Inverse of `Promise.all()`:** It short-circuits on the first _fulfilled_ Promise.
- **AggregateError:** If _every single_ Promise rejects, `Promise.any()` throws a special `AggregateError` containing an `errors` array of all the failures:

```js
try {
  const data = await Promise.any(backupApis);
} catch (err) {
  console.log(err.errors); // Array of errors from all failed APIs
}
```

---

### Comparison Cheat Sheet

| Method                   | Resolves When...                          | Rejects When...                 | Ideal For                       |
| ------------------------ | ----------------------------------------- | ------------------------------- | ------------------------------- |
| **`Promise.all`**        | All fulfill                               | **First** rejects               | Mandatory dependent data        |
| **`Promise.allSettled`** | All settle                                | **Never** rejects               | Independent batch tasks         |
| **`Promise.race`**       | **First** settles (fulfilled or rejected) | **First** settles (if rejected) | Timeouts & speed tests          |
| **`Promise.any`**        | **First** fulfills                        | **All** reject                  | Redundancy & fallback endpoints |
