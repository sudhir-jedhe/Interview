Optimizing image loading is one of the most effective ways to boost web performance, lower page load time, and improve **Largest Contentful Paint (LCP)** and **Cumulative Layout Shift (CLS)** scores.

---

## 1. Native Lazy Loading (`loading="lazy"`)

Defers fetching images until they are near the user's viewport, saving bandwidth and initial load time.

```html
<!-- Below-the-fold image: loads only when user scrolls near it -->
<img
  src="hero-banner.webp"
  alt="Hero"
  loading="lazy"
  width="800"
  height="400"
/>
```

> **Critical Rule:** Never lazy-load your main LCP image (e.g., hero banners or main hero text images at the top of the page). That hurts LCP performance!

---

## 2. Priority Hints (`fetchpriority="high"`)

Tell the browser to prioritize crucial images immediately during the initial page parse (great for LCP candidates).

```html
<!-- Hero image above the fold: Fetch at highest priority -->
<img
  src="hero-banner.webp"
  alt="Main Banner"
  loading="eager"
  fetchpriority="high"
  width="1200"
  height="600"
/>
```

---

## 3. Responsive Images (`srcset` and `sizes`)

Serve appropriately sized images based on the user's device resolution so mobile phones don't download desktop-sized assets.

```html
<img
  src="photo-medium.jpg"
  srcset="photo-small.jpg 480w, photo-medium.jpg 800w, photo-large.jpg 1200w"
  sizes="(max-width: 600px) 480px, (max-width: 1000px) 800px, 1200px"
  alt="Responsive Landscape"
  width="1200"
  height="800"
/>
```

---

## 4. Next-Gen Formats (`<picture>` tag)

Use modern compressed formats like **AVIF** or **WebP** instead of standard JPEG/PNG. AVIF offers up to 50% smaller file sizes than JPEG with comparable quality.

```html
<picture>
  <!-- 1. Best compression: AVIF -->
  <source srcset="image.avif" type="image/avif" />

  <!-- 2. Fallback modern format: WebP -->
  <source srcset="image.webp" type="image/webp" />

  <!-- 3. Legacy fallback -->
  <img
    src="image.jpg"
    alt="Optimized example"
    width="600"
    height="400"
    loading="lazy"
  />
</picture>
```

---

## 5. Prevent Layout Shifts (CLS Fix)

Always include explicit `width` and `height` attributes (or CSS `aspect-ratio`). This allows the browser to calculate aspect ratio spaces on the page _before_ the image downloads, eliminating annoying visual page jumps.

```css
/* CSS aspect ratio handling */
img {
  width: 100%;
  height: auto;
  aspect-ratio: 16 / 9;
}
```

---

## 6. Framework Image Components

If you are using modern web frameworks, leverage built-in image components that handle all of these optimizations automatically:

- **Next.js (`<Image/>` from `next/image`):** Automatically resizes, converts to WebP/AVIF, enforces aspect ratios, and handles lazy loading.
- **Nuxt / Vue (`<NuxtImg/>`):** Handles multi-provider dynamic resizing and responsive generation out of the box.

Here is a complete, production-ready Node.js script using **Sharp** that scans a directory for PNG and JPEG images and automatically converts them to WebP and AVIF formats while preserving the directory structure.

---

## 1. Prerequisites & Installation

Initialize your project and install **Sharp**:

```bash
npm init -y
npm install sharp

```

> Sharp automatically downloads pre-built `libvips` binaries for your platform, so no external tools or C++ compilers are required.

---

## 2. The Conversion Script (`convert-images.js`)

Create a file named `convert-images.js`:

```javascript
import fs from "node:fs/promises";
import path from "node:path";
import sharp from "sharp";

// Configuration
const CONFIG = {
  inputDir: "./images/raw",
  outputDir: "./images/optimized",
  // Quality settings (0 - 100)
  webpQuality: 80,
  avifQuality: 65, // AVIF achieves similar visual quality to WebP at lower numeric values
  // Target extensions to convert
  supportedExtensions: [".png", ".jpg", ".jpeg"],
};

/**
 * Recursively scans directory for image files
 */
async function getFiles(dir) {
  const entries = await fs.readdir(dir, { withFileTypes: true });
  const files = await Promise.all(
    entries.map((entry) => {
      const res = path.resolve(dir, entry.name);
      return entry.isDirectory() ? getFiles(res) : res;
    }),
  );
  return files.flat();
}

/**
 * Converts a single image to WebP and AVIF
 */
async function convertImage(filePath) {
  const ext = path.extname(filePath).toLowerCase();

  if (!CONFIG.supportedExtensions.includes(ext)) {
    return;
  }

  // Determine relative path to keep nested folder structure
  const relativePath = path.relative(CONFIG.inputDir, filePath);
  const parsedPath = path.parse(relativePath);

  // Define output destination directory
  const destDir = path.join(CONFIG.outputDir, parsedPath.dir);
  await fs.mkdir(destDir, { recursive: true });

  // Output paths
  const webpOutputPath = path.join(destDir, `${parsedPath.name}.webp`);
  const avifOutputPath = path.join(destDir, `${parsedPath.name}.avif`);

  const image = sharp(filePath);

  console.log(`⏳ Processing: ${relativePath}`);

  try {
    // Generate WebP
    await image
      .clone()
      .webp({ quality: CONFIG.webpQuality, effort: 4 })
      .toFile(webpOutputPath);

    // Generate AVIF
    await image
      .clone()
      .avif({ quality: CONFIG.avifQuality, effort: 4 })
      .toFile(avifOutputPath);

    console.log(`✅ Converted: ${parsedPath.name} -> WebP & AVIF`);
  } catch (err) {
    console.error(`❌ Failed to convert ${relativePath}:`, err.message);
  }
}

/**
 * Main execution function
 */
async function run() {
  console.time("Processing Time");

  try {
    await fs.access(CONFIG.inputDir);
  } catch {
    console.error(
      `Error: Input directory "${CONFIG.inputDir}" does not exist.`,
    );
    process.exit(1);
  }

  const allFiles = await getFiles(CONFIG.inputDir);
  const imageFiles = allFiles.filter((file) =>
    CONFIG.supportedExtensions.includes(path.extname(file).toLowerCase()),
  );

  console.log(`Found ${imageFiles.length} images to convert...\n`);

  // Process image conversions in parallel
  await Promise.all(imageFiles.map((file) => convertImage(file)));

  console.log("\n🎉 All conversions complete!");
  console.timeEnd("Processing Time");
}

run();
```

> **Note:** Make sure your `package.json` has `"type": "module"` set to use standard `import/export` syntax, or convert the imports to `const sharp = require('sharp')`.

## 3. Key Sharp Tuning Options Used

- **`effort` (0–6):** Controls the CPU effort vs. compression trade-off. Higher values result in smaller file sizes at the cost of processing speed. Value `4` is the sweet spot for batch processing.
- **`quality`:** Controls lossy compression levels.
- **WebP (75–80):** High quality with ~30% smaller size than JPEG.
- **AVIF (60–65):** Visually equivalent to WebP at lower quality ratings, resulting in up to 50% size reductions over JPEG.

- **`image.clone()`:** Allows Sharp to reuse the loaded image buffer in memory rather than reading the file twice from the filesystem disk.

The Next.js `<Image>` component acts as a high-performance wrapper around the native HTML `<img>` tag. Instead of serving static images directly, it executes an automated **on-demand optimization pipeline** behind the scenes.

---

## 1. On-Demand Image Optimization API (The Server Side)

When a browser requests an image, the request goes through Next.js's built-in Image Optimization API endpoint (`/_next/image?url=...&w=...&q=...`):

- **Modern Format Negotiation:** The server inspects the incoming browser's `Accept` HTTP header. If the browser supports **AVIF** or **WebP**, Next.js dynamically compresses and converts the source image (even legacy JPEGs or PNGs) into these modern formats on the fly.
- **Server-Side Resizing (Sharp Engine):** Next.js uses **Sharp** (a high-performance C++ Node.js module) under the hood to scale images down to the exact width requested by the client. Mobile devices never download desktop-resolution assets.
- **Quality Tuning:** Applies intelligent lossy compression. By default, it sets the `quality` parameter to `75`, cutting file sizes by 40–70% with virtually zero visible loss in quality.
- **Edge Caching:** Once an image variant (e.g., width 640px in AVIF format) is generated, Next.js caches the output on the server or CDN edge. Subsequent requests for the same variant bypass the processing pipeline and serve immediately.

---

## 2. Dynamic `srcset` Generation (The HTML Markup)

When you write `<Image alt="Hero" height="{600}" src="/hero.png" width="{1200}"/>`, Next.js compiles it into a standard HTML `<img>` tag with an automatically generated `srcset` and `sizes` attribute:

```html
<img
  alt="Hero"
  loading="lazy"
  decoding="async"
  src="/_next/image?url=%2Fhero.png&w=1200&q=75"
  srcset="
    /_next/image?url=%2Fhero.png&w=640&q=75   640w,
    /_next/image?url=%2Fhero.png&w=750&q=75   750w,
    /_next/image?url=%2Fhero.png&w=828&q=75   828w,
    /_next/image?url=%2Fhero.png&w=1200&q=75 1200w
  "
  sizes="100vw"
/>
```

The browser uses these `deviceSizes` and `imageSizes` defined in `next.config.js` to automatically pick and download the smallest necessary image variant based on the user's screen width and pixel density ($1\text{x}, 2\text{x}, 3\text{x}$).

## 3. Core Web Vitals Safeguards

Next.js automatically configures browser primitives to protect performance metrics:

### A. Zero Cumulative Layout Shift (CLS Protection)

Next.js **requires** explicit `width` and `height` props (or the `fill` property). It computes the intrinsic aspect ratio and injects CSS box sizing before the image finishes downloading, ensuring the browser reserves exact screen space so the page doesn't jump during rendering.

### B. Smart Lazy Loading & Priority Preloading

- **Default (`loading="lazy"`):** Off-screen images do not load until the user scrolls near them, reducing initial bandwidth consumption.
- **LCP Optimization (`priority` prop):** Adding `priority` disables lazy loading, sets `fetchpriority="high"`, and injects a `<link rel="preload">` tag into the HTML `<head>` so the browser downloads critical hero images before parsing JavaScript.

### C. Low-Quality Image Placeholders (LQIP)

If you pass `placeholder="blur"`, Next.js generates a tiny ($\sim 10\text{px}$) base64 inline blurred image string at build time. It displays this instantly as a smooth background skeleton while the full-resolution image streams in.

## 4. Offloading to External Cloud CDNs (Loaders)

By default, Next.js uses its Node.js server engine to process images. However, if you deploy on edge networks or use specialized image CDNs (like Cloudinary, Imgix, or AWS CloudFront), you can define a custom **`loader`** function:

```tsx
// Redirects Next.js image requests directly to an external image CDN
const cdnLoader = ({
  src,
  width,
  quality,
}: {
  src: string;
  width: number;
  quality?: number;
}) => {
  return `https://images.my-cdn.com/${src}?w=${width}&q=${quality || 75}&format=auto`;
};

<Image
  loader={cdnLoader}
  src="banner.jpg"
  width={800}
  height={400}
  alt="Banner"
/>;
```

This offloads the resizing and format conversion heavy lifting entirely to the external CDN, avoiding server CPU load.
