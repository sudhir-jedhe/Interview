How to prevent login page accessed again after user login

Here’s my take: To prevent a user from returning to the login page after logging in, you need to **check for an existing authentication session/token on the login route** and redirect the user to the application's home or dashboard page if they are already authenticated.

Here is how to implement this cleanly in modern React applications (using **React Router v6/v7**).

---

## 1. Create a Public-Only Route Wrapper (`PublicRoute`)

Just like you create a `ProtectedRoute` to block unauthenticated users from seeing the Dashboard, you create a `PublicRoute` (or `GuestRoute`) to block authenticated users from seeing the Login page.

### `src/routes/PublicRoute.jsx`

```jsx
import React from "react";
import { Navigate, Outlet } from "react-router-dom";
import { useAuth } from "../context/AuthContext"; // Or pull token from Redux / localStorage

export default function PublicRoute() {
  const { isAuthenticated, loading } = useAuth();

  // 1. Wait for auth state check to complete before deciding
  if (loading) {
    return <div>Loading...</div>;
  }

  // 2. If authenticated, redirect away from Login to Dashboard
  if (isAuthenticated) {
    return <Navigate to="/dashboard" replace />;
  }

  // 3. Otherwise, allow access to public route (Login / Register)
  return <Outlet />;
}
```

> **Why `replace`?**
> Using `<Navigate replace to="/dashboard"/>` replaces the `/login` entry in the browser's navigation history. This prevents the browser "Back" button from looping back to the login page.

---

## 2. Configure Your Routes

Wrap your public-only pages (`/login`, `/register`, `/forgot-password`) inside the `PublicRoute` component in your router setup.

### `src/App.jsx`

```jsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import PublicRoute from "./routes/PublicRoute";
import ProtectedRoute from "./routes/ProtectedRoute";

import Login from "./pages/Login";
import Register from "./pages/Register";
import Dashboard from "./pages/Dashboard";
import Profile from "./pages/Profile";

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        {/* PUBLIC-ONLY ROUTES (Blocked if logged in) */}
        <Route element={<PublicRoute />}>
          <Route path="/login" element={<Login />} />
          <Route path="/register" element={<Register />} />
        </Route>

        {/* PROTECTED ROUTES (Blocked if logged out) */}
        <Route element={<ProtectedRoute />}>
          <Route path="/dashboard" element={<Dashboard />} />
          <Route path="/profile" element={<Profile />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
```

## 3. Redirect Immediately Upon Successful Login

Inside your Login component, make sure you perform a replacement redirect right after the API returns a successful token/session.

```jsx
// src/pages/Login.jsx
import { useNavigate } from "react-router-dom";

export default function Login() {
  const navigate = useNavigate();
  const { login } = useAuth();

  const handleLogin = async (e) => {
    e.preventDefault();
    try {
      await login(credentials);

      // Redirect to dashboard and clear login from browser history stack
      navigate("/dashboard", { replace: true });
    } catch (err) {
      console.error("Login failed:", err);
    }
  };

  return (
    <form onSubmit={handleLogin}>
      {/* Login fields */}
      <button type="submit">Log In</button>
    </form>
  );
}
```

## 4. Key Best Practices to Avoid Glitches

1. **Handle the Initial Loading State:** If your auth state reads from an asynchronous source (like a `me` API endpoint or `localStorage` hydration), always maintain a `loading` flag. Otherwise, the app might briefly flash the Login screen before redirecting to the Dashboard.
2. **Handle Browser Back/Forward Buttons:** Using `{ replace: true }` when navigating from the login form removes `/login` from the browser history stack, preventing weird back-button behavior after authenticating.
3. **Clear Sessions Thoroughly on Logout:** When a user logs out, clear all tokens (`localStorage`, cookies, or Redux state) before navigating back to `/login` with `replace: true`.

Here is a comprehensive list of real-world React routing, state, and API scenarios—along with how to handle each one cleanly in a production application.

---

### 1. The "Return to Intended Page" Scenario (Deep Linking after Login)

- **The Problem:** A user clicks a link to view a specific item (`/orders/123`), but they aren't logged in. They get redirected to `/login`. After logging in, they are sent to the generic `/dashboard` instead of the order page they originally wanted.
- **The Solution:** Save the attempted URL in the router's location state when redirecting to `/login`, then navigate back to it after successful authentication.

```jsx
// Inside ProtectedRoute.jsx
import { Navigate, useLocation } from "react-router-dom";

export default function ProtectedRoute({ children }) {
  const { isAuthenticated } = useAuth();
  const location = useLocation();

  if (!isAuthenticated) {
    // Pass the current location in the state prop
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  return children;
}

// Inside Login.jsx
const location = useLocation();
const from = location.state?.from?.pathname || "/dashboard";

const handleLoginSuccess = () => {
  // Redirect back to original attempted path or fallback to dashboard
  navigate(from, { replace: true });
};
```

### 2. Multi-Tab Synchronized Logout / Login

- **The Problem:** A user opens your app in two browser tabs. They log out in Tab A, but Tab B still looks logged in and exposes private UI until the user clicks something that throws an error.
- **The Solution:** Listen to the browser's `storage` event. When `localStorage` changes in another tab, update the React state across all open tabs immediately.

```jsx
// Inside AuthContext.jsx
useEffect(() => {
  const handleStorageChange = (event) => {
    if (event.key === "authToken" && !event.newValue) {
      // Token was cleared in another tab -> Sync state & logout
      setIsAuthenticated(false);
      navigate("/login", { replace: true });
    }
  };

  window.addEventListener("storage", handleStorageChange);
  return () => window.removeEventListener("storage", handleStorageChange);
}, []);
```

### 3. Preventing Unsaved Form Changes on Navigation

- **The Problem:** A user spends 10 minutes typing a blog post or complex form, accidentally clicks a navigation link in the sidebar, and loses all their work.
- **The Solution:** Use React Router's `useBlocker` hook (or `unstable_useBlocker` depending on version) to trigger a modal warning when navigation is attempted with dirty state.

```jsx
import { useBlocker } from "react-router-dom";

function EditProfileForm() {
  const [isDirty, setIsDirty] = useState(false);

  // Block navigation if form has unsaved changes
  const blocker = useBlocker(
    ({ currentLocation, nextLocation }) =>
      isDirty && currentLocation.pathname !== nextLocation.pathname,
  );

  return (
    <>
      <form onChange={() => setIsDirty(true)}>...</form>

      {blocker.state === "blocked" && (
        <Modal>
          <p>You have unsaved changes. Are you sure you want to leave?</p>
          <button onClick={() => blocker.proceed()}>Leave</button>
          <button onClick={() => blocker.reset()}>Stay</button>
        </Modal>
      )}
    </>
  );
}
```

### 4. Role-Based Navigation & Page Isolation (RBAC)

- **The Problem:** A normal user types `/admin` in the browser URL bar. They shouldn't see administrative options or render admin component trees.
- **The Solution:** Extend your router guard to evaluate user roles or explicit permission scopes before rendering routes.

```jsx
// RoleGuard.jsx
export default function RoleGuard({ allowedRoles, children }) {
  const { user } = useAuth(); // e.g. user.role = 'USER'

  if (!user) return <Navigate to="/login" replace />;

  if (!allowedRoles.includes(user.role)) {
    return <Navigate to="/unauthorized" replace />; // Redirect to 403 page
  }

  return children;
}

// Router configuration
<Route
  path="/admin"
  element={
    <RoleGuard allowedRoles={["ADMIN", "SUPERADMIN"]}>
      <AdminDashboard />
    </RoleGuard>
  }
/>;
```

### 5. Silent Token Refresh (JWT Auto-Renewal)

- **The Problem:** Access tokens expire every 15 minutes. If a user is actively filling out a long form when the token expires, their next API call fails with a `401 Unauthorized`.
- **The Solution:** Intercept `401` responses in Axios, request a new access token using a refresh token, retry the failed request automatically behind the scenes, and keep the user on the screen uninterrupted.

```javascript
// axiosClient.js
apiClient.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    // If 401 error and we haven't retried yet
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;

      try {
        // Request fresh token from refresh endpoint
        const res = await axios.post("/api/auth/refresh");
        const newToken = res.data.accessToken;

        localStorage.setItem("authToken", newToken);
        originalRequest.headers.Authorization = `Bearer ${newToken}`;

        // Retry original request seamlessly
        return apiClient(originalRequest);
      } catch (refreshError) {
        // Refresh token failed or expired -> Force logout
        localStorage.clear();
        window.location.href = "/login";
        return Promise.reject(refreshError);
      }
    }

    return Promise.reject(error);
  },
);
```

### 6. Synchronizing URL Query Params with UI Filters

- **The Problem:** Users apply complex search filters (like category, price, sorting), but refreshing the page resets everything. Or, they want to share the filtered view link with a teammate, but the URL doesn't reflect the selected filters.
- **The Solution:** Treat the URL's query parameters (`useSearchParams`) as the single source of truth for UI state instead of `useState`.

```jsx
import { useSearchParams } from "react-router-dom";

export function ProductList() {
  const [searchParams, setSearchParams] = useSearchParams();

  // Read state directly from URL query string
  const category = searchParams.get("category") || "all";
  const page = parseInt(searchParams.get("page") || "1", 10);

  const updateCategory = (newCategory) => {
    setSearchParams({ category: newCategory, page: 1 }); // Resets page on filter change
  };

  return (
    <div>
      <Select
        value={category}
        onChange={(e) => updateCategory(e.target.value)}
      />
      {/* Fetch products using category & page derived from URL */}
    </div>
  );
}
```

When building React applications, combining the **Context API** and **React Router** allows you to manage global state while driving page-level behavior based on that state.

Here are the most common real-world use cases where Context API and Routes intersect:

---

### 1. Authentication & Protected Routes (Most Common)

**The Scenario:** You need a global `AuthContext` to track whether a user is logged in, their user object, and an authentication token. Certain routes (`/dashboard`, `/settings`) should only be accessible if `isAuthenticated` is true; otherwise, users must be redirected to `/login`.

#### Implementation:

```jsx
// 1. AuthContext.js
import { createContext, useContext, useState } from "react";

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null); // { name: 'Alice', token: '...' }

  const login = (userData) => setUser(userData);
  const logout = () => setUser(null);

  return (
    <AuthContext.Provider
      value={{ user, isAuthenticated: !!user, login, logout }}
    >
      {children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => useContext(AuthContext);
```

```jsx
// 2. ProtectedRoute.js
import { Navigate, Outlet, useLocation } from "react-router-dom";
import { useAuth } from "./AuthContext";

export function ProtectedRoute() {
  const { isAuthenticated } = useAuth();
  const location = useLocation();

  if (!isAuthenticated) {
    // Redirect to login, saving the location they were trying to access
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  return <Outlet />;
}
```

```jsx
// 3. AppRoutes.js
import { Routes, Route } from "react-router-dom";
import { ProtectedRoute } from "./ProtectedRoute";

export function AppRoutes() {
  return (
    <Routes>
      <Route path="/login" element={<Login />} />

      {/* Protected Group */}
      <Route element={<ProtectedRoute />}>
        <Route path="/dashboard" element={<Dashboard />} />
        <Route path="/profile" element={<Profile />} />
      </Route>
    </Routes>
  );
}
```

### 2. Role-Based Access Control (RBAC) Routes

**The Scenario:** Certain routes should be accessible only to specific roles (e.g., `/admin` should only be viewable by users with the `ADMIN` role).

#### Implementation:

```jsx
// RoleGuard.js
import { Navigate, Outlet } from "react-router-dom";
import { useAuth } from "./AuthContext";

export function RoleGuard({ allowedRoles }) {
  const { user } = useAuth();

  if (!user) {
    return <Navigate to="/login" replace />;
  }

  const hasRole = allowedRoles.includes(user.role);

  if (!hasRole) {
    return <Navigate to="/unauthorized" replace />; // Redirect to 403 page
  }

  return <Outlet />;
}

// Router Setup:
<Route element={<RoleGuard allowedRoles={["ADMIN", "SUPERADMIN"]} />}>
  <Route path="/admin/analytics" element={<AdminAnalytics />} />
  <Route path="/admin/users" element={<UserManagement />} />
</Route>;
```

### 3. Public-Only Routes (Preventing Access to Login Page)

**The Scenario:** If a user is _already_ logged in and manually navigates to `/login` or `/register`, they should be redirected immediately to `/dashboard` instead of seeing the login form again.

#### Implementation:

```jsx
// PublicOnlyRoute.js
import { Navigate, Outlet } from "react-router-dom";
import { useAuth } from "./AuthContext";

export function PublicOnlyRoute() {
  const { isAuthenticated } = useAuth();

  if (isAuthenticated) {
    return <Navigate to="/dashboard" replace />;
  }

  return <Outlet />;
}

// Router Setup:
<Route element={<PublicOnlyRoute />}>
  <Route path="/login" element={<Login />} />
  <Route path="/register" element={<Register />} />
</Route>;
```

### 4. Global Theme & Layout Customization Across Routes

**The Scenario:** You have a `ThemeContext` (Dark/Light mode) or a `LayoutContext` (Sidebar toggle, Navbar titles). Changing routes might automatically update layout titles, or toggling a theme should persist across all pages seamlessly.

#### Implementation:

```jsx
// ThemeContext.js
import { createContext, useContext, useState } from "react";

const ThemeContext = createContext();

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("dark");

  const toggleTheme = () => setTheme((t) => (t === "dark" ? "light" : "dark"));

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      <div className={`app-container ${theme}`}>{children}</div>
    </ThemeContext.Provider>
  );
}
```

```jsx
// App.js — Wrapping Router with Theme Context
export default function App() {
  return (
    <ThemeProvider>
      <BrowserRouter>
        <Navbar />
        <AppRoutes />
      </BrowserRouter>
    </ThemeProvider>
  );
}
```

### 5. Multi-Step Wizard / Checkout Funnel State

**The Scenario:** A multi-step process spans multiple URLs (`/checkout/address`, `/checkout/payment`, `/checkout/review`). You want to preserve the form state across routes without losing data if the user uses browser back/forward buttons.

#### Implementation:

```jsx
// CheckoutContext.js
const CheckoutContext = createContext();

export function CheckoutProvider({ children }) {
  const [checkoutData, setCheckoutData] = useState({
    address: {},
    payment: {},
    shippingMethod: "standard",
  });

  const updateCheckout = (step, data) => {
    setCheckoutData((prev) => ({ ...prev, [step]: data }));
  };

  return (
    <CheckoutContext.Provider value={{ checkoutData, updateCheckout }}>
      {children}
    </CheckoutContext.Provider>
  );
}

// Route Layout for Checkout Funnel
export function CheckoutLayout() {
  return (
    <CheckoutProvider>
      <div className="wizard-stepper">{/* Step indicator UI */}</div>
      <Outlet /> {/* Renders step-specific route components */}
    </CheckoutProvider>
  );
}
```

### 6. Dynamic Breadcrumbs and Page Headers

**The Scenario:** As the user navigates between nested routes (`/products/electronics/phones/iphone-15`), a breadcrumb bar needs to reflect the active page and parent names. A Context can store route metadata to keep the navbar synchronized.

#### Implementation:

```jsx
// HeaderContext.js
const HeaderContext = createContext();

export function HeaderProvider({ children }) {
  const [headerTitle, setHeaderTitle] = useState("Home");

  return (
    <HeaderContext.Provider value={{ headerTitle, setHeaderTitle }}>
      <Header title={headerTitle} />
      {children}
    </HeaderContext.Provider>
  );
}

// Inside a specific Page Component (e.g., Settings.js)
export function SettingsPage() {
  const { setHeaderTitle } = useContext(HeaderContext);

  useEffect(() => {
    setHeaderTitle("Account Settings");
  }, [setHeaderTitle]);

  return <div>Settings Content</div>;
}
```
