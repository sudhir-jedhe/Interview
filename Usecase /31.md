A great design system relies on a solid architecture: **Token Abstraction (Data)**, **Unstyled Primitives (Structure)**, **Tooling & AI Integration (Distribution)**, and **Flexible Composition (DX)**.

---

## 1. Multi-Tiered Design Tokens (Data Layer)

Never hardcode values like `red` or `#FF0000` into your components. A robust design system uses a **3-tier token architecture** so you can re-theme, add dark mode, or rebrand without touching component code.

```
  ┌─────────────────────────────────────────┐
  │ 1. Primitive / Brand Tokens             │  (Raw Values)
  │    --color-red-500: #ef4444;            │
  └────────────────────┬────────────────────┘
                       │
                       ▼
  ┌─────────────────────────────────────────┐
  │ 2. Semantic / Decision Tokens           │  (Purpose & Intent)
  │    --color-bg-danger: var(--color-red); │
  └────────────────────┬────────────────────┘
                       │
                       ▼
  ┌─────────────────────────────────────────┐
  │ 3. Component Tokens                     │  (Component Bound)
  │    --button-bg-error: var(--bg-danger); │
  └─────────────────────────────────────────┘

```

- **Tier 1: Primitive Tokens (Option Layer):** Global raw values (`brand-red: #ef4444`, `spacing-4: 1rem`). These are strictly **private** and never used directly in components.
- **Tier 2: Semantic Tokens (Decision Layer):** Maps values to _intent_ (`color-danger`, `color-bg-surface`, `border-radius-card`).
- **Tier 3: Component Tokens:** Component-specific bindings (`button-danger-bg: var(--color-danger)`).

## 2. Unstyled Primitives (Radix UI / Headless Layer)

Building accessible components from scratch (handling keyboard navigation, ARIA roles, focus traps, and screen readers) takes hundreds of hours. A strong design system separates **Behavior** from **Styling**.

Using headless libraries like **Radix UI** or **Headless UI** provides unstyled, accessible primitives out of the box.

```tsx
import * as DialogPrimitive from "@radix-ui/react-dialog";

// Radix handles focus management, escape keys, and ARIA attributes
// You only apply your system's styling tokens
export function Modal({ children, isOpen, onClose }) {
  return (
    <DialogPrimitive.Root open={isOpen} onOpenChange={onClose}>
      <DialogPrimitive.Portal>
        <DialogPrimitive.Overlay className="bg-black/50 backdrop-blur-sm fixed inset-0" />
        <DialogPrimitive.Content className="bg-(--color-surface) p-(--spacing-lg) rounded-(--radius-md)">
          {children}
        </DialogPrimitive.Content>
      </DialogPrimitive.Portal>
    </DialogPrimitive.Root>
  );
}
```

## 3. Tooling & AI Integration (Storybook + MCP)

Tooling bridges the gap between designers, developers, and AI coding agents.

### Storybook (The Visual Source of Truth)

Storybook isolates components, handles visual testing (via Chromatic), and documents prop interfaces and tokens.

### Design-to-Code MCP (Model Context Protocol)

To prevent AI models from generating "slop" or unstyled raw HTML, connect **Storybook MCP** or **Figma MCP** to your development environment.

- **Figma MCP:** Pulls variable design tokens directly into your CSS/Tailwind definitions.
- **Storybook MCP:** Teaches AI agents about existing components (`Button`, `Input`, `Form`), forcing the agent to **reuse design system primitives** rather than inventing new HTML elements.

## 4. Flexible Composition Patterns (The Form Architecture)

Rigid components that pack all logic into massive prop lists (`<Form hasSubmitButton="{true}" inputType="text" showEmail/>`) quickly fail as features scale. Use **Compound Component Composition** instead.

### Bad: Monolithic Rigid Props

```tsx
// ❌ Rigid: Hard to extend, messy conditional logic
<CustomInput label="Email" error="Invalid email" icon="mail" isRequired />
```

### Good: Compound Component Pattern

Break UI components down into small, composable building blocks that share implicit state via React Context:

```tsx
// ✅ Flexible: Fully customizable layout and accessibility bindings
<Form.Field name="email">
  <Form.Label>Email Address</Form.Label>
  <Form.Control asChild>
    <Input type="email" placeholder="alex@example.com" />
  </Form.Control>
  <Form.Error match="valueMissing">Please enter your email.</Form.Error>
  <Form.Error match="typeMismatch">
    Please enter a valid email address.
  </Form.Error>
</Form.Field>
```

## Summary Checklist

| Layer            | Good Design System Standard                                                            | Key Tools / Patterns                                            |
| ---------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| **Tokens**       | 3-Tier token abstraction (Primitives $\rightarrow$ Semantics $\rightarrow$ Components) | Style Dictionary, Figma Tokens, CSS Variables                   |
| **Primitives**   | Fully accessible, headless, unstyled foundational UI                                   | Radix UI, React Aria, Headless UI                               |
| **Tooling & AI** | Component inventory indexing & live agent context                                      | Storybook, Chromatic, Storybook MCP                             |
| **Composition**  | Compound patterns over rigid, deeply nested props                                      | React Context, Slot pattern (`asChild`), Compound Subcomponents |
