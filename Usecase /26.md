Here's the short answer: **changing `width` on `mouseenter` or hover is a performance trap.** It triggers layout **reflows**, which force the browser to recalculate the size and position of not just the button, but surrounding elements too.

If you want a button to expand on hover, using CSS `transform: scale()` instead of changing `width` is the standard, high-performance approach.

---

## What Happens During Reflow?

When a browser renders a web page, it follows a pipeline:

$$\text{JavaScript / CSS Changes} \longrightarrow \text{Style} \longrightarrow \text{Layout (Reflow)} \longrightarrow \text{Paint} \longrightarrow \text{Composite}$$

When your code changes geometric properties like `width`, `height`, `padding`, or `margin`:

1. **Reflow (Layout Recalculation):** The browser has to calculate the exact geometry and position of the button. Because changing `width` alters how much space the button takes up in the document flow, the browser must also re-calculate the positions of neighboring elements (siblings and parent containers).
2. **Repaint:** The pixels for all affected areas are redrawn.
3. **Frame Drops / Jank:** If this happens rapidly (like during an animation or mouse movement), it heavy-loads the main CPU thread, causing dropped frames below 60fps.

---

## The Better Approach: `transform: scale()`

Instead of animating `width`, apply a CSS scale transform:

```css
.button {
  transition: transform 0.2s ease-in-out;
  will-change: transform; /* Signals GPU optimization to the browser */
}

.button:hover {
  transform: scale(1.08); /* Grows 8% larger without layout reflow */
}
```

### Why `transform` Is Faster

- **Bypasses Reflow & Paint:** Modifying `transform` or `opacity` skips the Layout and Paint steps entirely.
- **Compositor Thread (GPU):** The scaling is calculated directly on the GPU using hardware acceleration.
- **No Layout Shift:** Surrounding elements remain completely untouched, avoiding visual jitter on the rest of the page.

---

## Why AI Coding Agents Default to `width`

AI coding models often take instructions literally. If prompted with _"Make a button that gets wider on mouseenter,"_ an AI agent will frequently write JavaScript modifying `element.style.width` or direct CSS `width` transitions because `width` literally maps to the prompt's wording.

### How to prompt your AI Agent for performance:

To prevent your AI agent from writing reflow-inducing code, include performance constraints in your prompt:

> _"Build a button that expands visually on hover. Use GPU-accelerated CSS transforms (like `transform: scale()`) instead of altering geometry properties like `width` to avoid browser layout reflows."_
