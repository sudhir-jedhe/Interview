An API works in Postman but fails in the browser with a CORS error. What is the browser enforcing, and what can the frontend actually fix?

## What the Browser is Enforcing

The browser is enforcing the **Same-Origin Policy (SOP)** via **CORS (Cross-Origin Resource Sharing)**.

An **origin** is defined as the combination of **Protocol + Domain + Port** (e.g., `http://localhost:3000` and `[http://api.mysite.com:8080](http://api.mysite.com:8080)` are different origins).

```
   Browser (http://localhost:3000)
             │
             ├─── 1. Preflight (OPTIONS) ───►  API Server (http://api.mysite.com)
             │                                        │
             │◄─── 2. Fails missing CORS ─────────────┘
             │     (Block request!)

```

### Why Postman Works

Postman, cURL, and backend services are **server-to-server or desktop clients**—they do not execute inside a web browser sandbox. The browser enforces CORS to protect users from malicious scripts on one site reading private data from another site without permission. Postman ignores these browser rules and sends the raw HTTP request directly.

### How CORS Works Under the Hood

When your web app makes a cross-origin request (especially one using `application/json`, custom headers, or methods like `PUT`/`DELETE`), the browser performs a **Preflight Check**:

1. The browser sends an HTTP `OPTIONS` request to the API server.
2. It asks: _"Is origin `http://localhost:3000` allowed to call this endpoint with these headers?"_
3. The server **must** respond with explicit headers (e.g., `Access-Control-Allow-Origin: http://localhost:3000`).
4. If the server doesn't respond properly to the `OPTIONS` preflight, the browser drops the request and throws a CORS error in the developer console.

## What the Frontend Can Actually Fix

Strictly speaking, **CORS must be configured on the API server**. The frontend cannot directly bypass browser security rules using client-side JavaScript.

However, depending on your development environment and architecture, you have a few practical options:

### 1. In Local Development: Use a Local Proxy (Recommended)

During local development, you can proxy API calls through your frontend development server (Vite, Next.js, Webpack, Create React App). The browser sends requests to your local frontend domain, and the dev server forwards them to the API server (server-to-server, which ignores CORS).

#### Example in Vite (`vite.config.js`):

```javascript
export default defineConfig({
  server: {
    proxy: {
      "/api": {
        target: "https://api.mysite.com",
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ""),
      },
    },
  },
});
```

_Your frontend calls `/api/users` instead of `[https://api.mysite.com/users](https://api.mysite.com/users)`, eliminating cross-origin checks completely during development._

---

### 2. In Production: Use a Backend Proxy / API Gateway

If you do not control the external API server, deploy a lightweight proxy server (Node.js/Express, Next.js API route, Cloudflare Worker, or NGINX).

```
Browser ──(Same Origin)──► Your Server API Route ──(Server-to-Server)──► External API

```

#### Example using a Next.js / Express API Route:

```javascript
// pages/api/external-data.js (Next.js API Route)
export default async function handler(req, res) {
  // Server-to-server request bypasses browser CORS entirely
  const response = await fetch("https://external-api.com/data");
  const data = await response.json();
  res.status(200).json(data);
}
```

---

### 3. Check for Self-Inflicted Frontend Triggers

Sometimes a frontend developer accidentally forces the browser to run a **preflight check** by including unnecessary custom headers.

- **Check Request Headers:** Adding non-standard headers (like `X-Custom-Header` or `Authorization`) triggers preflight `OPTIONS` requests. Ensure you aren't sending unused headers.
- **Check Content-Type:** Setting `Content-Type: application/json` forces a preflight check. Simple requests (`text/plain`, `application/x-www-form-urlencoded`) do not.

---

### What the Server Must Return (For Reference)

If you have access to the API server codebase, configure it to send the appropriate headers for preflight requests:

```http
Access-Control-Allow-Origin: https://your-frontend-domain.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization

```
