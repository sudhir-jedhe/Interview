Strict type checking in React is the process of enforcing compile-time validation on props, state, event handlers, and hooks so that bugs (like passing an undefined value or wrong data type) are caught **before** the code ever runs in the browser.

Historically, React used runtime `PropTypes`, but modern React applications strictly use **TypeScript** with TypeScript's compiler set to `strict` mode.

---

## 1. Compiler Foundation: `tsconfig.json` Setup

To enforce strict type checking across your entire React codebase, configure your `tsconfig.json` compiler options:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["DOM", "DOM.Iterable", "ESNext"],
    "jsx": "react-jsx",
    "moduleResolution": "bundler",

    /* Strict Type-Checking Options */
    "strict": true /* Enables all strict flags below */,
    "noImplicitAny": true /* Error on expressions with implied 'any' type */,
    "strictNullChecks": true /* Enforces explicit null and undefined handling */,
    "noUncheckedIndexedAccess": true /* Adds 'undefined' to array/object index lookups */,
    "exactOptionalPropertyTypes": true /* Prevents passing 'undefined' unless explicitly typed */
  }
}
```

## 2. Strictly Typing React Components & Props

Avoid using `React.FC` (which historically had implicit `children` bugs). Instead, type component props directly with **interfaces or types**.

### A. Basic Props & Discriminated Unions

```tsx
import { ReactNode } from "react";

// Define explicit prop contracts
interface UserCardProps {
  id: string;
  name: string;
  email?: string; // Optional property
  avatarUrl: string | null; // Nullable property
  children?: ReactNode; // Explicitly declare children when needed
  onSelect: (userId: string) => void; // Strictly typed callback
}

export function UserCard({
  id,
  name,
  email,
  avatarUrl,
  children,
  onSelect,
}: UserCardProps) {
  return (
    <div onClick={() => onSelect(id)} className="card">
      <img src={avatarUrl ?? "/default-avatar.png"} alt={name} />
      <h3>{name}</h3>
      {email && <p>{email}</p>}
      {children}
    </div>
  );
}
```

### B. Discriminated Unions for Variant Props (Strict Component States)

Use discriminated unions to prevent impossible prop combinations (e.g., a button that is both `loading` and has an `onClick` icon action).

```tsx
type ButtonProps =
  | { variant: "loading"; loadingText: string }
  | { variant: "action"; label: string; onClick: () => void };

// Usage enforces valid state combinations:
export function Button(props: ButtonProps) {
  if (props.variant === "loading") {
    return <button disabled>{props.loadingText}</button>;
  }

  // TypeScript automatically knows props.onClick and props.label exist here
  return <button onClick={props.onClick}>{props.label}</button>;
}
```

## 3. Strictly Typing Hooks & Events

### A. `useState` Inference & Discriminated State

Always explicitly type state when initialized as `null` or when using complex objects.

```tsx
import { useState } from "react";

interface User {
  id: string;
  role: "admin" | "user";
}

export function Profile() {
  // Explicitly type nullable state
  const [user, setUser] = useState<User | null>(null);

  return <div>{user ? user.role : "Guest"}</div>;
}
```

### B. DOM Events & Element Refs

Use React's built-in event and element types (`React.ChangeEvent`, `React.MouseEvent`, `HTMLInputElement`).

```tsx
import { useRef, ChangeEvent, MouseEvent } from "react";

export function Form() {
  // Bind ref strictly to HTMLInputElement
  const inputRef = useRef<HTMLInputElement>(null);

  const handleChange = (e: ChangeEvent<HTMLInputElement>) => {
    console.log(e.target.value);
  };

  const handleClick = (e: MouseEvent<HTMLButtonElement>) => {
    e.preventDefault();
    // Access DOM element safely with optional chaining
    inputRef.current?.focus();
  };

  return (
    <form>
      <input ref={inputRef} onChange={handleChange} type="text" />
      <button onClick={handleClick}>Focus Input</button>
    </form>
  );
}
```

## 4. Modern Type Boundaries (Zod for External Data)

TypeScript strictly validates code inside your app, but cannot validate external data arriving from an API at runtime. Use **Zod** to validate external JSON payloads at the network boundary:

```typescript
import { z } from "zod";

// Define runtime validation schema
const UserSchema = z.object({
  id: z.string(),
  username: z.string(),
  email: z.string().email(),
});

// Infer TypeScript type automatically from schema
type User = z.infer<typeof UserSchema>;

async function fetchUser(): Promise<User> {
  const response = await fetch("/api/user/1");
  const rawData = await response.json();

  // Throws a runtime error if API payload violates strict type contract
  return UserSchema.parse(rawData);
}
```

## Summary Checklist for Strict React Types

1. **`tsconfig.json`:** Set `"strict": true` and `"noUncheckedIndexedAccess": true`.
2. **Components:** Type props via `interface` / `type` without implicit `any`.
3. **Props:** Use Discriminated Unions for conflicting component variants.
4. **Refs:** Provide explicit HTML element types (`useRef<HTMLButtonElement>(null)`).
5. **Runtime Boundaries:** Validate API calls with Zod or TypeBox before passing data to React components.

Strictly typing custom React hooks with **TypeScript Generics** makes your hooks reusable across different data models while preserving complete, end-to-end type safety.

Here are three real-world custom hooks demonstrating how to use generics for state management, API data fetching, and local storage synchronization.

---

## 1. Generic Data Fetching Hook (`useFetch`)

This hook accepts an API fetcher function and infers the exact return type dynamically using a generic type parameter `<T>`.

```typescript
import { useState, useEffect, useCallback } from "react";

// Discriminated union for strict async state handling
export type AsyncState<T> =
  | { status: "idle"; data: null; error: null }
  | { status: "loading"; data: null; error: null }
  | { status: "success"; data: T; error: null }
  | { status: "error"; data: null; error: Error };

export function useFetch<T>(
  fetcherFn: () => Promise<T>,
  dependencies: unknown[] = [],
) {
  const [state, setState] = useState<AsyncState<T>>({
    status: "idle",
    data: null,
    error: null,
  });

  const execute = useCallback(async () => {
    setState({ status: "loading", data: null, error: null });
    try {
      const data = await fetcherFn();
      setState({ status: "success", data, error: null });
    } catch (err) {
      const error =
        err instanceof Error ? err : new Error("An unexpected error occurred");
      setState({ status: "error", data: null, error });
    }
  }, dependencies);

  useEffect(() => {
    execute();
  }, [execute]);

  return { state, refetch: execute };
}
```

### Usage:

TypeScript automatically infers `User` as `T` without requiring manual type casting:

```tsx
interface User {
  id: string;
  name: string;
  email: string;
}

export function UserProfile({ userId }: { userId: string }) {
  // T is inferred as User automatically from the fetcher return type
  const { state, refetch } = useFetch<User>(async () => {
    const res = await fetch(`/api/users/${userId}`);
    return res.json();
  }, [userId]);

  if (state.status === "loading") return <p>Loading...</p>;
  if (state.status === "error") return <p>Error: {state.error.message}</p>;
  if (state.status === "idle") return null;

  // TypeScript strictly knows state.data is User here!
  return (
    <div>
      <h1>{state.data.name}</h1>
      <p>{state.data.email}</p>
      <button onClick={refetch}>Reload</button>
    </div>
  );
}
```

## 2. Generic Local Storage Sync Hook (`useLocalStorage`)

This hook synchronizes React state with `localStorage`. It uses generic constraints (`<T>`) to ensure the value can be serialized to JSON.

```typescript
import { useState, useEffect, Dispatch, SetStateAction } from "react";

export function useLocalStorage<T>(
  key: string,
  initialValue: T | (() => T),
): [T, Dispatch<SetStateAction<T>>] {
  // Read value from LocalStorage or fall back to initialValue
  const [storedValue, setStoredValue] = useState<T>(() => {
    try {
      const item = window.localStorage.getItem(key);
      if (item !== null) {
        return JSON.parse(item) as T;
      }
    } catch (error) {
      console.error(`Error reading localStorage key "${key}":`, error);
    }
    return typeof initialValue === "function"
      ? (initialValue as () => T)()
      : initialValue;
  });

  // Sync state changes to LocalStorage
  useEffect(() => {
    try {
      window.localStorage.setItem(key, JSON.stringify(storedValue));
    } catch (error) {
      console.error(`Error writing to localStorage key "${key}":`, error);
    }
  }, [key, storedValue]);

  return [storedValue, setStoredValue];
}
```

### Usage:

```tsx
interface ThemeSettings {
  darkMode: boolean;
  fontSize: "sm" | "md" | "lg";
}

export function Settings() {
  // Enforces ThemeSettings shape for initial value and setSettings updates
  const [settings, setSettings] = useLocalStorage<ThemeSettings>("app-theme", {
    darkMode: true,
    fontSize: "md",
  });

  const toggleDarkMode = () => {
    setSettings((prev) => ({
      ...prev,
      darkMode: !prev.darkMode,
    }));
  };

  return (
    <button onClick={toggleDarkMode}>
      Mode: {settings.darkMode ? "Dark" : "Light"}
    </button>
  );
}
```

## 3. Generic Key-Value Map Hook with Constrained Generics (`useMap`)

This hook manages a stateful Map structure, constraining keys to valid Map key types using `K extends string | number | symbol`.

```typescript
import { useState, useCallback } from "react";

export interface MapActions<K, V> {
  set: (key: K, value: V) => void;
  remove: (key: K) => void;
  clear: () => void;
  reset: () => void;
}

export function useMap<K extends string | number | symbol, V>(
  initialEntries?: readonly (readonly [K, V])[],
): [ReadonlyMap<K, V>, MapActions<K, V>] {
  const [map, setMap] = useState<Map<K, V>>(() => new Map(initialEntries));

  const set = useCallback((key: K, value: V) => {
    setMap((prev) => {
      const copy = new Map(prev);
      copy.set(key, value);
      return copy;
    });
  }, []);

  const remove = useCallback((key: K) => {
    setMap((prev) => {
      const copy = new Map(prev);
      copy.delete(key);
      return copy;
    });
  }, []);

  const clear = useCallback(() => {
    setMap(new Map());
  }, []);

  const reset = useCallback(() => {
    setMap(new Map(initialEntries));
  }, [initialEntries]);

  return [map, { set, remove, clear, reset }];
}
```

### Usage:

```tsx
interface CartItem {
  id: string;
  quantity: number;
}

export function ShoppingCart() {
  // K = string (product ID), V = CartItem
  const [cart, actions] = useMap<string, CartItem>([
    ["p1", { id: "p1", quantity: 2 }],
  ]);

  return (
    <div>
      <p>Items in cart: {cart.size}</p>
      <button onClick={() => actions.set("p2", { id: "p2", quantity: 1 })}>
        Add Product 2
      </button>
      <button onClick={() => actions.remove("p1")}>Remove Product 1</button>
    </div>
  );
}
```

## Best Practices for Generic Custom Hooks

1. **Use Meaningful Generic Names:** Use `<TData, TError>` instead of single letters when a hook accepts multiple generics.
2. **Constrain Generics When Necessary:** Use `extends` (e.g., `<T extends id: string { }>` or `<K extends number string |>`) to prevent invalid types.
3. **Use `ReadonlyMap` or `ReadonlyArray` for Returned State:** Prevents consumers from mutating hook state directly without calling setter actions.

To strictly ban loose types (`any`, `unknown` escapes), unsafe type casting (`as`, `as unknown as T`), and unhandled promises in a React application, you need a combination of:

1. **Strict TypeScript Compiler Options (`tsconfig.json`)**
2. **Type-Aware ESLint Rules (`typescript-eslint`)**
3. **React-Specific Strict Linting (`eslint-plugin-react-hooks` & `@eslint-react`)**

Here is the exact setup and breakdown of rules needed to lock down your codebase.

---

## 1. The Foundation: `tsconfig.json`

ESLint enforces code rules, but TypeScript's compiler enforces type boundaries. Make sure your `tsconfig.json` has these strict flags enabled:

```json
{
  "compilerOptions": {
    /* Baseline Strictness */
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "strictFunctionTypes": true,
    "noImplicitThis": true,
    "alwaysStrict": true,

    /* Unsafe Cast & Loose Access Rules */
    "noUncheckedIndexedAccess": true /* Adds 'undefined' to array/object key lookups */,
    "exactOptionalPropertyTypes": true /* Prevents passing 'undefined' unless explicitly typed */,
    "noImplicitReturns": true /* Prevents implicit 'undefined' returns */,
    "noFallthroughCasesInSwitch": true
  }
}
```

---

## 2. Core ESLint Rules to Ban Loose Types & Casting

In your ESLint configuration (using the modern **ESLint Flat Config** `eslint.config.mjs` format), extend from `tseslint.configs.strictTypeChecked`. Then, explicitly configure these rules:

### A. Banning Loose Types (`any`, `unknown` leaks)

- **`@typescript-eslint/no-explicit-any`**: Set to `"error"` with `{ ignoreRestArgs: false }`. Prevents using `any` anywhere.
- **`@typescript-eslint/no-unsafe-argument`**: Prevents passing `any`-typed values into functions.
- **`@typescript-eslint/no-unsafe-assignment`**: Prevents assigning `any` to typed variables.
- **`@typescript-eslint/no-unsafe-call`**: Prevents calling functions typed as `any`.
- **`@typescript-eslint/no-unsafe-member-access`**: Prevents accessing properties on `any` types.
- **`@typescript-eslint/no-unsafe-return`**: Prevents returning `any` from functions.

### B. Banning Unsafe Type Casting (`as T`)

- **`@typescript-eslint/consistent-type-assertions`**: Enforce `{ assertionStyle: "never" }` or `{ assertionStyle: "as", objectLiteralTypeAssertions: "never" }`. Disallows casting object literals directly (forcing validation or explicit typing at initialization instead).
- **`@typescript-eslint/no-non-null-assertion`**: Disallows the `!` operator (e.g., `user!.name`). Forces proper `if (user)` or `user?.name` null-checking.
- **`@typescript-eslint/no-unnecessary-type-assertion`**: Warns/errors if a type assertion (`as T`) doesn't actually change the type because TypeScript already knows it.

### C. Banning Loose Async/Promise Code (Common in React Event Handlers)

- **`@typescript-eslint/no-misused-promises`**: Prevents passing async functions into places that expect synchronous handlers (e.g., `<button onClick={async () => ...}>` without proper handling).
- _Option:_ `{ checksVoidReturn: { attributes: false } }` if you allow async event handlers in JSX props.

- **`@typescript-eslint/no-floating-promises`**: Forces all promises (API calls, side effects) to be handled with `await`, `.catch()`, or `void`.

---

## 3. Complete Modern ESLint Config (`eslint.config.mjs`)

Here is a complete production setup using `@eslint/js`, `typescript-eslint`, and React hooks plugins:

```javascript
import eslint from "@eslint/js";
import tseslint from "typescript-eslint";
import reactHooks from "eslint-plugin-react-hooks";

export default tseslint.config(
  // 1. Standard recommended JS rules
  eslint.configs.recommended,

  // 2. Strict Type-Checked TypeScript Rules
  ...tseslint.configs.strictTypeChecked,
  ...tseslint.configs.stylisticTypeChecked,

  {
    languageOptions: {
      parserOptions: {
        // Enables type-aware linting
        projectService: true,
        tsconfigRootDir: import.meta.dirname,
      },
    },
    plugins: {
      "react-hooks": reactHooks,
    },
    rules: {
      /* ========================================================================
         1. BAN LOOSE TYPES & ANY LEAKS
         ======================================================================== */
      "@typescript-eslint/no-explicit-any": ["error", { fixToUnknown: false }],
      "@typescript-eslint/no-unsafe-argument": "error",
      "@typescript-eslint/no-unsafe-assignment": "error",
      "@typescript-eslint/no-unsafe-call": "error",
      "@typescript-eslint/no-unsafe-member-access": "error",
      "@typescript-eslint/no-unsafe-return": "error",

      /* ========================================================================
         2. BAN UNSAFE TYPE CASTING & ASSERTONS
         ======================================================================== */
      // Disallow "as T" object assertions (e.g., const x = {} as MyType)
      "@typescript-eslint/consistent-type-assertions": [
        "error",
        {
          assertionStyle: "as",
          objectLiteralTypeAssertions: "never",
        },
      ],
      // Disallow the non-null assertion operator (!)
      "@typescript-eslint/no-non-null-assertion": "error",
      // Flag unnecessary casts
      "@typescript-eslint/no-unnecessary-type-assertion": "error",

      /* ========================================================================
         3. ENFORCE STRICT ASYNC & PROMISES
         ======================================================================== */
      "@typescript-eslint/no-floating-promises": "error",
      "@typescript-eslint/no-misused-promises": [
        "error",
        {
          checksVoidReturn: {
            attributes: false, // Allows async handlers in JSX onClick={async () => ...}
          },
        },
      ],

      /* ========================================================================
         4. REACT-SPECIFIC SAFETY RULES
         ======================================================================== */
      "react-hooks/rules-of-hooks": "error",
      "react-hooks/exhaustive-deps": "warn",
    },
  },

  // Disable type-aware linting for pure JS config files (e.g., vite.config.js)
  {
    files: ["**/*.js", "**/*.mjs"],
    ...tseslint.configs.disableTypeChecked,
  },
);
```

## 4. Before & After Code Comparison

### ❌ Rejected by these strict rules:

```tsx
// 1. Blocked by @typescript-eslint/no-explicit-any
function UserProfile(data: any) {
  // 2. Blocked by @typescript-eslint/no-non-null-assertion
  const name = data.user!.name;

  // 3. Blocked by @typescript-eslint/consistent-type-assertions
  const settings = {} as UserSettings;

  // 4. Blocked by @typescript-eslint/no-floating-promises
  fetch("/api/log");

  return <div>{name}</div>;
}
```

### ✅ Allowed (Type-Safe Alternative):

```tsx
interface UserProfileProps {
  user: {
    name: string;
  } | null;
}

function UserProfile({ user }: UserProfileProps) {
  // 1. Safe null checking instead of non-null assertions (!)
  if (!user) {
    return <div>Guest</div>;
  }

  // 2. Explicit object literal matching interface instead of "as UserSettings"
  const settings: UserSettings = {
    theme: "dark",
    notifications: true,
  };

  // 3. Explicitly handling or voiding promises
  void fetch("/api/log").catch(console.error);

  return <div>{user.name}</div>;
}
```
