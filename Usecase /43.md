**`<React.StrictMode>`** is a built-in development-only tool in React that acts as an "alarm system" for your application. It helps you catch common bugs early during development before they hit production.

It carries **zero runtime overhead in production** because it only runs in development builds.

---

## What Does `<React.StrictMode>` Do?

When you wrap a section of your app in `<React.StrictMode>`, React enables extra checks and warnings for the component tree inside it:

```tsx
import React from "react";
import { createRoot } from "react-dom/client";
import App from "./App";

const root = createRoot(document.getElementById("root")!);

root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
);
```

### Key Checks Enabled by StrictMode:

### 1. Intentional Double-Rendering & Double-Mounting (React 18+)

In development mode, React intentionally **runs component functions twice** and **mounts components twice** (`Mount` $\rightarrow$ `Unmount` $\rightarrow$ `Remount`).

- **Why?** React does this to reveal missing cleanup logic in your `useEffect` hooks and catch accidental side effects during rendering (e.g., mutating global variables or pushing to external arrays inside the component body).
- **What you see:** `console.log()` calls inside your components or `useEffect` triggers twice in development.

```tsx
// ❌ Dangerous Effect: Missing cleanup function
useEffect(() => {
  const subscription = api.subscribe();
  // In StrictMode, double-mounting without a cleanup will create DUPLICATE subscriptions!
}, []);

// ✅ Correct Effect with Cleanup
useEffect(() => {
  const subscription = api.subscribe();
  return () => {
    subscription.unsubscribe(); // Cleans up first mount before second mount
  };
}, []);
```

---

### 2. Warning About Deprecated or Unsafe Lifecycle Methods

If legacy Class Components are present in your app, StrictMode warns about unsafe lifecycle methods like `UNSAFE_componentWillMount` or `UNSAFE_componentWillUpdate`.

---

### 3. Detecting Deprecated Legacy APIs

StrictMode issues console warnings if you use outdated React features:

- **Legacy String Refs:** `<input ref="myInput" />` (Replaced by `useRef()`).
- **Deprecated `findDOMNode`:** Directly searching DOM nodes on class components.
- **Legacy Context API:** Outdated `childContextTypes` syntax.

---

### 4. Detecting Unexpected Side Effects in Concurrent Rendering

Since React 18 uses Concurrent Rendering (which allows React to pause or abandon in-progress renders), component rendering functions must remain **pure** (given the same props/state, they should return the same JSX).

By running render functions twice, StrictMode helps identify impure renders before they cause race conditions or inconsistent UI states in production.

---

## Common Gotchas & Misconceptions

| Myth                                               | Fact                                                                                                            |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| _"StrictMode slows down my production app."_       | **False.** StrictMode logic is completely stripped out in production builds (`NODE_ENV=production`).            |
| _"Why is my API call running twice on page load?"_ | This is caused by StrictMode's **double-mounting** in development. In production, it only runs once.            |
| _"Does StrictMode affect the entire app?"_         | Only the components wrapped inside `<React.StrictMode>`. You can wrap your entire app or just a single subtree. |

---

## How to Disable It for Specific Components (Not Recommended)

If third-party legacy libraries break due to StrictMode's double-rendering, you can temporarily position `<React.StrictMode>` lower down in your component tree, wrapping only your modern, clean code.
