Explain Shadow DOM, custom elements, and Web Components with code examples

**Web Components** is a suite of three main W3C standard technologies—**Custom Elements**, **Shadow DOM**, and **HTML Templates**—that allow developers to create reusable, encapsulated, custom HTML tags that work across any web application without relying on third-party frameworks like React or Vue.

---

## 1. The 3 Pillar Technologies

1. **Custom Elements:** A set of JavaScript APIs to define custom HTML tags (e.g., `<user-card>`) and extend existing tags with custom lifecycle behavior.
2. **Shadow DOM:** An isolated DOM subtree attached to an element that provides complete encapsulation for styling (CSS) and DOM structure, preventing styles from leaking out or external styles from leaking in.
3. **HTML Templates (`<template>` and `<slot>`):** Declarative HTML markup fragments that remain unrendered on page load, serving as reusable blueprints for custom elements.

---

## 2. Step-by-Step Breakdown with Code Examples

### A. HTML Template (`<template>` and `<slot>`)

The `<template>` tag holds HTML markup that the browser ignores until instantiated by JavaScript. Slots act as placeholders for consumer-provided content.

```html
<template id="user-card-template">
  <style>
    /* These styles apply ONLY inside this component (Shadow DOM) */
    :host {
      display: block;
      font-family: system-ui, sans-serif;
    }
    .card {
      border: 1px solid #ccc;
      border-radius: 8px;
      padding: 16px;
      max-width: 300px;
      background: #f9f9f9;
      box-shadow: 0 2px 5px rgba(0,0,0,0.1);
    }
    .avatar {
      width: 50px;
      height: 50px;
      border-radius: 50%;
    }
    h2 {
      margin: 8px 0 4px;
      color: #333;
    }
  </style>

  <div class="card">
    <img class="avatar" src="" alt="Avatar" />
    <h2><slot name="username">Default User</slot></h2>
    <p><slot name="role">Member</slot></p>
  </div>
</template>

```

### B. Custom Element & Shadow DOM (JavaScript)

To define a custom element, extend the global `HTMLElement` class, attach a Shadow Root using `this.attachShadow({ mode: 'open' })`, and register it with `customElements.define()`.

```javascript
class UserCard extends HTMLElement {
  constructor() {
    super();

    // 1. Attach a Shadow DOM root (mode: 'open' allows access via element.shadowRoot)
    const shadowRoot = this.attachShadow({ mode: "open" });

    // 2. Clone the content from the HTML template
    const template = document.getElementById("user-card-template");
    const templateContent = template.content.cloneNode(true);

    // 3. Append the cloned template to the Shadow DOM
    shadowRoot.appendChild(templateContent);
  }

  // Lifecycle Method: Triggered when the element is inserted into the DOM
  connectedCallback() {
    // Read attribute values passed by consumer
    const avatarSrc = this.getAttribute("avatar") || "https://via.placeholder.com/50";
    
    // Update internal Shadow DOM elements safely
    this.shadowRoot.querySelector(".avatar").src = avatarSrc;
  }

  // Observe specific attributes for reactive changes
  static get observedAttributes() {
    return ["avatar"];
  }

  // Lifecycle Method: Triggered when an observed attribute changes
  attributeChangedCallback(name, oldValue, newValue) {
    if (name === "avatar" && oldValue !== newValue && this.shadowRoot) {
      this.shadowRoot.querySelector(".avatar").src = newValue;
    }
  }
}

// Register the custom element tag name (MUST contain a hyphen)
customElements.define("user-card", UserCard);

```

## 3. Custom Element Lifecycle Hooks

| Lifecycle Method                                     | Triggered When...                                                           | Common Use Case                                                   |
| ---------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **`constructor()`**                                  | The element is instantiated or created via `document.createElement()`.      | Attaching Shadow DOM and setting initial state.                   |
| **`connectedCallback()`**                            | The element is attached to the main document DOM.                           | Fetching data, rendering template, attaching event listeners.     |
| **`disconnectedCallback()`**                         | The element is removed from the DOM.                                        | Cleanup work (canceling timers, removing global event listeners). |
| **`attributeChangedCallback(name, oldVal, newVal)`** | An attribute listed in `observedAttributes` is added, removed, or modified. | Updating component state in response to attribute changes.        |
| **`adoptedCallback()`**                              | The element is moved to a new document (e.g., inside an `<iframe>`).        | Handling cross-document transfers.                                |

## 4. Shadow DOM Isolation Benefits

```text
 Main Page DOM (Light DOM)             Shadow DOM Subtree
 ┌─────────────────────────┐          ┌──────────────────────────┐
 │ <h2>Main Heading</h2>   │          │ #shadow-root (open)      │
 │                         │  Encapsulated │ <h2>Inside Card</h2>  │
 │ <style>                 │ ─────────►│ <style>                  │
 │   h2 { color: red; }    │  Blocked │   h2 { color: #333; }   │
 │ </style>                │          │ </style>                 │
 └─────────────────────────┘          └──────────────────────────┘

```

* **CSS Isolation:** Styles defined inside a Shadow Root do not leak out to contaminate other elements on the page, and main page styles cannot break internal component styling.
* **DOM Query Isolation:** `document.querySelector('h2')` from the main page will **not** match or select `<h2>` elements located inside an open Shadow Root.

In Web Components, data transfer follows a clear directional rule:

* **Data Down (Parent to Component):** Accomplished via **Attributes** or **JavaScript Properties**.
* **Data Up (Component to Parent):** Accomplished via **Custom Events** using standard DOM event mechanisms (`CustomEvent`).

Because Shadow DOM creates a DOM boundary, emitting custom events requires understanding how event **bubbles** and **composed** options allow events to cross the Shadow DOM barrier into the main page (Light DOM).

---

## 1. Data Passing Mechanisms

### Direction 1: Data Down (Parent $\rightarrow$ Custom Element)

#### A. Attributes (Strings / Primitive Values)

Attributes are passed directly in HTML markup. Changes can be observed using `observedAttributes` and `attributeChangedCallback`.

```javascript
// HTML: <user-profile user-id="42"></user-profile>

class UserProfile extends HTMLElement {
  static get observedAttributes() {
    return ["user-id"];
  }

  attributeChangedCallback(name, oldValue, newValue) {
    if (name === "user-id" && oldValue !== newValue) {
      this.fetchUserData(newValue);
    }
  }

  fetchUserData(id) {
    console.log(`Fetching profile for ID: ${id}`);
  }
}
customElements.define("user-profile", UserProfile);

```

#### B. JavaScript Properties (Complex Types: Objects, Arrays, Functions)

Attributes can only hold strings. To pass complex objects or arrays, define JS getters and setters directly on the custom element instance.

```javascript
class ShoppingCart extends HTMLElement {
  constructor() {
    super();
    this._items = [];
  }

  // Define property setter for complex objects
  set items(data) {
    if (Array.isArray(data)) {
      this._items = data;
      this.render();
    }
  }

  get items() {
    return this._items;
  }

  render() {
    this.innerHTML = `<p>Total items in cart: ${this._items.length}</p>`;
  }
}
customElements.define("shopping-cart", ShoppingCart);

// Parent Script:
const cart = document.querySelector("shopping-cart");
// Pass an array directly to the element property
cart.items = [{ id: 1, name: "Laptop" }, { id: 2, name: "Mouse" }];

```

## 2. Direction 2: Data Up via Custom Events (Custom Element $\rightarrow$ Parent)

To notify parent scripts of internal interactions (e.g., button clicks or form submissions), the custom element dispatches a `CustomEvent` holding a payload in its `detail` property.

### Shadow DOM Event Crossing Rules (`bubbles` and `composed`)

When dispatching an event from inside a Shadow DOM, two flags govern its traversal:

* **`bubbles: true`**: Allows the event to travel up the DOM tree hierarchy to parent nodes.
* **`composed: true`**: Allows the event to **cross the Shadow DOM boundary** into the main document (Light DOM).

| Event Configuration                   | Crosses Shadow DOM Boundary? | Bubbles Up Parent Tree?         |
| ------------------------------------- | ---------------------------- | ------------------------------- |
| `{ bubbles: false, composed: false }` | ❌ No                         | ❌ No                            |
| `{ bubbles: true, composed: false }`  | ❌ No                         | ✅ Yes (Only within Shadow Root) |
| `{ bubbles: true, composed: true }`   | ✅ **Yes**                    | ✅ **Yes**                       |

## 3. Complete Working Example: Interactive Rating Component

Here is a complete, self-contained example of a custom element emitting data upward to a parent application.

### A. Component Definition (`star-rating.js`)

```javascript
class StarRating extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" });
    this.rating = 0;
  }

  connectedCallback() {
    this.shadowRoot.innerHTML = `
      <style>
        .star-container { display: flex; gap: 8px; cursor: pointer; }
        .star { font-size: 24px; color: #ccc; transition: color 0.2s; }
        .star.selected { color: gold; }
      </style>
      <div class="star-container">
        <span class="star" data-value="1">★</span>
        <span class="star" data-value="2">★</span>
        <span class="star" data-value="3">★</span>
        <span class="star" data-value="4">★</span>
        <span class="star" data-value="5">★</span>
      </div>
    `;

    // Listen to click events inside Shadow DOM
    this.shadowRoot.querySelector(".star-container")
      .addEventListener("click", (e) => this.handleStarClick(e));
  }

  handleStarClick(event) {
    const star = event.target.closest(".star");
    if (!star) return;

    this.rating = parseInt(star.dataset.value, 10);
    this.updateUI();
    this.dispatchRatingEvent();
  }

  updateUI() {
    const stars = this.shadowRoot.querySelectorAll(".star");
    stars.forEach(star => {
      const val = parseInt(star.dataset.value, 10);
      star.classList.toggle("selected", val <= this.rating);
    });
  }

  dispatchRatingEvent() {
    // Create CustomEvent with detail payload
    const ratingEvent = new CustomEvent("rating-changed", {
      detail: {
        rating: this.rating,
        timestamp: Date.now()
      },
      bubbles: true,   // Allow bubbling up through parent DOM
      composed: true   // Allow crossing the Shadow DOM boundary
    });

    // Dispatch event from the custom element
    this.dispatchEvent(ratingEvent);
  }
}

customElements.define("star-rating", StarRating);

```

---

### B. Consuming Page (`index.html`)

The parent document can listen for the custom event either declaratively (via `addEventListener`) or through event delegation.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Custom Events Demo</title>
</head>
<body>

  <h1>Product Feedback</h1>

  <!-- Custom Element -->
  <star-rating id="product-rating"></star-rating>

  <p id="output-log">Selected Rating: None</p>

  <script src="star-rating.js"></script>
  <script>
    const ratingComponent = document.querySelector("#product-rating");
    const outputLog = document.querySelector("#output-log");

    // Parent listens for the custom "rating-changed" event
    ratingComponent.addEventListener("rating-changed", (event) => {
      // Access payload stored inside event.detail
      const { rating, timestamp } = event.detail;

      outputLog.textContent = `Selected Rating: ${rating} Stars (Recorded at ${new Date(timestamp).toLocaleTimeString()})`;
      
      console.log("Custom event received:", event.detail);
    });
  </script>
</body>
</html>

```

Explain state management patterns across Web Components with code examples

Managing state across multiple Web Components without a framework requires relying on browser-native APIs and design patterns. Since Web Components operate independently inside their own encapsulate Shadow DOMs, passing state efficiently between sibling, nested, or deeply separated components is critical.

Here are the 4 primary state management patterns used in modern Web Components applications.

---

## Pattern Overview

```text
1. Props & Events         2. Shared Event Bus        3. Centralized Store          4. Context API
(Parent-Child)            (Loose Coupling)           (Single Source of Truth)      (Deep Trees)

   [Parent]                 [Component A]               ┌─────────────┐             [Provider]
   │      ▲                       │                     │ Centralized │                 │ (Provides)
   │Data  │Event                  │ (Custom Event)      │    Store    │                 ▼
   ▼      │                       ▼                     └──────┬──────┘            [Container]
  [Child Component]         [ Event Bus ]                      │                        │
                                  │                            │ (Subscribe)            ▼
                                  ▼                            ▼                  [Consumer Node]
                            [Component B]               [Component A/B]

```

## 1. Top-Down Data Flow & Events (Parent-Child)

For simple, shallow parent-child component hierarchies, use the standard DOM flow: **Properties down, Custom Events up**.

* **Parent $\rightarrow$ Child:** Set property directly on the child instance.
* **Child $\rightarrow$ Parent:** Dispatch a bubbling `CustomEvent` holding payload in `detail`.

```javascript
// --- Child Component: <counter-display> ---
class CounterDisplay extends HTMLElement {
  set count(val) {
    this._count = val;
    this.render();
  }

  render() {
    this.textContent = `Count: ${this._count || 0}`;
  }
}
customElements.define('counter-display', CounterDisplay);

// --- Parent Component: <counter-app> ---
class CounterApp extends HTMLElement {
  constructor() {
    super();
    this.state = { count: 0 };
  }

  connectedCallback() {
    this.innerHTML = `
      <button id="inc">+1</button>
      <counter-display></counter-display>
    `;

    this.display = this.querySelector('counter-display');
    this.display.count = this.state.count;

    this.querySelector('#inc').addEventListener('click', () => {
      this.state.count++;
      this.display.count = this.state.count; // Push state down
    });
  }
}
customElements.define('counter-app', CounterApp);

```

## 2. Event Bus Pattern (Pub/Sub for Unrelated Components)

When two components live in completely different branches of the DOM tree (siblings, header vs. sidebar) and have no direct parent-child relationship, use a **Global Event Bus**.

```javascript
// --- EventBus Singleton ---
class EventBus extends EventTarget {
  publish(event, data) {
    this.dispatchEvent(new CustomEvent(event, { detail: data }));
  }

  subscribe(event, callback) {
    const handler = (e) => callback(e.detail);
    this.addEventListener(event, handler);
    // Return unsubscribe function for cleanup
    return () => this.removeEventListener(event, handler);
  }
}

export const globalBus = new EventBus();

```

### Subscriber & Publisher Components

```javascript
// --- Component A: Publisher (<cart-button>) ---
class CartButton extends HTMLElement {
  connectedCallback() {
    this.innerHTML = `<button>Add Item to Cart</button>`;
    this.querySelector('button').addEventListener('click', () => {
      // Publish event to Bus
      globalBus.publish('cart-updated', { id: 101, name: 'Laptop', price: 999 });
    });
  }
}
customElements.define('cart-button', CartButton);

// --- Component B: Subscriber (<cart-badge>) ---
class CartBadge extends HTMLElement {
  connectedCallback() {
    this.count = 0;
    this.render();

    // Subscribe to Bus events
    this.unsubscribe = globalBus.subscribe('cart-updated', (item) => {
      this.count++;
      this.render();
    });
  }

  disconnectedCallback() {
    // Clean up memory when component leaves DOM
    this.unsubscribe();
  }

  render() {
    this.textContent = `Cart Items: ${this.count}`;
  }
}
customElements.define('cart-badge', CartBadge);

```

## 3. Centralized Reactive Store (Redux/Signal Pattern)

For complex applications with multi-step workflows, async side effects, or global user sessions, use a **Reactive Central Store**. Components subscribe to store changes and re-render automatically when reactive state updates.

### Lightweight Reactive Store Implementation

```javascript
// store.js
export class Store {
  constructor(initialState = {}) {
    this.listeners = new Set();
    
    // Wrap state in JS Proxy to trigger listeners on modification
    this.state = new Proxy(initialState, {
      set: (target, key, value) => {
        target[key] = value;
        this.notify();
        return true;
      }
    });
  }

  subscribe(listener) {
    this.listeners.add(listener);
    listener(this.state); // Immediately push current state on subscription
    return () => this.listeners.delete(listener);
  }

  notify() {
    this.listeners.forEach((listener) => listener(this.state));
  }
}

// Global store instance
export const appStore = new Store({ user: 'Guest', theme: 'light' });

```

### Consuming the Store inside Web Components

```javascript
class UserGreeting extends HTMLElement {
  connectedCallback() {
    // Subscribe component to global store
    this.unsubscribe = appStore.subscribe((state) => {
      this.textContent = `Welcome back, ${state.user}! Mode: ${state.theme}`;
    });
  }

  disconnectedCallback() {
    this.unsubscribe();
  }
}
customElements.define('user-greeting', UserGreeting);

class ThemeToggle extends HTMLElement {
  connectedCallback() {
    this.innerHTML = `<button>Toggle Theme</button>`;
    this.querySelector('button').addEventListener('click', () => {
      // Direct state mutation triggers reactive update across all subscribers
      appStore.state.theme = appStore.state.theme === 'light' ? 'dark' : 'light';
    });
  }
}
customElements.define('theme-toggle', ThemeToggle);

```

## 4. DOM Context Protocol Pattern (W3C Community Protocol)

To avoid "prop drilling" state through 5 levels of container elements, modern Web Components leverage the **Community Context Protocol**. It uses native bubbling DOM events to request state from the nearest ancestral context provider element.

### Context Provider & Consumer Example

```javascript
// --- Define Context Key ---
const ThemeContext = "app-theme-context";

// --- Ancestor: Context Provider (<theme-provider>) ---
class ThemeProvider extends HTMLElement {
  constructor() {
    super();
    this.currentTheme = "dark";
  }

  connectedCallback() {
    // Listen for bubbling context-request events from deep descendants
    this.addEventListener("context-request", (event) => {
      if (event.detail.context === ThemeContext) {
        event.stopPropagation(); // Stop event bubbling
        // Provide value and subscribe callback
        event.detail.callback(this.currentTheme);
      }
    });
  }
}
customElements.define("theme-provider", ThemeProvider);

// --- Deep Descendant: Context Consumer (<themed-card>) ---
class ThemedCard extends HTMLElement {
  connectedCallback() {
    // Dispatch bubbling event to search up DOM tree for closest Provider
    this.dispatchEvent(
      new CustomEvent("context-request", {
        detail: {
          context: ThemeContext,
          callback: (themeValue) => {
            this.style.background = themeValue === "dark" ? "#222" : "#fff";
            this.style.color = themeValue === "dark" ? "#fff" : "#000";
          }
        },
        bubbles: true,
        composed: true // Traverses Shadow DOM boundaries
      })
    );
  }
}
customElements.define("themed-card", ThemedCard);

```

```html
<!-- HTML Structure -->
<theme-provider>
  <div>
    <section>
      <!-- Automatically receives context without explicit property passing -->
      <themed-card>Card content inside deep tree</themed-card>
    </section>
  </div>
</theme-provider>

```

## Comparison Matrix: Pattern Selection

| Pattern                       | Best For                            | Pros                                | Cons                                  |
| ----------------------------- | ----------------------------------- | ----------------------------------- | ------------------------------------- |
| **Parent-Child Props/Events** | Direct parent & child elements      | Native browser behavior, simple     | Suffers from prop-drilling if deep    |
| **Event Bus (Pub/Sub)**       | Unrelated/distant components        | Highly decoupled, flexible          | Hard to trace data flow in large apps |
| **Centralized Store**         | Application-wide shared state       | Single source of truth, predictable | Higher initial boilerplate setup      |
| **Context API Protocol**      | Deep component trees (Themes, Auth) | Zero prop-drilling, modular         | Requires ancestor provider wrapper    |
