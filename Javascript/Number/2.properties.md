Here is a complete, practical guide covering all static **Number Properties** in JavaScript.

Static properties belong to the global `Number` object itself—you access them directly via `Number.PROPERTY_NAME` rather than on a number instance (e.g., `Number.MAX_VALUE`, not `(123).MAX_VALUE`).

---

## Quick Reference Summary

| Property                       | Value / Description                          | Primary Use Case                                      |
| ------------------------------ | -------------------------------------------- | ----------------------------------------------------- |
| **`Number.EPSILON`**           | $\approx 2.220446049250313 \times 10^{-16}$  | Safely comparing floating-point numbers.              |
| **`Number.MAX_VALUE`**         | $\approx 1.7976931348623157 \times 10^{308}$ | Largest positive representable float.                 |
| **`Number.MIN_VALUE`**         | $\approx 5 \times 10^{-324}$                 | Smallest positive representable float (closest to 0). |
| **`Number.MAX_SAFE_INTEGER`**  | $2^{53} - 1 = 9,007,199,254,740,991$         | Maximum integer for accurate math calculations.       |
| **`Number.MIN_SAFE_INTEGER`**  | $-(2^{53} - 1) = -9,007,199,254,740,991$     | Minimum integer for accurate math calculations.       |
| **`Number.POSITIVE_INFINITY`** | `Infinity`                                   | Represents values exceeding `MAX_VALUE`.              |
| **`Number.NEGATIVE_INFINITY`** | `-Infinity`                                  | Represents negative values exceeding `-MAX_VALUE`.    |
| **`Number.NaN`**               | `"Not-a-Number"`                             | Represents invalid mathematical operations.           |

## 1. `Number.EPSILON` — Floating-Point Precision Equality

`Number.EPSILON` represents the difference between $1$ and the smallest floating-point value greater than $1$.

Because binary floating-point math causes rounding inaccuracies (e.g., `0.1 + 0.2 === 0.30000000000000004`), comparing floats directly with `===` fails. `Number.EPSILON` provides an acceptable tolerance threshold.

```javascript
// Direct equality check fails due to floating-point rounding
console.log(0.1 + 0.2 === 0.3); // false

// Safe floating-point equality comparison using EPSILON
function areFloatsEqual(a, b) {
  return Math.abs(a - b) < Number.EPSILON;
}

console.log(areFloatsEqual(0.1 + 0.2, 0.3)); // true

```

## 2. Safe Integer Boundaries

JavaScript represents all standard numbers as 64-bit floating point numbers. Due to mantissa limits (53 bits of precision), integer calculations become inaccurate beyond these boundaries.

### `Number.MAX_SAFE_INTEGER` & `Number.MIN_SAFE_INTEGER`

```javascript
console.log(Number.MAX_SAFE_INTEGER); //  9007199254740991 ( 2^53 - 1 )
console.log(Number.MIN_SAFE_INTEGER); // -9007199254740991 ( -(2^53 - 1) )

// Exceeding MAX_SAFE_INTEGER loses math accuracy:
const max = Number.MAX_SAFE_INTEGER;
console.log(max + 1); // 9007199254740992
console.log(max + 2); // 9007199254740992 (❌ Loss of precision! +1 and +2 yield the same result)

// Recommendation: Use BigInt for integers beyond safe bounds
console.log(BigInt(max) + 2n); // 9007199254740993n (✅ Accurate)

```

## 3. Physical Value Limits

These properties define the raw limits of floating-point representation in 64-bit IEEE 754 format.

### `Number.MAX_VALUE` & `Number.MIN_VALUE`

* **`MAX_VALUE`**: The largest positive number JavaScript can represent. Any value greater than `MAX_VALUE` overflows to `Infinity`.
* **`MIN_VALUE`**: The smallest **positive** number closest to `0` (not the most negative number!). Any value smaller than `MIN_VALUE` underflows to `0`.

```javascript
console.log(Number.MAX_VALUE); // 1.7976931348623157e+308
console.log(Number.MIN_VALUE); // 5e-324

// Exceeding MAX_VALUE results in Infinity
console.log(Number.MAX_VALUE * 2); // Infinity

// Values below MIN_VALUE underflow to 0
console.log(Number.MIN_VALUE / 2); // 0

```

---

## 4. Infinity Constants

These represent mathematical infinity resulting from overflow or division by zero.

### `Number.POSITIVE_INFINITY` & `Number.NEGATIVE_INFINITY`

```javascript
console.log(Number.POSITIVE_INFINITY); // Infinity
console.log(Number.NEGATIVE_INFINITY); // -Infinity

// Operations that yield infinity
console.log(1 / 0);          // Infinity
console.log(-1 / 0);         // -Infinity
console.log(Math.pow(10, 1000)); // Infinity

// Checking for infinity
console.log(Number.POSITIVE_INFINITY === Infinity); // true

```

---

## 5. `Number.NaN` — Not a Number

`Number.NaN` represents a value that is not a legal number, usually resulting from undefined or invalid mathematical calculations (e.g., `0 / 0` or `Math.sqrt(-1)`).

### Unique Property of `NaN`

`NaN` is the **only value in JavaScript that is not equal to itself** (`NaN === NaN` is `false`).

```javascript
console.log(Number.NaN); // NaN

// Invalid operations that produce NaN
console.log("hello" * 5); // NaN
console.log(0 / 0);       // NaN

// NaN self-inequality check
console.log(Number.NaN === Number.NaN); // false

// ✅ Safe check for NaN
console.log(Number.isNaN(Number.NaN)); // true

```
