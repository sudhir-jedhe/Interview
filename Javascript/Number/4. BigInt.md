**`BigInt`** is a primitive numeric type in JavaScript (introduced in ES2020) designed to represent integers of **arbitrary size**. It overcomes the precision limits of standard JavaScript numbers, which lose accuracy beyond $2^{53} - 1$ (`Number.MAX_SAFE_INTEGER`).

---

## Why BigInt is Needed

Standard JavaScript numbers follow the **IEEE 754 double-precision 64-bit floating-point format**. Because only 52 bits are used for the fraction/mantissa, integers larger than $9,007,199,254,740,991$ cannot be represented accurately:

```javascript
const maxSafe = Number.MAX_SAFE_INTEGER; // 9007199254740991

console.log(maxSafe + 1); // 9007199254740992
console.log(maxSafe + 2); // 9007199254740992 (❌ Precision loss: +1 and +2 yield the same result!)

```

`BigInt` solves this by dynamically allocating memory to store integers as large as system RAM permits:

```javascript
const maxSafeBig = 9007199254740991n;

console.log(maxSafeBig + 1n); // 9007199254740992n
console.log(maxSafeBig + 2n); // 9007199254740993n (✅ Exact precision maintained)

```

---

## 1. Syntax & Creation

You can create a `BigInt` in two ways:

1. **Literal Syntax:** Append an **`n`** to the end of an integer.
2. **Constructor:** Call `BigInt(value)` passing a string, number, or hex/binary literal.

```javascript
// 1. Literal notation
const bigLiteral = 123456789012345678901234567890n;

// 2. BigInt constructor from String (recommended for large numbers)
const bigFromString = BigInt("9007199254740991234567890");

// From Hex, Binary, or Octal literals
const bigHex = BigInt("0x1fffffffffffff"); // 9007199254740991n
const bigBin = 0b101010n;                 // 42n

console.log(typeof bigLiteral); // "bigint"

```

> **Warning:** Avoid passing large numbers as raw numeric literals to `BigInt(9007199254740991234)` because the Number value loses precision *before* `BigInt()` receives it. Always pass large values as **Strings** (`BigInt("9007199254740991234")`).

## 2. Supported Operations

`BigInt` supports standard arithmetic operators (`+`, `-`, `*`, `/`, `%`, `**`) and bitwise operators (`&`, `|`, `^`, `~`, `<<`, `>>`).

### Key Operational Rules

#### A. Division Truncates Decimals (No Floats)

Because `BigInt` represents strictly integers, division discards any fractional/decimal remainder towards zero:

```javascript
console.log(5n / 2n); // 2n (NOT 2.5n)
console.log(-5n / 2n); // -2n

```

#### B. Cannot Mix `BigInt` and `Number` Directly

To prevent silent precision loss, implicit type coercion between `Number` and `BigInt` throws a `TypeError`:

```javascript
const num = 10;
const big = 20n;

// ❌ Throws TypeError: Cannot mix BigInt and other types
// const result = num + big; 

// ✅ Convert explicitly to a single type
const result1 = BigInt(num) + big; // 30n
const result2 = num + Number(big);  // 30

```

#### C. Comparisons & Equality

* **Strict Equality (`===`):** Returns `false` because they are different primitive types.
* **Loose Equality (`==`):** Coerces types for comparison.
* **Relational Operators (`<`, `>`):** Work seamlessly between `Number` and `BigInt`.

```javascript
console.log(0n === 0); // false
console.log(0n == 0);  // true

console.log(1n < 2);   // true
console.log(2n > 1);   // true

```

## 3. Comparison: `Number` vs `BigInt`

| Feature                       | `Number`                                     | `BigInt`                                       |
| ----------------------------- | -------------------------------------------- | ---------------------------------------------- |
| **Type Name**                 | `"number"`                                   | `"bigint"`                                     |
| **Data Representation**       | 64-bit IEEE 754 Floating Point               | Arbitrary-precision Integer                    |
| **Maximum Value**             | $\approx 1.79 \times 10^{308}$ (`MAX_VALUE`) | Unbounded (memory limit)                       |
| **Safe Integer Range**        | $\pm(2^{53} - 1)$                            | Infinite whole integers                        |
| **Decimal Support**           | ✅ Yes (`10.5`)                               | ❌ No (`10.5n` throws `SyntaxError`)            |
| **Math Object Compatibility** | ✅ Supported (`Math.sqrt(16)`)                | ❌ Throws `TypeError`                           |
| **JSON.stringify Support**    | ✅ Supported                                  | ❌ Throws `TypeError` without custom serializer |

## 4. Common Edge Cases & Caveats

### 1. `Math` Object Methods Do Not Work

Methods on the global `Math` object (like `Math.max()`, `Math.pow()`, `Math.sqrt()`, `Math.round()`) expect `Number` arguments and throw a `TypeError` when passed a `BigInt`:

```javascript
// ❌ Throws TypeError: Cannot convert a BigInt value to a number
// Math.max(1n, 2n); 

// Use conditional comparisons or BigInt operators instead:
const max = 1n > 2n ? 1n : 2n; // 2n

```

### 2. `JSON.stringify()` Throws an Error

`JSON.stringify()` does not know how to serialize `BigInt` values by default and throws an error:

```javascript
const data = { id: 12345678901234567890n };

// ❌ Throws TypeError: Do not know how to serialize a BigInt
// JSON.stringify(data);

// ✅ Fix: Add a custom prototype method to serialize BigInt as a string or number
BigInt.prototype.toJSON = function () {
  return this.toString();
};

console.log(JSON.stringify(data)); 
// Output: '{"id":"12345678901234567890"}'

```

## Practical Real-World Use Cases

1. **64-bit Database IDs:** Handling high-precision primary keys from databases like PostgreSQL (`BIGINT`) or Twitter Snowflake IDs (`1823120194812391234`).
2. **Financial & Cryptocurrency Calculations:** Working with crypto token values (e.g., Ethereum Wei, where $1 \text{ ETH} = 10^{18} \text{ Wei}$) without floating-point inaccuracies.
3. **High-Precision Timestamps:** Reading nanosecond-level execution benchmarks (`process.hrtime.bigint()`).
