Here is a complete, practical guide covering both **Basic Instance Methods** and **Static Number Methods** in JavaScript.

---

## 1. Basic Number Methods (Instance Methods)

These methods are called directly on a number variable or literal (e.g., `num.toFixed(2)`).

| Method                      | Description                                                                                      | Example                     | Output      |
| --------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------- | ----------- |
| **`toString(radix)`**       | Converts a number to a string. Supports base conversion (2 for binary, 16 for hex).              | `(255).toString(16)`        | `"ff"`      |
| **`toExponential(digits)`** | Returns a string with the number written in exponential/scientific notation.                     | `(123456).toExponential(2)` | `"1.23e+5"` |
| **`toFixed(digits)`**       | Returns a string with the number written with a **fixed number of decimals** (rounds as needed). | `(9.656).toFixed(2)`        | `"9.66"`    |
| **`toPrecision(digits)`**   | Returns a string with a number written with a **specified total length/precision**.              | `(9.656).toPrecision(2)`    | `"9.7"`     |
| **`valueOf()`**             | Returns the primitive number value from a Number object wrapper.                                 | `(123).valueOf()`           | `123`       |

### Code Examples

```javascript
const num = 12.34567;

// 1. toString() - String conversion & Radix/Base switching
console.log(num.toString());       // "12.34567"
console.log((16).toString(2));     // "10000" (Binary for 16)

// 2. toExponential() - Scientific notation
console.log(num.toExponential(2)); // "1.23e+1"

// 3. toFixed() - Formatting currency / specific decimal places
console.log(num.toFixed(2));       // "12.35" (String)
console.log(num.toFixed(0));       // "12"

// 4. toPrecision() - Total significant digits
console.log(num.toPrecision(3));   // "12.3"
console.log((0.00123).toPrecision(2)); // "0.0012"

// 5. valueOf() - Primitive extraction
const numObj = new Number(42);
console.log(typeof numObj);         // "object"
console.log(typeof numObj.valueOf()); // "number"

```

## 2. Static Number Methods

Static methods belong to the global `Number` object itself and cannot be called directly on an instance variable (e.g., use `Number.isInteger(x)`, NOT `x.isInteger()`).

> **Note on `Number.parseInt()` & `Number.parseFloat()`:**
> These work identically to the global `parseInt()` and `parseFloat()` functions introduced in ES5 to avoid polluting the global scope.

| Method                       | Description                                                                                   | Example                       | Output  |
| ---------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------- | ------- |
| **`Number.isFinite()`**      | Checks if a value is a finite number (returns `false` for `Infinity`, `-Infinity`, or `NaN`). | `Number.isFinite(100)`        | `true`  |
| **`Number.isInteger()`**     | Checks if a value is a whole integer (no decimals).                                           | `Number.isInteger(10.5)`      | `false` |
| **`Number.isNaN()`**         | Checks if a value is strictly `NaN` without coercion.                                         | `Number.isNaN(NaN)`           | `true`  |
| **`Number.isSafeInteger()`** | Checks if an integer falls within IEEE-754 safe bounds ($-2^{53} + 1$ to $2^{53} - 1$).       | `Number.isSafeInteger(10)`    | `true`  |
| **`Number.parseInt()`**      | Parses a string argument and returns an integer.                                              | `Number.parseInt("42.9px")`   | `42`    |
| **`Number.parseFloat()`**    | Parses a string argument and returns a floating-point number.                                 | `Number.parseFloat("42.9px")` | `42.9`  |

### Code Examples

```javascript
// 1. Number.isFinite() vs Global isFinite()
console.log(Number.isFinite(500));         // true
console.log(Number.isFinite(Infinity));    // false
console.log(Number.isFinite("500"));       // false (Strict: doesn't coerce string to number)

// 2. Number.isInteger()
console.log(Number.isInteger(10));         // true
console.log(Number.isInteger(10.0));       // true
console.log(Number.isInteger(10.5));       // false

// 3. Number.isNaN() vs Global isNaN()
console.log(Number.isNaN(NaN));            // true
console.log(Number.isNaN("hello"));        // false (Strict: "hello" is a string, not NaN)
console.log(isNaN("hello"));               // true (Global isNaN coerces string to NaN first!)

// 4. Number.isSafeInteger()
console.log(Number.isSafeInteger(9007199254740991)); // true (MAX_SAFE_INTEGER)
console.log(Number.isSafeInteger(9007199254740992)); // false (Exceeds precise representation limit)

// 5. Parsing Utilities
console.log(Number.parseInt("100px"));      // 100
console.log(Number.parseInt("1101", 2));    // 13 (Parses binary string to decimal)
console.log(Number.parseFloat("3.14159abc")); // 3.14159

```

## Key Takeaway Summary

* **Formatting methods (`toFixed`, `toPrecision`, `toExponential`) return `Strings`, not numbers.** You can wrap them in `Number()` or use unary `+` if you need them back as numbers (e.g., `+num.toFixed(2)`).
* **Static `Number.isNaN()` and `Number.isFinite()` are safer** than global `isNaN()` and `isFinite()` because they do not perform implicit type coercion.

JavaScript represents all standard numbers using **IEEE 754 double-precision 64-bit floating-point format**.

Because of how binary floating-point arithmetic works, standard numbers have strict precision limits. **`BigInt`** was introduced in ES2020 to overcome these limitations and safely represent arbitrarily large integers.

---

## 1. How Double-Precision Floating-Point Works

In memory, every JavaScript `Number` occupies **64 bits**, divided into three distinct components:

$$\text{64 Bits Total} = 1 \text{ Sign Bit} + 11 \text{ Exponent Bits} + 52 \text{ Mantissa Bits}$$

```
   1 Bit         11 Bits                             52 Bits
+---------+--------------------+--------------------------------------------------+
|  Sign   |   Exponent (E)     |              Mantissa / Significand (M)          |
| (0=+,1=-) (Biased offset 1023)|            (Fractional precision bits)           |
+---------+--------------------+--------------------------------------------------+

```

1. **Sign Bit (1 bit):** Determines whether the number is positive (`0`) or negative (`1`).
2. **Exponent (11 bits):** Represents the magnitude scale (power of 2), biased by $1023$.
3. **Mantissa / Significand (52 bits):** Stores the actual binary digits of the number. Using an implicit leading bit strategy, this provides **53 bits of effective precision**.

---

## 2. Precision Limitations of IEEE 754 Numbers

Because standard numbers rely on a fixed 53 bits of precision, they run into two major issues: **binary decimal rounding errors** and **safe integer limits**.

### A. Binary Decimal Inexactness (`0.1 + 0.2 !== 0.3`)

In base 10, fractions like $1/3$ produce repeating decimals ($0.3333\dots$). Similarly, in base 2 (binary), numbers like $0.1$ ($1/10$) and $0.2$ ($1/5$) cannot be represented exactly in floating-point binary format—they become infinite repeating fractions.

```javascript
console.log(0.1 + 0.2); 
// Output: 0.30000000000000004

console.log(0.1 + 0.2 === 0.3); 
// Output: false

```

### B. The Safe Integer Boundary (`Number.MAX_SAFE_INTEGER`)

Because the mantissa offers 53 bits of precision, the maximum integer that can be represented unambiguously without losing precision is $2^{53} - 1$:

$$\text{Number.MAX\_SAFE\_INTEGER} = 2^{53} - 1 = 9,007,199,254,740,991$$

When you exceed this limit, there aren't enough bits in the mantissa to represent every individual integer. As a result, adjacent integers map to the exact same floating-point representation, causing calculation errors:

```javascript
const maxSafe = Number.MAX_SAFE_INTEGER; // 9007199254740991

console.log(maxSafe + 1); // 9007199254740992
console.log(maxSafe + 2); // 9007199254740992 (❌ Loss of precision! +1 and +2 produce the same result)

console.log(maxSafe + 1 === maxSafe + 2); // true

```

---

## 3. Enter `BigInt` — Infinite Precision for Integers

To solve precision loss for large integers, JavaScript introduced **`BigInt`**.

Unlike standard numbers, `BigInt` is a distinct primitive type (`typeof x === "bigint"`) that allocates memory dynamically, allowing it to store integers of **arbitrary size** bounded only by available system RAM.

### Creating a BigInt

You create a `BigInt` by appending an **`n`** suffix to an integer literal, or by passing a string to the `BigInt()` constructor:

```javascript
// 1. Literal syntax with 'n'
const hugeNumber = 9007199254740991n;

// 2. BigInt constructor from String
const parsedHuge = BigInt("90071992547409912345678901234567890");

// Safe calculations far beyond MAX_SAFE_INTEGER:
console.log(hugeNumber + 1n); // 9007199254740992n
console.log(hugeNumber + 2n); // 9007199254740993n (✅ Exact precision maintained)

```

---

## 4. Key Rules & Differences: `Number` vs `BigInt`

| Property / Operation    | Standard `Number`                 | `BigInt`                                                |
| ----------------------- | --------------------------------- | ------------------------------------------------------- |
| **Type**                | Floating-point (IEEE 754)         | Arbitrary-precision integer                             |
| **Max Safe Limit**      | $2^{53} - 1$ (`9007199254740991`) | Unlimited (bounded by memory)                           |
| **Decimals/Floats**     | Supported (`10.5`)                | **Not supported** (`10.5n` throws `SyntaxError`)        |
| **Division Behavior**   | Produces decimals (`5 / 2 = 2.5`) | **Truncates decimals** (`5n / 2n = 2n`)                 |
| **Math Object Support** | Supported (`Math.sqrt(16)`)       | **Not supported** (`Math.sqrt(16n)` throws `TypeError`) |

### Mixing `Number` and `BigInt`

To prevent accidental loss of precision from implicit rounding, JavaScript **disallows direct arithmetic between `Number` and `BigInt**`:

```javascript
const num = 10;
const big = 20n;

// ❌ Throws TypeError: Cannot mix BigInt and other types
// const result = num + big; 

// ✅ Correct: Convert explicitly to one common type
const result1 = BigInt(num) + big; // 30n
const result2 = num + Number(big);  // 30

```

## When Do You Need `BigInt` in Real Applications?

1. **Database Identifiers:** Handling 64-bit integer Primary Keys (e.g., PostgreSQL `BIGINT` or Twitter/X Snowflake IDs like `1823120194812391234`).
2. **High-Precision Timestamps:** Nanosecond-level performance timing metrics (`process.hrtime.bigint()`).
3. **Cryptography & Finance:** Working with cryptocurrency tokens (e.g., Wei values in Ethereum where $1 \text{ ETH} = 10^{18} \text{ Wei}$) or cryptographic key pairs.
