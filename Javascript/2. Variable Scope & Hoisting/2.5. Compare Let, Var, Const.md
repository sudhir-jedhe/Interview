**Hoisting** is a behavior in JavaScript where variable and function declarations are conceptually moved to the top of their respective scopes before the code is executed.

Technically, the code isn't physically moved anywhere. Instead, during the "compile phase" (right before execution), the JavaScript engine scans the code, finds all the declarations, and reserves memory space for them.

However, *how* that memory is handled differs drastically depending on whether you are using a function, `var`, `let`, or `const`.

Here is a breakdown of how hoisting applies to each.

## 1. Function Declarations (Fully Hoisted)

Standard function declarations are **fully hoisted**. The engine hoists both the function's name and its entire body. This means you can invoke a function in your code lines before you actually write the function out.

```javascript
// ✅ Works perfectly! 
greet("Alice"); 

// The declaration is fully hoisted to the top
function greet(name) {
  console.log(`Hello, ${name}!`);
}

```

## 2. `var` Variables (Hoisted and Initialized to `undefined`)

When the engine hoists a variable declared with `var`, it moves the declaration to the top of the scope, but it **does not hoist the assignment**. Instead, it automatically initializes the variable with the value `undefined`.

If you try to use a `var` before it is declared, the code won't crash, but it won't have your value yet.

```javascript
// ⚠️ Does not throw an error, but outputs 'undefined'
console.log(score); 

var score = 100;

// Now it has the value
console.log(score); // Outputs: 100

```

*Behind the scenes, JavaScript reads it like this:*

```javascript
var score = undefined; // Hoisted to the top
console.log(score);
score = 100;           // Assignment stays where you wrote it

```

## 3. `let` and `const` (Hoisted, but in the Temporal Dead Zone)

It is a common misconception that `let` and `const` are not hoisted. They **are** hoisted to the top of their block scope.

However, unlike `var`, the engine does **not** initialize them with `undefined`. Instead, they are placed in the **Temporal Dead Zone (TDZ)**. If you try to access them before the exact line where they are declared, JavaScript will immediately throw a `ReferenceError`.

```javascript
// 🚨 Throws ReferenceError: Cannot access 'playerName' before initialization
console.log(playerName); 

let playerName = "Mario";

```

## 4. Function Expressions and Arrow Functions

If you assign a function to a variable (known as a function expression or an arrow function), the hoisting rules follow the **variable**, not the function.

This means you **cannot** call an arrow function before you define it, unlike a standard function declaration.

```javascript
// 🚨 Throws TypeError: jump is not a function
// (Because 'jump' is hoisted as a var, so it equals 'undefined' right now)
jump(); 

var jump = function() {
  console.log("Jumping!");
};

// 🚨 Throws ReferenceError: Cannot access 'run' before initialization
// (Because 'run' is hoisted as a const, placing it in the TDZ)
run(); 

const run = () => {
  console.log("Running!");
};

```

## Summary Cheat Sheet

| Declaration Type     | Is it Hoisted? | Initialized With               | Can use before declaration?      |
| -------------------- | -------------- | ------------------------------ | -------------------------------- |
| **`function () {}`** | Yes            | The function body              | **Yes**                          |
| **`var`**            | Yes            | `undefined`                    | Yes (but returns `undefined`)    |
| **`let` / `const**`  | Yes            | *Nothing* (Enters TDZ)         | **No** (Throws `ReferenceError`) |
| **Arrow Functions**  | Yes            | Depends on `var`/`let`/`const` | **No**                           |

#### **Key Differences**

| **Feature**                      | **`var`**                              | **`let`**                | **`const`**              |
| -------------------------------- | -------------------------------------- | ------------------------ | ------------------------ |
| **Scope**                        | Function or global scope               | Block scope              | Block scope              |
| **Re-declaration**               | Allowed                                | Not allowed              | Not allowed              |
| **Updation**                     | Allowed                                | Allowed                  | Not allowed              |
| **Initialization**               | Optional                               | Optional                 | Mandatory                |
| **Hoisting**                     | Hoisted and initialized to `undefined` | Hoisted but stays in TDZ | Hoisted but stays in TDZ |
| **Access Before Initialization** | Returns `undefined`                    | Throws `ReferenceError`  | Throws `ReferenceError`  |
