**TypeScript** is fundamentally a syntactic superset of **JavaScript**. This means that any valid JavaScript code is also valid TypeScript code, but TypeScript adds an additional layer on top: **static typing**.

Here is a breakdown of the core differences between the two languages.

### 1. Type System (Dynamic vs. Static)

* **JavaScript (Dynamic):** Variables do not have fixed types. A variable can hold a string, and later be reassigned to a number. Type checking happens at **runtime** (when the code is actually executing).
* **TypeScript (Static):** You can define what type of data a variable, function parameter, or object should hold. Type checking happens at **compile time** (while you are writing and building the code).

### 2. Execution and Compilation

* **JavaScript:** Can be read and executed directly by browsers (like Chrome or Safari) and Node.js environments.
* **TypeScript:** Browsers and Node.js cannot execute TypeScript directly. It must first be **transpiled** (compiled) down into plain JavaScript before it can run.

### 3. Error Catching

* **JavaScript:** Errors (like passing a string into a function that expects a number) are usually discovered when the code is run, which can lead to bugs in production if not thoroughly tested.
* **TypeScript:** Catches type-related errors and typos directly in your code editor as you type. It will refuse to compile if there are type mismatches, preventing many common bugs before the code ever runs.

### 4. Code Example

**JavaScript:**

```javascript
function calculateTotal(price, taxRate) {
  return price + (price * taxRate);
}

// JavaScript won't stop you from doing this, which results in NaN (Not a Number)
calculateTotal(100, "high"); 

```

**TypeScript:**

```typescript
function calculateTotal(price: number, taxRate: number): number {
  return price + (price * taxRate);
}

// The editor will immediately throw an error here before the code is even run:
// "Argument of type 'string' is not assignable to parameter of type 'number'."
calculateTotal(100, "high"); 

```

### 5. Features and Tooling

* **JavaScript:** Continues to evolve with ECMAScript (ES6+) updates, but lacks native support for strict object shaping.
* **TypeScript:** Introduces concepts from object-oriented programming that don't exist natively in JavaScript, such as **Interfaces**, **Enums**, and **Generics**. Because of these explicit types, IDEs (like VS Code) can provide vastly superior autocomplete, refactoring tools, and inline documentation for TypeScript.

### Summary: When to use which?

* **Choose JavaScript** for smaller scripts, quick prototyping, simple web projects, or when you want to minimize build steps and configuration.
* **Choose TypeScript** for large-scale applications, projects with multiple developers, or complex codebases where maintainability, refactoring, and catching bugs early are top priorities.

Here is the comparison between JavaScript and TypeScript formatted as a table for quick reference:

| Feature                   | JavaScript                                                                                    | TypeScript                                                                                  |
| ------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **Type System**           | **Dynamic**: Variables do not have fixed types and can be reassigned to different data types. | **Static**: Variable types are explicitly defined and cannot hold data of a different type. |
| **Type Checking**         | **Runtime**: Types are checked while the code is actively executing.                          | **Compile-time**: Types are checked by the compiler before the code is run.                 |
| **Execution**             | Runs directly in web browsers (Chrome, Safari, etc.) and Node.js environments.                | Cannot be run directly; must be **transpiled** (compiled) into plain JavaScript first.      |
| **Error Catching**        | Errors (like type mismatches) are typically discovered when the code is executed.             | Errors are caught immediately in your code editor as you type, preventing runtime bugs.     |
| **Unique Concepts**       | Relies on standard ECMAScript (ES6+) features and prototype-based inheritance.                | Adds Interfaces, Enums, Generics, and strict object shaping on top of standard JavaScript.  |
| **Tooling & IDE Support** | Basic autocomplete and refactoring based on inference.                                        | Superior autocomplete, safer refactoring, and inline documentation due to explicit types.   |
| **Best For...**           | Quick prototyping, smaller scripts, simple web projects, and fast setup.                      | Large-scale applications, team environments, and complex React/Node codebases.              |
