When target environments don't support native `async`/`await` (such as ES5 or older ES6 runtimes), compilers like TypeScript and Babel transpile `async` functions into a combination of **ES6 Generators (`function*` / `yield`)** and a **Promise runner / helper function** (commonly known as `__awaiter` in TypeScript or `_asyncToGenerator` in Babel).

---

### 1. The Original Source Code

```javascript
async function fetchUserData(userId) {
  console.log('Start fetching');
  const user = await getUser(userId);
  console.log('Got user:', user.name);
  const posts = await getPosts(user.id);
  return { user, posts };
}

```

---

### 2. How the Compiler Rewrites It

The compiler breaks this down into two distinct parts:

1. A **Generator Function** that replaces every `await <expr>` with `yield <expr>`.
2. A **Runner / Driver (`__awaiter`)** that steps through the generator, waiting for yielded promises to resolve before pushing results back in.

```javascript
// The transpiled version of fetchUserData:
function fetchUserData(userId) {
  return __awaiter(this, void 0, void 0, function* () {
    console.log('Start fetching');
    const user = yield getUser(userId);
    console.log('Got user:', user.name);
    const posts = yield getPosts(user.id);
    return { user, posts };
  });
}

```

---

### 3. The Underlying Runner (`__awaiter` / `_asyncToGenerator`)

Here is the exact runtime helper TypeScript and Babel generate to drive the generator:

```javascript
function __awaiter(thisArg, _arguments, P, generator) {
  function adopt(value) {
    // Ensures non-promise yielded values are wrapped into Promises
    return value instanceof (P || (P = Promise))
      ? value
      : new P(function (resolve) {
          resolve(value);
        });
  }

  return new (P || (P = Promise))(function (resolve, reject) {
    // 1. Instantiate the generator iterator
    const iterator = generator.apply(thisArg, _arguments || []);

    // 2. Advance the generator with fulfilled values
    function step(result) {
      if (result.done) {
        // Function returned: resolve the outer promise
        resolve(result.value);
      } else {
        // Function yielded: wait for promise to settle, then step again
        adopt(result.value).then(fulfilled, rejected);
      }
    }

    function fulfilled(value) {
      try {
        // Resumes execution at the `yield` and injects the resolved value
        step(iterator.next(value));
      } catch (e) {
        reject(e);
      }
    }

    function rejected(value) {
      try {
        // Resumes execution by throwing the rejection into the generator's `try/catch`
        step(iterator.throw(value));
      } catch (e) {
        reject(e);
      }
    }

    // 3. Kick off the first step synchronously
    step(iterator.next());
  });
}

```

---

### 4. How the Execution Loop Works

1. **Initial Synchronous Call:**

* `__awaiter` creates and returns a new `Promise`.
* It immediately calls `iterator.next()`. The generator runs synchronously until it reaches the first `yield` (`yield getUser(userId)`).
* It yields `{ value: promiseFromGetUser, done: false }`.

1. **Microtask Hand-off:**

* `__awaiter` wraps the yielded value with `adopt(result.value)`.
* It attaches `.then(fulfilled, rejected)`.
* The synchronous call finishes and returns the outer promise.

1. **Resuming on Resolution:**

* When `getUser` resolves with `userObject`, the microtask queue fires `fulfilled(userObject)`.
* `fulfilled` calls `iterator.next(userObject)`.
* The generator resumes right where it stopped, assigning `userObject` to the `user` variable, and proceeds until the next `yield` or `return`.

1. **Handling Errors (`try/catch`):**

* If a yielded promise rejects, `rejected(err)` calls `iterator.throw(err)`.
* The generator engine injects an exception directly at the `yield` site, allowing standard JavaScript `try { ... } catch (err)` blocks inside the generator to catch it. If unhandled inside the generator, the outer promise rejects.

---

### 5. What If the Target is ES5 (No Native Generators)?

When targeting ES5 where `function*` is not supported, Babel (via `regeneratorRuntime`) or TypeScript compiles the generator into a **State Machine switch-case statement**:

```javascript
// Conceptual ES5 state-machine output:
function fetchUserData(userId) {
  var _state = 0, user, posts;

  return __awaiter(this, void 0, void 0, function (_context) {
    while (1) {
      switch (_state) {
        case 0: // Synchronous phase up to first yield
          console.log('Start fetching');
          _state = 1;
          return { value: getUser(userId), done: false };

        case 1: // Resume with user
          user = _context.sent; // injected from iterator.next()
          console.log('Got user:', user.name);
          _state = 2;
          return { value: getPosts(user.id), done: false };

        case 2: // Resume with posts and complete
          posts = _context.sent;
          return { value: { user: user, posts: posts }, done: true };
      }
    }
  });
}

```
