An **asynchronous Promise** in JavaScript is an object representing the ultimate completion (or failure) of an asynchronous operation and its resulting value.

Instead of passing callback functions into an asynchronous call (which leads to "Callback Hell"), Promises allow you to attach handlers to return objects, treating asynchronous calls more like synchronous functions.

---

## 1. The 3 States of a Promise

A Promise is always in one of three mutually exclusive states:

| State           | Description                                                     | Next Transition                                      |
| --------------- | --------------------------------------------------------------- | ---------------------------------------------------- |
| **`pending`**   | Initial state; the asynchronous operation is still in progress. | Can transition to `fulfilled` or `rejected`.         |
| **`fulfilled`** | The operation completed successfully. Has a **result value**.   | Terminal state (Settled). Cannot change state again. |
| **`rejected`**  | The operation failed. Has a **reason (error)**.                 | Terminal state (Settled). Cannot change state again. |

---

## 2. Creating a Promise

You create a Promise using the `new Promise()` constructor, which takes an **executor function** with two callbacks: `resolve` and `reject`.

```javascript
const myPromise = new Promise((resolve, reject) => {
  const success = true;

  // Simulate an asynchronous operation (e.g. network request)
  setTimeout(() => {
    if (success) {
      resolve("Data fetched successfully!"); // Transitions state to fulfilled
    } else {
      reject(new Error("Network connection failed.")); // Transitions state to rejected
    }
  }, 1000);
});

```

## 3. Consuming Promises

### A. Using `.then()`, `.catch()`, and `.finally()`

```javascript
myPromise
  .then((result) => {
    // Executes if the Promise is fulfilled
    console.log("Success:", result);
    return "Next step data"; // Returns a new Promise automatically
  })
  .then((nextData) => {
    // Promise Chaining: Receives return value of previous .then()
    console.log(nextData);
  })
  .catch((error) => {
    // Executes if ANY previous Promise in the chain is rejected
    console.error("Error:", error.message);
  })
  .finally(() => {
    // Always executes when the Promise is settled (fulfilled OR rejected)
    console.log("Operation complete (cleanup phase).");
  });

```

### B. Using `async / await` (Modern Standard)

`async/await` is syntactic sugar built on top of Promises. An `async` function always returns a Promise, and `await` pauses execution inside the `async` block until the Promise settles.

```javascript
async function handleData() {
  try {
    // Pause execution until myPromise resolves
    const result = await myPromise;
    console.log("Success:", result);
  } catch (error) {
    // Catches rejections using standard try...catch
    console.error("Caught error:", error.message);
  } finally {
    console.log("Operation complete.");
  }
}

handleData();

```

## 4. Static Combinator Methods

JavaScript provides 6 built-in static methods on the `Promise` class to coordinate multiple concurrent Promises:

### 1. `Promise.all([p1, p2, p3])`

* **Behavior:** Waits for **ALL** promises to fulfill. Rejects **immediately** if any single promise rejects ("All or Nothing").
* **Use Case:** Loading page dependencies where every piece of data is required.

```javascript
const [users, posts] = await Promise.all([
  fetch("/api/users").then(r => r.json()),
  fetch("/api/posts").then(r => r.json())
]);

```

### 2. `Promise.allSettled([p1, p2, p3])`

* **Behavior:** Waits for **ALL** promises to settle, regardless of fulfillment or rejection. Never rejects.
* **Use Case:** Running independent background tasks where you want complete results even if some fail.

```javascript
const results = await Promise.allSettled([fetchUser(), fetchConfig()]);
// Returns array of objects: [{ status: 'fulfilled', value: ... }, { status: 'rejected', reason: ... }]

```

### 3. `Promise.race([p1, p2, p3])`

* **Behavior:** Resolves or rejects as soon as **the FIRST** promise settles (fastest response wins).
* **Use Case:** Implementing timeouts for network requests.

```javascript
// Races an API call against a 5-second timeout timer
const data = await Promise.race([
  fetch("/api/data"),
  new Promise((_, reject) => setTimeout(() => reject(new Error("Timeout")), 5000))
]);

```

### 4. `Promise.any([p1, p2, p3])`

* **Behavior:** Resolves as soon as **the FIRST** promise **fulfills**. Ignores rejections unless *all* promises reject (throwing an `AggregateError`).
* **Use Case:** Fetching an asset from multiple mirror servers (use whichever answers first).

## 5. Promises and the Event Loop

Promise callbacks (`.then()`, `.catch()`, `.finally()`, and `await`) execute inside the **Microtask Queue**, which has a higher priority than standard timers (`setTimeout` macrotasks).

```javascript
console.log("1. Synchronous Code");

setTimeout(() => {
  console.log("4. setTimeout (Macrotask)");
}, 0);

Promise.resolve().then(() => {
  console.log("3. Promise Callback (Microtask)");
});

console.log("2. Synchronous Code");

/*
Output Order:
1. Synchronous Code
2. Synchronous Code
3. Promise Callback (Microtask)
4. setTimeout (Macrotask)
*/

```

Explain how to create custom Promises and convert callback functions to Promises with code examples

Converting legacy callback-based functions into Promises—a process known as **Promisification**—allows you to modernize asynchronous JavaScript code, avoid callback hell, and take advantage of modern `async/await` syntax.

---

## 1. Creating Custom Promises from Scratch

To create a custom Promise, instantiate the `new Promise()` constructor. It accepts an **executor function** with two parameters:

* `resolve(value)`: Call this when the operation succeeds.
* `reject(error)`: Call this when an error occurs.

### Example: Delay Utility (`sleep`)

```javascript
// A Promise-based sleep/delay helper
function sleep(ms) {
  return new Promise((resolve) => {
    // Resolve after the specified delay
    setTimeout(() => {
      resolve(`Slept for ${ms}ms`);
    }, ms);
  });
}

// Usage with async/await
async function run() {
  console.log("Start");
  await sleep(2000); // Pauses execution for 2 seconds
  console.log("End (after 2 seconds)");
}

run();

```

---

## 2. Converting Legacy Callbacks to Promises

Legacy APIs (like DOM events, older browser APIs, or standard Node.js modules) often rely on callbacks. You can wrap these functions inside a custom Promise.

### Example A: Converting `navigator.geolocation` (Browser API)

The HTML5 Geolocation API uses success and error callbacks:

```javascript
// 1. Traditional Callback Usage (Old Way)
navigator.geolocation.getCurrentPosition(
  (position) => console.log(position.coords),
  (error) => console.error(error)
);

// 2. Wrapped in a Custom Promise (Modern Way)
function getCurrentPositionPromise(options = {}) {
  return new Promise((resolve, reject) => {
    navigator.geolocation.getCurrentPosition(
      (position) => resolve(position), // Success callback -> resolve
      (error) => reject(error),        // Error callback -> reject
      options
    );
  });
}

// 3. Clean usage with async/await
async function getUserLocation() {
  try {
    const position = await getCurrentPositionPromise();
    console.log("Latitude:", position.coords.latitude);
    console.log("Longitude:", position.coords.longitude);
  } catch (error) {
    console.error("Location error:", error.message);
  }
}

```

---

### Example B: Converting Node.js Error-First Callbacks

Standard Node.js callbacks follow the **Error-First** convention: `(error, result) => { ... }`.

```javascript
const fs = require("fs");

// 1. Promisifying fs.readFile manually
function readFilePromise(filePath, encoding = "utf8") {
  return new Promise((resolve, reject) => {
    fs.readFile(filePath, encoding, (err, data) => {
      if (err) {
        return reject(err); // Reject if error exists
      }
      resolve(data); // Resolve with file contents
    });
  });
}

// 2. Usage
async function readConfig() {
  try {
    const data = await readFilePromise("./config.json");
    console.log("Config contents:", data);
  } catch (error) {
    console.error("Failed to read file:", error);
  }
}

```

## 3. Built-In Helpers for Automatic Promisification

Writing manual Promise wrappers for every function can be tedious. Node.js and modern JavaScript offer built-in tools to automate this.

### A. Node.js `util.promisify` (Node.js)

Node.js includes `util.promisify`, which automatically converts any standard error-first callback function into a Promise-returning function.

```javascript
const fs = require("fs");
const util = require("util");

// Automatically convert fs.readFile to return a Promise
const readFileAsync = util.promisify(fs.readFile);

async function loadData() {
  try {
    const content = await readFileAsync("example.txt", "utf8");
    console.log(content);
  } catch (err) {
    console.error("Read error:", err);
  }
}

```

### B. Node.js Promises API (`fs/promises`)

For built-in Node.js modules like `fs`, `dns`, `stream`, or `child_process`, Node provides native Promise-based submodules out of the box, eliminating the need for `util.promisify`:

```javascript
// Native Promise-based file system module
import { readFile } from "fs/promises";

async function read() {
  const content = await readFile("example.txt", "utf8");
  console.log(content);
}

```

## 4. Writing a Universal Promisify Helper Function

If you are working in a browser environment where `util.promisify` is unavailable, you can write a lightweight utility function to convert any error-first callback function:

```javascript
/**
 * Utility to turn any error-first callback function into a Promise
 */
function promisify(fn) {
  return function (...args) {
    return new Promise((resolve, reject) => {
      fn.call(this, ...args, (err, result) => {
        if (err) {
          return reject(err);
        }
        resolve(result);
      });
    });
  };
}

// --- Example Usage ---
function fakeAsyncDatabaseCall(query, callback) {
  setTimeout(() => {
    if (!query) {
      callback(new Error("Query required"));
    } else {
      callback(null, { id: 1, result: "Query Data" });
    }
  }, 1000);
}

// Convert function
const queryAsync = promisify(fakeAsyncDatabaseCall);

// Usage
async function executeQuery() {
  try {
    const res = await queryAsync("SELECT * FROM users");
    console.log(res);
  } catch (err) {
    console.error(err.message);
  }
}

executeQuery();

```

## Summary Checklist

| Task                         | Pattern                                                                      |
| ---------------------------- | ---------------------------------------------------------------------------- |
| **New Async Logic**          | Use `new Promise((resolve, reject) => { ... })`.                             |
| **Node.js Core Modules**     | Use native promise imports (e.g., `import { readFile } from 'fs/promises'`). |
| **Node.js Legacy Functions** | Use `util.promisify(legacyFunction)`.                                        |
| **Browser Web APIs**         | Wrap success/error callbacks manually inside `new Promise()`.                |
