Debounce a JavaScript function and return a promise

Debouncing is a technique used to limit the number of times a function is called. We've previously seen how to debounce a function, but what if we want to return a promise instead?

Same as before, we can use timeouts to create a delay as needed. We need to clear the current pending timeout, using clearTimeout(), and create a new timeout with setTimeout() each time the debounced function is invoked. Similarly, we can use Function.prototype.apply() to apply the this context to the function and provide the necessary arguments.

However, we also need to keep track of all pending promises and resolve/reject them when the function is invoked. To do that, we can create a pending array and add the resolve and reject callbacks of each promise to it.

When the function is invoked, the current pending array will have to be copied, as it can change between the function call and its resolution. Then, we can clear the pending array and call the provided function.

Finally, when the function resolves/rejects, we can resolve/reject all promises in the copied array with the returned data. This means that all promises created in the meantime will resolve/reject with the same data.

```js
const debouncePromise = (fn, ms = 0) => {
  let timeoutId;
  const pending = [];
  return (...args) =>
    new Promise((res, rej) => {
      clearTimeout(timeoutId);
      timeoutId = setTimeout(() => {
        const currentPending = [...pending];
        pending.length = 0;
        Promise.resolve(fn.apply(this, args)).then(
          data => {
            currentPending.forEach(({ resolve }) => resolve(data));
          },
          error => {
            currentPending.forEach(({ reject }) => reject(error));
          }
        );
      }, ms);
      pending.push({ resolve: res, reject: rej });
    });
};

const fn = arg => new Promise(resolve => {
  setTimeout(resolve, 1000, ['resolved', arg]);
});
const debounced = debouncePromise(fn, 200);
debounced('foo').then(console.log);
debounced('bar').then(console.log);
// Will log ['resolved', 'bar'] both times


Here is a detailed breakdown of how the `debouncePromise` implementation works, how it manages promises, and its potential edge cases:

### How It Works Step-by-Step

1. **Closure State:**
* `timeoutId`: Tracks the active timer created by `setTimeout`.
* `pending`: An array that acts as a queue storing `{ resolve, reject }` control pairs for every pending Promise initiated during the quiet period.


2. **Promise Queueing:**
* Every time the returned function is called, it immediately returns a new `Promise`.
* Its `res` and `rej` callbacks are pushed into the `pending` array.
* Any previously scheduled execution is cancelled via `clearTimeout(timeoutId)`.


3. **Batched Resolution:**
* Once the caller stops invoking the debounced function for `ms` milliseconds, `setTimeout` fires.
* It captures a snapshot of the pending promise callbacks (`currentPending`) and clears `pending` so new incoming calls start a fresh batch.
* The original function `fn` is called using **only the arguments from the last invocation** (`args`).
* Once `fn` settles (resolves or rejects), it iterates through `currentPending` and settles every waiting promise in the batch with the exact same result.



---

### Key Considerations & Bugs in the Snippet

While the overall concept works, there are two subtle issues in the provided code snippet to keep in mind:

#### 1. The `this` Context Loss

In arrow functions, `this` is lexically bound to the outer scope:

```js
const debouncePromise = (fn, ms = 0) => {
  // ...
  return (...args) => // Arrow function doesn't have its own `this`
    new Promise((res, rej) => {
      // ...
      // `this` refers to the outer scope where `debouncePromise` was defined, NOT where the debounced function is invoked.
      Promise.resolve(fn.apply(this, args)) 
    });
};

```

**Fix:** Use standard `function` syntax for the returned function if context preservation matters:

```js
const debouncePromise = (fn, ms = 0) => {
  let timeoutId;
  let pending = [];
  return function (...args) {
    const context = this;
    return new Promise((resolve, reject) => {
      clearTimeout(timeoutId);
      timeoutId = setTimeout(() => {
        const currentPending = [...pending];
        pending = [];
        Promise.resolve(fn.apply(context, args)).then(
          data => currentPending.forEach(p => p.resolve(data)),
          error => currentPending.forEach(p => p.reject(error))
        );
      }, ms);
      pending.push({ resolve, reject });
    });
  };
};

```

#### 2. Cancelled Calls Receive Final Results

Because all calls within the debounce window share the same result batch, every caller gets the result generated by the **last call's arguments**.

If your use case requires dropped/cancelled invocations to reject rather than resolve with shared data (for example, to cancel an outdated auto-complete search request), you can reject earlier promises explicitly instead of queueing them:

```js
// Alternative: Reject cancelled promises instead of resolving them with shared data
const debouncePromiseWithCancel = (fn, ms = 0) => {
  let timeoutId;
  let pendingReject;

  return function (...args) {
    if (pendingReject) {
      pendingReject(new Error('Cancelled by subsequent debounced call'));
    }
    clearTimeout(timeoutId);

    return new Promise((resolve, reject) => {
      pendingReject = reject;
      timeoutId = setTimeout(async () => {
        pendingReject = null;
        try {
          const result = await fn.apply(this, args);
          resolve(result);
        } catch (err) {
          reject(err);
        }
      }, ms);
    });
  };
};

```

Leading-edge (or **immediate**) debouncing executes the underlying function on the **first call** of a cluster rather than waiting for a pause in invocations. Any subsequent calls made within the delay window are silenced—or in the case of Promises, receive the result of that initial call.

---

## How Leading-Edge Promise Debouncing Works

1. **Immediate Execution:** On the first invocation, execute `fn` immediately and store the resulting Promise.
2. **Window Lockout:** Start a timer (`setTimeout`). Any subsequent calls during this timer window reuse the active Promise without triggering `fn` again.
3. **Reset:** Once no calls have occurred for `ms` milliseconds, reset the state so the next call can fire immediately again.

---

## Complete Implementation

```js
const debouncePromiseLeading = (fn, ms = 0) => {
  let timeoutId = null;
  let activePromise = null;

  return function (...args) {
    const context = this;

    // Reset timer on every call during the debounce window
    if (timeoutId) {
      clearTimeout(timeoutId);
    } else {
      // Leading edge: Execute fn immediately on the first call
      activePromise = Promise.resolve().then(() => fn.apply(context, args));
    }

    // Set/reset the quiet period timer
    timeoutId = setTimeout(() => {
      timeoutId = null;
      activePromise = null;
    }, ms);

    // Return the active Promise (or a chain off it) to all callers in the window
    return activePromise;
  };
};

```

## Usage Example

```js
const fetchData = id => new Promise(resolve => {
  console.log(`Fetching data for ID: ${id}...`);
  setTimeout(() => resolve(`Result for ${id}`), 500);
});

const debouncedFetch = debouncePromiseLeading(fetchData, 300);

// Call 1: Triggers fetchData immediately
debouncedFetch('A').then(res => console.log('Call 1:', res));

// Call 2 (after 100ms): In debounce window -> skips execution, returns Call 1's Promise
setTimeout(() => {
  debouncedFetch('B').then(res => console.log('Call 2:', res));
}, 100);

// Call 3 (after 500ms): Debounce window expired -> triggers fetchData fresh for ID 'C'
setTimeout(() => {
  debouncedFetch('C').then(res => console.log('Call 3:', res));
}, 500);

/*
 Console Output:
 Fetching data for ID: A...
 Call 1: Result for A
 Call 2: Result for A
 Fetching data for ID: C...
 Call 3: Result for C
*/

```

## Key Differences: Trailing vs. Leading Promise Debounce

| Behavior             | Trailing-Edge Debounce                    | Leading-Edge Debounce                        |
| -------------------- | ----------------------------------------- | -------------------------------------------- |
| **When `fn` runs**   | After calls stop for `ms` period          | Immediately on the 1st call                  |
| **Arguments used**   | Arguments from the **last** call          | Arguments from the **first** call            |
| **Shared Promise**   | Resolves all callers with **last** result | Resolves all callers with **first** result   |
| **Primary Use Case** | Search auto-complete, window resize       | Button double-click protection, form submits |

Here is a complete, production-ready implementation of a configurable promise-based debounce function supporting `leading`, `trailing`, and a `maxWait` limit.

---

## Unified Implementation

```js
const debouncePromise = (fn, wait = 0, options = {}) => {
  const {
    leading = false,
    trailing = true,
    maxWait
  } = options;

  let timeoutId = null;
  let maxTimeoutId = null;
  let pending = [];
  let lastArgs = null;
  let lastContext = null;
  let activePromise = null;

  // Resolves/rejects all pending promises with the same outcome
  const settleBatch = (promise) => {
    const currentPending = [...pending];
    pending = [];
    promise.then(
      result => currentPending.forEach(p => p.resolve(result)),
      error => currentPending.forEach(p => p.reject(error))
    );
  };

  // Invokes the underlying function fn
  const invoke = () => {
    const args = lastArgs;
    const context = lastContext;
    lastArgs = null;
    lastContext = null;

    return Promise.resolve().then(() => fn.apply(context, args));
  };

  const clearTimers = () => {
    if (timeoutId) {
      clearTimeout(timeoutId);
      timeoutId = null;
    }
    if (maxTimeoutId) {
      clearTimeout(maxTimeoutId);
      maxTimeoutId = null;
    }
  };

  const flush = () => {
    clearTimers();
    if (trailing && lastArgs) {
      const promise = invoke();
      settleBatch(promise);
      return promise;
    }
    activePromise = null;
  };

  function debounced(...args) {
    lastArgs = args;
    lastContext = this;

    return new Promise((resolve, reject) => {
      pending.push({ resolve, reject });

      const isFirstCall = !timeoutId;

      // Handle leading edge call
      if (isFirstCall && leading) {
        activePromise = invoke();
        settleBatch(activePromise);
      }

      // Reset quiet-period timer
      if (timeoutId) clearTimeout(timeoutId);
      timeoutId = setTimeout(flush, wait);

      // Handle maxWait timeout if configured
      if (maxWait && !maxTimeoutId) {
        maxTimeoutId = setTimeout(flush, maxWait);
      }
    });
  }

  // Option to manually cancel pending execution and reject callers
  debounced.cancel = () => {
    clearTimers();
    lastArgs = null;
    lastContext = null;
    activePromise = null;
    const currentPending = [...pending];
    pending = [];
    currentPending.forEach(p => p.reject(new Error('Debounced call cancelled')));
  };

  return debounced;
};

```

---

## How Configuration Modes Behave

| Configuration                                    | First Call in Window      | Subsequent Calls in Window                                             | Result Sent to Callers                                    |
| ------------------------------------------------ | ------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------- |
| `{ leading: false, trailing: true }` *(Default)* | Waits `wait` ms           | Resets timer                                                           | Result of **last** call                                   |
| `{ leading: true, trailing: false }`             | Executes `fn` immediately | Ignored during window                                                  | Result of **first** call                                  |
| `{ leading: true, trailing: true }`              | Executes `fn` immediately | Collects args; executes `fn` again at trailing edge if called > 1 time | First call gets 1st result; remaining get trailing result |

## Usage Examples

### 1. Trailing (Default - e.g., Auto-complete Search)

```js
const search = debouncePromise(fetchResults, 300);

search('a'); 
search('ab'); 
search('abc').then(console.log); 
// Only triggers fetchResults('abc') after 300ms pause.

```

### 2. Leading (e.g., Action Buttons / Prevent Double-Submit)

```js
const submitForm = debouncePromise(saveData, 1000, {
  leading: true,
  trailing: false
});

submitForm(formData); // Fires immediately
submitForm(formData); // Ignored; returns the Promise of the first call

```

### 3. Maximum Wait (`maxWait` - e.g., High-Frequency Events)

```js
// Ensures fn is called at least once every 1000ms even if calls keep coming
const logPosition = debouncePromise(updateCoords, 200, {
  maxWait: 1000
});

```

To add a `.cancel()` method, you attach the method directly onto the returned function object.

When `.cancel()` is called, it needs to do two main things:

1. **Clear all active timers** (`clearTimeout`) to prevent the debounced function from firing.
2. **Handle pending promises** by rejecting all waiting callers with an explicit cancellation error (or optionally leaving them hanging, depending on your application's needs).

---

### Implementation

```js
const debouncePromise = (fn, ms = 0) => {
  let timeoutId = null;
  let pending = [];

  function debounced(...args) {
    const context = this;

    return new Promise((resolve, reject) => {
      // Store resolve/reject handlers for this caller
      pending.push({ resolve, reject });

      // Reset the timer on subsequent calls
      clearTimeout(timeoutId);

      timeoutId = setTimeout(() => {
        // Capture pending promises and clear the queue for future calls
        const currentPending = [...pending];
        pending = [];
        timeoutId = null;

        Promise.resolve(fn.apply(context, args)).then(
          data => currentPending.forEach(({ resolve }) => resolve(data)),
          error => currentPending.forEach(({ reject }) => reject(error))
        );
      }, ms);
    });
  }

  // Attached cancellation method
  debounced.cancel = (reason = 'Debounced execution cancelled') => {
    // 1. Stop the scheduled execution
    clearTimeout(timeoutId);
    timeoutId = null;

    // 2. Reject all waiting promises so callers aren't left hanging indefinitely
    const currentPending = [...pending];
    pending = [];
    
    const cancelError = new Error(reason);
    cancelError.isCancelled = true;

    currentPending.forEach(({ reject }) => reject(cancelError));
  };

  return debounced;
};

```

---

### Usage Example

```js
const searchApi = query => new Promise(resolve => {
  setTimeout(() => resolve(`Results for "${query}"`), 1000);
});

const debouncedSearch = debouncePromise(searchApi, 500);

// Caller 1
debouncedSearch('react')
  .then(res => console.log('Resolved:', res))
  .catch(err => console.log('Caller 1 Catch:', err.message));

// Caller 2 (200ms later)
setTimeout(() => {
  debouncedSearch('react native')
    .then(res => console.log('Resolved:', res))
    .catch(err => console.log('Caller 2 Catch:', err.message));
}, 200);

// Cancel the execution before the 500ms debounce timer completes
setTimeout(() => {
  debouncedSearch.cancel('User navigated away from page');
}, 300);

/*
 Console Output:
 Caller 1 Catch: User navigated away from page
 Caller 2 Catch: User navigated away from page
 (searchApi is never invoked)
*/

```

---

### Key Details to Keep in Mind

* **Promise Settlement:** Rejecting pending promises on cancellation prevents memory leaks and ensures component unmounts (e.g., in React or Vue) don't leave dangling `await` calls in your application.
* **Checking Cancellation:** You can attach a custom property (like `err.isCancelled = true`) to the rejected error so UI layers can distinguish intentional cancellations from true runtime exceptions.
