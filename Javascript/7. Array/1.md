Explain practical techniques for maintaining array and object immutability in JavaScript.

Immutability means that once an array or object is created, its values are never modified directly. Instead of changing (mutating) the existing data structure, you create and return a new copy containing the updated values.

---

## 1. Updating Objects Immutably

### Adding or Updating Properties

Use object spread syntax (`...`) to create a new object with the updated properties.

```javascript
const user = { name: "Alex", age: 28, role: "Developer" };

// ❌ Mutation:
// user.age = 29;

// ✅ Immutable update:
const updatedUser = {
  ...user,
  age: 29 // Overwrites 'age' while preserving 'name' and 'role'
};

```

### Deleting Properties

Use object rest destructuring to extract the property to remove and gather the rest into a new object.

```javascript
const user = { name: "Alex", age: 28, role: "Developer" };

// ❌ Mutation:
// delete user.role;

// ✅ Immutable removal:
const { role, ...userWithoutRole } = user;
console.log(userWithoutRole); // { name: "Alex", age: 28 }

```

### Updating Nested Objects

Spread syntax performs a **shallow copy**. For nested structures, every nested level being modified must be spread.

```javascript
const user = {
  name: "Alex",
  preferences: { theme: "light", notifications: true }
};

// ❌ Mutation:
// user.preferences.theme = "dark";

// ✅ Immutable nested update:
const updatedUser = {
  ...user,
  preferences: {
    ...user.preferences,
    theme: "dark"
  }
};

```

## 2. Updating Arrays Immutably

### Adding Elements

Avoid `push()` or `unshift()` (which mutate in place). Use spread syntax or `concat()`.

```javascript
const items = ["Apple", "Banana"];

// ❌ Mutation: items.push("Cherry");

// ✅ Immutable add to end:
const appended = [...items, "Cherry"]; // ["Apple", "Banana", "Cherry"]

// ✅ Immutable add to start:
const prepended = ["Mango", ...items]; // ["Mango", "Apple", "Banana"]

```

### Removing Elements

Avoid `splice()` or `pop()`. Use `filter()` or `slice()`.

```javascript
const numbers = [10, 20, 30, 40];

// ❌ Mutation: numbers.splice(1, 1);

// ✅ Immutable removal by condition:
const filtered = numbers.filter((n) => n !== 20); // [10, 30, 40]

// ✅ Immutable removal by index:
const removeIndex = 1;
const withoutIndex = [
  ...numbers.slice(0, removeIndex),
  ...numbers.slice(removeIndex + 1)
]; // [10, 30, 40]

```

### Modifying Elements

Avoid direct index assignment (`arr[0] = value`). Use `map()`, `with()`, or `slice()`.

```javascript
const fruits = ["Apple", "Banana", "Cherry"];

// ❌ Mutation: fruits[1] = "Blueberry";

// ✅ Immutable update using map():
const updatedMap = fruits.map((item, index) =>
  index === 1 ? "Blueberry" : item
);

// ✅ Immutable update using Array.prototype.with() (Modern ES2023+):
const updatedWith = fruits.with(1, "Blueberry"); // ["Apple", "Blueberry", "Cherry"]

```

### Sorting or Reversing

Methods like `sort()` and `reverse()` mutate the original array. Use `toSorted()`, `toReversed()`, or spread before sorting.

```javascript
const numbers = [3, 1, 4, 2];

// ❌ Mutation: numbers.sort();

// ✅ Modern ES2023+ immutable methods:
const sorted = numbers.toSorted();   // [1, 2, 3, 4]
const reversed = numbers.toReversed(); // [2, 4, 1, 3]

// ✅ Pre-ES2023 fallback:
const legacySorted = [...numbers].sort();

```

## 3. Enforcing Immutability in Code

### Shallow Immutability: `Object.freeze()`

`Object.freeze()` prevents properties from being added, removed, or changed. However, it is only shallow.

```javascript
const config = Object.freeze({
  endpoint: "https://api.example.com",
  timeout: 5000,
  nested: { key: "value" }
});

config.timeout = 10000; // Fails silently (or throws TypeError in strict mode)
config.nested.key = "changed"; // ⚠️ Still mutates! Nested objects are not frozen.

```

### Deep Immutability Solutions

For complex state trees, shallow spreads become verbose and error-prone. Two main strategies prevent accidental mutations:

1. **Structured Clone for Deep Copies:** `structuredClone()` creates a deep copy before performing safe mutations on the draft.

```javascript
const deepCopy = structuredClone(complexObject);
deepCopy.nested.key = "new value"; // Safe to mutate the cloned copy

```

1. **Immer Library:** Allows writing code using native mutation syntax (`draft.a.b = 1`) while automatically generating an immutable structural copy behind the scenes.

## Summary Cheat Sheet

| Operation                | Mutating Method (Avoid)        | Immutable Alternative                           |
| ------------------------ | ------------------------------ | ----------------------------------------------- |
| **Add to Array**         | `push()`, `unshift()`          | `[...arr, val]`, `[val, ...arr]`                |
| **Remove from Array**    | `pop()`, `shift()`, `splice()` | `filter()`, `slice()`                           |
| **Update Array Item**    | `arr[i] = val`                 | `map()`, `arr.with(i, val)`                     |
| **Sort / Reverse Array** | `sort()`, `reverse()`          | `toSorted()`, `toReversed()`, `[...arr].sort()` |
| **Add/Update Object**    | `obj.key = val`                | `{ ...obj, key: val }`                          |
| **Delete Object Prop**   | `delete obj.key`               | `const { key, ...rest } = obj`                  |

Show how to implement a memoization wrapper function in JavaScript for pure functions.

Managing complex state immutably in React is essential because React relies on reference equality (`Object.is`) to detect state changes and trigger re-renders. If you mutate state directly, React will not re-render your component.

Here are practical, real-world patterns for handling nested objects, arrays of objects, dynamic keys, and state updates using `useState` and `useReducer`.

---

## 1. Updating Deeply Nested Objects

When dealing with nested form data or settings objects, every level of nesting that you touch must be spread.

### Scenario: Updating a user's address state

```jsx
import { useState } from 'react';

function UserProfile() {
  const [user, setUser] = useState({
    id: 101,
    name: 'Alex',
    contact: {
      email: 'alex@example.com',
      address: {
        city: 'Seattle',
        zip: '98101'
      }
    }
  });

  const updateCity = (newCity) => {
    setUser(prevUser => ({
      ...prevUser, // Copy level 1
      contact: {
        ...prevUser.contact, // Copy level 2
        address: {
          ...prevUser.contact.address, // Copy level 3
          city: newCity // Update value
        }
      }
    }));
  };

  return (
    <button onClick={() => updateCity('San Francisco')}>
      Move to SF (Current: {user.contact.address.city})
    </button>
  );
}

```

## 2. Managing Arrays of Objects

Common operations for lists include updating an item by ID, removing an item, and toggling a property.

### Scenario: Shopping Cart CRUD operations

```jsx
import { useState } from 'react';

function ShoppingCart() {
  const [cart, setCart] = useState([
    { id: 1, name: 'Laptop', quantity: 1, price: 999 },
    { id: 2, name: 'Mouse', quantity: 2, price: 25 }
  ]);

  // 1. Update quantity of a specific item (using .map())
  const incrementQuantity = (id) => {
    setCart(prevCart =>
      prevCart.map(item =>
        item.id === id ? { ...item, quantity: item.quantity + 1 } : item
      )
    );
  };

  // 2. Remove an item from the cart (using .filter())
  const removeItem = (id) => {
    setCart(prevCart => prevCart.filter(item => item.id !== id));
  };

  // 3. Add a new item to the cart (using spread operator)
  const addItem = (newItem) => {
    setCart(prevCart => [...prevCart, newItem]);
  };

  return (
    <ul>
      {cart.map(item => (
        <li key={item.id}>
          {item.name} - Qty: {item.quantity}
          <button onClick={() => incrementQuantity(item.id)}>+</button>
          <button onClick={() => removeItem(item.id)}>Remove</button>
        </li>
      ))}
    </ul>
  );
}

```

## 3. Dynamic Form Inputs (Key-Value Objects)

When building complex forms, handling each field individually creates boilerplate. Use dynamic property names `[name]` to update state generically.

### Scenario: Generic form handler

```jsx
import { useState } from 'react';

function Form() {
  const [formData, setFormData] = useState({
    username: '',
    email: '',
    role: 'user',
    subscribe: false
  });

  const handleChange = (e) => {
    const { name, value, type, checked } = e.target;
    
    setFormData(prevData => ({
      ...prevData,
      [name]: type === 'checkbox' ? checked : value
    }));
  };

  return (
    <form>
      <input
        name="username"
        value={formData.username}
        onChange={handleChange}
        placeholder="Username"
      />
      <input
        name="email"
        value={formData.email}
        onChange={handleChange}
        placeholder="Email"
      />
      <label>
        <input
          type="checkbox"
          name="subscribe"
          checked={formData.subscribe}
          onChange={handleChange}
        />
        Subscribe
      </label>
    </form>
  );
}

```

## 4. Simplifying Complex State with `useReducer`

When state updates involve multiple sub-values or complex logic, `useReducer` centralizes state mutations and keeps updating logic clean.

### Scenario: Todo list manager with `useReducer`

```jsx
import { useReducer } from 'react';

const initialState = {
  todos: [],
  filter: 'all' // 'all', 'completed', 'pending'
};

function todoReducer(state, action) {
  switch (action.type) {
    case 'ADD_TODO':
      return {
        ...state,
        todos: [...state.todos, { id: Date.now(), text: action.payload, completed: false }]
      };

    case 'TOGGLE_TODO':
      return {
        ...state,
        todos: state.todos.map(todo =>
          todo.id === action.payload
            ? { ...todo, completed: !todo.completed }
            : todo
        )
      };

    case 'DELETE_TODO':
      return {
        ...state,
        todos: state.todos.filter(todo => todo.id !== action.payload)
      };

    case 'SET_FILTER':
      return {
        ...state,
        filter: action.payload
      };

    default:
      return state;
  }
}

function TodoApp() {
  const [state, dispatch] = useReducer(todoReducer, initialState);

  return (
    <div>
      <button onClick={() => dispatch({ type: 'ADD_TODO', payload: 'Learn React Immutability' })}>
        Add Task
      </button>
      {state.todos.map(todo => (
        <div key={todo.id}>
          <span style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>
            {todo.text}
          </span>
          <button onClick={() => dispatch({ type: 'TOGGLE_TODO', payload: todo.id })}>
            Toggle
          </button>
          <button onClick={() => dispatch({ type: 'DELETE_TODO', payload: todo.id })}>
            Delete
          </button>
        </div>
      ))}
    </div>
  );
}

```

## 5. Alternative: Using `use-immer` for Clean Syntax

When state structures become too deeply nested to manually spread, the `use-immer` hook allows writing standard mutating syntax while producing immutable updates under the hood.

```jsx
import { useImmer } from 'use-immer';

function DeepStateWithImmer() {
  const [person, updatePerson] = useImmer({
    name: "Alex",
    details: {
      preferences: {
        theme: "light"
      }
    }
  });

  const toggleTheme = () => {
    // Draft can be mutated directly! Immer creates a fresh immutable copy.
    updatePerson(draft => {
      draft.details.preferences.theme = 
        draft.details.preferences.theme === 'light' ? 'dark' : 'light';
    });
  };

  return <button onClick={toggleTheme}>Theme: {person.details.preferences.theme}</button>;
}

```

### Quick Selection Guide

| Situation                                     | Recommended Approach                                  |
| --------------------------------------------- | ----------------------------------------------------- |
| **Simple primitive values / Shallow objects** | `useState` with spread syntax (`...`)                 |
| **Arrays (add, remove, update item)**         | `useState` with `[...arr]`, `.filter()`, and `.map()` |
| **Complex state with interconnected logic**   | `useReducer` to consolidate transitions               |
| **3+ levels of nested object updates**        | `use-immer` hook or normalizer patterns               |
