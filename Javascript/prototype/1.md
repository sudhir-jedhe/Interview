Here are the most common and high-impact interview questions on prototypes and inheritance in JavaScript, categorized from fundamental concepts to tricky code-output questions.

---

### Core Conceptual Questions

#### 1. What is the prototype chain, and how does property lookup work?

* **Answer:** Every JavaScript object has an internal hidden property called `[[Prototype]]` (exposed in most runtimes as `__proto__` or via `Object.getPrototypeOf()`). When you attempt to access a property or method on an object:

1. The engine checks if the property exists directly on the object (an **own property**).
2. If not found, it checks the object referenced by `[[Prototype]]`.
3. It traverses up the chain until it either finds the property or reaches the end (`Object.prototype.[[Prototype]]`, which is `null`).
4. If it reaches `null` without finding the property, it returns `undefined`.

---

#### 2. What is the difference between `prototype` and `__proto__`?

* **`prototype`**: A property that exists on constructor functions (and ES6 `class` definitions). It defines what object will become the `[[Prototype]]` of any instance created with `new FuncName()`.
* **`__proto__`**: An accessor property on object instances that exposes their internal `[[Prototype]]` reference.
* **Relationship:**

```javascript
function Person() {}
const p = new Person();

console.log(p.__proto__ === Person.prototype); // true
console.log(Person.prototype.constructor === Person); // true

```

---

#### 3. How did inheritance work before ES6 classes (Prototypal Inheritance)?

Before `class` and `extends`, prototypal inheritance was implemented using constructor functions and `Object.create`:

```javascript
function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function () {
  return `${this.name} makes a sound.`;
};

function Dog(name, breed) {
  Animal.call(this, name); // 1. Call parent constructor (borrow fields)
  this.breed = breed;
}

// 2. Link prototype chain
Dog.prototype = Object.create(Animal.prototype);

// 3. Restore constructor reference
Dog.prototype.constructor = Dog;

Dog.prototype.bark = function () {
  return `${this.name} barks.`;
};

const d = new Dog("Buddy", "Golden");
console.log(d.speak()); // "Buddy makes a sound."
console.log(d.bark());  // "Buddy barks."

```

---

#### 4. How does ES6 `class` syntax differ from prototypical inheritance under the hood?

* ES6 `class` syntax is primarily **syntactic sugar** over prototype-based inheritance; objects still share behavior via the prototype chain.
* **Key differences under the hood:**
* Class constructors cannot be called without `new` (throws `TypeError`).
* Class declarations are **not hoisted** in the same way functions are (they sit in the Temporal Dead Zone).
* Methods defined inside a class body are non-enumerable by default.
* Static methods are attached to the constructor itself (inheriting through `SuperClass.__proto__`).

### Deep-Dive & Practical Questions

#### 5. Why is modifying `Object.prototype` (Monkey Patching) considered an anti-pattern?

* **Pollution:** Adding properties to `Object.prototype` makes them accessible on every plain object in your codebase and libraries.
* **Collisions:** If a third-party library or future ECMAScript specification introduces a property with the same name, it creates silent bugs or breaks the application.
* **Performance:** Mutating core prototypes invalidates internal V8/SpiderMonkey optimization paths (inline caches).

---

#### 6. What is the difference between `Object.create(null)` and `{}`?

* `{}` creates an object that inherits from `Object.prototype`. It has built-in methods like `.toString()`, `.hasOwnProperty()`, and `valueOf()`.
* `Object.create(null)` creates a **bare object** (dictionary) with no prototype chain (`[[Prototype]]` is `null`).
* It is useful for secure hash maps/dictionaries where you don't want unexpected collisions with default `Object` properties (e.g., checking user-supplied keys like `constructor` or `toString`).

---

#### 7. What does the `new` keyword actually do?

When you execute `new ConstructorFunction(...args)`:

1. Creates a brand-new, empty plain JavaScript object: `{}`.
2. Sets this new object's `[[Prototype]]` to `ConstructorFunction.prototype`.
3. Binds `this` to the newly created object and executes the constructor function with the supplied arguments.
4. If the constructor returns an object explicitly, that object is returned. Otherwise, the newly created object from step 1 is returned.

### Output-Based & Tricky Interview Snippets

#### Snippet A: Property Shadowing vs Prototype Mutation

```javascript
function User() {}
User.prototype.hobbies = ["reading"];

const user1 = new User();
const user2 = new User();

// Action 1: Mutating the array
user1.hobbies.push("gaming");

console.log(user2.hobbies); // Output: ?

// Action 2: Reassigning the property
user1.hobbies = ["coding"];

console.log(user1.hobbies); // Output: ?
console.log(user2.hobbies); // Output: ?

```

* **Output:**
* Action 1: `["reading", "gaming"]` (Both instances share the same reference on `User.prototype`).
* Action 2: `["coding"]` for `user1` (creates an own property on `user1` shadowing the prototype) and `["reading", "gaming"]` for `user2`.

---

#### Snippet B: `hasOwnProperty` vs `in` operator

```javascript
const proto = { shared: 42 };
const obj = Object.create(proto);
obj.own = 10;

console.log("shared" in obj);              // Output: ?
console.log(obj.hasOwnProperty("shared")); // Output: ?

```

* **Output:**
* `"shared" in obj` $\rightarrow$ `true` (checks the object and entire prototype chain).
* `obj.hasOwnProperty("shared")` $\rightarrow$ `false` (checks only own properties on the instance).

---

#### Snippet C: Broken Prototype Reference

```javascript
function Shape() {}
const s1 = new Shape();

Shape.prototype = {
  getArea: function () { return 0; }
};

const s2 = new Shape();

console.log(typeof s1.getArea); // Output: ?
console.log(typeof s2.getArea); // Output: ?

```

* **Output:**
* `s1.getArea` $\rightarrow$ `undefined` (its `__proto__` points to the old `Shape.prototype` object).
* `s2.getArea` $\rightarrow$ `function` (created after reassignment, points to the new prototype object).

### 1. Custom Polyfill for the `new` Keyword

When executing `new Constructor(...args)`, the runtime executes four distinct operations:

1. Creates an empty object.
2. Binds the object's `[[Prototype]]` to the constructor's `prototype` property.
3. Invokes the constructor with `this` set to the newly created object.
4. Returns the instance, unless the constructor explicitly returns a non-primitive value (an object, array, function, etc.).

```javascript
function customNew(Constructor, ...args) {
  // Step 1 & 2: Create a plain object linked to Constructor's prototype
  const instance = Object.create(Constructor.prototype);

  // Step 3: Execute constructor with instance bound as `this`
  const result = Constructor.apply(instance, args);

  // Step 4: Handle explicit returns (non-primitive overrides instance)
  const isObject = typeof result === "object" && result !== null;
  const isFunction = typeof result === "function";

  return (isObject || isFunction) ? result : instance;
}

```

#### Verification & Edge Cases

```javascript
// Case A: Standard constructor
function User(name, age) {
  this.name = name;
  this.age = age;
}
User.prototype.greet = function () {
  return `Hi, I am ${this.name}`;
};

const u = customNew(User, "Alice", 28);
console.log(u.name); // "Alice"
console.log(u.greet()); // "Hi, I am Alice"
console.log(u instanceof User); // true

// Case B: Constructor returns a primitive (ignored by `new`)
function PrimitiveReturn(val) {
  this.val = val;
  return "Ignored primitive string";
}
console.log(customNew(PrimitiveReturn, 42).val); // 42

// Case C: Constructor returns an object (overrides instance)
function ObjectReturn(val) {
  this.val = val;
  return { custom: "Overridden", val: val * 2 };
}
const obj = customNew(ObjectReturn, 10);
console.log(obj.val); // 20
console.log(obj.custom); // "Overridden"
console.log(obj instanceof ObjectReturn); // false

```

### 2. Tricky Prototype Output Puzzles

#### Puzzle 1: Instance Property vs Prototype Property Lookup

```javascript
function Item() {}
Item.prototype.count = 1;

const a = new Item();
const b = new Item();

a.count++;

console.log(a.count);
console.log(b.count);
console.log(Item.prototype.count);

```

* **Output:**

```text
2
1
1

```

* **Explanation:** `a.count++` is evaluated as `a.count = a.count + 1`. During the read phase (`a.count + 1`), JavaScript walks up the prototype chain and reads `Item.prototype.count` (`1`). During the assignment phase, it creates an **own property** `count` directly on `a` with the value `2`. The prototype and `b` remain untouched.

---

#### Puzzle 2: The Default `constructor` Property Behavior

```javascript
function Dog(name) {
  this.name = name;
}

const d1 = new Dog("Milo");

Dog.prototype = {
  bark() {
    return "Woof";
  }
};

const d2 = new Dog("Otis");

console.log(d1.constructor === Dog);
console.log(d2.constructor === Dog);
console.log(d2.constructor === Object);

```

* **Output:**

```text
true
false
true

```

* **Explanation:**
* `d1` was created when `Dog.prototype` was the original compiler-generated prototype object, which has a built-in `.constructor` property pointing to `Dog`.
* For `d2`, `Dog.prototype` was completely overwritten with a plain object literal (`{ bark() { ... } }`). Object literals inherit directly from `Object.prototype`, where `.constructor` points to `Object`. Because `Dog.prototype.constructor` was not manually restored, `d2.constructor` resolves to `Object`.

---

#### Puzzle 3: Primitive Wrapper Prototypes

```javascript
Number.prototype.add = function (n) {
  return this + n;
};

const val = (5).add(3).add(2);
console.log(val);
console.log(typeof (5).add(3));

```

* **Output:**

```text
10
number

```

* **Explanation:** When calling `.add()` on the primitive `5`, the engine automatically boxes it into a `Number` object instance. Inside `.add`, `this + n` invokes value coercion (`valueOf()`), returning a primitive number (`8`). Because the return value is a primitive number, calling `.add(2)` on it boxes it again, resulting in `10`.

---

#### Puzzle 4: Prototype Cycles

```javascript
const parent = { x: 10 };
const child = Object.create(parent);

try {
  Object.setPrototypeOf(parent, child);
} catch (err) {
  console.log(err.name);
}

```

* **Output:**

```text
TypeError

```

* **Explanation:** V8 and modern engines strictly disallow cyclic prototype structures. Calling `Object.setPrototypeOf(parent, child)` when `child` already has `parent` in its prototype chain throws `TypeError: Cyclic __proto__ value`.

---

#### Puzzle 5: Deleting Shadowed Properties

```javascript
const proto = { score: 100 };
const player = Object.create(proto);

player.score = 50;
console.log(player.score);

delete player.score;
console.log(player.score);

delete player.score;
console.log(player.score);

```

* **Output:**

```text
50
100
100

```

* **Explanation:** The `delete` operator **only removes own properties** from an object.

1. `player.score = 50` creates an own property.
2. The first `delete` removes this own property, exposing the shadowed `score` on `proto` (`100`).
3. The second `delete` attempts to remove `score` from `player`. Since `player` no longer has an own property named `score`, the operation succeeds silently (`true`), but it does not touch `proto`. The fallback value `100` remains intact.

### 3. Composition vs. Prototypal Inheritance

| Dimension            | Prototypal / Class Inheritance                                         | Composition                                                     |
| -------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------- |
| **Core Concept**     | What things **are** (Taxonomy, `is-a`)                                 | What things **can do** or **have** (`has-a`, behaviors)         |
| **Coupling**         | Tightly coupled to parent class/prototype hierarchy                    | Loosely coupled independent functions or modules                |
| **Refactoring Risk** | High; changes to base classes ripple down (Fragile Base Class problem) | Low; features can be added or removed independently             |
| **Memory Footprint** | Low; methods live on the shared prototype object                       | Slightly higher if closures/instances duplicate method wrappers |

#### The Pitfall of Inheritance (The "Gorilla/Banana" Problem)

When requirements change, deep class hierarchies force subclasses to inherit irrelevant or conflicting behaviors:

```javascript
// Base class
class User {
  constructor(name) { this.name = name; }
  login() { return `${this.name} logged in`; }
}

// Subclasses
class Customer extends User {
  checkout() { return "Order placed"; }
}

class Admin extends User {
  deleteDatabase() { return "DB purged"; }
}

// Problem: What if you need a "SupportAgent" who can checkout on behalf of a customer,
// but also has partial administrative capabilities?
// JavaScript only supports single inheritance.

```

#### Implementing Composition (Mixins / Functional Composition)

Behaviors are defined as standalone factory functions and assembled into an object:

```javascript
// 1. Define atomic behaviors (abilities)
const canLogin = (state) => ({
  login: () => `${state.name} logged in successfully.`
});

const canCheckout = (state) => ({
  checkout: (cartId) => `${state.name} processed checkout for cart #${cartId}.`
});

const canModerate = (state) => ({
  banUser: (userId) => `User #${userId} has been banned.`
});

// 2. Compose specific entity factories
function createCustomer(name) {
  const state = { name };
  return Object.assign(
    {},
    canLogin(state),
    canCheckout(state)
  );
}

function createSupportAgent(name) {
  const state = { name };
  return Object.assign(
    {},
    canLogin(state),
    canCheckout(state),
    canModerate(state)
  );
}

// 3. Usage
const agent = createSupportAgent("Marcus");
console.log(agent.login());                   // "Marcus logged in successfully."
console.log(agent.checkout(1042));           // "Marcus processed checkout for cart #1042."
console.log(agent.banUser(99));               // "User #99 has been banned."
console.log(agent.deleteDatabase);           // undefined (no unnecessary base class bloat)

```

#### Production Architecture Recommendation

* **Use Prototype / Class Inheritance** when modeling a stable, fixed domain where instances share many identical methods and memory efficiency is the primary constraint (e.g., custom UI framework components, game engine nodes, data structures like Trees and Linked Lists).
* **Use Composition** for business logic, services, API clients, and application entities where behavior requirements evolve rapidly across different domain roles.
