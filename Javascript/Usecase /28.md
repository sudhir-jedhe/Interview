To maintain high code quality while working with AI coding agents, you need a **multi-layered validation pipeline**. AI model outputs are probabilistic, which means without hard boundaries, AI will naturally introduce code duplication, bloated components, high cyclomatic complexity, tight coupling, and brittle tests.

A production-proven approach structures quality guardrails into **Static Analysis**, **Architectural/Metrics Enforcers**, and **Dynamic Tests**, tying them all together in an automated verification loop.

---

## 1. Static Analysis & Compilation Layer

Static analysis acts as the first, fastest defense line (sub-second execution).

### A. TypeScript (`tsc --noEmit`)

- **Strict Mode:** Set `"strict": true`, `"noImplicitAny": true`, `"strictNullChecks": true`, and `"noUncheckedIndexedAccess": true` in `tsconfig.json`.
- **Interface-First Contracts:** Force AI to export types/interfaces into dedicated files (`*.types.ts`). AI code generation becomes substantially cleaner when constrained by pre-declared TypeScript interfaces.

### B. Linters (ESLint / Biome / Stylelint)

- **AST Restrictions (`eslint-plugin-no-restricted-syntax`):** Block anti-patterns before they get committed:
- Block `px` units in inline styles or CSS-in-JS (force `rem`/`em`/relative units).
- Block wildcards like `transition: all` or reflow animations (`width`, `height`, `margin` animations).
- Block implicit `any` and unsafe casts (`as unknown as X`).

- **Automated Formatting:** Run `biome check --write .` or `prettier` automatically on AI-generated files to normalize formatting immediately.

## 2. Structural Metrics & Architectural Safeguards

This is where you prevent AI-generated "spaghetti code" and monolithic files.

```
┌─────────────────────────────────────────────────────────────┐
│                    AI Code Generation                       │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│             Structural Metrics Verification                 │
├──────────────────────────────┬──────────────────────────────┤
│  Cyclomatic Complexity <= 10 │ File Length <= 150-200 Lines │
│  Duplication Score <= 3%    │ Component Length <= 50 Lines │
└──────────────────────────────┬──────────────────────────────┘
                               │
                      (Passed) ▼ (Failed)
              ┌────────────────┴────────────────┐
              │                                 │
              ▼                                 ▼
    Proceed to Unit Tests             Reject & Feed Log to AI

```

### A. Cyclomatic Complexity

AI tends to nest `if/else` checks, ternary operators, and switch statements indefinitely.

- **ESLint Rule:** Set `"complexity": ["error", 10]` to throw an error if any function exceeds a complexity score of 10.
- **Refactoring Strategy:** Force the AI to refactor complex branching into lookup tables, strategy patterns, or early returns.

### B. File Length & Component Length Boundaries

AI models often generate 600-line "god components" containing state, UI, helper utilities, and styles in a single file.

- **File Line Limit:** Set `"max-lines": ["error", { "max": 200, "skipBlankLines": true, "skipComments": true }]`.
- **Function/Component Limit:** Set `"max-lines-per-function": ["error", { "max": 50, "skipComments": true }]`.
- **Single Record State:** Enforce state bundling (discriminated unions) rather than 10 individual `useState` calls.

### C. Code Duplication Analysis (JSCPD)

AI frequently reinvents existing utility functions or duplicates JSX blocks.

- **Tool:** Use **[jscpd](https://www.google.com/search?q=https://github.com/kucherenko/jscpd)** (Copy/Paste Detector) in your pipeline.
- **Rule:** Flag any duplicate code block exceeding 5 lines or 3% overall duplication across the workspace.

```bash
# Command to run jscpd duplicate analysis
npx jscpd ./src --threshold 3 --min-lines 5

```

## 3. Dynamic Testing Matrix

Verify functional correctness across three testing tiers.

| Test Tier             | Tool                  | Primary Purpose for AI Code                                                                  | Execution Time   |
| --------------------- | --------------------- | -------------------------------------------------------------------------------------------- | ---------------- |
| **Unit Tests**        | Vitest / Jest         | Verifies pure functions, domain logic, utility helpers, and hook state transitions.          | Fast (~Seconds)  |
| **Integration Tests** | React Testing Library | Verifies component trees, user event interaction flows, and API mock boundaries (MSW).       | Medium (~10-30s) |
| **End-to-End (E2E)**  | Playwright / Cypress  | Verifies critical user journeys, routing, real network interactions, and visual regressions. | Slower (~1-3m)   |

### Key E2E Practice: Visual Regression Testing

AI frequently breaks layout styling without throwing JS errors. Use **Playwright Visual Comparisons** (`expect(page).toHaveScreenshot()`) to catch unintended layout shifts or pixel overflow errors.

## 4. The Closed Feedback Loop (Connecting it All)

To make AI work autonomously with these checks, wrap everything in a CLI loop that catches errors, writes them to a log file, and prompts the AI to self-correct.

```javascript
// scripts/verify-ai.mjs
import { execSync } from "node:child_process";
import fs from "node:fs";

const steps = [
  { name: "1. TypeScript Check", cmd: "npx tsc --noEmit" },
  {
    name: "2. ESLint & Complexity Check",
    cmd: "npx eslint src/ --max-warnings 0",
  },
  {
    name: "3. Duplication Check (JSCPD)",
    cmd: "npx jscpd ./src --threshold 3",
  },
  { name: "4. Unit & Integration Tests", cmd: "npx vitest run" },
  { name: "5. E2E Tests (Playwright)", cmd: "npx playwright test" },
];

function runPipeline() {
  console.log("🔍 Verifying AI Output Quality...\n");
  const failures = [];

  for (const step of steps) {
    try {
      console.log(`Running: ${step.name}...`);
      execSync(step.cmd, { stdio: "pipe" });
      console.log(`✅ Passed: ${step.name}\n`);
    } catch (err) {
      console.log(`❌ Failed: ${step.name}\n`);
      failures.push({
        name: step.name,
        output: `${err.stdout?.toString()}\n${err.stderr?.toString()}`,
      });
      break; // Stop at first failure
    }
  }

  if (failures.length > 0) {
    const report =
      `# AI VERIFICATION FAILURE\n\nFix these issue(s) before proceeding:\n\n` +
      failures
        .map((f) => `## ${f.name}\n\`\`\`text\n${f.output}\n\`\`\``)
        .join("\n\n");

    fs.writeFileSync("ai-errors.log", report);
    console.error("❌ Pipeline failed. Output written to ai-errors.log");
    process.exit(1);
  }

  console.log("🚀 All Quality Checks Passed!");
  process.exit(0);
}

runPipeline();
```

## 5. Summary Checklist for AI-Driven Codebases

1. **Context Rules (`.cursorrules`):** Constrain file lengths, forbid raw `px` units, enforce relative CSS, and mandate contract-first TypeScript interface design.
2. **Pre-Commit Gate (Husky + `lint-staged`):** Automatically run `tsc`, ESLint/Biome, and `vitest` on staged files prior to every commit.
3. **Complexity & Duplication Guards:** Fail builds if cyclomatic complexity > 10 or code duplication > 3%.
4. **Self-Correction Feedback Loop:** Feed stderr outputs back into the AI agent prompt until `verify-ai.mjs` exits with status `0`.
