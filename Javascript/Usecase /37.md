**Short answer:** `ReactDOM.render()` was the standard method used in React (prior to React 18) to render a React element/component tree into a real browser DOM node.

In modern React (React 18+), **`ReactDOM.render()` is deprecated** and has been replaced by **`createRoot()`**.

---

## Historical Usage (React 17 and earlier)

Before React 18, you initialized a React application like this:

```javascript
import React from "react";
import ReactDOM from "react-dom";
import App from "./App";

const container = document.getElementById("root");

// Deprecated syntax in React 18+
ReactDOM.render(<App />, container);
```

### What It Did Under the Hood

1. Took a **React Element** (e.g., `<App/>`) as its first argument.
2. Took a **DOM Container Node** (e.g., `document.getElementById('root')`) as its second argument.
3. Cleared any existing DOM content inside the container and mounted the React application tree into it.
4. Managed subsequent updates/re-renders if called again on the same container.

---

## Why Was It Deprecated?

`ReactDOM.render()` operated synchronously under React's legacy concurrent model. To unlock React 18's major performance features—such as **Concurrent Rendering**, **Automatic Batching**, **`useTransition`**, and **`useDeferredValue`**—React needed a new root API.

---

## The Modern Replacement: `createRoot()`

In React 18+, you should use `createRoot` from `react-dom/client` instead:

```javascript
import React from "react";
import { createRoot } from "react-dom/client";
import App from "./App";

const container = document.getElementById("root");

// Modern React 18+ syntax
const root = createRoot(container);
root.render(<App />);
```

### Key Benefits of `createRoot`

- **Concurrent Features:** Enables non-blocking background rendering for smoother UI updates.
- **Automatic Batching:** Groups multiple state updates inside promises, timeouts, or native event handlers into a single re-render for better performance.
- **Cleaner API:** Separates root creation from the rendering step.

Migrating from React 17's `ReactDOM.render` to React 18's `createRoot` is straightforward. It primarily involves updating your entry point file (usually `index.js` or `main.tsx`) and running the dependency update.

---

## Step 1: Update Dependencies

First, upgrade your project dependencies to React 18 in your terminal:

```bash
npm install react@18 react-dom@18

```

---

## Step 2: Update the Entry Point (`index.js` / `main.tsx`)

Replace the deprecated `ReactDOM.render` import and execution with `createRoot` from `react-dom/client`.

### Legacy React 17 Entry Point:

```javascript
// ❌ Legacy React 17
import React from "react";
import ReactDOM from "react-dom";
import App from "./App";

const container = document.getElementById("root");

ReactDOM.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
  container,
);
```

### Modern React 18 Entry Point:

```javascript
// ✅ Modern React 18+
import React from "react";
import { createRoot } from "react-dom/client";
import App from "./App";

const container = document.getElementById("root");

// 1. Throw a helpful runtime error if the root container is missing
if (!container) {
  throw new Error("Failed to find the root element");
}

// 2. Create the root instance
const root = createRoot(container);

// 3. Render your application wrapped in StrictMode
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
);
```

---

## Step 3: Important Behavior Change with `<React.StrictMode>` in React 18

When using `<React.StrictMode>` in React 18 in **Development Mode**, React will **intentionally double-mount components** (Mount $\rightarrow$ Unmount $\rightarrow$ Remount).

### Why React Does This:

This behavior ensures that your components are resilient to reusable state and that your `useEffect` cleanups work properly.

```typescript
useEffect(() => {
  const subscription = api.subscribe();

  // ⚠️ CRITICAL IN REACT 18: You MUST return a cleanup function.
  // Otherwise, StrictMode double-mounting will create duplicate subscriptions!
  return () => {
    subscription.unsubscribe();
  };
}, []);
```

> **Note:** Double-mounting happens **only in development mode** to help you catch side-effect bugs. Production builds behave normally.

---

## Step 4: Optional TypeScript Types Update

If your project uses TypeScript, update the types declarations to match React 18:

```bash
npm install --save-dev @types/react@18 @types/react-dom@18

```

If you encounter `children` prop errors in custom components, update your type definitions: React 18 removed implicit `children` from `React.FC`. You must now explicitly define `children?: React.ReactNode` in your component prop interfaces.
