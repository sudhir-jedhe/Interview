The order of JavaScript execution is governed by the **JavaScript Engine** and the **Browser/Node.js Runtime Event Loop**.

Because JavaScript is **single-threaded** (it has only one Call Stack and executes one piece of code at a time), it relies on a specific priority hierarchy to handle synchronous code, asynchronous tasks, and DOM rendering.

Here is the exact order of execution, ranked from **highest priority to lowest priority**:

```
┌─────────────────────────────────────────────────────────────┐
1. Synchronous Code Execution (Call Stack)                   │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
2. Microtask Queue (Promises, process.nextTick, MutationObs) │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
3. Animation Frames (requestAnimationFrame - Browser only)   │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
4. Render / Paint Phase (Browser repaints UI if needed)       │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
5. Macrotask / Task Queue (setTimeout, setInterval, I/O, UI)  │
└─────────────────────────────────────────────────────────────┘

```

---

## 1. Synchronous Code (The Call Stack)

When JavaScript executes a script, it first runs all synchronous code line-by-line from top to bottom.

- Functions and expressions are pushed onto the **Call Stack** and popped off immediately after execution.
- Asynchronous calls (like `setTimeout` or `fetch`) are handed off to Web APIs / C++ bindings, and the main stack keeps executing without waiting.

---

## 2. Microtask Queue (High-Priority Async Tasks)

Once the Call Stack is completely empty, the Event Loop checks the **Microtask Queue**.

- **What goes here?** `Promise` callbacks (`.then()`, `.catch()`, `.finally()`), `async/await` continuations, `MutationObserver`, and Node.js `process.nextTick()`.
- **Behavior:** The Event Loop will execute **ALL pending microtasks** in the queue until it is completely empty before moving on to the next phase. (If a microtask schedules another microtask, it runs in the same tick).

---

## 3. Animation Frames (`requestAnimationFrame` — Browser Only)

In browser environments, before redrawing the screen, callbacks registered via `requestAnimationFrame()` are executed. This aligns code updates directly with the browser's display refresh rate (e.g., 60Hz or 120Hz).

---

## 4. Render / Paint Phase (Browser Only)

If DOM changes occurred or layout recalculations are needed, the browser engine performs **Style Recalculation, Layout (Reflow), and Repaint**.

---

## 5. Macrotask / Task Queue (Low-Priority Async Tasks)

Once microtasks and rendering are finished, the Event Loop processes **ONE macrotask** from the Macrotask Queue.

- **What goes here?** `setTimeout`, `setInterval`, `setImmediate` (Node.js), I/O operations, network callbacks (`fetch`/`XHR` resolution), and UI events (click, scroll, keypress).
- **Behavior:** Unlike the Microtask Queue, the Event Loop executes **only ONE macrotask per loop turn**, then checks back to see if new microtasks or render passes are required.

---

## Concrete Example: Tracing the Execution Order

Predict the output of the following code snippet:

```javascript
console.log("1. Sync Start");

setTimeout(() => {
  console.log("2. Macrotask (setTimeout)");
}, 0);

Promise.resolve().then(() => {
  console.log("3. Microtask (Promise .then)");
});

requestAnimationFrame(() => {
  console.log("4. Animation Frame (rAF)");
});

console.log("5. Sync End");
```

### Execution Step-by-Step:

1. **Synchronous Execution:**

- `console.log("1. Sync Start")` runs $\rightarrow$ Prints **`1. Sync Start`**.
- `setTimeout` is sent to Web APIs. Its callback is queued into the **Macrotask Queue**.
- `Promise.resolve().then(...)` queues its callback into the **Microtask Queue**.
- `requestAnimationFrame` registers its callback for the next animation frame.
- `console.log("5. Sync End")` runs $\rightarrow$ Prints **`5. Sync End`**.

2. **Microtask Queue Check:**

- Call Stack is empty. The Event Loop drains the Microtask Queue.
- Prints **`3. Microtask (Promise .then)`**.

3. **Animation Frame Phase:**

- Browser prepares to paint $\rightarrow$ Prints **`4. Animation Frame (rAF)`**.

4. **Macrotask Queue Execution:**

- Event Loop executes the first Macrotask $\rightarrow$ Prints **`2. Macrotask (setTimeout)`**.

### Final Output Log:

```text
1. Sync Start
5. Sync End
3. Microtask (Promise .then)
4. Animation Frame (rAF)
2. Macrotask (setTimeout)

```

---

## Summary Checklist

- **Synchronous code always wins:** Runs first until the stack is $0$.
- **Microtasks run before Macrotasks:** Promises always resolve before `setTimeout`, even if `setTimeout` is set to `0ms`.
- **Microtask starvation:** An infinite loop of Promises (`function loop() { Promise.resolve().then(loop); }`) will freeze the UI because the Event Loop will never reach the Rendering or Macrotask phases.

## The Complex Code Scenario

```javascript
console.log("1. Script Start");

// Macrotask A
setTimeout(() => {
  console.log("2. Macrotask A (Timer)");

  // Microtask nested inside Macrotask A
  Promise.resolve().then(() => {
    console.log("3. Microtask A1 (Inside Macrotask A)");
  });
}, 0);

// Async Function Call
async function asyncFlow() {
  console.log("4. Async Start (Synchronous body)");

  // Await pauses asyncFlow and queues a microtask for the remaining code
  await Promise.resolve();

  console.log("5. Async After Await");

  // Macrotask B queued inside microtask phase
  setTimeout(() => {
    console.log("6. Macrotask B (Queued after await)");
  }, 0);
}

asyncFlow();

// Promise with nested Microtasks
new Promise((resolve) => {
  console.log("7. Promise Constructor (Synchronous)");
  resolve();
})
  .then(() => {
    console.log("8. Microtask B1");

    // Dynamically scheduling another Microtask inside a Microtask
    return Promise.resolve();
  })
  .then(() => {
    console.log("9. Microtask B2 (Chained)");
  });

console.log("10. Script End");
```

---

## Step-by-Step Execution Flow

Let's trace how the JavaScript runtime processes each phase:

### Phase 1: Initial Synchronous Execution (Call Stack)

1. **`console.log("1. Script Start")`** executes $\rightarrow$ Logs **`1. Script Start`**.
2. **`setTimeout` (Macrotask A)** is registered with Web APIs. Its callback is pushed to the **Macrotask Queue**.
3. **`asyncFlow()` is called:**

- **`console.log("4. Async Start...")`** runs synchronously $\rightarrow$ Logs **`4. Async Start (Synchronous body)`**.
- **`await Promise.resolve()`** executes. The rest of `asyncFlow` pauses, and its continuation (`console.log("5. Async After Await")`) is scheduled into the **Microtask Queue** (Microtask 1).

4. **`new Promise(...)` constructor** executes synchronously:

- **`console.log("7. Promise Constructor...")`** runs $\rightarrow$ Logs **`7. Promise Constructor (Synchronous)`**.
- `resolve()` is called. `.then(8. Microtask B1)` is added to the **Microtask Queue** (Microtask 2).

5. **`console.log("10. Script End")`** executes $\rightarrow$ Logs **`10. Script End`**.

---

### Phase 2: Draining the Microtask Queue (Tick 1)

The Call Stack is now empty. The Event Loop processes all microtasks present in the **Microtask Queue**:

1. **Pop Microtask 1 (`asyncFlow` continuation):**

- Logs **`5. Async After Await`**.
- Registers a new **`setTimeout` (Macrotask B)**. Web APIs push it to the **Macrotask Queue**.

2. **Pop Microtask 2 (`Microtask B1`):**

- Logs **`8. Microtask B1`**.
- Returns `Promise.resolve()`, which queues **`9. Microtask B2 (Chained)`** into the **Microtask Queue** (Microtask 3).

3. **Pop Microtask 3 (`Microtask B2`):**

- Logs **`9. Microtask B2 (Chained)`**.

> **Queue Status:** The Microtask Queue is now completely empty. The Macrotask Queue contains `[Macrotask A, Macrotask B]`.

---

### Phase 3: Executing First Macrotask (Macrotask A)

The Event Loop picks **only the first item** from the Macrotask Queue.

1. **Execute Macrotask A:**

- Logs **`2. Macrotask A (Timer)`**.
- Executes `Promise.resolve().then(...)`, pushing **`3. Microtask A1`** into the **Microtask Queue**.

---

### Phase 4: Intercepting Microtasks Created inside Macrotasks

Before moving to `Macrotask B`, the Event Loop **must drain any new microtasks** generated by `Macrotask A`.

1. **Pop `3. Microtask A1`:**

- Logs **`3. Microtask A1 (Inside Macrotask A)`**.

---

### Phase 5: Executing Second Macrotask (Macrotask B)

With the Microtask Queue empty again, the Event Loop executes the next Macrotask.

1. **Execute Macrotask B:**

- Logs **`6. Macrotask B (Queued after await)`**.

---

## Final Output Log

```text
1. Script Start
4. Async Start (Synchronous body)
7. Promise Constructor (Synchronous)
10. Script End
5. Async After Await
8. Microtask B1
9. Microtask B2 (Chained)
2. Macrotask A (Timer)
3. Microtask A1 (Inside Macrotask A)
6. Macrotask B (Queued after await)

```

---

## Key Architectural Insights from this Flow

1. **`async/await` is Syntactic Sugar for Promises:** Code up to the first `await` keyword runs **synchronously**. Everything _after_ the `await` is deferred as a microtask.
2. **Promise Constructor is Synchronous:** The executor function inside `new Promise((resolve) => { ... })` runs immediately on the main thread. Only `.then()`, `.catch()`, and `.finally()` callbacks are asynchronous microtasks.
3. **Inter-Macrotask Microtask Draining:** Between every single macrotask, the Event Loop sweeps and empties the entire microtask queue. That is why `3. Microtask A1` executed _before_ `6. Macrotask B`.
