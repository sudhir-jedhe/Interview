Handling API errors effectively in a React UI

Handling API errors effectively in a React UI requires combining local error handling (`try/catch`), recovery strategies (**Retry** mechanisms), and global or targeted user feedback (**Notifications**).

Here is a comprehensive breakdown of how to structure this in a clean, production-ready React application.

---

## 1. Local Request Handling (`try / catch / finally`)

When making async network requests inside component handlers or custom hooks, always wrap the call in a `try/catch/finally` block to keep track of **loading**, **data**, and **error** states.

```jsx
import React, { useState } from "react";
import { fetchUserProfile } from "../api/userApi";

export function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  const loadProfile = async () => {
    setLoading(true);
    setError(null);

    try {
      const data = await fetchUserProfile(userId);
      setUser(data);
    } catch (err) {
      // Capture error locally for inline UI fallback
      setError(err.message || "Failed to load profile.");
    } finally {
      setLoading(false); // Guarantees loading state resets whether call succeeds or fails
    }
  };

  if (loading) return <div>Loading user details...</div>;

  if (error) {
    return (
      <div className="error-card">
        <p>{error}</p>
        <button onClick={loadProfile}>Try Again</button>
      </div>
    );
  }

  return user ? (
    <div>
      <h1>{user.name}</h1>
    </div>
  ) : null;
}
```

## 2. Implementing a Retry Mechanism

When network glitches or server hiccups occur, offering automatic or manual retries improves reliability.

### Approach A: Manual Retry Button

Provide an explicit "Retry" button when an operation fails so users can trigger the API call again manually (as shown in the code above).

### Approach B: Automatic Exponential Backoff Retry (with React Query / TanStack Query)

If you use a data-fetching library like TanStack Query, automatic retry logic with backoff is built-in out of the box:

```javascript
import { useQuery } from "@tanstack/react-query";
import { fetchUserProfile } from "../api/userApi";

export function useUserProfileQuery(userId) {
  return useQuery({
    queryKey: ["user", userId],
    queryFn: () => fetchUserProfile(userId),
    retry: 3, // Retry failed requests up to 3 times before throwing error
    retryDelay: (attemptIndex) => Math.min(1000 * 2 ** attemptIndex, 30000), // Exponential backoff (1s, 2s, 4s...)
  });
}
```

### Approach C: Custom Vanilla JS Retry Helper

If not using React Query, you can write a utility function that wraps standard `fetch` with retries:

```javascript
export async function fetchWithRetry(fn, retries = 3, delay = 1000) {
  try {
    return await fn();
  } catch (err) {
    if (retries <= 0) throw err;

    // Wait for delay duration, then retry recursively
    await new Promise((resolve) => setTimeout(resolve, delay));
    return fetchWithRetry(fn, retries - 1, delay * 2);
  }
}
```

## 3. User Notification System (Toasts & Global Feedback)

For temporary actions like saving a form, submitting a payment, or updating settings, presenting an unobtrusive **Toast Notification** provides immediate visual feedback.

### Centralized Toast Integration (e.g., using `react-toastify` or `sonner`)

#### Step 1: Intercept & Trigger Toast in Axios Interceptor

```javascript
// api/client.js
import axios from "axios";
import { toast } from "sonner"; // Or react-toastify

export const apiClient = axios.create({ baseURL: "/api" });

apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    const status = error.response?.status;
    const message = error.response?.data?.message || "Something went wrong";

    // Global Notifications for non-form errors
    if (status === 500) {
      toast.error("Internal Server Error. Please try again later.");
    } else if (status === 403) {
      toast.warning("You do not have permission to perform this action.");
    } else if (status === 408 || error.code === "ECONNABORTED") {
      toast.error("Request timed out. Please check your network connection.");
    } else if (!error.response) {
      toast.error("Network error. Unable to reach server.");
    }

    return Promise.reject(error);
  },
);
```

#### Step 2: Triggering Contextual Toasts in Component Mutations

```jsx
import { toast } from "sonner";

const handleSaveSettings = async (formData) => {
  const toastId = toast.loading("Saving changes...");

  try {
    await apiClient.post("/settings", formData);
    toast.success("Settings updated successfully!", { id: toastId });
  } catch (err) {
    toast.error(err.message || "Failed to update settings", { id: toastId });
  }
};
```

## 4. Full Error Handling Strategy Matrix

To deliver a polished user experience, map your error visual patterns based on the type of error and context:

| Error Type                                    | User Impact               | Recommended UI Response                                                    |
| --------------------------------------------- | ------------------------- | -------------------------------------------------------------------------- |
| **Form Validation (`400 Bad Request`)**       | High (User can fix)       | **Inline Field Errors** directly next to the input inputs.                 |
| **Authentication (`401 Unauthorized`)**       | Session Expired           | **Automatic Redirect** to `/login` with an informative toast message.      |
| **Permission (`403 Forbidden`)**              | Restricted Access         | **Banner / Toast** explaining missing privileges.                          |
| **Missing Resource (`404 Not Found`)**        | Resource Missing          | **Empty State Component** or dedicated 404 screen with a navigation link.  |
| **Transient Network / Timeout (`408 / 504`)** | Temporary Connection Drop | **Toast Notification** + **Automatic Retry Button**.                       |
| **Server Crash (`500 Internal Error`)**       | Server Failure            | **Global Toast Notification** or **React Error Boundary** fallback screen. |
