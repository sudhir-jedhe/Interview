Handling a large form with 20+ fields in React requires avoiding the common pitfall of binding every single keystroke to a top-level component's `useState`. In standard React, updating a single state object on every keypress causes the entire form—and all 20+ fields—to re-render on every keystroke, leading to noticeable input lag.

Here is the industry-standard architecture for handling large, complex forms efficiently.

---

## 1. Use Uncontrolled Inputs via React Hook Form

The most effective way to handle 20+ fields is with **React Hook Form (RHF)**. It relies on uncontrolled inputs under the hood, meaning typing in field #1 **does not trigger a re-render** of fields #2 through #20.

### Complete Example with Schema Validation (Zod)

```tsx
import React from "react";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";

// 1. Define schema for all 20+ fields
const formSchema = z.object({
  firstName: z.string().min(1, "First name is required"),
  lastName: z.string().min(1, "Last name is required"),
  email: z.string().email("Invalid email address"),
  phone: z.string().min(10, "Phone must be at least 10 digits"),
  addressLine1: z.string().min(1, "Address is required"),
  city: z.string().min(1, "City is required"),
  zipCode: z.string().min(5, "Zip code required"),
  // ... rest of your 20+ fields
});

type FormValues = z.infer<typeof formSchema>;

export function LargeForm() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm<FormValues>({
    resolver: zodResolver(formSchema),
    mode: "onBlur", // Validate only on blur to avoid unnecessary checks while typing
  });

  const onSubmit = async (data: FormValues) => {
    console.log("Submitting 20+ fields:", data);
    // Submit API call
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-4">
      <h2>User Information</h2>

      <div>
        <label>First Name</label>
        <input {...register("firstName")} />
        {errors.firstName && (
          <p className="error">{errors.firstName.message}</p>
        )}
      </div>

      <div>
        <label>Last Name</label>
        <input {...register("lastName")} />
        {errors.lastName && <p className="error">{errors.lastName.message}</p>}
      </div>

      <div>
        <label>Email</label>
        <input type="email" {...register("email")} />
        {errors.email && <p className="error">{errors.email.message}</p>}
      </div>

      {/* Repeat for all remaining fields... */}

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? "Saving..." : "Submit Form"}
      </button>
    </form>
  );
}
```

## 2. Break the Form into Smaller Sections / Sub-Components

Instead of placing all 20+ inputs inside a single giant component file, break the form into logical fieldsets or modular components. Use `useFormContext` so child components can register inputs directly without passing `register` props down through multiple layers.

### Step A: Wrap Parent in `FormProvider`

```tsx
import { useForm, FormProvider } from "react-hook-form";

export function MasterForm() {
  const methods = useForm<FormValues>({ mode: "onBlur" });

  return (
    <FormProvider {...methods}>
      <form onSubmit={methods.handleSubmit((data) => console.log(data))}>
        <PersonalDetailsSection />
        <AddressSection />
        <FinancialDetailsSection />
        <button type="submit">Submit</button>
      </form>
    </FormProvider>
  );
}
```

### Step B: Create Isolated Section Components

```tsx
import { useFormContext } from "react-hook-form";

export function AddressSection() {
  // Access register and errors directly from FormProvider context
  const {
    register,
    formState: { errors },
  } = useFormContext();

  return (
    <fieldset className="border p-4 rounded">
      <legend>Address Details</legend>

      <div>
        <label>Address Line 1</label>
        <input {...register("addressLine1")} />
        {errors.addressLine1 && <p>{errors.addressLine1.message as string}</p>}
      </div>

      <div>
        <label>City</label>
        <input {...register("city")} />
        {errors.city && <p>{errors.city.message as string}</p>}
      </div>
    </fieldset>
  );
}
```

## 3. Implement a Multi-Step (Wizard) Form UI

For 20+ fields, showing all fields at once creates visual overload for the user. Grouping fields into a **Multi-step Wizard** (`Step 1: Account`, `Step 2: Address`, `Step 3: Payment`) improves both UX and DOM rendering performance.

```tsx
function MultiStepForm() {
  const [step, setStep] = useState(1);
  const methods = useForm({ mode: "onTouched" });

  const nextStep = async () => {
    // Validate ONLY the fields on the current step before advancing
    const isStepValid = await methods.trigger([
      "firstName",
      "lastName",
      "email",
    ]);
    if (isStepValid) setStep((prev) => prev + 1);
  };

  return (
    <FormProvider {...methods}>
      <form onSubmit={methods.handleSubmit(onSubmit)}>
        {step === 1 && <PersonalInfoStep />}
        {step === 2 && <AddressStep />}
        {step === 3 && <ReviewStep />}

        <div className="flex gap-2">
          {step > 1 && (
            <button type="button" onClick={() => setStep((s) => s - 1)}>
              Back
            </button>
          )}
          {step < 3 && (
            <button type="button" onClick={nextStep}>
              Next
            </button>
          )}
          {step === 3 && <button type="submit">Submit</button>}
        </div>
      </form>
    </FormProvider>
  );
}
```

## 4. Key Performance Strategies for Large Forms

| Strategy                                     | Why It Matters                                                                                                                                                                            |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Validate `onBlur` or `onSubmit**`          | Avoid running schema checks (`Zod`/`Yup`) on every single keypress (`onChange`). Running validation on keypresses across 20+ fields wastes CPU cycles.                                    |
| **Avoid Top-Level `useState` for Form Data** | Storing `{ field1: '', field2: '', ... }` in a single React `useState` forces the entire tree to re-render every time any character changes.                                              |
| **Use Native/Uncontrolled UI Components**    | Standard `<input>` and `<select>` elements managed by refs perform significantly faster than heavily customized controlled components when field counts grow large.                       |
| **Debounce Dynamic Calculations**            | If field #18 depends on values typed into field #2 (e.g., auto-calculating tax or shipping cost based on zip code), debounce the watcher using `useWatch` + `useDebounce` to prevent lag. |

Building a multi-step form with conditional fields is one of the most common requirements in modern web development. When choosing between tools, **React Hook Form (RHF)** paired with **Zod** has become the industry standard over Formik due to better performance (uncontrolled inputs prevent full-form re-renders on every keystroke) and superior TypeScript integration.

Below is a complete breakdown comparing both approaches, followed by a production-ready **Multi-Step Form with Conditional Rendering** using React Hook Form and Zod.

---

### Quick Comparison: RHF vs. Formik

| Feature                    | React Hook Form + Zod                              | Formik + Yup                                          |
| -------------------------- | -------------------------------------------------- | ----------------------------------------------------- |
| **Performance**            | **High** (Isolates re-renders to modified inputs)  | **Moderate** (Re-renders whole form on keystrokes)    |
| **Bundle Size**            | ~8.5 kB (RHF) + ~12 kB (Zod)                       | ~15 kB (Formik) + ~15 kB (Yup)                        |
| **Type Safety**            | Native TypeScript inference via `z.infer`          | Requires manual type definitions or extra boilerplate |
| **Conditional Validation** | Clean built-in discriminated unions or `.refine()` | Requires `.when()` chains in Yup                      |

### Production-Ready Pattern: Multi-Step Form with Conditional Logic

Here is an end-to-end implementation featuring **React Hook Form**, **Zod**, a step-based wizard, and **conditional field rendering**.

#### 1. Define the Schema with Zod (Including Conditional Rules)

```tsx
import { z } from "zod";

export const formSchema = z
  .object({
    // Step 1: Account Type
    accountType: z.enum(["personal", "business"]),

    // Step 1: Conditional Field
    companyName: z.string().optional(),

    // Step 2: Personal Info
    fullName: z.string().min(2, "Full name is required"),
    email: z.string().email("Invalid email address"),

    // Step 3: Preferences
    notifications: z.boolean(),
  })
  // Conditional Validation Rule using superRefine
  .superRefine((data, ctx) => {
    if (
      data.accountType === "business" &&
      (!data.companyName || data.companyName.trim() === "")
    ) {
      ctx.addIssue({
        code: z.ZodIssueCode.custom,
        path: ["companyName"],
        message: "Company name is required for business accounts",
      });
    }
  });

export type FormSchema = z.infer<typeof formSchema>;
```

#### 2. Build the Multi-Step Component

```tsx
import React, { useState } from "react";
import { useForm, FormProvider, useFormContext } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { formSchema, FormSchema } from "./schema";

export function MultiStepForm() {
  const [currentStep, setCurrentStep] = useState(1);

  const methods = useForm<FormSchema>({
    resolver: zodResolver(formSchema),
    mode: "onBlur",
    defaultValues: {
      accountType: "personal",
      companyName: "",
      fullName: "",
      email: "",
      notifications: false,
    },
  });

  const { handleSubmit, trigger, watch } = methods;

  // Step 1 validation fields (including conditional check)
  const accountType = watch("accountType");

  const nextStep = async () => {
    let fieldsToValidate: (keyof FormSchema)[] = [];

    if (currentStep === 1) {
      fieldsToValidate =
        accountType === "business"
          ? ["accountType", "companyName"]
          : ["accountType"];
    } else if (currentStep === 2) {
      fieldsToValidate = ["fullName", "email"];
    }

    // Validate only the fields present in the current step before proceeding
    const isValid = await trigger(fieldsToValidate);
    if (isValid) {
      setCurrentStep((prev) => Math.min(prev + 1, 3));
    }
  };

  const prevStep = () => setCurrentStep((prev) => Math.max(prev - 1, 1));

  const onSubmit = (data: FormSchema) => {
    console.log("Final Submitted Data:", data);
    alert("Form submitted successfully!");
  };

  return (
    <div className="max-w-md mx-auto p-6 bg-white rounded-lg shadow-md">
      {/* Step Indicator */}
      <div className="flex justify-between mb-6 border-b pb-4">
        <span
          className={
            currentStep === 1 ? "font-bold text-blue-600" : "text-gray-400"
          }
        >
          1. Account
        </span>
        <span
          className={
            currentStep === 2 ? "font-bold text-blue-600" : "text-gray-400"
          }
        >
          2. Details
        </span>
        <span
          className={
            currentStep === 3 ? "font-bold text-blue-600" : "text-gray-400"
          }
        >
          3. Preferences
        </span>
      </div>

      <FormProvider {...methods}>
        <form onSubmit={handleSubmit(onSubmit)}>
          {currentStep === 1 && <Step1AccountType />}
          {currentStep === 2 && <Step2UserDetails />}
          {currentStep === 3 && <Step3Preferences />}

          {/* Wizard Controls */}
          <div className="flex justify-between mt-6">
            {currentStep > 1 && (
              <button
                type="button"
                onClick={prevStep}
                className="px-4 py-2 bg-gray-200 rounded hover:bg-gray-300"
              >
                Back
              </button>
            )}

            {currentStep < 3 ? (
              <button
                type="button"
                onClick={nextStep}
                className="ml-auto px-4 py-2 bg-blue-600 text-white rounded hover:bg-blue-700"
              >
                Next
              </button>
            ) : (
              <button
                type="submit"
                className="ml-auto px-4 py-2 bg-green-600 text-white rounded hover:bg-green-700"
              >
                Submit
              </button>
            )}
          </div>
        </form>
      </FormProvider>
    </div>
  );
}
```

### Key Takeaways for Multi-Step Conditional Forms

1. **Use `FormProvider` + `useFormContext**`: Avoid passing `register`and`errors`down through props. Wrapping sub-steps in`FormProvider` grants clean access to the form methods across all step components.
2. **Selective Validation with `trigger()**`: Don't run full-form validation on step transitions. Use `await trigger(['fieldName1', 'fieldName2'])` to validate only the inputs rendered on the current active step before advancing.
3. **Use `watch()` for Conditional Fields**: `watch('field')` allows you to render or hide fields dynamically based on active selections without breaking RHF's state management.
4. **Zod Discriminated Unions or `.superRefine()**`: Handle dynamic validation rules gracefully by applying `.superRefine()`or`.refine()` at the schema root so hidden fields don't accidentally throw schema errors when unmounted.
