A component displays an old value inside a callback even though the state has already changed. Is this a closure problem, a dependency problem, or both?

Short answer: **It is both.** They are two sides of the same coin in React.

The root cause in JavaScript is a **stale closure**, but in React, it is triggered by an **incorrect or missing dependency array**.

---

### How Stale Closures Work in React

In JavaScript, a closure "captures" the variables in its outer scope at the exact moment the closure is created.

In React, state variables (`const [count, setCount] = useState(0)`) are local constants inside your component function. Every time your component re-renders with a new state value, React executes the component function again, creating a **brand new scope** with new variables.

```jsx
function Counter() {
  const [count, setCount] = useState(0); // On Render 1: count is 0

  const handleClick = useCallback(() => {
    // This closure captured 'count' from Render 1 (count = 0)
    console.log(count);
  }, []); // ❌ Missing 'count' in dependencies

  return <button onClick={handleClick}>Log Count</button>;
}
```

Here is what happens step-by-step:

1. **Render 1:** `count` is `0`. `useCallback` creates `handleClick`, closing over `count = 0`.
2. **State Updates:** `setCount(1)` triggers **Render 2**.
3. **Render 2:** A new variable `count` equal to `1` is created in Render 2's scope.
4. **The Dependency Problem:** Because `useCallback` has an empty dependency array `[]`, React **skips** recreating `handleClick`. It returns the exact same function reference created during Render 1.
5. **The Closure Problem:** When clicked, that Render 1 function runs. It looks into its preserved lexical closure and reads `count`, which is still `0`.

---

### How to Fix It

#### 1. Include State in the Dependency Array (Standard Fix)

By adding `count` to the dependency array, React drops the old function reference and creates a new closure containing the updated `count` whenever `count` changes.

```jsx
const handleClick = useCallback(() => {
  console.log(count);
}, [count]); // ✅ Updates closure whenever count changes
```

#### 2. Use Functional State Updates (When Setting State)

If your callback only needs the previous state to calculate the new state, pass a updater function to `setCount`. This avoids needing the state in the dependency array altogether.

```jsx
// ❌ Reads stale closure if called repeatedly in old scope
const increment = useCallback(() => {
  setCount(count + 1);
}, []);

// ✅ Always receives the latest pending state from React
const increment = useCallback(() => {
  setCount((prevCount) => prevCount + 1);
}, []);
```

#### 3. Use `useRef` for Mutable Latest Values (Escape Hatch)

If you need a callback reference to remain strictly stable (e.g., passed to an expensive third-party subscription) without re-subscribing, store the value in a `ref`.

```jsx
const countRef = useRef(count);
countRef.current = count; // Always kept up-to-date synchronously

const handleClick = useCallback(() => {
  console.log(countRef.current); // ✅ Always reads latest value without triggering re-creation
}, []);
```
