JavaScript Iterables

An **Iterable** in JavaScript is any object that defines its iteration behavior—meaning it allows its values to be looped over using constructs like `for...of`, the spread operator (`...`), or destructuring.

For an object to be an iterable, it must implement the **Iterable Protocol** by having a method with the key `[Symbol.iterator]`.

---

## 1. Built-in Iterables

JavaScript includes several built-in objects that implement the iterable protocol by default:

* **Arrays**
* **Strings**
* **Maps**
* **Sets**
* **TypedArrays**
* **`arguments` object**
* **NodeList** *(in browser environments)*

```javascript
// Example 1: Iterating over an Array
const fruits = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
  console.log(fruit); // Output: "apple", "banana", "cherry"
}

// Example 2: Iterating over a String
const str = "JS";
for (const char of str) {
  console.log(char); // Output: "J", "S"
}

// Example 3: Iterating over a Map
const map = new Map([["a", 1], ["b", 2]]);
for (const [key, value] of map) {
  console.log(`${key}: ${value}`); // Output: "a: 1", "b: 2"
}

```

---

## 2. The Iteration Protocols

The iterable mechanism works through two complementary protocols:

### A. The Iterable Protocol

An object is an **Iterable** if it has a property with the `Symbol.iterator` key—a function that returns an **Iterator** object.

### B. The Iterator Protocol

An object is an **Iterator** if it implements a `.next()` method that returns an object with two properties:

* `value`: The current iteration value.
* `done`: A boolean (`true` if iteration is complete, `false` otherwise).

```javascript
// Manually calling the iterator of an array
const numbers = [10, 20];
const iterator = numbers[Symbol.iterator]();

console.log(iterator.next()); // Output: { value: 10, done: false }
console.log(iterator.next()); // Output: { value: 20, done: false }
console.log(iterator.next()); // Output: { value: undefined, done: true }

```

---

## 3. Creating Custom Iterables

You can make any plain JavaScript object iterable by adding a `[Symbol.iterator]` method to it.

### Method 1: Using the Iterator Protocol Directly

```javascript
const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {
    let current = this.from;
    let last = this.to;
    return {
      next() {
        if (current <= last) {
          return { value: current++, done: false };
        }
        return { done: true };
      }
    };
  }
};

for (const num of range) {
  console.log(num); 
}
// Output: 1, 2, 3

```

### Method 2: Using a Generator Function (Cleaner & Recommended)

Generator functions (`function*`) automatically return a generator object that conforms to both the iterable and iterator protocols.

```javascript
const customCollection = {
  items: ["Alpha", "Beta", "Gamma"],
  *[Symbol.iterator]() {
    for (const item of this.items) {
      yield item;
    }
  }
};

console.log([...customCollection]); 
// Output: ["Alpha", "Beta", "Gamma"]

```

## 4. Constructs That Expect Iterables

Many JavaScript syntax constructs and built-in methods require an iterable as input:

```javascript
// 1. for...of loop
for (const val of new Set([1, 2, 3])) {
  console.log(val);
}

// 2. Spread operator (...)
const digits = [..."123"]; 
console.log(digits); // Output: ["1", "2", "3"]

// 3. Array.from()
const arr = Array.from("HELLO");
console.log(arr); // Output: ["H", "E", "L", "L", "O"]

// 4. Destructuring Assignment
const [first, second] = new Set(["x", "y"]);
console.log(first, second); // Output: "x" "y"

// 5. Promise.all() / Promise.race()
Promise.all([Promise.resolve(1), Promise.resolve(2)]);

```

## 5. Iterables vs. Array-Likes

It is important to distinguish between an **Iterable** and an **Array-Like** object:

* **Iterable:** An object that implements `[Symbol.iterator]` (works with `for...of`).
* **Array-Like:** An object that has indexed properties and a `.length` property (e.g., `{ 0: "a", 1: "b", length: 2 }`), but lacks `[Symbol.iterator]`.

To convert an array-like object or an iterable into a true Array, use **`Array.from()`**:

```javascript
// Array-like object (not iterable by default)
const arrayLike = { 0: "first", 1: "second", length: 2 };

// Convert array-like to true array using Array.from()
const realArray = Array.from(arrayLike);
console.log(realArray.map(item => item.toUpperCase())); 
// Output: ["FIRST", "SECOND"]

```

Explain JavaScript Generator functions (* function) and the yield keyword with examples

**Generator functions** are a special category of functions in JavaScript that can be **paused and resumed** during their execution.

Unlike normal functions that execute from top to bottom until they reach a `return` statement or the end of the block, a generator function yields control back to the caller while preserving its internal state (variable values, execution position).

---

## 1. Syntax & Core Concepts

A generator function is declared using the `function*` syntax (with an asterisk). Calling a generator function **does not execute its body immediately**. Instead, it returns a special **Generator object** that conforms to both the **Iterable** and **Iterator** protocols.

* **`function*`**: Defines a generator function.
* **`yield`**: Pauses function execution and returns a value to the caller.
* **`.next()`**: Resumes execution from the exact point where it was paused until it hits the next `yield` or `return`.

```javascript
// Example 1: Basic Generator declaration and usage
function* simpleGenerator() {
  console.log("Execution started");
  yield 1;
  console.log("Execution resumed");
  yield 2;
  return "Done";
}

const gen = simpleGenerator(); // Returns generator object, body hasn't executed yet

console.log(gen.next()); 
// Logs: "Execution started"
// Output: { value: 1, done: false }

console.log(gen.next()); 
// Logs: "Execution resumed"
// Output: { value: 2, done: false }

console.log(gen.next()); 
// Output: { value: "Done", done: true }

```

---

## 2. How the `yield` Keyword Works

The `yield` operator pauses execution and sends a value back. However, `yield` can also **receive values** passed into `.next(val)` on subsequent calls.

### A. Passing Arguments into `.next()`

Values passed to `.next(value)` replace the `yield` expression inside the generator function.

```javascript
function* conversation() {
  const name = yield "What is your name?";
  console.log(`Hello, ${name}!`);
  
  const age = yield "How old are you?";
  console.log(`You are ${age} years old.`);
}

const chat = conversation();

// First next() starts execution until first yield
console.log(chat.next().value); 
// Output: "What is your name?"

// Second next("Alice") passes "Alice" as result of first yield expression
console.log(chat.next("Alice").value); 
// Logs: "Hello, Alice!"
// Output: "How old are you?"

// Third next(30) passes 30 as result of second yield expression
chat.next(30); 
// Logs: "You are 30 years old."

```

---

## 3. Delegation with `yield*`

The `yield*` expression is used to **delegate execution to another generator** or iterable object (like an array or set).

```javascript
function* numbers() {
  yield 1;
  yield 2;
}

function* alphabet() {
  yield "A";
  yield "B";
}

function* combined() {
  yield* numbers();  // Delegates to numbers generator
  yield* alphabet(); // Delegates to alphabet generator
  yield* [10, 20];   // Delegates to an Array
}

console.log([...combined()]); 
// Output: [1, 2, "A", "B", 10, 20]

```

---

## 4. Practical Use Cases for Generators

### A. Creating Infinite Data Streams

Because generators pause execution until `.next()` is called, you can create infinite sequences without filling up memory or causing stack overflow errors.

```javascript
function* infiniteIDGenerator() {
  let id = 1;
  while (true) {
    yield `user_${id++}`;
  }
}

const idGen = infiniteIDGenerator();

console.log(idGen.next().value); // Output: "user_1"
console.log(idGen.next().value); // Output: "user_2"
console.log(idGen.next().value); // Output: "user_3"

```

### B. Making Custom Objects Iterable

Generators simplify implementing `Symbol.iterator` on custom objects.

```javascript
const company = {
  employees: ["Alice", "Bob", "Charlie"],
  *[Symbol.iterator]() {
    for (const emp of this.employees) {
      yield emp;
    }
  }
};

for (const employee of company) {
  console.log(employee);
}
// Output: "Alice", "Bob", "Charlie"

```

### C. Paginated Data Fetching

Generators allow consumer code to request the next page of data on demand rather than loading everything into memory at once.

```javascript
function* paginate(items, pageSize) {
  for (let i = 0; i < items.length; i += pageSize) {
    yield items.slice(i, i + pageSize);
  }
}

const data = [1, 2, 3, 4, 5, 6, 7, 8, 9];
const pager = paginate(data, 3);

console.log(pager.next().value); // Output: [1, 2, 3]
console.log(pager.next().value); // Output: [4, 5, 6]
console.log(pager.next().value); // Output: [7, 8, 9]

```

---

## Summary of Generator Methods

| Method                  | Description                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| **`gen.next(value)`**   | Resumes execution, optionally passing `value` into the `yield` expression.                  |
| **`gen.return(value)`** | Immediately terminates the generator and returns `{ value: value, done: true }`.            |
| **`gen.throw(error)`**  | Throws an error into the generator at the current `yield` point for `try...catch` handling. |
