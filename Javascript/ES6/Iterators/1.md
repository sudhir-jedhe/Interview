JavaScript Iterators

In JavaScript, an **Iterator** is an object that defines a sequence and a return value upon its termination. Specifically, an iterator implements the **Iterator Protocol** by providing a `.next()` method.

When `.next()` is called, it returns an object with two properties:

* `value`: The next value in the iteration sequence.
* `done`: A boolean set to `false` if there are more values, or `true` if the sequence has finished.

---

## 1. The Iterator Protocol & Manual Iteration

You can obtain an iterator from built-in iterables (like Arrays, Strings, Sets, and Maps) by calling their `[Symbol.iterator]()` method.

```javascript
// Example 1: Manually stepping through an Array iterator
const colors = ["red", "green"];
const iterator = colors[Symbol.iterator]();

console.log(iterator.next()); // Output: { value: "red", done: false }
console.log(iterator.next()); // Output: { value: "green", done: false }
console.log(iterator.next()); // Output: { value: undefined, done: true }

// Example 2: String iterator
const charIterator = "Hi"[Symbol.iterator]();
console.log(charIterator.next().value); // Output: "H"
console.log(charIterator.next().value); // Output: "i"

// Example 3: Iterating until done using a while loop
const numbers = [10, 20];
const numIterator = numbers[Symbol.iterator]();
let result = numIterator.next();

while (!result.done) {
  console.log(result.value);
  result = numIterator.next();
}
// Output: 10, 20

```

---

## 2. Creating Custom Iterators

You can turn any plain object into a custom iterator or iterable by implementing the `.next()` method or assigning a `[Symbol.iterator]` property.

### Approach A: Custom Iterator Function

```javascript
// Example 1: Helper function that creates a custom range iterator
function createRangeIterator(start, end, step = 1) {
  let nextIndex = start;
  return {
    next() {
      if (nextIndex <= end) {
        const value = nextIndex;
        nextIndex += step;
        return { value: value, done: false };
      }
      return { value: undefined, done: true };
    }
  };
}

const myRange = createRangeIterator(1, 5, 2);
console.log(myRange.next().value); // Output: 1
console.log(myRange.next().value); // Output: 3
console.log(myRange.next().value); // Output: 5
console.log(myRange.next().done);  // Output: true

```

---

### Approach B: Making an Object Iterable with `Symbol.iterator`

```javascript
// Example 1: Plain object with custom iterator logic
const counter = {
  start: 1,
  end: 3,
  [Symbol.iterator]() {
    let current = this.start;
    let last = this.end;
    return {
      next() {
        if (current <= last) {
          return { value: current++, done: false };
        }
        return { done: true };
      }
    };
  }
};

// Now usable in for...of loops and spread syntax
for (const num of counter) {
  console.log(num); 
}
// Output: 1, 2, 3

console.log([...counter]); 
// Output: [1, 2, 3]

```

## 3. Built-in Object Iterators

Objects like `Map` and `Array` provide built-in methods that return specialized iterator objects: `.keys()`, `.values()`, and `.entries()`.

```javascript
// Example 1: Map.prototype.entries() iterator
const userMap = new Map([["name", "Alice"], ["role", "Admin"]]);
const entriesIterator = userMap.entries();

console.log(entriesIterator.next().value); 
// Output: ["name", "Alice"]

// Example 2: Array.prototype.keys() iterator
const fruits = ["apple", "banana"];
const keysIterator = fruits.keys();

console.log(keysIterator.next().value); // Output: 0
console.log(keysIterator.next().value); // Output: 1

// Example 3: Array.prototype.values() iterator
const valuesIterator = fruits.values();
console.log(valuesIterator.next().value); // Output: "apple"

```

## 4. Asynchronous Iterators (`Symbol.asyncIterator`)

Introduced in ES2018, **Async Iterators** return promises for `{ value, done }` pairs via their `.next()` method. They are consumed using `for await...of` loops.

```javascript
// Example 1: Creating an async iterable object
const asyncSequence = {
  [Symbol.asyncIterator]() {
    let i = 1;
    return {
      async next() {
        if (i <= 2) {
          return { value: i++, done: false };
        }
        return { done: true };
      }
    };
  }
};

(async () => {
  for await (const val of asyncSequence) {
    console.log(val);
  }
})();
// Output: 1, 2

```

## Iterables vs. Iterators Quick Summary

| Concept      | Definition                                                        | Key Requirement                                                   |
| ------------ | ----------------------------------------------------------------- | ----------------------------------------------------------------- |
| **Iterable** | An object that can be iterated over (e.g., Array, String, Set).   | Implements `[Symbol.iterator]()` method that returns an Iterator. |
| **Iterator** | The actual pointer object used to step through values one by one. | Implements a `.next()` method returning `{ value, done }`.        |

**Iterator Helpers** in JavaScript (ECMAScript 2025) bring array-like functional programming methods directly to iterators and generators.

Unlike traditional array methods (`.map()`, `.filter()`), iterator helpers evaluate **lazily** (processing elements one at a time on demand) and work directly on infinite sequences, generators, or custom iterables without allocating full arrays in memory.

---

## 1. `Iterator.from()`

`Iterator.from()` converts any iterable (such as an Array, Set, String, or custom object with `[Symbol.iterator]`) or plain iterator into a standard **`Iterator` helper instance** that inherits all new helper methods.

```javascript
// Example 1: Creating an Iterator instance from a Set
const mySet = new Set(["apple", "banana", "cherry"]);
const setIterator = Iterator.from(mySet);

console.log(setIterator.next().value); // Output: "apple"

// Example 2: Creating an Iterator instance from a String
const charIterator = Iterator.from("HELLO");
console.log(charIterator.take(2).toArray()); // Output: ["H", "E"]

// Example 3: Wrapping an array-like object with an iterator interface
const arrayLike = { 0: "a", 1: "b", length: 2 };
const iter = Iterator.from(Array.from(arrayLike));
console.log(iter.toArray()); // Output: ["a", "b"]

```

---

## 2. Lazy Transformation Methods (Return New Iterators)

These methods transform or slice an iterator and return a **new Iterator object**. Operations are lazy and do not execute until consumed (e.g., via `.toArray()` or `for...of`).

### A. `map(fn)`

Transforms each element produced by the iterator.

```javascript
const numbers = [1, 2, 3][Symbol.iterator]();
const doubled = Iterator.from(numbers).map(x => x * 2);

console.log(doubled.toArray()); 
// Output: [2, 4, 6]

```

### B. `filter(predicate)`

Retains only elements that satisfy a testing function.

```javascript
const nums = [1, 2, 3, 4, 5][Symbol.iterator]();
const evens = Iterator.from(nums).filter(x => x % 2 === 0);

console.log(evens.toArray()); 
// Output: [2, 4]

```

### C. `take(limit)`

Yields only the first `limit` elements from the iterator and then stops.

```javascript
function* naturalNumbers() {
  let n = 1;
  while (true) yield n++; // Infinite generator
}

// Safely take the first 3 numbers from an infinite generator
const firstThree = Iterator.from(naturalNumbers()).take(3);

console.log(firstThree.toArray()); 
// Output: [1, 2, 3]

```

### D. `drop(limit)`

Skips the first `limit` elements and yields the rest.

```javascript
const items = ["a", "b", "c", "d", "e"][Symbol.iterator]();
const skipped = Iterator.from(items).drop(2);

console.log(skipped.toArray()); 
// Output: ["c", "d", "e"]

```

### E. `flatMap(fn)`

Maps each element using a transformation function and flattens the resulting iterable into the output iterator.

```javascript
const words = ["hello", "world"][Symbol.iterator]();
const letters = Iterator.from(words).flatMap(w => w.split(""));

console.log(letters.toArray()); 
// Output: ["h", "e", "l", "l", "o", "w", "o", "r", "l", "d"]

```

---

## 3. Terminal Executing Methods (Consume the Iterator)

These methods iterate through elements until completion or until a condition is met, returning a single value or primitive.

### A. `find(predicate)`

Returns the first element that satisfies the test function, or `undefined`.

```javascript
const users = [{ id: 1 }, { id: 2 }, { id: 3 }][Symbol.iterator]();
const match = Iterator.from(users).find(u => u.id === 2);

console.log(match); 
// Output: { id: 2 }

```

### B. `some(predicate)` & `every(predicate)`

Check whether at least one or all elements satisfy a test function.

```javascript
const scores = [80, 90, 95][Symbol.iterator]();

console.log(Iterator.from(scores).some(s => s < 85));  // Output: true
console.log(Iterator.from([80, 90]).every(s => s >= 80)); // Output: true

```

### C. `reduce(reducerFn, initialValue)`

Reduces the iterator down to a single value.

```javascript
const nums = [10, 20, 30][Symbol.iterator]();
const sum = Iterator.from(nums).reduce((acc, curr) => acc + curr, 0);

console.log(sum); 
// Output: 60

```

### D. `forEach(fn)`

Executes a function once for each element in the iterator.

```javascript
const list = ["A", "B"][Symbol.iterator]();
Iterator.from(list).forEach(item => console.log(item));
// Output: "A", "B"

```

### E. `toArray()`

Convenience method that collects all remaining iterator elements directly into a standard Array.

```javascript
function* fibonacci() {
  let [a, b] = [0, 1];
  while (true) {
    yield a;
    [a, b] = [b, a + b];
  }
}

// Combine take() with toArray()
const fibFive = Iterator.from(fibonacci()).take(5).toArray();

console.log(fibFive); 
// Output: [0, 1, 1, 2, 3]

```

Demonstrate how ES2025 Iterator Helpers work with infinite generators using lazy evaluation examples

**Lazy evaluation** means elements are computed **on demand, one at a time**, rather than generating an entire dataset upfront.

With traditional Array methods like `.map()` or `.filter()`, chaining operations on infinite data streams causes memory overflow or infinite loops because arrays attempt to hold all values in memory simultaneously. **ES2025 Iterator Helpers** evaluate lazily, allowing you to chain operations like `.filter()`, `.map()`, `.take()`, and `.drop()` directly on infinite generators safely.

---

## 1. The Core Setup: An Infinite Generator

Consider an infinite generator that continuously yields prime numbers or incremental natural numbers:

```javascript
// Infinite generator of natural numbers (1, 2, 3, 4, ...)
function* naturalNumbers() {
  let n = 1;
  while (true) {
    yield n++;
  }
}

```

---

## 2. Example 1: Pipelining Operations on Infinite Data

In this pipeline, we want to:

1. Start with an infinite stream of natural numbers.
2. Filter for numbers divisible by `3`.
3. Square each of those numbers.
4. Skip the first `2` results using `.drop(2)`.
5. Take the next `4` results using `.take(4)`.
6. Collect them into an array using `.toArray()`.

```javascript
// Step 1: Wrap generator with Iterator.from()
const stream = Iterator.from(naturalNumbers());

// Step 2: Build a lazy processing pipeline
const pipeline = stream
  .filter(n => n % 3 === 0) // Keep multiples of 3: (3, 6, 9, 12, 15, 18, 21, ...)
  .map(n => n ** 2)         // Square them:          (9, 36, 81, 144, 225, 324, 441, ...)
  .drop(2)                  // Skip first 2:         (81, 144, 225, 324, 441, ...)
  .take(4);                 // Take next 4:          (81, 144, 225, 324)

// NOTE: Up to this point, ZERO numbers have been generated or computed!

// Step 3: Consume the pipeline (Triggers evaluation step-by-step)
const result = pipeline.toArray();

console.log(result); 
// Output: [81, 144, 225, 324]

```

### Why This Works (Lazy Execution Flow)

When `.toArray()` is invoked, it requests elements from `.take(4)`. `.take(4)` pulls values through `.drop(2)`, which pulls from `.map()`, `.filter()`, and finally `naturalNumbers()`. Execution stops the moment `4` elements reach the end of the pipeline, leaving the generator paused at `n = 19`.

---

## 3. Example 2: Tracking Lazy Execution with Loggers

To see lazy evaluation in action, we can log every step to see how elements move through the pipeline one at a time.

```javascript
function* infiniteStream() {
  let i = 1;
  while (true) {
    console.log(`[Generator] Yielding: ${i}`);
    yield i++;
  }
}

const pipeline = Iterator.from(infiniteStream())
  .filter(x => {
    const keep = x % 2 === 0;
    console.log(`  [Filter] Testing ${x}: ${keep ? "KEEP" : "DISCARD"}`);
    return keep;
  })
  .map(x => {
    console.log(`    [Map] Transforming ${x} -> ${x * 10}`);
    return x * 10;
  })
  .take(2); // Only stop after 2 items pass through

console.log("--- Starting Pipeline Evaluation ---");
const output = pipeline.toArray();
console.log("--- Finished Pipeline Evaluation ---");

console.log("Final Result:", output);

```

### Execution Log Output

```text
--- Starting Pipeline Evaluation ---
[Generator] Yielding: 1
  [Filter] Testing 1: DISCARD
[Generator] Yielding: 2
  [Filter] Testing 2: KEEP
    [Map] Transforming 2 -> 20
[Generator] Yielding: 3
  [Filter] Testing 3: DISCARD
[Generator] Yielding: 4
  [Filter] Testing 4: KEEP
    [Map] Transforming 4 -> 40
--- Finished Pipeline Evaluation ---
Final Result: [20, 40]

```

Notice how `3` was discarded immediately by `.filter()` without ever reaching `.map()`, and after generating `4`, the loop halted completely.

## 4. Example 3: Searching Infinite Streams safely with `.find()` and `.some()`

Terminal helper methods like `.find()` or `.some()` consume values lazily until a match is found, then **terminate iteration immediately**, preventing infinite loops.

```javascript
function* fibonacci() {
  let [a, b] = [0, 1];
  while (true) {
    yield a;
    [a, b] = [b, a + b];
  }
}

// Find the first Fibonacci number greater than 1000
const firstOver1000 = Iterator.from(fibonacci())
  .find(n => n > 1000);

console.log(firstOver1000); 
// Output: 1597

// Check if any Fibonacci number between 100 and 500 is prime
function isPrime(num) {
  if (num < 2) return false;
  for (let i = 2; i <= Math.sqrt(num); i++) {
    if (num % i === 0) return false;
  }
  return true;
}

const hasPrimeInRange = Iterator.from(fibonacci())
  .drop(10)               // Skip initial small fib numbers
  .take(10)               // Limit search window to next 10 items
  .some(n => isPrime(n)); // Returns true as soon as it hits a prime

console.log(hasPrimeInRange); 
// Output: true

```

## Comparison: Array Chaining vs. Iterator Helper Chaining

| Aspect                  | Array Methods (`.map().filter()`)                                 | ES2025 Iterator Helpers                                            |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------ |
| **Evaluation Strategy** | **Eager**: Computes and allocates entire arrays at each stage.    | **Lazy**: Computes 1 item at a time through the full pipeline.     |
| **Infinite Sequences**  | **Fatal Error**: Crashes due to memory overflow or infinite loop. | **Safe**: Works natively when paired with bounds (`take`, `find`). |
| **Memory Footprint**    | $O(N)$ memory allocations per chained method.                     | $O(1)$ memory consumption regardless of stream length.             |

Explain how ES2025 Async Iterator Helpers work with asynchronous generators and streams

**Async Iterator Helpers** bring the same functional, lazy pipeline capabilities (`.map()`, `.filter()`, `.take()`, `.drop()`, etc.) to **asynchronous data streams**.

Where synchronous Iterator Helpers process elements on demand, Async Iterator Helpers process **Promises for values on demand**. This makes working with real-time events, WebSockets, paginated API fetches, and Node.js or Web ReadableStreams significantly cleaner and more memory-efficient.

---

## 1. The Core Constructor: `AsyncIterator.from()`

Similar to `Iterator.from()`, **`AsyncIterator.from()`** wraps any async iterable, standard async generator, or sync iterable into an `AsyncIterator` instance that inherits all helper methods.

```javascript
// Example: Converting a sync iterable or async generator into an AsyncIterator
const syncNumbers = [10, 20, 30];
const asyncStream = AsyncIterator.from(syncNumbers);

// Each value is wrapped in a Promise
asyncStream.next().then(result => console.log(result)); 
// Output: { value: 10, done: false }

```

---

## 2. Using Helpers with Async Generators

An async generator yields values asynchronously using `await` inside the generator body. You can chain `.filter()`, `.map()`, `.take()`, and `.drop()` directly on the stream.

```javascript
// Simulated async generator fetching paginated user records with API delay
async function* fetchUsers() {
  let page = 1;
  while (page <= 5) {
    // Simulate network latency
    await new Promise(resolve => setTimeout(resolve, 200));
    
    // Yield a batch of users
    yield* [
      { id: page * 2 - 1, active: page % 2 !== 0 },
      { id: page * 2, active: true }
    ];
    page++;
  }
}

// Processing the async stream lazily:
async function processActiveUsers() {
  const activeUserIds = await AsyncIterator.from(fetchUsers())
    .filter(user => user.active)      // Filter out inactive users
    .map(user => `User #${user.id}`)   // Transform into string
    .take(3)                           // Halted as soon as 3 items match!
    .toArray();                        // Collect into an array

  console.log(activeUserIds);
}

processActiveUsers();
// Output: ["User #1", "User #2", "User #3"]

```

### Key Execution Detail

The async generator **stops making API calls** the moment `.take(3)` is satisfied. Unnecessary subsequent network requests are never executed.

## 3. Working with Web ReadableStreams and Node.js Streams

Web `ReadableStream` (such as `fetch()` response bodies) and Node.js streams implement the async iterable protocol (`Symbol.asyncIterator`), making them natively compatible with `AsyncIterator.from()`.

```javascript
// Example: Reading line-by-line from a Web ReadableStream
async function processStream(readableStream) {
  const lineStream = AsyncIterator.from(readableStream)
    .map(chunk => new TextDecoder().decode(chunk)) // Decode Uint8Array to string
    .flatMap(text => text.split("\n"))             // Split text into individual lines
    .filter(line => line.trim().length > 0)        // Strip empty lines
    .drop(1)                                       // Skip CSV header line
    .take(5);                                      // Process top 5 data rows

  // Consume using for await...of
  for await (const line of lineStream) {
    console.log("Line:", line);
  }
}

```

## 4. Terminal Methods for Async Streams

Terminal methods consume the async stream and return a **Promise** resolving to the final value.

### A. `toArray()`

Collects all remaining async stream items into an array.

```javascript
async function* getRatings() {
  yield 4.5;
  yield 5.0;
  yield 3.8;
}

const ratings = await AsyncIterator.from(getRatings()).toArray();
console.log(ratings); // Output: [4.5, 5.0, 3.8]

```

### B. `find(predicate)`

Searches an async stream and resolves with the first matching item.

```javascript
async function* eventStream() {
  yield { type: "click" };
  yield { type: "submit", payload: { valid: true } };
}

const submitEvent = await AsyncIterator.from(eventStream())
  .find(event => event.type === "submit");

console.log(submitEvent); // Output: { type: "submit", payload: { valid: true } }

```

### C. `reduce(reducer, initialValue)`

Accumulates values across an async sequence into a single Promise result.

```javascript
async function* prices() {
  yield 10;
  yield 25;
  yield 15;
}

const total = await AsyncIterator.from(prices())
  .reduce((sum, price) => sum + price, 0);

console.log(total); // Output: 50

```

Show a benchmark performance comparison between Array chaining and ES2025 Iterator Helpers

To see the difference between traditional **Array chaining** (`.map()`, `.filter()`) and **ES2025 Iterator Helpers** (`Iterator.from()`), we need to look at two core metrics: **Memory Allocation** and **Execution Time**.

Array chaining creates a **full temporary array in memory for every chained method**. Iterator Helpers process elements **one at a time through a lazy pipeline**, keeping memory usage flat regardless of input size.

---

## 1. Benchmarking Memory & Execution Time

Below is an executable benchmark script using Node.js (`process.memoryUsage()`) processing a dataset of **10,000,000 numbers**.

### The Task

1. Filter for even numbers (`x % 2 === 0`).
2. Multiply each by 3 (`x * 3`).
3. Take the first **100 matches**.

```javascript
// benchmark.js
const { performance } = require('perf_hooks');

// Dataset size: 10 Million items
const DATA_SIZE = 10_000_000;
const rawData = Array.from({ length: DATA_SIZE }, (_, i) => i + 1);

function getMemoryInMB() {
  return (process.memoryUsage().heapUsed / 1024 / 1024).toFixed(2);
}

// -------------------------------------------------------------
// BENCHMARK 1: Traditional Array Chaining
// -------------------------------------------------------------
function runArrayBenchmark() {
  if (global.gc) global.gc(); // Force Garbage Collection if exposed
  
  const startMem = process.memoryUsage().heapUsed;
  const startTime = performance.now();

  // Eager evaluation: .filter() creates a 5-million element array,
  // .map() creates another 5-million element array, then .slice() picks 100.
  const result = rawData
    .filter(x => x % 2 === 0)
    .map(x => x * 3)
    .slice(0, 100);

  const endTime = performance.now();
  const endMem = process.memoryUsage().heapUsed;

  return {
    time: (endTime - startTime).toFixed(2),
    memUsedMB: ((endMem - startMem) / 1024 / 1024).toFixed(2),
    resultLength: result.length
  };
}

// -------------------------------------------------------------
// BENCHMARK 2: ES2025 Iterator Helpers
// -------------------------------------------------------------
function runIteratorBenchmark() {
  if (global.gc) global.gc(); // Force Garbage Collection if exposed
  
  const startMem = process.memoryUsage().heapUsed;
  const startTime = performance.now();

  // Lazy evaluation: Evaluates item-by-item and stops at 100.
  // It only processes 200 items out of 10,000,000!
  const result = Iterator.from(rawData)
    .filter(x => x % 2 === 0)
    .map(x => x * 3)
    .take(100)
    .toArray();

  const endTime = performance.now();
  const endMem = process.memoryUsage().heapUsed;

  return {
    time: (endTime - startTime).toFixed(2),
    memUsedMB: ((endMem - startMem) / 1024 / 1024).toFixed(2),
    resultLength: result.length
  };
}

console.log(`Dataset size: ${DATA_SIZE.toLocaleString()} items\n`);

const arrayStats = runArrayBenchmark();
console.log("--- Array Chaining ---");
console.log(`Execution Time : ${arrayStats.time} ms`);
console.log(`Heap Allocation: ~${arrayStats.memUsedMB} MB\n`);

const iterStats = runIteratorBenchmark();
console.log("--- Iterator Helpers ---");
console.log(`Execution Time : ${iterStats.time} ms`);
console.log(`Heap Allocation: ~${iterStats.memUsedMB} MB`);

```

### Scenario B: Full Array Consumption (e.g., Processing ALL 10M items)

What happens if you process **all** items without early termination (e.g., transforming every single item in a large dataset)?

| Metric (Processing 10M items fully) | Array Chaining                                         | Iterator Helpers                                            |
| ----------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------- |
| **Time Overhead**                   | Slightly Faster (Monomorphic V8 array optimization)    | Slightly Slower (~10-15% function call wrapper overhead)    |
| **Peak Memory Allocation**          | **Extremely High** (2 intermediate 10M arrays created) | **Near Zero** ($O(1)$ memory, items processed sequentially) |

---

## Key Takeaways

1. **Short-Circuiting Operations (`take`, `drop`, `find`, `some`):** Iterator Helpers offer orders of magnitude better execution speed and memory efficiency because they do not process unneeded trailing elements.
2. **Garbage Collector Impact:** Array chaining generates massive temporary arrays that put immediate pressure on V8's Garbage Collector (GC), causing potential frame drops or latency spikes in high-throughput applications. Iterator Helpers create virtually no GC pressure.
3. **Memory Footprint:** Use Iterator Helpers when memory footprint is a concern—especially in Node.js server pipelines processing large CSVs, database streams, or WebSockets.

Explain how to create polyfills or fallback implementations for ES2025 Iterator Helpers

A **polyfill** provides modern functionality to older environments that lack native support.

To polyfill ES2025 Iterator Helpers, you need to implement two key mechanisms:

1. **The `Iterator.from()` static method** to wrap any iterable or iterator object into a custom helper-enabled instance.
2. **The Prototype Methods** (`map`, `filter`, `take`, `drop`, `flatMap`, `toArray`, `find`, `some`, `every`, `reduce`, `forEach`) added to `Iterator.prototype` (or a fallback wrapper class).

---

## 1. Creating a Polyfill Architecture

The cleanest way to build a polyfill is to define a custom class (e.g., `IteratorHelper`) that wraps existing iterators and exposes lazy transformer and terminal methods.

```javascript
// Step 1: polyfill-iterator-helpers.js

(function () {
  // Check if native Iterator.from already exists
  if (typeof Iterator !== "undefined" && typeof Iterator.from === "function") {
    return; // Native support exists; do nothing
  }

  // Fallback wrapper class that implements the Iterator interface
  class HelperIterator {
    constructor(iterator) {
      this._iterator = iterator;
    }

    // Must implement [Symbol.iterator] to return itself
    [Symbol.iterator]() {
      return this;
    }

    // Delegate next() calls to the underlying wrapped iterator
    next(...args) {
      return this._iterator.next(...args);
    }

    // --- LAZY TRANSFORMERS (Return new HelperIterator instances) ---

    map(mapper) {
      const source = this;
      let index = 0;
      return new HelperIterator({
        next() {
          const { value, done } = source.next();
          if (done) return { value: undefined, done: true };
          return { value: mapper(value, index++), done: false };
        }
      });
    }

    filter(predicate) {
      const source = this;
      let index = 0;
      return new HelperIterator({
        next() {
          while (true) {
            const { value, done } = source.next();
            if (done) return { value: undefined, done: true };
            if (predicate(value, index++)) {
              return { value, done: false };
            }
          }
        }
      });
    }

    take(limit) {
      const source = this;
      let remaining = limit;
      return new HelperIterator({
        next() {
          if (remaining <= 0) return { value: undefined, done: true };
          remaining--;
          return source.next();
        }
      });
    }

    drop(limit) {
      const source = this;
      let remaining = limit;
      return new HelperIterator({
        next() {
          while (remaining > 0) {
            const { done } = source.next();
            if (done) return { value: undefined, done: true };
            remaining--;
          }
          return source.next();
        }
      });
    }

    flatMap(mapper) {
      const source = this;
      let currentInner = null;

      return new HelperIterator({
        next() {
          while (true) {
            if (!currentInner) {
              const { value, done } = source.next();
              if (done) return { value: undefined, done: true };
              
              const mapped = mapper(value);
              // Wrap mapped iterable/iterator with Symbol.iterator
              currentInner = mapped[Symbol.iterator] ? mapped[Symbol.iterator]() : mapped;
            }

            const { value, done } = currentInner.next();
            if (!done) return { value, done: false };
            
            currentInner = null; // Inner iterator exhausted; fetch next outer
          }
        }
      });
    }

    // --- TERMINAL EXECUTING METHODS ---

    toArray() {
      const result = [];
      for (const item of this) {
        result.push(item);
      }
      return result;
    }

    find(predicate) {
      let index = 0;
      for (const item of this) {
        if (predicate(item, index++)) return item;
      }
      return undefined;
    }

    some(predicate) {
      let index = 0;
      for (const item of this) {
        if (predicate(item, index++)) return true;
      }
      return false;
    }

    every(predicate) {
      let index = 0;
      for (const item of this) {
        if (!predicate(item, index++)) return false;
      }
      return true;
    }

    reduce(reducer, initialValue) {
      let accumulator = initialValue;
      let isFirst = initialValue === undefined;

      for (const item of this) {
        if (isFirst) {
          accumulator = item;
          isFirst = false;
        } else {
          accumulator = reducer(accumulator, item);
        }
      }
      return accumulator;
    }

    forEach(fn) {
      let index = 0;
      for (const item of this) {
        fn(item, index++);
      }
    }
  }

  // Step 2: Define static Iterator.from() method
  const IteratorPolyfill = {
    from(iterable) {
      if (iterable === null || iterable === undefined) {
        throw new TypeError("Cannot convert undefined or null to iterator");
      }

      // If it already has [Symbol.iterator], extract it
      if (typeof iterable[Symbol.iterator] === "function") {
        return new HelperIterator(iterable[Symbol.iterator]());
      }

      // If it is already an iterator with a .next() method
      if (typeof iterable.next === "function") {
        return new HelperIterator(iterable);
      }

      throw new TypeError("Object is not iterable or an iterator");
    }
  };

  // Attach global Iterator object if missing
  if (typeof globalThis.Iterator === "undefined") {
    globalThis.Iterator = IteratorPolyfill;
  } else {
    globalThis.Iterator.from = IteratorPolyfill.from;
  }
})();

```
