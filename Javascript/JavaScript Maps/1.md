A **JavaScript `Map**` is a built-in collection of key-value pairs introduced in ES6.

Unlike plain JavaScript Objects, a `Map` allows keys of **any data type** (including functions, objects, and primitives), remembers the **original insertion order** of keys, and provides built-in methods for checking size and manipulating entries.

---

## 1. Key Differences: `Map` vs. Plain Object (`{}`)

| Feature                | `Map`                                          | Object (`{}`)                                  |
| ---------------------- | ---------------------------------------------- | ---------------------------------------------- |
| **Key Types**          | Any data type (Primitives, Objects, Functions) | Strings and Symbols only                       |
| **Element Order**      | Maintained strictly by insertion order         | Not guaranteed across all cases                |
| **Size Determination** | Direct property: `map.size`                    | Manual: `Object.keys(obj).length`              |
| **Iterability**        | Directly iterable with `for...of`              | Requires `Object.keys()` / `Object.entries()`  |
| **Performance**        | Optimized for frequent addition & deletion     | Optimized for static/fixed property structures |

---

## 2. Core Map Methods and Properties

### A. Creating, Adding, and Retrieving Entries

```javascript
// Example 1: Creating an empty Map and setting key-value pairs
const userMap = new Map();

userMap.set("name", "Alice");
userMap.set("age", 30);
userMap.set(101, "User ID 101"); // Number key

console.log(userMap.get("name")); // Output: "Alice"
console.log(userMap.get(101));    // Output: "User ID 101"

// Example 2: Initializing Map with an array of key-value pairs
const fruitMap = new Map([
  ["apple", 5],
  ["banana", 2]
]);

console.log(fruitMap.get("apple")); // Output: 5

// Example 3: Checking size and key existence
console.log(fruitMap.size);         // Output: 2
console.log(fruitMap.has("banana")); // Output: true
console.log(fruitMap.has("grape"));  // Output: false

```

### B. Deleting Entries and Clearing

```javascript
const settings = new Map([
  ["theme", "dark"],
  ["notifications", true]
]);

// Example 1: Deleting a key-value pair
settings.delete("notifications");
console.log(settings.has("notifications")); // Output: false

// Example 2: Clearing all entries
settings.clear();
console.log(settings.size); // Output: 0

```

---

## 3. Objects and Functions as Map Keys

Because `Map` supports non-primitive keys, you can use objects or DOM elements directly as unique keys.

```javascript
// Example 1: Using Objects as Map Keys
const user1 = { name: "John" };
const user2 = { name: "Jane" };

const roleMap = new Map();
roleMap.set(user1, "Admin");
roleMap.set(user2, "Editor");

console.log(roleMap.get(user1)); // Output: "Admin"

// Example 2: Functions as Map Keys
const logFunc = () => {};
const funcMetadata = new Map();

funcMetadata.set(logFunc, { executedCount: 10 });
console.log(funcMetadata.get(logFunc)); // Output: { executedCount: 10 }

```

---

## 4. Iterating Over Maps

`Map` instances are native **Iterables** and provide three main iterator methods: `.keys()`, `.values()`, and `.entries()`.

```javascript
const priceMap = new Map([
  ["Laptop", 1200],
  ["Mouse", 25]
]);

// Example 1: Iterating over key-value pairs using for...of
for (const [item, price] of priceMap) {
  console.log(`${item}: $${price}`);
}
// Output: 
// "Laptop: $1200"
// "Mouse: $25"

// Example 2: Using map.forEach()
priceMap.forEach((value, key) => {
  console.log(`${key} -> ${value}`);
});

// Example 3: Extracting keys or values into arrays
const allKeys = [...priceMap.keys()];
console.log(allKeys); // Output: ["Laptop", "Mouse"]

```

---

## 5. Converting Between Objects and Maps

JavaScript provides `Object.entries()` and `Object.fromEntries()` for seamless conversions.

```javascript
// Example 1: Convert Plain Object -> Map
const obj = { a: 1, b: 2 };
const mapFromObj = new Map(Object.entries(obj));

console.log(mapFromObj.get("a")); // Output: 1

// Example 2: Convert Map -> Plain Object
const map = new Map([["x", 10], ["y", 20]]);
const objFromMap = Object.fromEntries(map);

console.log(objFromMap.x); // Output: 10

```

Want to explore JavaScript WeakMap and how it prevents memory leaks with garbage collection?

A **`WeakMap`** is a specialized variant of `Map` designed specifically for **garbage collection efficiency** and **preventing memory leaks**.

While a standard `Map` holds **strong references** to its keys—preventing them from being garbage collected even if they are no longer used anywhere else in your application—a `WeakMap` holds **weak references** to its keys.

---

## 1. Key Differences: `Map` vs. `WeakMap`

| Feature                | `Map`                                                             | `WeakMap`                                                                  |
| ---------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Key Types Allowed**  | Any data type (Primitives, Objects, Functions)                    | **Objects and non-registered Symbols ONLY**                                |
| **Garbage Collection** | Prevents keys from being garbage collected (**Strong**)           | Allows keys to be garbage collected when unreferenced elsewhere (**Weak**) |
| **Iterability**        | Fully iterable (`for...of`, `.keys()`, `.values()`, `.entries()`) | **Not iterable** (No iteration methods)                                    |
| **Size Property**      | Has `.size` property                                              | **No `.size` property**                                                    |
| **Clearing**           | Has `.clear()` method                                             | **No `.clear()` method**                                                   |

---

## 2. The Core Difference: Strong vs. Weak References

### Standard `Map` (Prevents Garbage Collection)

Even if you set an object variable to `null`, as long as that object is used as a key in a standard `Map`, it remains in memory.

```javascript
let user = { name: "Alice" };

const strongMap = new Map();
strongMap.set(user, "User Metadata");

user = null; // Remove external reference

// The object { name: "Alice" } CANNOT be garbage collected
// because strongMap still retains a strong reference to it!
console.log(strongMap.size); // Output: 1

```

---

### `WeakMap` (Allows Automatic Garbage Collection)

When the key object has no other references in memory, JavaScript automatically removes the entry from the `WeakMap` during the next Garbage Collection (GC) cycle.

```javascript
let user = { name: "Alice" };

const weakMap = new WeakMap();
weakMap.set(user, "User Metadata");

console.log(weakMap.has(user)); // Output: true

user = null; // Remove the ONLY external reference to the object

// The { name: "Alice" } object is now eligible for Garbage Collection.
// Once garbage collected, its entry in weakMap will automatically disappear!

```

---

## 3. Real-World Use Cases for `WeakMap`

### Use Case 1: Caching/Memoization Without Memory Leaks

`WeakMap` is ideal for associate-data caching (memoization) where you want cached results to exist **only as long as the input object exists**.

```javascript
const computeCache = new WeakMap();

function processHeavyData(dataObject) {
  if (computeCache.has(dataObject)) {
    console.log("Fetching from cache...");
    return computeCache.get(dataObject);
  }

  console.log("Computing heavy data...");
  const result = { processed: dataObject.value * 2 };
  
  computeCache.set(dataObject, result);
  return result;
}

let item = { value: 100 };

processHeavyData(item); // Output: Computing heavy data...
processHeavyData(item); // Output: Fetching from cache...

// When item is no longer needed:
item = null; 
// The cached result in computeCache is automatically cleaned up by GC!

```

---

### Use Case 2: Storing Private Data for Objects/Classes

Before native private class fields (`#private`), `WeakMap` was the standard pattern for encapsulating private state on instance objects.

```javascript
const privateData = new WeakMap();

class User {
  constructor(name, secretToken) {
    // Save public properties directly on the instance
    this.name = name;
    
    // Save private state in WeakMap keyed by 'this' instance
    privateData.set(this, { secretToken });
  }

  getSecret() {
    return privateData.get(this).secretToken;
  }
}

let alice = new User("Alice", "TOKEN_123");

console.log(alice.name);        // Output: "Alice"
console.log(alice.secretToken); // Output: undefined (Private!)
console.log(alice.getSecret());  // Output: "TOKEN_123"

// When the 'alice' instance is destroyed:
alice = null; 
// Her private data in privateData is garbage collected automatically.

```

---

### Use Case 3: Tracking DOM Element Metadata or Event Listeners

When building UI libraries or web applications, you often need to attach metadata to DOM nodes (e.g., tracking click counts or state) without keeping deleted nodes in memory.

```javascript
const buttonClickTracker = new WeakMap();

function registerButtonClick(buttonElement) {
  const currentCount = buttonClickTracker.get(buttonElement) || 0;
  buttonClickTracker.set(buttonElement, currentCount + 1);
  return currentCount + 1;
}

let btn = document.createElement("button");

console.log(registerButtonClick(btn)); // Output: 1
console.log(registerButtonClick(btn)); // Output: 2

// When the element is removed from the DOM and unreferenced:
btn.remove();
btn = null; 
// The button node and its click count entry are garbage collected together!

```

---

## 4. Why Can't You Iterate Over a `WeakMap`?

`WeakMap` intentionally exposes **no `.keys()`, `.values()`, `.entries()`, or `.size` properties**.

This is because Garbage Collection in JavaScript JavaScript engines (like V8) runs non-deterministically in the background. If iteration were allowed, the contents or size of the `WeakMap` could unpredictably change from one instant to the next depending on whether garbage collection just ran—leading to unpredictable bug behavior.

---

## Summary Matrix

| Need                                                                  | Recommended Structure |
| --------------------------------------------------------------------- | --------------------- |
| Need to store keys that are primitives (strings, numbers)             | **`Map`**             |
| Need to iterate through all key-value entries                         | **`Map`**             |
| Need to track total size or clear all items at once                   | **`Map`**             |
| Need to attach auxiliary data to objects that come and go dynamically | **`WeakMap`**         |
| Need to store private object properties or instance state             | **`WeakMap`**         |

Explain JavaScript WeakSet vs Set with examples and memory garbage collection use cases

A **`WeakSet`** is a specialized, collection-like data structure in JavaScript designed for **garbage collection efficiency** and **memory leak prevention**.

Just as a `WeakMap` compares to a standard `Map`, a `WeakSet` differs from a standard `Set` primarily in how it references stored items: a `Set` holds **strong references** to its values, whereas a `WeakSet` holds **weak references**.

---

## 1. Key Differences: `Set` vs. `WeakSet`

| Feature                 | `Set`                                                             | `WeakSet`                                                       |
| ----------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------- |
| **Allowed Value Types** | Any data type (Primitives, Objects, Functions)                    | **Objects and non-registered Symbols ONLY**                     |
| **Garbage Collection**  | Holds **strong references** (Prevents garbage collection)         | Holds **weak references** (Allows automatic garbage collection) |
| **Iterability**         | Fully iterable (`for...of`, `.keys()`, `.values()`, `.forEach()`) | **Not iterable** (No iteration methods)                         |
| **Size Property**       | Has `.size` property                                              | **No `.size` property**                                         |
| **Clearing**            | Has `.clear()` method                                             | **No `.clear()` method**                                        |
| **Supported Methods**   | `.add()`, `.has()`, `.delete()`, `.clear()`, iterators            | `.add()`, `.has()`, `.delete()` only                            |

---

## 2. Strong vs. Weak References

### Standard `Set` (Prevents Garbage Collection)

If an object is placed inside a standard `Set`, it will stay in memory as long as the `Set` itself exists, even if you clean up all other external references to that object.

```javascript
let user = { name: "Alice" };

const strongSet = new Set();
strongSet.add(user);

user = null; // Remove external reference

// The object { name: "Alice" } CANNOT be garbage collected
// because strongSet still retains a strong reference to it!
console.log(strongSet.size); // Output: 1

```

---

### `WeakSet` (Allows Automatic Garbage Collection)

When an object stored in a `WeakSet` has no other remaining references anywhere else in your application, the JavaScript engine's Garbage Collector (GC) automatically frees that object's memory and removes it from the `WeakSet`.

```javascript
let user = { name: "Alice" };

const weakSet = new WeakSet();
weakSet.add(user);

console.log(weakSet.has(user)); // Output: true

user = null; // Remove the ONLY external reference to the object

// The { name: "Alice" } object is now eligible for Garbage Collection.
// Once GC runs, its entry in weakSet automatically disappears!

```

---

## 3. Real-World Use Cases for `WeakSet`

### Use Case 1: Tagging or Tracking Objects (Without Modifying Them)

`WeakSet` is ideal for tracking state or membership flags on objects without mutating the original object structure or leaking memory when those objects are destroyed.

```javascript
// Track which DOM nodes or objects have already been processed
const processedObjects = new WeakSet();

function processItem(item) {
  if (processedObjects.has(item)) {
    console.log("Item already processed! Skipping...");
    return;
  }

  // Do processing work...
  console.log("Processing item:", item.id);

  // Mark as processed
  processedObjects.add(item);
}

let itemA = { id: "A" };
let itemB = { id: "B" };

processItem(itemA); // Output: "Processing item: A"
processItem(itemA); // Output: "Item already processed! Skipping..."

// When itemA is no longer needed:
itemA = null; 
// itemA is garbage collected automatically, cleaning up the WeakSet entry!

```

---

### Use Case 2: Guarding Class Methods (Ensuring Invocations on Valid Instances)

`WeakSet` can be used to ensure that internal helper methods are only called on instances created by a specific constructor, preventing invalid execution via `call` or `apply`.

```javascript
const validInstances = new WeakSet();

class SecureClient {
  constructor() {
    validInstances.add(this);
  }

  performSensitiveOperation() {
    if (!validInstances.has(this)) {
      throw new TypeError("Method invoked on an invalid or forged instance!");
    }
    console.log("Sensitive operation executed successfully.");
  }
}

const client = new SecureClient();
client.performSensitiveOperation(); 
// Output: "Sensitive operation executed successfully."

// Attempting to invoke method on an arbitrary object fails safely:
const fakeClient = {};
try {
  client.performSensitiveOperation.call(fakeClient);
} catch (err) {
  console.error(err.message); 
  // Output: "Method invoked on an invalid or forged instance!"
}

```

---

### Use Case 3: Detecting Circular References in Data Structures

When serializing or walking deep object graphs, a `WeakSet` helps keep track of visited nodes to prevent infinite recursion loops caused by circular references.

```javascript
function detectCircularReference(obj, visited = new WeakSet()) {
  if (typeof obj !== "object" || obj === null) {
    return false;
  }

  if (visited.has(obj)) {
    return true; // Circular reference detected!
  }

  visited.add(obj);

  for (const key of Object.keys(obj)) {
    if (detectCircularReference(obj[key], visited)) {
      return true;
    }
  }

  return false;
}

const parent = { name: "Parent" };
const child = { name: "Child", parent: parent };
parent.child = child; // Circular loop!

console.log(detectCircularReference(parent)); // Output: true

```

---

## 4. Why Can't You Iterate Over a `WeakSet`?

`WeakSet` intentionally lacks methods like `.values()`, `.keys()`, `.forEach()`, or a `.size` property.

Because garbage collection in JavaScript runs non-deterministically in the background, allowing iteration over a `WeakSet` would yield unpredictable results depending on whether the garbage collector executed a sweep right before reading the set.

| Need to convert collected values into an Array (`[...set]`)             | **`Set`**             |
| Need to tag or track objects without modifying them                     | **`WeakSet`**         |

## 2. Creating & Modifying a `Map`

### Option A: Initialize empty and populate with `.set()`

```javascript
// 1. Create an empty Map
const fruits = new Map();

// 2. Add key-value pairs
fruits.set("apples", 500);
fruits.set("bananas", 300);
fruits.set("oranges", 200);

// 3. Update existing value (set overwrites matching key)
fruits.set("apples", 200); 

// 4. Retrieve value
console.log(fruits.get("apples")); // Output: 200

```

### Option B: Pass a 2D Array to `new Map()`

```javascript
// Initialize directly with an array of [key, value] pairs
const fruits = new Map([

  ["bananas", 300],
  ["oranges", 200]
]);

console.log(fruits.get("bananas")); // Output: 300

```

## 3. Type Checking: `typeof` & `instanceof`

In JavaScript, `Map` is an instance of the global `Object` type:

```javascript
const fruits = new Map([["apples", 500]]);

console.log(typeof fruits);       // Output: "object"
console.log(fruits instanceof Map); // Output: true

```

Here is the complete reference of all built-in methods, properties, and static utilities for JavaScript `Map` objects.

---

## 1. Instance Property

### `size`

Returns the total count of key-value pairs in the Map.

```javascript
const map = new Map([["a", 1], ["b", 2]]);
console.log(map.size); // Output: 2

```

---

## 2. Core Mutation & Retrieval Methods

### `set(key, value)`

Adds or updates a key-value pair. Returns the Map object (allows chaining).

```javascript
const map = new Map();
map.set("name", "Alice").set("role", "Admin");

```

### `get(key)`

Returns the value associated with the specified key, or `undefined` if the key doesn't exist.

```javascript
console.log(map.get("name")); // Output: "Alice"

```

### `has(key)`

Returns a boolean indicating whether an entry with the specified key exists.

```javascript
console.log(map.has("role")); // Output: true

```

### `delete(key)`

Removes the specified key-value pair. Returns `true` if removed, or `false` if not found.

```javascript
map.delete("role"); // Output: true

```

### `clear()`

Removes all key-value pairs from the Map.

```javascript
map.clear();
console.log(map.size); // Output: 0

```

---

## 3. Iteration Methods

### `keys()`

Returns an iterator of all keys in insertion order.

```javascript
const fruits = new Map([["apple", 5], ["banana", 2]]);
console.log([...fruits.keys()]); // Output: ["apple", "banana"]

```

### `values()`

Returns an iterator of all values in insertion order.

```javascript
console.log([...fruits.values()]); // Output: [5, 2]

```

### `entries()`

Returns an iterator of `[key, value]` pairs in insertion order.

```javascript
for (const [key, value] of fruits.entries()) {
  console.log(`${key}: ${value}`);
}

```

### `forEach(callbackFn [, thisArg])`

Executes a callback function once for each key-value pair `(value, key, map)`.

```javascript
fruits.forEach((value, key) => {
  console.log(`${key} -> ${value}`);
});

```

---

## 4. Static Utility Methods

### `Map.groupBy(items, callbackFn)`

Groups elements from an iterable into a new Map based on key values returned by a callback.

```javascript
const inventory = [
  { name: "Bananas", type: "fruit" },
  { name: "Carrots", type: "vegetable" },
  { name: "Apples", type: "fruit" }
];

const grouped = Map.groupBy(inventory, item => item.type);
console.log(grouped.get("fruit"));
// Output: [{ name: "Bananas", type: "fruit" }, { name: "Apples", type: "fruit" }]

```

### Interoperating with Objects

```javascript
// Object to Map
const obj = { x: 10, y: 20 };
const mapFromObj = new Map(Object.entries(obj));

// Map to Object
const objFromMap = Object.fromEntries(mapFromObj);

```
