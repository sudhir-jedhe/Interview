Here is a complete, categorical reference for all built-in methods and properties of the JavaScript **`Map`** object, with concrete code examples for each.

---

## 1. Instance Properties

### `Map.prototype.size`

*Returns the total number of key-value pairs currently in the Map.*

```javascript
const map = new Map([["a", 1], ["b", 2]]);

console.log(map.size); 
// Output: 2

```

---

## 2. Core Mutation & Access Methods

### `set(key, value)`

*Adds or updates an entry with a specified key and value. Returns the Map object (allows chaining).*

```javascript
const userRoles = new Map();

// Single set
userRoles.set("alice", "Admin");

// Chained set calls
userRoles.set("bob", "Editor").set("charlie", "Viewer");

console.log(userRoles.get("alice")); 
// Output: "Admin"

```

### `get(key)`

*Returns the value associated with the key, or `undefined` if the key does not exist.*

```javascript
const map = new Map([["theme", "dark"]]);

console.log(map.get("theme"));   // Output: "dark"
console.log(map.get("sidebar")); // Output: undefined

```

### `has(key)`

*Returns a boolean indicating whether an entry with the specified key exists in the Map.*

```javascript
const map = new Map([["id", 101]]);

console.log(map.has("id"));     // Output: true
console.log(map.has("status")); // Output: false

```

### `delete(key)`

*Removes the specified key-value pair from the Map. Returns `true` if an element existed and was removed, or `false` otherwise.*

```javascript
const map = new Map([["a", 1], ["b", 2]]);

console.log(map.delete("a")); // Output: true
console.log(map.delete("z")); // Output: false (key did not exist)
console.log(map.has("a"));    // Output: false

```

### `clear()`

*Removes all key-value pairs from the Map object.*

```javascript
const map = new Map([["x", 10], ["y", 20]]);

map.clear();

console.log(map.size); // Output: 0

```

---

## 3. Iteration & Traversal Methods

### `forEach(callbackFn [, thisArg])`

*Executes a provided callback function once for each key-value pair in insertion order.*
*(Note the signature order: `(value, key, map)`).*

```javascript
const map = new Map([
  ["apple", 5],
  ["banana", 2]
]);

map.forEach((value, key) => {
  console.log(`${key}: ${value}`);
});
// Output:
// "apple: 5"
// "banana: 2"

```

### `keys()`

*Returns a new Iterator object that contains the **keys** for each element in insertion order.*

```javascript
const map = new Map([["x", 10], ["y", 20]]);
const keyIterator = map.keys();

console.log(keyIterator.next().value); // Output: "x"
console.log(keyIterator.next().value); // Output: "y"

// Convert to Array using spread operator
console.log([...map.keys()]); 
// Output: ["x", "y"]

```

### `values()`

*Returns a new Iterator object that contains the **values** for each element in insertion order.*

```javascript
const map = new Map([["x", 10], ["y", 20]]);

console.log([...map.values()]); 
// Output: [10, 20]

```

### `entries()`

*Returns a new Iterator object that contains the `[key, value]` pairs for each element in insertion order.*

```javascript
const map = new Map([["a", 1], ["b", 2]]);
const entryIterator = map.entries();

console.log(entryIterator.next().value); 
// Output: ["a", 1]

// Directly usable in for...of loops
for (const [key, val] of map.entries()) {
  console.log(key, val);
}

```

### `[Symbol.iterator]()`

*The default iterator for `Map`. By default, iterating over a Map returns `[key, value]` pairs (same as `map.entries()` point-for-point).*

```javascript
const map = new Map([["a", 1], ["b", 2]]);

// Directly loop over map without calling .entries()
for (const [key, value] of map) {
  console.log(key, value);
}

```

---

## 4. Static Utility Methods

### `Object.fromEntries(map)`

*Converts a `Map` (or any iterable of key-value pairs) into a plain JavaScript Object.*

```javascript
const map = new Map([
  ["name", "Alice"],
  ["role", "Developer"]
]);

const obj = Object.fromEntries(map);

console.log(obj); 
// Output: { name: "Alice", role: "Developer" }

```

### `Object.entries(obj)`

*Converts a plain JavaScript Object into an Array of `[key, value]` pairs, making it easy to pass directly into `new Map()`.*

```javascript
const obj = { x: 100, y: 200 };

const map = new Map(Object.entries(obj));

console.log(map.get("x")); // Output: 100

```

---

## 5. ES2025 Map Grouping Methods

### `Map.groupBy(items, callbackFn)`

*A static method introduced in ES2024/ES2025 that groups elements from an iterable into a new `Map` instance based on keys returned by a testing function.*

```javascript
const products = [
  { name: "Apple", category: "Fruit" },
  { name: "Carrot", category: "Vegetable" },
  { name: "Banana", category: "Fruit" }
];

// Groups items into a Map keyed by category
const groupedMap = Map.groupBy(products, product => product.category);

console.log(groupedMap.get("Fruit"));
// Output: [ { name: "Apple", category: "Fruit" }, { name: "Banana", category: "Fruit" } ]

```

Explain JavaScript Set methods with examples and compare Set vs Map

A **`Set`** in JavaScript is a built-in collection of **unique values**. Unlike an Array, a `Set` cannot contain duplicate elements—if you attempt to add an existing value, the operation is ignored.

---

## 1. Complete `Set` Methods Reference

Here is a breakdown of all built-in methods and properties of the `Set` object.

### A. Core Mutation & Access Methods

#### `size` (Property)

*Returns the total number of unique elements in the Set.*

```javascript
const numbers = new Set([1, 2, 3, 3, 3]);

console.log(numbers.size); 
// Output: 3 (duplicates were ignored)

```

#### `add(value)`

*Appends a new value to the Set. Returns the Set instance (allows method chaining).*

```javascript
const colors = new Set();

// Method chaining
colors.add("red").add("green").add("red"); // Duplicate "red" ignored

console.log(colors.size); // Output: 2

```

#### `has(value)`

*Returns `true` if an element with the specified value exists in the Set.*

```javascript
const set = new Set(["apple", "banana"]);

console.log(set.has("apple"));  // Output: true
console.log(set.has("orange")); // Output: false

```

#### `delete(value)`

*Removes a specified value from the Set. Returns `true` if the element existed and was removed, or `false` otherwise.*

```javascript
const set = new Set([10, 20, 30]);

console.log(set.delete(20)); // Output: true
console.log(set.delete(99)); // Output: false
console.log(set.has(20));    // Output: false

```

#### `clear()`

*Removes all elements from the Set.*

```javascript
const set = new Set(["a", "b", "c"]);

set.clear();

console.log(set.size); // Output: 0

```

---

### B. Iteration & Traversal Methods

#### `forEach(callbackFn [, thisArg])`

*Executes a function once for each element in insertion order.*
*(Note: To maintain compatibility with `Map.prototype.forEach`, the callback receives `(value, key, set)` where `value` and `key` are identical).*

```javascript
const set = new Set(["x", "y"]);

set.forEach((value, key) => {
  console.log(`${key} -> ${value}`);
});
// Output:
// "x -> x"
// "y -> y"

```

#### `values()` / `keys()`

*Returns a new Iterator containing the values in insertion order. In Sets, `.keys()` is an alias for `.values()`.*

```javascript
const set = new Set(["A", "B"]);

const iter = set.values();
console.log(iter.next().value); // Output: "A"

// Convert Set to Array using spread operator
console.log([...set.values()]); // Output: ["A", "B"]

```

#### `entries()`

*Returns an Iterator containing `[value, value]` pairs for each element in insertion order.*

```javascript
const set = new Set(["alpha", "beta"]);

for (const [v1, v2] of set.entries()) {
  console.log(v1, v2);
}
// Output:
// "alpha alpha"
// "beta beta"

```

---

### C. Standard Set Operations (ES2024 / Modern Engine Standard)

Modern JavaScript engines include built-in set operation methods for combining and comparing sets:

```javascript
const setA = new Set([1, 2, 3]);
const setB = new Set([3, 4, 5]);

// 1. Union: Elements in setA OR setB
console.log([...setA.union(setB)]); 
// Output: [1, 2, 3, 4, 5]

// 2. Intersection: Elements in BOTH setA AND setB
console.log([...setA.intersection(setB)]); 
// Output: [3]

// 3. Difference: Elements in setA BUT NOT in setB
console.log([...setA.difference(setB)]); 
// Output: [1, 2]

// 4. Symmetric Difference: Elements in setA or setB, but NOT both
console.log([...setA.symmetricDifference(setB)]); 
// Output: [1, 2, 4, 5]

// 5. Subset / Superset checks
console.log(new Set([1, 2]).isSubsetOf(setA));   // Output: true
console.log(setA.isSupersetOf(new Set([1, 2]))); // Output: true

```

---

## 2. Detailed Comparison: `Set` vs `Map`

| Feature                   | `Set`                                | `Map`                                            |
| ------------------------- | ------------------------------------ | ------------------------------------------------ |
| **Data Structure**        | Collection of **unique values**      | Collection of **key-value pairs**                |
| **Duplicates**            | Disallows duplicate values           | Disallows duplicate **keys** (values can repeat) |
| **Primary Method to Add** | `.add(value)`                        | `.set(key, value)`                               |
| **Primary Method to Get** | `.has(value)` (Returns boolean)      | `.get(key)` (Returns value)                      |
| **Iteration Element**     | Yields `value`                       | Yields `[key, value]` tuple                      |
| **Primary Use Case**      | Deduplication and membership testing | Lookups, dictionaries, key-based indexing        |

---

## 3. When to Use Which?

### Use a `Set` when

* **Deduplicating Arrays:** Converting an array with duplicate values into a unique collection (`[...new Set(array)]`).
* **Fast Membership Checks:** Checking whether an element exists (`set.has(item)`) runs in $O(1)$ time, whereas checking an array (`array.includes(item)`) runs in $O(N)$ time.
* **Tracking Unique Visitor / Action IDs:** Keeping track of unique user IDs or processed items during execution.

### Use a `Map` when

* **Associating Data:** You need to pair keys with values (e.g., mapping User IDs to User Objects).
* **Non-String Keys:** You need keys that are non-string types (Objects, Functions, Numbers, DOM nodes).
* **Frequent Dynamic Modifications:** Performing frequent key additions and deletions where dictionary performance is critical.

Show a benchmark performance comparison between Array search methods and Set.has()

To evaluate search efficiency, we compare **Array search methods** (`.includes()`, `.indexOf()`, `.find()`) against **`Set.prototype.has()`**.

The fundamental difference lies in their **algorithmic time complexity**:

* **Array Search Methods:** $O(N)$ linear time. The engine must scan array elements sequentially from index `0` until it finds a match or reaches the end.
* **`Set.has()`:** $O(1)$ constant time. Sets use hash tables internally, computing a hash code to jump directly to the memory location of the value.

---

## 1. Benchmarking Array Search vs. `Set.has()`

Below is a benchmark script using Node.js (`perf_hooks`) testing search speed on datasets ranging from **1,000 items** to **10,000,000 items**.

### The Task

Find an item located at the **very end of the collection** (worst-case scenario for sequential scanning).

```javascript
// search-benchmark.js
const { performance } = require('perf_hooks');

function runBenchmark(size) {
  console.log(`\n======================================================`);
  console.log(` BENCHMARK DATASET SIZE: ${size.toLocaleString()} ITEMS`);
  console.log(`======================================================`);

  // Generate dataset
  const targetItem = `item_${size}`;
  const rawArray = Array.from({ length: size }, (_, i) => `item_${i + 1}`);
  const rawSet = new Set(rawArray);

  // 1. Benchmark Array.includes()
  const startArray = performance.now();
  const foundInArray = rawArray.includes(targetItem);
  const endArray = performance.now();
  const arrayTime = (endArray - startArray).toFixed(4);

  // 2. Benchmark Set.has()
  const startSet = performance.now();
  const foundInSet = rawSet.has(targetItem);
  const endSet = performance.now();
  const setTime = (endSet - startSet).toFixed(4);

  // Calculate speed difference ratio
  const ratio = (arrayTime / setTime).toFixed(1);

  console.log(`Array.includes() : ${arrayTime} ms (Found: ${foundInArray})`);
  console.log(`Set.has()        : ${setTime} ms (Found: ${foundInSet})`);
  console.log(`RESULT           : Set.has() is ~${ratio}x FASTER`);
}

// Run benchmarks across different collection sizes
[1000, 100000, 1000000, 10000000].forEach(runBenchmark);

```

## 4. Construction Cost Consideration

While `Set.has()` lookups are vastly superior, creating a `Set` from an Array incurs an initial one-time conversion overhead of $O(N)$ time and memory:

```javascript
// Creation overhead: O(N)
const mySet = new Set(largeArray); 

```

### When to use `Set.has()` over Array methods

| Scenario                                                   | Recommended Choice     | Reason                                                                          |
| ---------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------- |
| Single lookup in a small array ($<100$ items)              | **`Array.includes()`** | The overhead of building a `Set` exceeds the tiny speed gain.                   |
| Repeated lookups ($>5$ checks) on medium/large collections | **`Set.has()`**        | Converting once to a `Set` pays off almost immediately across multiple lookups. |
| Large dynamic datasets requiring existence checks          | **`Set.has()`**        | Prevents $O(N^2)$ nested lookup bottlenecks.                                    |

## 5. Avoiding the Common $O(N^2)$ Pitfall

A common performance bug occurs when calling `Array.includes()` inside an array loop or `.filter()` callback:

```javascript
// BAD: O(N * M) Quadratic complexity
const allowedIds = [/* 100,000 IDs */];
const users = [/* 100,000 Users */];

// Takes several seconds or freezes the UI!
const filtered = users.filter(u => allowedIds.includes(u.id));

// GOOD: O(N + M) Linear complexity
const allowedSet = new Set(allowedIds); // O(N) build time

// Executes in a few milliseconds!
const filteredFast = users.filter(u => allowedSet.has(u.id)); // O(M) time

```

Explain JavaScript WeakSet vs WeakMap with garbage collection examples
Both **`WeakSet`** and **`WeakMap`** are specialized, collections-like data structures in JavaScript built specifically to **prevent memory leaks** through **weak references**.

The fundamental rule for both is simple: if an object stored inside a `WeakSet` or used as a key in a `WeakMap` has **no other references remaining anywhere else in your code**, the JavaScript Garbage Collector (GC) will automatically clear it from memory—and remove its entry from the weak collection.

---

## 1. Direct Comparison

| Feature                     | `WeakMap`                                                        | `WeakSet`                                              |
| --------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------ |
| **Data Structure**          | Collection of **key-value pairs**                                | Collection of **unique values**                        |
| **Weakly Referenced Items** | The **keys** only (values are strongly held *through* the key)   | The **values** themselves                              |
| **Allowed Keys / Values**   | Keys must be **Objects** (or non-registered Symbols)             | Values must be **Objects** (or non-registered Symbols) |
| **Primary Methods**         | `.set(key, val)`, `.get(key)`, `.has(key)`, `.delete(key)`       | `.add(val)`, `.has(val)`, `.delete(val)`               |
| **Iterability**             | **Not iterable** (No `for...of`, `.keys()`, `.values()`)         | **Not iterable** (No `for...of`, `.values()`)          |
| **Size / Clearing**         | No `.size` property, no `.clear()` method                        | No `.size` property, no `.clear()` method              |
| **Primary Use Case**        | Associating extra metadata to an object or storing private state | Tracking/tagging objects or guarding method execution  |

---

## 2. Garbage Collection in Action

To understand how garbage collection works with weak structures, contrast them with their strong counterparts (`Map` and `Set`).

### A. Garbage Collection with `WeakMap`

In a standard `Map`, keeping an object as a key creates a **strong reference**. In a `WeakMap`, the key reference is **weak**.

```javascript
// --- 1. Standard Map (Memory Leak Potential) ---
let userObj1 = { name: "Alice" };
const strongMap = new Map();

strongMap.set(userObj1, { role: "Admin" });
userObj1 = null; 

// { name: "Alice" } CANNOT be garbage collected because strongMap holds a strong reference.
console.log(strongMap.size); // Output: 1


// --- 2. WeakMap (Auto Garbage Collection) ---
let userObj2 = { name: "Bob" };
const weakMap = new WeakMap();

weakMap.set(userObj2, { role: "Editor" });
console.log(weakMap.has(userObj2)); // Output: true

userObj2 = null; 

// The object { name: "Bob" } now has zero strong references.
// The engine's Garbage Collector will free { name: "Bob" } from memory,
// and its entry in weakMap will automatically disappear!

```

---

### B. Garbage Collection with `WeakSet`

Similarly, a standard `Set` holds strong references to its elements, while a `WeakSet` holds weak references.

```javascript
// --- 1. Standard Set (Prevents Cleanup) ---
let element1 = { id: "button_1" };
const strongSet = new Set();

strongSet.add(element1);
element1 = null; 

// element1 remains in memory because strongSet still points to it.


// --- 2. WeakSet (Auto Garbage Collection) ---
let element2 = { id: "button_2" };
const weakSet = new WeakSet();

weakSet.add(element2);
console.log(weakSet.has(element2)); // Output: true

element2 = null; 

// { id: "button_2" } is now eligible for Garbage Collection.
// Once GC runs, the element automatically disappears from weakSet!

```

---

## 3. Real-World Use Cases

### Practical Use Case for `WeakMap`: Metadata Caching

Attach temporary calculation or metadata results to an object without altering the object or causing a memory leak if the object is deleted.

```javascript
const userCache = new WeakMap();

function getProcessedUserData(user) {
  if (userCache.has(user)) {
    console.log("Fetching from WeakMap cache...");
    return userCache.get(user);
  }

  console.log("Processing user data...");
  const processed = { fullName: `${user.firstName} ${user.lastName}`, id: user.id };
  userCache.set(user, processed);
  return processed;
}

let activeUser = { id: 101, firstName: "Jane", lastName: "Doe" };

getProcessedUserData(activeUser); // Output: Processing user data...
getProcessedUserData(activeUser); // Output: Fetching from WeakMap cache...

// When activeUser logs out or is dereferenced:
activeUser = null; 
// The cached object in userCache is safely garbage collected.

```

---

### Practical Use Case for `WeakSet`: Object Tagging & Duplicate Prevention

Mark objects as "visited" or "processed" without mutating them or keeping track of deleted nodes.

```javascript
const processedRequests = new WeakSet();

function handleApiRequest(requestObject) {
  if (processedRequests.has(requestObject)) {
    console.log("Duplicate request detected. Skipping...");
    return;
  }

  // Process request...
  console.log("Processing request:", requestObject.endpoint);

  // Tag request object as processed
  processedRequests.add(requestObject);
}

let req = { endpoint: "/api/checkout", payload: { item: 1 } };

handleApiRequest(req); // Output: Processing request: /api/checkout
handleApiRequest(req); // Output: Duplicate request detected. Skipping...

// Once request handling lifecycle completes:
req = null; 
// Cleaned up from memory and WeakSet automatically.

```

---

## 4. Why Are They Not Iterable?

Neither `WeakMap` nor `WeakSet` exposes `.keys()`, `.values()`, `.forEach()`, or `.size`.

Garbage Collection in JavaScript engines (like V8) runs **non-deterministically** in the background. If iteration were permitted, reading the contents or size of a `WeakMap` or `WeakSet` could yield different results from one millisecond to the next depending on whether the Garbage Collector ran a sweep, leading to unpredictable software bugs.
