To understand how JavaScript actually runs under the hood, we need to look at three key actors working together in harmony: **the Engine**, **the Compiler**, and **Scope**.

---

## The Three Main Actors

1. **The Engine (e.g., V8, SpiderMonkey):** The manager responsible for start-to-finish compilation and execution of JavaScript code.
2. **The Compiler:** The worker that handles Lexing/Tokenization, Parsing (AST generation), and translating code into Bytecode or Native Machine Code.
3. **Scope:** The record-keeper that collects and maintains a look-up list of all declared identifiers (variables, functions) and enforces strict rules on how they can be accessed.

---

## 1. Declarations vs. Assignments (The Two-Pass System)

JavaScript processes code in two distinct phases: **Compilation** (Pass 1) and **Execution** (Pass 2).

### Pass 1: Compilation Phase

Before any code executes, the **Compiler** parses the code line by line and registers all variable and function declarations with **Scope**.

* During this pass, executable code (like assignments or function calls) is ignored.
* Only keywords like `var`, `let`, `const`, `function`, and `class` trigger Scope registration.

### Pass 2: Execution Phase

Once compilation is complete, the **Engine** steps in to execute the code. Whenever it encounters a variable, it asks **Scope** to retrieve or assign it.

---

## 2. LHS vs. RHS Lookups

When the Engine encounters a variable during execution, it asks Scope for a lookup. There are two types of lookups:

* **LHS (Left-Hand Side):** *"Find the container variable so I can assign a value to it."*
* **RHS (Right-Hand Side):** *"Find the value stored inside this variable so I can use it."*

```javascript
let a = 2; // LHS lookup for 'a' (Target of assignment)
console.log(a); // RHS lookup for 'a' (Source of value)

```

---

## 3. Step-by-Step Execution Example

Let's trace how the Engine, Compiler, and Scope interact with a simple snippet:

```javascript
function foo(a) {
  var b = a;
  return a + b;
}

var c = foo(2);

```

### Phase 1: Compilation (Scope Setup)

1. **Compiler:** *"Scope, I see `var c`. Have you heard of `c`?"*
**Scope:** *"No, I'll register `c` in the Global Scope."*
2. **Compiler:** *"Scope, I see `function foo`. Have you heard of `foo`?"*
**Scope:** *"No, I'll register `foo` in the Global Scope."*
3. **Compiler:** *"Now inside `foo`: Scope, I see parameter `a` and `var b`. Have you heard of them?"*
**Scope:** *"No, I'll register `a` and `b` in `foo`'s local scope."*

---

### Phase 2: Execution (Runtime Engine)

1. **Engine:** *"Global Scope, I need an RHS lookup for `foo`. Do you have it?"*
**Scope:** *"Yes, `foo` is a function."*
2. **Engine:** *"I'm invoking `foo(2)`. Local Scope of `foo`, I need an LHS lookup for parameter `a` to assign `2`."*
**Scope:** *"Found `a`."* (`a = 2`)
3. **Engine:** *"Local Scope of `foo`, I need an LHS lookup for `b`."*
**Scope:** *"Found `b`."*
4. **Engine:** *"I need an RHS lookup for `a` to get its value."*
**Scope:** *"It's `2`."*
*(Engine assigns `2` to `b`)*
5. **Engine:** *"I need RHS lookups for `a` and `b` to calculate `a + b`."*
**Scope:** *"Both are `2`."*
*(Engine computes `4`)*
6. **Engine:** *"Global Scope, I need an LHS lookup for `c` to assign the result `4`."*
**Scope:** *"Found `c`."* (`c = 4`)

---

## 4. Scope Chain & Error Handling

If a variable isn't found in the current scope, the Engine asks Scope to check the **outer parent scope**, walking all the way up to the **Global Scope**.

```javascript
function outer() {
  function inner() {
    console.log(x); // Looks in inner -> outer -> global
  }
  inner();
}

```

```
[ Inner Scope ] ──(not found)──► [ Outer Scope ] ──(not found)──► [ Global Scope ]

```

### What Happens When Lookups Fail?

| Lookup Type | Fail Condition                                                        | Result (Non-Strict)                                         | Result (Strict Mode)               |
| ----------- | --------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------- |
| **RHS**     | Variable doesn't exist anywhere in the scope chain                    | `ReferenceError: x is not defined`                          | `ReferenceError: x is not defined` |
| **LHS**     | Target variable doesn't exist anywhere in the scope chain             | **Creates global variable automatically** (implicit global) | `ReferenceError: x is not defined` |
| **RHS**     | Variable exists, but executing an illegal action (e.g., `null.foo()`) | `TypeError`                                                 | `TypeError`                        |

---

## 5. Modern JIT Compilation Pipeline (V8 Engine)

Modern engines combine interpreted bytecodes with just-in-time compilation to execute JavaScript efficiently:

```
Source Code
    │
    ▼
  Parser ──► Abstract Syntax Tree (AST)
    │
    ▼
Ignition (Interpreter) ──► Generates Bytecode (Runs immediately)
    │
    ▼ (Monitors "Hot Code")
TurboFan (JIT Compiler) ──► Generates Optimized Machine Code
    │
    ▼ (If assumptions fail, e.g. types change)
Deoptimization ──► Falls back to Bytecode

```

1. **Ignition (Interpreter):** Parses AST into bytecode for fast initial startup.
2. **Profiler:** Monitors code execution. If a function is called repeatedly ("hot code"), it gets sent to TurboFan.
3. **TurboFan (JIT Compiler):** Compiles hot bytecode into direct native **CPU Machine Code** based on type profiling.
4. **Deoptimization:** If runtime types unexpectedly change (e.g., passing a string into an optimized integer addition function), TurboFan discards the machine code and falls back to Ignition's bytecode.
