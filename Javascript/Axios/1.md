**Axios** is a popular, Promise-based HTTP client for JavaScript that runs both in the browser and in Node.js environments. It provides a clean, unified API for making asynchronous network requests, handling response transformation, and managing global request configurations.

---

## 1. Key Features & Advantages

* **Automatic JSON Data Transformation:** Parses incoming JSON responses into JavaScript objects automatically (`response.data`).
* **HTTP Error Handling:** Rejects the promise automatically for non-2xx status codes (like 404, 401, or 500).
* **Interceptors:** Intercept and modify requests or responses before they are handled (`.then` / `.catch`).
* **Built-in Progress Tracking:** Easily monitor real-time upload and download progress (`onUploadProgress` and `onDownloadProgress`).
* **Request Cancellation:** Abort in-flight requests using `AbortController`.
* **Cross-Environment:** Uses `XMLHttpRequest` or `fetch` in the browser and native `http` modules in Node.js under the hood.

### Making a `GET` Request

```javascript
import axios from "axios";

async function fetchUser() {
  try {
    const response = await axios.get("https://api.example.com/users/1");
    // Access response data directly (already parsed JSON)
    console.log(response.data);
    console.log(response.status); // e.g., 200
  } catch (error) {
    // Automatically triggers on 4xx/5xx status or network errors
    if (error.response) {
      console.error(`Server error: ${error.response.status}`);
    } else {
      console.error("Network or connection error:", error.message);
    }
  }
}

```

### Making a `POST` Request

```javascript
async function createUser() {
  try {
    const payload = { name: "Alice", role: "Developer" };
    
    const response = await axios.post("https://api.example.com/users", payload, {
      headers: {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    });

    console.log("User created:", response.data);
  } catch (error) {
    console.error("Error creating user:", error);
  }
}

```

## 4. Axios Interceptors (Middleware Pattern)

Interceptors allow you to run code or transform requests/responses before they are executed.

```javascript
import apiClient from "./client";

// 1. Request Interceptor (e.g. Automatically attach Auth Tokens)
apiClient.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem("auth_token");
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)

// 2. Response Interceptor (e.g. Global Error Handling / Refresh Token)
apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      console.warn("Unauthorized! Redirecting to login...");
      window.location.href = "/login";
    }
    return Promise.reject(error);
  }
);
```

| Feature             | Axios                              | Native Fetch                                     |
| ------------------- | ---------------------------------- | ------------------------------------------------ |

## 1. Setting Request Timeouts

A **timeout** specifies the maximum duration (in milliseconds) a request is allowed to run before Axios automatically aborts it and throws an error.

### A. Per-Request Timeout

Set the `timeout` property inside an individual request's configuration object:

```javascript
import axios from "axios";

async function fetchFastData() {
  try {
    const response = await axios.get("https://api.example.com/data", {
      timeout: 3000 // Timeout after 3000 ms (3 seconds)
    });
    console.log("Data received:", response.data);
  } catch (error) {
    // Axios throws a specific code when a request times out
    if (error.code === "ECONNABORTED") {
      console.error("Request timed out! Server took longer than 3 seconds.");
    } else {
      console.error("Request failed:", error.message);
    }
  }
}

```

### B. Global or Instance Timeout

Specify a default timeout when creating a reusable Axios instance:

```javascript
const apiClient = axios.create({
  baseURL: "https://api.example.com",
  timeout: 5000 // Default 5-second timeout for ALL requests using this instance
});

// Inherits the 5000ms timeout
apiClient.get("/users");

```

## 2. Cancelling Requests with `AbortController`

Modern versions of Axios (v0.22.0+) use the standard browser **`AbortController`** API to cancel pending in-flight requests.

### A. Basic Request Cancellation

To cancel a request, create an `AbortController` instance and pass its `signal` to the Axios request options:

```javascript
import axios from "axios";

// 1. Instantiate the controller
const controller = new AbortController();

async function getData() {
  try {
    const response = await axios.get("https://api.example.com/long-task", {
      signal: controller.signal // Link signal to request
    });
    console.log(response.data);
  } catch (error) {
    // 2. Check if the request was specifically cancelled
    if (axios.isCancel(error)) {
      console.log("Request successfully cancelled by user or cleanup.");
    } else {
      console.error("HTTP error:", error.message);
    }
  }
}

// Start request
getData();

// 3. Cancel the request dynamically (e.g., when clicking a "Cancel" button)
document.querySelector("#cancelBtn").addEventListener("click", () => {
  controller.abort(); // Triggers cancellation
});

```

## 3. Real-World Patterns

### Pattern 1: Debounced Auto-Complete Search Input

When building live search inputs, cancel previous pending search requests as the user types new characters:

```javascript
let currentSearchController = null;

async function handleSearchInput(searchTerm) {
  // If a previous search request is still running, abort it
  if (currentSearchController) {
    currentSearchController.abort();
  }

  // Create a new controller for the current search
  currentSearchController = new AbortController();

  try {
    const response = await axios.get(`/api/search?q=${encodeURIComponent(searchTerm)}`, {
      signal: currentSearchController.signal
    });

    console.log("Search results:", response.data);
  } catch (error) {
    if (axios.isCancel(error)) {
      console.log(`Cancelled search for previous input`);
    } else {
      console.error("Search failed:", error);
    }
  } finally {
    currentSearchController = null;
  }
}

```

### Pattern 2: Component Cleanup in React (`useEffect`)

In frontend frameworks like React, cancel active API calls when a component unmounts to avoid state updates on unmounted nodes:

```javascript
import { useEffect, useState } from "react";
import axios from "axios";

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    async function loadUser() {
      try {
        const response = await axios.get(`/api/users/${userId}`, {
          signal: controller.signal,
          timeout: 5000 // Combine timeout + cancellation signal
        });
        setUser(response.data);
      } catch (error) {
        if (!axios.isCancel(error)) {
          console.error("Failed to load user:", error);
        }
      }
    }

    loadUser();

    // Cleanup function triggers on unmount or when userId changes
    return () => {
      controller.abort();
    };
  }, [userId]);

  return <div>{user ? user.name : "Loading..."}</div>;
}

```

Explain how to implement JWT access token refresh logic using Axios interceptors with code examples

Implementing JWT access token refresh logic using **Axios Interceptors** ensures your application seamlessly re-authenticates expired tokens in the background without forcing the user to log in again or disrupting their session.

---

## 1. Architecture Flow

```text
 Client                       Server
   │                            │
 1.│── Request with Expired ───►│
   │   Access Token             │
   │                            │
 2.│◄── 401 Unauthorized ───────│ (Token Expired)
   │                            │
   │ [Response Interceptor Triggered]
   │ 
 3.│── POST /refresh ──────────►│ (Sends Refresh Token)
   │                            │
 4.│◄── New Access Token ───────│
   │                            │
 5.│── Retry Original Request ─►│ (With New Access Token)
   │                            │
 6.│◄── 200 OK (Data) ──────────│

```

### Critical Edge Cases to Handle

* **Multiple Concurrent Requests:** If 3 API calls fail with `401` at the exact same moment, you must issue **only ONE refresh request**, queuing the other two until the new token arrives.
* **Infinite Loops:** If the `/refresh` endpoint itself returns `401` (e.g., refresh token is revoked or expired), stop retrying immediately and log the user out.

---

## 2. Complete Implementation Code

Below is a production-ready setup handling queueing, lock flags, and automatic retries.

```javascript
// api/client.js
import axios from "axios";

// 1. Create configured Axios instance
const apiClient = axios.create({
  baseURL: "https://api.example.com/v1",
  headers: {
    "Content-Type": "application/json"
  }
});

// State variables to prevent duplicate refresh requests
let isRefreshing = false;
let failedQueue = [];

// Helper function to process queued requests after token refresh
const processQueue = (error, token = null) => {
  failedQueue.forEach((prom) => {
    if (error) {
      prom.reject(error);
    } else {
      prom.resolve(token);
    }
  });

  failedQueue = [];
};

// ==========================================
// 2. REQUEST INTERCEPTOR
// ==========================================
apiClient.interceptors.request.use(
  (config) => {
    const accessToken = localStorage.getItem("access_token");
    if (accessToken) {
      config.headers.Authorization = `Bearer ${accessToken}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// ==========================================
// 3. RESPONSE INTERCEPTOR
// ==========================================
apiClient.interceptors.response.use(
  (response) => response, // Pass through successful responses
  async (error) => {
    const originalRequest = error.config;

    // Check if error is 401 Unauthorized AND request hasn't been retried yet
    if (error.response?.status === 401 && !originalRequest._retry) {
      
      // Prevent infinite loop if the refresh endpoint itself returns 401
      if (originalRequest.url.includes("/auth/refresh")) {
        handleLogout();
        return Promise.reject(error);
      }

      // If another request is currently refreshing the token, queue this request
      if (isRefreshing) {
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject });
        })
          .then((newToken) => {
            originalRequest.headers.Authorization = `Bearer ${newToken}`;
            return apiClient(originalRequest); // Retry original request
          })
          .catch((err) => Promise.reject(err));
      }

      // Mark request as retried to prevent loops
      originalRequest._retry = true;
      isRefreshing = true;

      try {
        const refreshToken = localStorage.getItem("refresh_token");

        // Request a new access token
        const response = await axios.post("https://api.example.com/v1/auth/refresh", {
          refreshToken: refreshToken
        });

        const { accessToken: newAccessToken, refreshToken: newRefreshToken } = response.data;

        // Save new tokens
        localStorage.setItem("access_token", newAccessToken);
        if (newRefreshToken) {
          localStorage.setItem("refresh_token", newRefreshToken);
        }

        // Update default auth header
        apiClient.defaults.headers.common["Authorization"] = `Bearer ${newAccessToken}`;
        originalRequest.headers["Authorization"] = `Bearer ${newAccessToken}`;

        // Resolve all queued requests waiting for the new token
        processQueue(null, newAccessToken);

        // Retry the original failed request
        return apiClient(originalRequest);

      } catch (refreshError) {
        // Refresh token failed or expired -> force logout
        processQueue(refreshError, null);
        handleLogout();
        return Promise.reject(refreshError);

      } finally {
        isRefreshing = false;
      }
    }

    return Promise.reject(error);
  }
);

// Helper function to handle full session logout
function handleLogout() {
  localStorage.removeItem("access_token");
  localStorage.removeItem("refresh_token");
  window.location.href = "/login";
}

export default apiClient;

```

Explain how to handle concurrent parallel requests using Axios with code examples

Handling concurrent parallel requests in Axios allows your application to execute multiple API calls simultaneously instead of sequentially, significantly reducing overall load times.

Axios supports two main approaches for parallel requests: standard **`Promise.all()`** (recommended for modern JavaScript) and the legacy **`axios.all()`** helper.

---

## 1. Modern Approach: `Promise.all()` (Recommended)

Since Axios methods return standard ES6 Promises, using native `Promise.all()` is the cleaner, standard approach. It executes all promises concurrently and resolves when **all** requests complete.

```javascript
import axios from "axios";

async function fetchDashboardData() {
  try {
    // 1. Execute requests simultaneously
    const [userRes, postsRes, statsRes] = await Promise.all([
      axios.get("https://api.example.com/user/profile"),
      axios.get("https://api.example.com/user/posts"),
      axios.get("https://api.example.com/analytics/stats")
    ]);

    // 2. Destructure individual response payloads
    console.log("User Profile:", userRes.data);
    console.log("User Posts:", postsRes.data);
    console.log("Analytics Stats:", statsRes.data);

  } catch (error) {
    // Note: Promise.all fails fast! If ANY request fails, execution jumps here.
    console.error("One or more requests failed:", error.message);
  }
}

fetchDashboardData();

```

---

## 2. Handling Failures Gracefully: `Promise.allSettled()`

A common limitation of `Promise.all()` is that if **a single request fails** (e.g., 404 or 500 error), the entire batch rejects immediately, ignoring successful responses.

To ensure successful requests are still processed even if others fail, use **`Promise.allSettled()`**:

```javascript
import axios from "axios";

async function fetchDataResiliently() {
  const requests = [
    axios.get("https://api.example.com/users"),
    axios.get("https://api.example.com/broken-endpoint"), // Will fail
    axios.get("https://api.example.com/settings")
  ];

  // Executes all requests and waits for ALL of them to complete or fail
  const results = await Promise.allSettled(requests);

  results.forEach((result, index) => {
    if (result.status === "fulfilled") {
      console.log(`Request ${index + 1} Succeeded:`, result.value.data);
    } else {
      console.error(`Request ${index + 1} Failed:`, result.reason.message);
    }
  });
}

fetchDataResiliently();

```

---

## 3. Legacy Approach: `axios.all()` and `axios.spread()`

In older codebases, you may see `axios.all()` paired with `axios.spread()`. `axios.all()` is simply a wrapper around `Promise.all()`, while `axios.spread()` destructures the array of responses into individual parameters.

```javascript
import axios from "axios";

function fetchLegacyWay() {
  axios.all([
    axios.get("https://api.example.com/users"),
    axios.get("https://api.example.com/posts")
  ])
  .then(axios.spread((usersRes, postsRes) => {
    console.log("Users:", usersRes.data);
    console.log("Posts:", postsRes.data);
  }))
  .catch((error) => {
    console.error("Error fetching data:", error);
  });
}

```

> **Note:** While still supported for backward compatibility, `axios.all()` and `axios.spread()` are considered legacy patterns. Prefer native `Promise.all()` or `Promise.allSettled()`.

## 4. Batching Dynamic Arrays of Concurrent Requests

When processing a dynamic list of items (such as fetching details for an array of 5 user IDs), map the items into an array of Axios requests:

```javascript
import axios from "axios";

async function fetchMultipleUsers(userIds) {
  try {
    // 1. Map IDs to an array of Axios GET promises
    const requestPromises = userIds.map((id) =>
      axios.get(`https://api.example.com/users/${id}`)
    );

    // 2. Resolve all promises concurrently
    const responses = await Promise.all(requestPromises);

    // 3. Extract data array from responses
    const usersData = responses.map((res) => res.data);
    console.log("Fetched users:", usersData);

  } catch (error) {
    console.error("Error fetching user array:", error);
  }
}

// Example usage:
fetchMultipleUsers([101, 102, 103, 104]);

```

Here are the answers to how Axios handles server responses:

### 1. Which HTTP status codes does Axios treat as successful by default?

Axios treats **any HTTP status code in the $2xx$ range** (from `200` up to `299`) as successful.

### 2. Which status codes cause Axios to reject the Promise?

Any status code **outside the $2xx$ range** (such as $3xx$ redirects, $4xx$ client errors, and $5xx$ server errors) will cause Axios to reject the Promise and jump to the `.catch()` block.
*(Note: You can customize this behavior using the `validateStatus` config option if you want Axios to treat specific status codes like $304$ or $401$ as successes).*

### 3. How does Axios decide whether to execute `.then()` or .catch()?

Axios looks at the HTTP status code returned by the server:

* If the status code falls within the successful range ($2xx$), Axios resolves the promise, triggering the **`.then()`** block.
* If the status code falls outside that range (or if a network error occurs like a timeout or DNS failure), Axios rejects the promise, triggering the **`.catch()`** block.

### 4. Does the browser return an AxiosResponse object?

**No.** The browser's native networking APIs (like `XMLHttpRequest` or the `Fetch API`) return their own response formats—such as a `Response` object in the Fetch API or raw `xhr` properties in an XHR request. They know nothing about "Axios."

### 5. If not, who creates it?

**Axios itself creates it.** Axios acts as a wrapper around the browser's native transport mechanisms. When the browser finishes downloading the raw data, Axios intercepts it and transforms it into its own standardized wrapper object known as the `AxiosResponse` object before handing it over to your `.then()` callback.

### 6. Where does the actual HTTP response body get stored inside the Axios response object?

The actual response body parsed from the server is stored inside the **`data`** property of the Axios response object (`response.data`).
