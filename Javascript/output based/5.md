Here are exactly **50 output-based JavaScript questions** covering `let`, `var`, `const`, Closures, Temporal Dead Zone (TDZ), IIFEs, and Anonymous functions.

---

### **Part 1: `var`, `let`, and `const**`

**1.**

```javascript
console.log(a);
var a = 5;

```

**Output:** `undefined`
**Explanation:** `var` is hoisted and initialized with `undefined`.

**2.**

```javascript
let b = 10;
{
  let b = 20;
  console.log(b);
}
console.log(b);

```

**Output:** `20`, then `10`
**Explanation:** `let` is block-scoped. The inner `b` shadows the outer `b` only inside the block.

**3.**

```javascript
const obj = { name: "John" };
obj.name = "Doe";
console.log(obj.name);

```

**Output:** `Doe`
**Explanation:** `const` prevents reassignment of the variable, but does not make objects immutable.

**4.**

```javascript
const arr = [1, 2];
arr = [3, 4];

```

**Output:** `TypeError: Assignment to constant variable.`
**Explanation:** You cannot reassign a new array reference to a `const` variable.

**5.**

```javascript
var x = 1;
var x = 2;
console.log(x);

```

**Output:** `2`
**Explanation:** `var` allows redeclaration in the same scope.

**6.**

```javascript
let y = 1;
let y = 2;

```

**Output:** `SyntaxError: Identifier 'y' has already been declared`
**Explanation:** `let` and `const` do not allow redeclaration in the same scope.

**7.**

```javascript
const z;
z = 10;

```

**Output:** `SyntaxError: Missing initializer in const declaration`
**Explanation:** `const` variables must be initialized at the time of declaration.

**8.**

```javascript
var a = 10;
function test() {
  var a = 20;
}
test();
console.log(a);

```

**Output:** `10`
**Explanation:** `var` is function-scoped. The inner `a` does not affect the outer `a`.

**9.**

```javascript
var myVar = 100;
if (true) {
  var myVar = 200;
}
console.log(myVar);

```

**Output:** `200`
**Explanation:** `var` is not block-scoped. The `if` block overwrites the global `myVar`.

**10.**

```javascript
for (var i = 0; i < 3; i++) {}
console.log(i);

```

**Output:** `3`
**Explanation:** `var` leaks out of the `for` loop block into the surrounding scope.

### **Part 2: Temporal Dead Zone (TDZ)**

**11.**

```javascript
console.log(a);
let a = 5;

```

**Output:** `ReferenceError: Cannot access 'a' before initialization`
**Explanation:** `let` is hoisted but stays in the TDZ until the execution reaches its declaration.

**12.**

```javascript
console.log(typeof a);
console.log(typeof b);
let b = 10;

```

**Output:** `undefined`, then `ReferenceError`
**Explanation:** `typeof` on an undeclared variable (`a`) is safely `"undefined"`, but `typeof` on a variable in the TDZ (`b`) throws an error.

**13.**

```javascript
let x = 10;
function show() {
  console.log(x);
  let x = 20;
}
show();

```

**Output:** `ReferenceError: Cannot access 'x' before initialization`
**Explanation:** The local `let x` is hoisted inside the block, creating a TDZ. It shadows the outer `x`.

**14.**

```javascript
function tdzCheck(a = b, b = 2) {
  console.log(a);
}
tdzCheck();

```

**Output:** `ReferenceError: Cannot access 'b' before initialization`
**Explanation:** Default parameters evaluate left-to-right. `b` is in the TDZ when `a` tries to read it.

**15.**

```javascript
let val = 1;
{
  var val = 2;
}

```

**Output:** `SyntaxError: Identifier 'val' has already been declared`
**Explanation:** `var` tries to declare globally/functionally, clashing with the outer block-scoped `let`.

**16.**

```javascript
const a = 1;
{
  console.log(a);
  const a = 2;
}

```

**Output:** `ReferenceError`
**Explanation:** Like `let`, `const` is hoisted and placed in the TDZ for that specific block.

**17.**

```javascript
function foo() {
  return bar;
}
let bar = 10;
console.log(foo());

```

**Output:** `10`
**Explanation:** `foo` is called *after* `bar` is initialized. The TDZ only matters chronologically during execution.

**18.**

```javascript
let x = 1;
switch(x) {
  case 1:
    let y = 2;
  case 2:
    let y = 3;
}

```

**Output:** `SyntaxError: Identifier 'y' has already been declared`
**Explanation:** A `switch` statement has a single block scope, so declaring `y` twice with `let` fails.

**19.**

```javascript
class MyClass extends BaseClass {}
class BaseClass {}

```

**Output:** `ReferenceError: Cannot access 'BaseClass' before initialization`
**Explanation:** Classes act like `let`/`const` and have a TDZ. They must be declared before use.

**20.**

```javascript
let a = f();
const f = () => 5;

```

**Output:** `ReferenceError: Cannot access 'f' before initialization`
**Explanation:** The anonymous arrow function is assigned to a `const`, which is in the TDZ when called.

### **Part 3: Closures**

**21.**

```javascript
function outer() {
  let count = 0;
  return function() {
    return ++count;
  }
}
const counter = outer();
console.log(counter());
console.log(counter());

```

**Output:** `1`, then `2`
**Explanation:** The inner function forms a closure, remembering the `count` variable's memory reference.

**22.**

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}

```

**Output:** `3, 3, 3`
**Explanation:** `var` shares one memory space. The loop finishes before the async callbacks run.

**23.**

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}

```

**Output:** `0, 1, 2`
**Explanation:** `let` creates a new lexical scope for each iteration, binding a fresh `i` to each closure.

**24.**

```javascript
let f;
if (true) {
  let a = 10;
  f = () => { console.log(a); }
}
f();

```

**Output:** `10`
**Explanation:** Even though the block finished executing, the closure `f` retains access to `a`.

**25.**

```javascript
function multiplier(factor) {
  return (num) => num * factor;
}
const twice = multiplier(2);
console.log(twice(5));

```

**Output:** `10`
**Explanation:** The anonymous arrow function remembers the `factor` parameter from its lexical scope.

**26.**

```javascript
let count = 0;
const increment = () => count++;
const log = () => console.log(count);
increment();
increment();
log();

```

**Output:** `2`
**Explanation:** Closures capture references to variables, not values. `log` sees the updated `count`.

**27.**

```javascript
function create() {
  let val = 1;
  return {
    get: () => val,
    set: (v) => val = v
  };
}
const obj = create();
obj.set(5);
console.log(obj.get());

```

**Output:** `5`
**Explanation:** Both methods share the same closure scope and can manipulate the private `val`.

**28.**

```javascript
const arr = [10, 12, 15, 21];
for (var i = 0; i < arr.length; i++) {
  setTimeout(function() {
    console.log('Index: ' + i + ', element: ' + arr[i]);
  }, 1000);
}

```

**Output:** `Index: 4, element: undefined` (printed 4 times)
**Explanation:** `i` becomes 4. `arr[4]` is `undefined`.

**29.**

```javascript
function a(x) {
  return function b(y) {
    return function c(z) {
      return x + y + z;
    }
  }
}
console.log(a(1)(2)(3));

```

**Output:** `6`
**Explanation:** Nested closures chain their lexical scopes. `c` has access to `x`, `y`, and `z`.

**30.**

```javascript
let x = 10;
function outer() {
  let x = 20;
  return function inner() {
    console.log(x);
  }
}
let fn = outer();
fn();

```

**Output:** `20`
**Explanation:** Closures remember the environment where they were *created*, not where they are executed.

### **Part 4: IIFE (Immediately Invoked Function Expressions)**

**31.**

```javascript
(function() {
  var x = 10;
})();
console.log(x);

```

**Output:** `ReferenceError: x is not defined`
**Explanation:** IIFEs encapsulate variables, preventing them from polluting the global scope.

**32.**

```javascript
let result = (function(a, b) {
  return a + b;
})(5, 10);
console.log(result);

```

**Output:** `15`
**Explanation:** An IIFE can return a value which can be immediately assigned.

**33.**

```javascript
var a = 1;
(function(a) {
  a = 2;
})(a);
console.log(a);

```

**Output:** `1`
**Explanation:** The IIFE's parameter `a` is a local copy. Modifying it doesn't affect the global `a`.

**34.**

```javascript
for (var i = 0; i < 3; i++) {
  (function(i) {
    setTimeout(() => console.log(i), 100);
  })(i);
}

```

**Output:** `0, 1, 2`
**Explanation:** The IIFE creates a new scope per iteration, capturing the current value of `var i`.

**35.**

```javascript
let a = 5
(function() {
  console.log(a)
})()

```

**Output:** `TypeError: 5 is not a function`
**Explanation:** Missing semicolon. JS interprets it as `let a = 5(function(){...})()`.

**36.**

```javascript
+function() {
  console.log("Ran");
}();

```

**Output:** `Ran` (and returns `NaN` in console)
**Explanation:** Unary operators (`+`, `-`, `!`) force the parser to treat the function as an expression, making it an IIFE.

**37.**

```javascript
var module = (function() {
  var privateNum = 5;
  return {
    get: function() { return privateNum; }
  };
})();
console.log(module.privateNum);

```

**Output:** `undefined`
**Explanation:** The classic module pattern. `privateNum` is hidden inside the IIFE scope.

**38.**

```javascript
(function namedIIFE() {
  console.log("Inside");
})();
namedIIFE();

```

**Output:** `Inside`, then `ReferenceError: namedIIFE is not defined`
**Explanation:** The name of an IIFE is not bound in the enclosing scope.

**39.**

```javascript
const value = (() => {
  return "Arrow IIFE";
})();
console.log(value);

```

**Output:** `Arrow IIFE`
**Explanation:** Arrow functions can also be used as IIFEs.

**40.**

```javascript
let b = 10;
(function b() {
  b = 20;
  console.log(b);
})();

```

**Output:** `[Function: b]`
**Explanation:** Inside a named IIFE expression, the function name (`b`) is read-only. Reassignment fails silently.

### **Part 5: Anonymous Functions**

**41.**

```javascript
setTimeout(function() {
  console.log("Anon");
}, 0);
console.log("Global");

```

**Output:** `Global`, then `Anon`
**Explanation:** The anonymous callback function is queued in the Macrotask queue.

**42.**

```javascript
const obj = {
  name: "Sam",
  say: function() {
    setTimeout(function() {
      console.log(this.name);
    }, 100);
  }
};
obj.say();

```

**Output:** `undefined`
**Explanation:** The anonymous standard function in `setTimeout` loses the `this` context (binds to window/global).

**43.**

```javascript
const obj2 = {
  name: "Sam",
  say: function() {
    setTimeout(() => {
      console.log(this.name);
    }, 100);
  }
};
obj2.say();

```

**Output:** `Sam`
**Explanation:** The anonymous arrow function inherits `this` lexically from the `say` method.

**44.**

```javascript
function() {
  console.log("Hello");
}

```

**Output:** `SyntaxError: Function statements require a function name`
**Explanation:** A function declaration must have a name unless it's an expression (e.g., assigned to a variable).

**45.**

```javascript
const actions = [
  function() { return 1; },
  function() { return 2; }
];
console.log(actions[1]());

```

**Output:** `2`
**Explanation:** Anonymous functions can be stored inside arrays and invoked via index.

**46.**

```javascript
var myFunc = function() {
  console.log(a);
  var a = 2;
};
myFunc();

```

**Output:** `undefined`
**Explanation:** Standard `var` hoisting occurs inside the anonymous function scope.

**47.**

```javascript
let nums = [1, 2, 3];
let doubled = nums.map(function(n) {
  return n * 2;
});
console.log(doubled);

```

**Output:** `[2, 4, 6]`
**Explanation:** Anonymous function passed as a callback to a higher-order array method.

**48.**

```javascript
console.log((function(x) { return x * x })(4));

```

**Output:** `16`
**Explanation:** An anonymous function immediately invoked directly inside a `console.log`.

**49.**

```javascript
const makeCounter = function() {
  let count = 0;
  return function() {
    return ++count;
  };
};
const c = makeCounter();
console.log(c());

```

**Output:** `1`
**Explanation:** An anonymous function expression returning another anonymous function forming a closure.

**50.**

```javascript
let i = 0;
const interval = setInterval(function() {
  i++;
  if (i === 2) {
    clearInterval(interval);
    console.log(i);
  }
}, 10);

```

**Output:** `2`
**Explanation:** The anonymous callback forms a closure over `i` and `interval`, stopping itself conditionally.
