Here is a batch of advanced output-based questions focusing on the powerful data structures and meta-programming features introduced in ES6+: **Maps, Sets, Generators, Proxies, and Reflect**.

---

### **1. Sets and Object References**

**Question:**
What will be the output of the following code?

```javascript
const mySet = new Set();

mySet.add(1);
mySet.add(1);
mySet.add({ id: 1 });
mySet.add({ id: 1 });

console.log(mySet.size);

```

**Output:**

```text
3

```

* **Explanation:** A `Set` stores only unique values. It uses the `SameValueZero` algorithm to check for equality. Primitive values like `1` are identical, so the second `1` is ignored. However, the two object literals `{ id: 1 }` are created at different memory addresses. Because they do not share the same reference, the Set treats them as two completely distinct items.

### **2. Maps and the `NaN` Quirks**

**Question:**
What will this code output?

```javascript
const map = new Map();

map.set(NaN, "First");
map.set(NaN, "Second");
map.set("1", "String");
map.set(1, "Number");

console.log(map.get(NaN));
console.log(map.size);

```

**Output:**

```text
"Second"
3

```

* **Explanation:**

1. Unlike the strict equality operator (`===`), which evaluates `NaN === NaN` as `false`, Maps use `SameValueZero` for key comparison. This means a Map correctly recognizes `NaN` as being equal to itself. The second `set(NaN)` overwrites the first one.
2. Unlike standard JavaScript Objects (which stringify all keys), Maps preserve the type of their keys. `"1"` (String) and `1` (Number) are treated as two separate keys.
3. The final keys are `NaN`, `"1"`, and `1`, making the size `3`.

### **3. WeakMap Key Constraints**

**Question:**
What is logged to the console?

```javascript
const weakMap = new WeakMap();
const obj = {};

try {
  weakMap.set(obj, "Data");
  weakMap.set(Symbol("id"), "Symbol Data");
  weakMap.set("key", "String Data");
  console.log("Success");
} catch (error) {
  console.log("TypeError Caught");
}

```

**Output:**

```text
TypeError Caught

```

* **Explanation:** A `WeakMap` is heavily restricted to allow for automatic Garbage Collection. **Its keys must be objects (or non-registered Symbols in ES2023+)**. You absolutely cannot use primitive values like strings, numbers, or booleans as keys. When `weakMap.set("key", ...)` executes, it throws a `TypeError`.

### **4. Generators and Two-Way Communication**

**Question:**
What gets logged as the generator yields?

```javascript
function* mathGenerator() {
  const a = yield 10;
  const b = yield a * 2;
  return a + b;
}

const iterator = mathGenerator();

console.log(iterator.next().value);
console.log(iterator.next(5).value);
console.log(iterator.next(6).value);

```

**Output:**

```text
10
10
11

```

* **Explanation:** The `next()` method both receives values from `yield` and injects values back into the generator.

1. `next()` starts execution. It pauses at the first yield and outputs `10`.
2. `next(5)` resumes execution, permanently replacing the entire `yield 10` expression with the injected value `5`. So `a = 5`. It then calculates `5 * 2`, pauses, and outputs `10`.
3. `next(6)` resumes execution, injecting `6` in place of the second yield. So `b = 6`. The function then reaches `return 5 + 6`, returning `{ value: 11, done: true }`.

### **5. Proxy Traps vs. The Original Target**

**Question:**
What will be logged to the console?

```javascript
const target = { secret: "Password123" };

const proxy = new Proxy(target, {
  get(obj, prop) {
    if (prop === "secret") {
      return "REDACTED";
    }
    return obj[prop];
  }
});

console.log(proxy.secret);
console.log(target.secret);

```

**Output:**

```text
"REDACTED"
"Password123"

```

* **Explanation:** A `Proxy` wraps an object and intercepts fundamental operations like reading properties. When you query the `proxy` for `"secret"`, the `get` trap intercepts it and returns `"REDACTED"`. However, the original `target` object is completely unmodified. Interacting with the target directly bypasses the Proxy entirely.

### **6. Proxy Context Loss and `Reflect**`

**Question:**
What gets logged to the console?

```javascript
const user = {
  _name: "Alice",
  get name() {
    return this._name;
  }
};

const proxy = new Proxy(user, {
  get(target, prop, receiver) {
    if (prop === "_name") return "Bob";
    
    // Using standard target lookup instead of Reflect:
    return target[prop];
  }
});

console.log(proxy.name);

```

**Output:**

```text
"Alice"

```

* **Explanation:** This illustrates why `Reflect` was introduced alongside `Proxy`.
* We call `proxy.name`. The Proxy forwards this to the original object's getter via `target[prop]`.
* Inside the getter `get name()`, `this` evaluates to the original `user` object, *not* the proxy.
* It asks for `this._name` (which is `"Alice"`). It completely bypasses the proxy's `_name` trap ("Bob").
* **The Fix:** If the proxy returned `Reflect.get(target, prop, receiver)`, it would force `this` inside the getter to point back to the proxy, properly triggering the `_name` trap and returning `"Bob"`.

### **7. Generator Delegation (`yield*`)**

**Question:**
What is the final array output?

```javascript
function* letters() {
  yield 'A';
  yield 'B';
}

function* numbers() {
  yield 1;
  yield* letters();
  yield 2;
  yield* ['X', 'Y'];
}

console.log([...numbers()]);

```

**Output:**

```text
[1, "A", "B", 2, "X", "Y"]

```

* **Explanation:** The `yield*` expression is used to delegate execution to another iterable object (like another generator, an array, a Set, etc.). The main `numbers` generator pauses itself, fully exhausts the `letters()` generator (yielding "A" and "B"), continues to `2`, and then fully exhausts the array `['X', 'Y']` before finally completing. Spread syntax (`...`) consumes the entire resulting sequence into an array.
