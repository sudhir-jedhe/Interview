### **1. The Stateful Regex Trap (The `g` flag)**

**Question:**
What will be logged to the console?

```javascript
const regex = /hello/g;
const str = "hello world, hello universe";

console.log(regex.test(str));
console.log(regex.test(str));
console.log(regex.test(str));

```

**Output:**

```text
true
true
false

```

* **Explanation:** When a regular expression has the global `g` flag, it becomes **stateful**. It keeps track of the `lastIndex` where the previous match ended.
* First `test()` matches the first "hello" and updates `lastIndex` to `5`.
* Second `test()` starts searching from index 5, finds the second "hello", and updates `lastIndex` to `18`.
* Third `test()` starts from 18, finds no more matches, returns `false`, and resets `lastIndex` to `0`.

### **2. String Splitting with Capturing Groups**

**Question:**
What is the difference in output between these two split operations?

```javascript
const str = "apple,banana,cherry";

const split1 = str.split(/,/);
const split2 = str.split(/(,)/);

console.log(split1.length);
console.log(split2.length);

```

**Output:**

```text
3
5

```

* **Explanation:** When you use `String.prototype.split()` with a regular expression that contains **capturing groups** `()`, the matched results of the capturing groups are spliced into the output array.
* `split1` outputs: `["apple", "banana", "cherry"]` (Length: 3).
* `split2` outputs: `["apple", ",", "banana", ",", "cherry"]` (Length: 5).

### **3. Implicit Coercion in Regex Methods**

**Question:**
What will this code output?

```javascript
const regex = /undefined/;

console.log(regex.test());
console.log(regex.test(undefined));
console.log(regex.test(null));

```

**Output:**

```text
true
true
false

```

* **Explanation:** The `RegExp.prototype.test()` method expects a string. If you pass a non-string (or nothing at all), JavaScript implicitly coerces the argument into a string using `String(val)`.
* Calling `test()` with no arguments passes `undefined`, which becomes the string `"undefined"`.
* Explicitly passing `undefined` does the same.
* Passing `null` becomes the string `"null"`, which does not match `/undefined/`.

### **4. Greedy vs. Lazy Quantifiers**

**Question:**
What will be extracted by these two match operations?

```javascript
const html = "<div>hello</div><div>world</div>";

const greedy = html.match(/<div>.*<\/div>/)[0];
const lazy = html.match(/<div>.*?<\/div>/)[0];

console.log(greedy);
console.log(lazy);

```

**Output:**

```text
"<div>hello</div><div>world</div>"
"<div>hello</div>"

```

* **Explanation:** By default, regex quantifiers like `*` and `+` are **greedy**—they match as much text as possible while still allowing the overall pattern to succeed. The first regex grabs everything from the very first `<div>` to the very last `</div>`. Adding a `?` after a quantifier (`.*?`) makes it **lazy**, meaning it stops at the very first valid match it encounters.

### **5. String.replace() with Replacer Functions**

**Question:**
What will the final string look like?

```javascript
const str = "a1b2c3";

const result = str.replace(/\d/g, (match, offset) => {
  return match * 2;
});

console.log(result);

```

**Output:**

```text
"a2b4c6"

```

* **Explanation:** `String.prototype.replace()` can take a callback function as its second argument. The function is invoked for every single match (because of the `g` flag). The `match` argument is the matched string (e.g., `"1"`, `"2"`, `"3"`). The mathematical multiplication implicitly coerces the string digits into numbers, doubles them, and replaces the original matched characters with the new values.

### **6. Positive Lookahead Assertions**

**Question:**
What will be logged to the console?

```javascript
const prices = "100 USD and 200 EUR";

const regex = /\d+(?= USD)/;
const match = prices.match(regex);

console.log(match[0]);

```

**Output:**

```text
"100"

```

* **Explanation:** The `(?=...)` syntax is a **Positive Lookahead**. It tells the regex engine to find digits `\d+`, but *only* if they are immediately followed by `" USD"`. Crucially, lookaheads do not consume characters; they merely assert a condition. Therefore, the resulting match only contains the digits `"100"`, excluding the `" USD"` part.

### **7. Replacing Strings: Regex vs String primitives**

**Question:**
What is the output of these two replace operations?

```javascript
const str = "apple apple apple";

console.log(str.replace("apple", "orange"));
console.log(str.replaceAll(/apple/, "orange"));

```

**Output:**

```text
"orange apple apple"
TypeError: String.prototype.replaceAll called with a non-global RegExp argument

```

* **Explanation:**

1. When using `replace()` with a string literal as the first argument, it only ever replaces the **first** occurrence it finds.
2. `replaceAll()` was introduced in ES2021 to replace all occurrences. However, if you pass a regular expression to `replaceAll()`, it **must** include the global `g` flag. If it doesn't, JavaScript intentionally throws a `TypeError` to prevent logical bugs.
