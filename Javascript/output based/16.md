Here is a masterclass batch of output-based questions focusing on the deep mechanics of **`useMemo`, `useCallback`, and `useEffect` dependencies**. These questions test your grasp of referential equality, stale closures, and infinite render loops.

---

### **1. The Stale `useCallback` Closure**

**Question:**
Assume the user clicks the "Increment" button 3 times. What will be displayed on the UI as the final count?

```jsx
import { useState, useCallback } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  const handleIncrement = useCallback(() => {
    setCount(count + 1);
  }, []); // Empty dependency array

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={handleIncrement}>Increment</button>
    </div>
  );
}

```

**Output:**

```text
Count: 1

```

* **Explanation:** `useCallback` memoizes the function definition. Because the dependency array is empty `[]`, React never recreates the `handleIncrement` function after the initial mount. The function permanently holds a **stale closure** where `count` is `0`. Every time you click the button, it simply executes `setCount(0 + 1)`, leaving the state permanently stuck at `1`. *(Fix: add `count` to the dependency array, or use `setCount(prev => prev + 1)`).*

### **2. The Referential Equality Infinite Loop**

**Question:**
What happens to the console when this component mounts?

```jsx
import { useState, useEffect } from "react";

function UserProfile() {
  const [renders, setRenders] = useState(0);

  // Object defined inside the component body
  const userConfig = { role: "admin", theme: "dark" };

  useEffect(() => {
    console.log("Effect executed");
    setRenders(renders + 1);
  }, [userConfig]);

  return <div>Renders: {renders}</div>;
}

```

**Output:**

```text
Effect executed
Effect executed
Effect executed
... (Infinite loop, eventually crashing the browser)

```

* **Explanation:** In JavaScript, objects are compared by their memory reference. Every time `UserProfile` renders, a brand new `userConfig` object is created in a new memory address.

1. Component mounts, creates `userConfig` (Ref A).
2. `useEffect` sees Ref A, runs, and calls `setRenders(1)`.
3. State update triggers a re-render.
4. Component creates a new `userConfig` (Ref B).
5. `useEffect` compares Ref A to Ref B. They are different. Effect runs again, calling `setRenders(2)`.
*(Fix: Wrap `userConfig` in `useMemo`, or move it completely outside the component if it doesn't depend on state/props).*

### **3. `useMemo` Execution Timing vs `useEffect**`

**Question:**
What is the exact sequence of console logs when the component mounts?

```jsx
import { useMemo, useEffect } from "react";

function Calculator() {
  console.log("Component Render Start");

  const expensiveValue = useMemo(() => {
    console.log("Running useMemo");
    return 100;
  }, []);

  useEffect(() => {
    console.log("Running useEffect");
  }, []);

  console.log("Component Render End");

  return <div>{expensiveValue}</div>;
}

```

**Output:**

```text
Component Render Start
Running useMemo
Component Render End
Running useEffect

```

* **Explanation:** `useMemo` executes **synchronously during the render phase**. React pauses rendering the UI, calculates the value, and then continues. `useEffect`, however, executes **asynchronously after the render phase** (after the DOM has been painted). You should never put side effects (like data fetching or DOM mutations) inside `useMemo`.

### **4. `React.memo` and `useCallback` Synergy**

**Question:**
Assume `<Child/>` is wrapped in `React.memo`. If the user types a character into the input field, does "Child Rendered" get logged?

```jsx
import { useState, useCallback, memo } from "react";

const Child = memo(({ onClick }) => {
  console.log("Child Rendered");
  return <button onClick={onClick}>Click Me</button>;
});

function Parent() {
  const [text, setText] = useState("");
  const [count, setCount] = useState(0);

  const increment = useCallback(() => {
    setCount(count + 1);
  }, [count]); // Depends ONLY on count

  return (
    <div>
      <input value={text} onChange={(e) => setText(e.target.value)} />
      <Child onClick={increment} />
    </div>
  );
}

```

**Output:**
*No, "Child Rendered" does NOT get logged when typing.*

* **Explanation:** Typing in the input updates the `text` state, which forces the `Parent` to re-render. However, because `increment` is wrapped in `useCallback` with `[count]` as its only dependency, React returns the exact same function reference from the previous render. `React.memo` on the `Child` compares the new props to the old props. Since `onClick === onClick`, `React.memo` successfully bails out of rendering the child.

### **5. The Updater Function Bailout**

**Question:**
What gets logged to the console every second? Does it get stuck like Question 1?

```jsx
import { useState, useEffect } from "react";

function Timer() {
  const [ticks, setTicks] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setTicks(prevTicks => {
        console.log("Current tick:", prevTicks);
        return prevTicks + 1;
      });
    }, 1000);
    
    return () => clearInterval(id);
  }, []); // Empty dependency array!

  return <div>Ticks: {ticks}</div>;
}

```

**Output:**

```text
Current tick: 0
Current tick: 1
Current tick: 2
... (Continues incrementing infinitely)

```

* **Explanation:** Even though the dependency array is empty and the closure is completely stale (it only knows `ticks` as `0`), this code works perfectly. By passing a callback function to the state setter (`prevTicks => ...`), React automatically injects the most up-to-date state value directly into the function at the exact moment the update is processed. This completely bypasses the need for the `useEffect` closure to know the current state.

### **6. Breaking `useMemo` with Primitive Dependencies**

**Question:**
How many times will "Calculating..." be logged if the user clicks the button 3 times?

```jsx
import { useState, useMemo } from "react";

function Score() {
  const [score, setScore] = useState(10);
  const [bonus, setBonus] = useState(5);

  const total = useMemo(() => {
    console.log("Calculating...");
    return score + bonus;
  }, [score > 5]);

  return <button onClick={() => setScore(score + 1)}>Increase Score</button>;
}

```

**Output:**

```text
Calculating... (Once on mount)

```

*(No further logs occur on click)*

* **Explanation:** Look closely at the dependency array: `[score > 5]`.

1. On mount, `score` is 10. `10 > 5` evaluates to `true`. The dependency array is `[true]`.
2. First click: `score` becomes 11. `11 > 5` is `true`. The array is `[true]`. Since `true === true`, `useMemo` bails out.
3. Subsequent clicks keep evaluating to `true`. The dependency never actually changes, so the memoized calculation never runs again.
