### **Part 1: `call`, `apply`, and `bind` (Explicit Binding)**

**1. The Chained Bind**

```javascript
function greet() {
  console.log(this.name);
}
const person1 = { name: "Alice" };
const person2 = { name: "Bob" };

const boundFunc = greet.bind(person1).bind(person2);
boundFunc();

```

**Output:** `Alice`
**Explanation:** Once a function is bound using `.bind()`, its `this` context is permanently locked to the first provided object. Subsequent `.bind()` calls are completely ignored.

**2. Arrow Functions and `call**`

```javascript
const person = { name: "John" };
const arrowGreet = () => console.log(this.name);

arrowGreet.call(person);

```

**Output:** `undefined` (or empty string in some browsers)
**Explanation:** Arrow functions do not have their own `this`. They lexically inherit `this` from their surrounding scope (the global object here). You cannot change an arrow function's `this` using `call`, `apply`, or `bind`.

**3. Borrowing Math Methods with `apply**`

```javascript
const numbers = [5, 6, 2, 3, 7];
const max = Math.max.apply(null, numbers);
console.log(max);

```

**Output:** `7`
**Explanation:** `Math.max` does not accept an array; it accepts a comma-separated list of arguments. `.apply()` takes an array as its second argument and unpacks it into individual arguments for the function.

**4. Primitive Boxed Binding**

```javascript
function checkType() {
  console.log(typeof this);
}
checkType.call(5);

```

**Output:** `"object"`
**Explanation:** When you pass a primitive (like a number or string) to `call`, `apply`, or `bind`, JavaScript automatically "boxes" it into its corresponding Object wrapper (e.g., `new Number(5)`).

**5. `setTimeout` Context Loss**

```javascript
const user = {
  name: "Raj",
  logName() {
    console.log(this.name);
  }
};
setTimeout(user.logName, 10);

```

**Output:** `undefined`
**Explanation:** `setTimeout` executes the function independently in the global scope. To fix this, you must explicitly bind it: `setTimeout(user.logName.bind(user), 10)`.

### **Part 2: Object Mutation - `freeze`, `seal`, `preventExtensions**`

**6. Shallow Freeze**

```javascript
const user = Object.freeze({
  name: "Alice",
  profile: { age: 25 }
});

user.name = "Bob";
user.profile.age = 30;

console.log(user.name);
console.log(user.profile.age);

```

**Output:** `Alice`, `30`
**Explanation:** `Object.freeze()` is **shallow**. It prevents modification, addition, and deletion of top-level properties (so `name` remains "Alice"). However, nested objects (`profile`) are still mutable unless explicitly frozen.

**7. `Object.seal()` Behavior**

```javascript
const car = { brand: "Toyota" };
Object.seal(car);

car.brand = "Honda";
car.price = 10000;
delete car.brand;

console.log(car);

```

**Output:** `{ brand: "Honda" }`
**Explanation:** `Object.seal()` allows you to **modify existing properties** but prevents you from adding new properties (`price`) or deleting existing ones.

**8. `Object.preventExtensions()**`

```javascript
const book = { title: "1984" };
Object.preventExtensions(book);

book.title = "Animal Farm";
delete book.title;
book.author = "Orwell";

console.log(book);

```

**Output:** `{}`
**Explanation:** `Object.preventExtensions()` only prevents **adding new properties**. You can still modify existing properties and delete them. The output is an empty object because `title` was deleted.

**9. Strict Mode and Mutation Limitations**

```javascript
"use strict";
const obj = Object.freeze({ key: 1 });
obj.key = 2;

```

**Output:** `TypeError: Cannot assign to read only property 'key'`
**Explanation:** In non-strict mode, modifying a frozen object fails silently. In strict mode, it throws a `TypeError`.

### **Part 3: Call by Value vs Call by Reference & Copying**

**10. Mutating vs Reassigning Parameters**

```javascript
function modify(obj1, obj2) {
  obj1.name = "Changed";
  obj2 = { name: "Changed" };
}
let p1 = { name: "Original" };
let p2 = { name: "Original" };

modify(p1, p2);
console.log(p1.name, p2.name);

```

**Output:** `Changed Original`
**Explanation:** Objects are passed by reference-copy. `obj1.name` mutates the original object in memory. However, `obj2 = {...}` reassigns the local parameter variable to point to a new memory address, leaving the original `p2` unaffected.

**11. Shallow Copy with Spread**

```javascript
const a = { x: 1, y: { z: 2 } };
const b = { ...a };
b.x = 10;
b.y.z = 20;
console.log(a.x, a.y.z);

```

**Output:** `1 20`
**Explanation:** The spread operator creates a shallow copy. The primitive `x` is copied by value, but the nested object `y` is copied by reference. Modifying `b.y.z` changes `a.y.z`.

**12. Comparing Objects**

```javascript
console.log({} === {});
const obj = {};
const ref = obj;
console.log(obj === ref);

```

**Output:** `false`, `true`
**Explanation:** Objects are compared by their memory reference, not their structural contents. Two empty object literals occupy different spaces in memory.

**13. Arrays as References**

```javascript
const arr1 = [1, 2, 3];
const arr2 = arr1;
arr2.push(4);
console.log(arr1.length);

```

**Output:** `4`
**Explanation:** `arr2` is not a copy; it points to the exact same array in memory as `arr1`.

### **Part 4: The `delete` Operator**

```javascript
var x = 1;
let y = 2;
z = 3;

console.log(delete x);
console.log(delete y);
console.log(delete z);

```

**Output:** `false`, `false`, `true`
**Explanation:** You cannot delete variables declared with `var`, `let`, or `const`. However, `z = 3` without a keyword creates a configurable property on the global object (Window), which *can* be deleted.

**15. Deleting Array Elements**

```javascript
const arr = [10, 20, 30];
delete arr[1];
console.log(arr.length);
console.log(arr[1]);

```

**Output:** `3`, `undefined`
**Explanation:** Using `delete` on an array index removes the value but leaves an "empty slot". It does **not** reindex the array or change its `.length`.

**Output:** `4`
**Explanation:** The `delete` operator only deletes **own properties** of an object. `dog` does not have its own `legs` property; it inherits it. To delete it, you must do `delete Animal.prototype.legs`.

### **Part 5: Prototypes & Prototype Chaining**

**17. Shadowing Prototype Properties**

```javascript
function User(name) {
  this.name = name;
}
User.prototype.role = "Guest";

const u1 = new User("Alice");
u1.role = "Admin";
console.log(u1.role);
delete u1.role;
console.log(u1.role);

```

**Output:** `Admin`, `Guest`
**Explanation:** Assigning `u1.role = "Admin"` creates an **own property** on `u1` that shadows (hides) the prototype's `role`. Deleting the own property uncovers the underlying prototype property again.

**18. Mutating the Prototype Chain**

```javascript
const parent = { surname: "Stark" };
const child = Object.create(parent);
child.name = "Arya";

parent.surname = "Targaryen";
console.log(child.surname);

```

**Output:** `Targaryen`
**Explanation:** `child` holds a live reference to `parent` via its prototype chain. If the parent object is mutated, the changes reflect immediately on the child.

**19. `Object.create(null)**`

```javascript
const obj = Object.create(null);
console.log(obj.toString);

```

**Output:** `undefined`
**Explanation:** `Object.create(null)` creates a completely empty object with **no prototype chain** (no `__proto__`). Therefore, it does not inherit standard Object methods like `toString()`.

**20. `__proto__` vs `prototype**`

```javascript
function Car() {}
const myCar = new Car();
console.log(myCar.__proto__ === Car.prototype);
console.log(Car.__proto__ === Function.prototype);

```

**Output:** `true`, `true`
**Explanation:** An instance's `__proto__` points to its constructor's `prototype` object. Furthermore, `Car` itself is a function, so its `__proto__` points to `Function.prototype`.

### **Part 6: Iterating Prototypes and Objects**

**21. `for...in` Loop Vulnerability**

```javascript
Object.prototype.globalVar = "Oops";
const obj = { a: 1, b: 2 };

for (let key in obj) {
  console.log(key);
}

```

**Output:** `a`, `b`, `globalVar`
**Explanation:** The `for...in` loop iterates over an object's own enumerable properties **and** those inherited through its prototype chain.

**22. Defending against Prototype Iteration**

```javascript
Object.prototype.globalVar = "Oops";
const obj = { a: 1 };

for (let key in obj) {
  if (obj.hasOwnProperty(key)) {
    console.log(key);
  }
}

```

**Output:** `a`
**Explanation:** `hasOwnProperty()` is the standard defense mechanism inside `for...in` loops to ensure you only process properties physically attached to the object itself.

**23. `Object.keys()` vs `for...in**`

```javascript
const proto = { hidden: true };
const obj = Object.create(proto);
obj.visible = true;

console.log(Object.keys(obj));

```

**Output:** `["visible"]`
**Explanation:** Unlike `for...in`, `Object.keys()` (and `Object.entries()`, `Object.values()`) strictly return the object's **own enumerable properties**, ignoring the prototype chain completely.

**24. Non-enumerable Properties**

```javascript
const obj = {};
Object.defineProperty(obj, 'secret', {
  value: 42,
  enumerable: false

console.log(obj.secret);
console.log(Object.keys(obj));

```

**Output:** `42`, `[]`
**Explanation:** Properties defined via `defineProperty` are non-enumerable by default. They can be accessed directly but will not show up in iterations.

```javascript
arr.length = 2;
console.log(arr);

```

**Output:** `[1, 2]`
**Explanation:** The `.length` property of an array is not just a getter; it is a setter. Reducing the length permanently deletes elements beyond the new length.

**27. String Keys vs Numeric Keys**

```javascript
const obj = { 1: "a", "1": "b", [1]: "c" };
console.log(Object.keys(obj));
console.log(obj[1]);

```

**Output:** `["1"]`, `"c"`
**Explanation:** Object keys are always converted to strings. `1`, `"1"`, and the computed property `[1]` all resolve to the exact same string key `"1"`, constantly overwriting each other. The last one wins.

**28. Array `push` return value**

```javascript

const result = arr.push(3, 4);
console.log(result);

```

**Output:** `4`
**Explanation:** The `push()` method mutates the array but returns the **new length** of the array, not the array itself.

**29. Object Coercion as Keys**

```javascript
const b = { key: 'b' };
const c = { key: 'c' };

a[b] = 123;
a[c] = 456;
console.log(a[b]);

```

**Output:** `456`
**Explanation:** Objects used as keys are implicitly coerced to the string `"[object Object]"`. Both `b` and `c` become the exact same key, so `a[c]` overwrites `a[b]`.

**30. Sparse Arrays and Methods**

```javascript

console.log(arr.map(x => x * 2));

```

**Output:** `[2, empty, 6]` (or `[2, , 6]`)
**Explanation:** Array methods like `map`, `forEach`, and `filter` skip "empty slots" (uninitialized indexes) in sparse arrays. They do not treat them as `undefined`.

**31. `instanceof` with Arrays**

```javascript
console.log(arr instanceof Array);
console.log(arr instanceof Object);

```

**Output:** `true`, `true`
**Explanation:** Because of the prototype chain, `Array.prototype` inherits from `Object.prototype`.

**32. The `typeof null` Bug**

```javascript
console.log(null instanceof Object);
```

**Output:** `"object"`, `false`
**Explanation:** `typeof null === "object"` is a famous, unfixable legacy bug in JavaScript. However, `null` is not actually an instance of `Object`, which is why the second check is false.

**33. Deep Copying using JSON**

```javascript
console.log(typeof b.date);
console.log(b.func);
```

**Explanation:** `JSON.stringify` is a quick way to deep copy, but it has flaws: Dates are converted to strings, and Functions/Undefined values are completely stripped out.

**Output:** `10`
**Explanation:** In non-strict mode, the `arguments` object is linked to the function's parameters. Modifying `arguments[0]` directly mutates the parameter `a`. (In strict mode, this link is severed, and output would be `1`).

**Output:** `true`, `false`
**Explanation:** Rest parameters (`...args`) generate a true JavaScript Array. The legacy `arguments` object is an "Array-like object" (it has length and indexes, but lacks array methods like `map` or `push`).

**36. Reassigning `this**`

```javascript
new User();

```

**Output:** `SyntaxError: Invalid left-hand side in assignment`
**Explanation:** You cannot directly reassign the `this` keyword. It is not a variable; it is a binding context provided by the JavaScript engine.

**37. Calling Constructor without `new**`

**38. The `in` operator vs `hasOwnProperty**`

```javascript
obj.b = 2;

console.log('a' in obj);
console.log(obj.hasOwnProperty('a'));

```

**Output:** `true`, `false`
**Explanation:** The `in` operator checks both own properties and prototype properties. `hasOwnProperty` strictly checks for properties defined directly on the object itself.

**39. Freezing Arrays**

```javascript

numbers.sort();
console.log(numbers);

```

**Output:** `[1, 10, 20, 5]`
**Explanation:** By default, the `.sort()` method converts all elements to strings and compares their UTF-16 character codes. Alphabetically, `"10"` comes before `"20"`, and `"20"` comes before `"5"`.

**42. `NaN` in Arrays: `indexOf` vs `includes**`

```javascript
const arr = [NaN];
console.log(arr.indexOf(NaN));
console.log(arr.includes(NaN));

```

**Output:** `-1`, `true`
**Explanation:** `indexOf` uses strict equality (`===`), and in JavaScript, `NaN === NaN` is false, so it cannot find it. `includes` was introduced later in ES7 and uses a different internal comparison algorithm (SameValueZero) that correctly identifies `NaN`.

**43. Mutating Array Methods: `slice` vs `splice**`

```javascript
console.log(arr2.length);
```

**Output:** `4`, `2`
**Explanation:** `.slice()` returns a shallow copy of a portion of an array and **does not mutate** the original array. `.splice()` extracts elements and **mutates** the original array by completely removing those elements.

**44. Array Indexes as Strings**

```javascript
const source = { a: 1, nested: { b: 2 } };
```

**Explanation:** The array `users` stores a reference to the `user` object in memory, not a detached copy. Mutating the object via the `user` variable is immediately reflected inside the array.

**Explanation:** When an array is used as an object key, JavaScript implicitly calls `.toString()` on it. The array `[1, 2, 3]` stringifies to `"1,2,3"`, which becomes the actual key in the object.

**49. Self-Referencing Objects and Stringification**

**51. Reassigning the Prototype Object**

**53. `Object.create(null)` vs `{}**`

```javascript
console.log('toString' in obj2);
```

**Output:** `true`, `false`
**Explanation:** `{}` inherits from `Object.prototype`, giving it access to built-in methods like `toString`. `Object.create(null)` creates an object completely devoid of a prototype chain.

**54. Function Prototype Chain**

```javascript
console.log(test.__proto__ === Function.prototype);
console.log(Function.prototype.__proto__ === Object.prototype);
```

**Output:** `true`, `true`

**55. Prototype Shadowing with `this**`

```javascript
function Widget() {}
Widget.prototype.id = 1;
Widget.prototype.getId = function() {
  this.id = 2;
  return this.id;
};

console.log(w1.id);
console.log(w1.getId());
console.log(Widget.prototype.id);

```

**Output:** `1`, `2`, `1`
**Explanation:** Initially, `w1.id` falls back to the prototype (`1`). Calling `getId()` executes `this.id = 2`, which creates a new **own property** `id` directly on the `w1` instance. This shadows the prototype's `id`, but the prototype's `id` remains `1`.

### **Part 11: Edge Cases with `call`, `bind`, and Context**

**56. `bind` with the `new` Keyword**

```javascript
function Person(name) {
  this.name = name;
}
const BoundPerson = Person.bind({ name: "Fake" });

const user = new BoundPerson("Real");
console.log(user.name);

```

**Output:** `"Real"`
**Explanation:** When a function is invoked with the `new` keyword, the JavaScript engine creates a brand new object and forces `this` to point to that new object. This **overrides** any `this` context previously set by `.bind()`.

**57. Arrow Functions as Methods Inheritance**

```javascript
function User() {
  this.name = "Alice";
  this.sayHi = () => {
    console.log(this.name);
  };
}
const u = new User();
const func = u.sayHi;
func();

```

**Output:** `"Alice"`
**Explanation:** When `new User()` is called, the arrow function `sayHi` is created. Arrow functions permanently bind to the lexical `this` of their surrounding scope at the time of creation. Inside the constructor, `this` is the new instance (`u`). So even if we extract `func`, it remembers `u` as its context.

**58. Chaining `call` on `bind**`

```javascript
function greet() {
  console.log(this.name);
}
const bound = greet.bind({ name: "First" });
bound.call({ name: "Second" });

```

**Output:** `"First"`
**Explanation:** `.bind()` permanently locks the `this` context. You cannot override a bound function's context using `.call()` or `.apply()`.

**59. Passing Array to `Math.max` without `apply**`

```javascript
const nums = [1, 2, 3];
console.log(Math.max(nums));
console.log(Math.max(...nums));

```

**Output:** `NaN`, `3`
**Explanation:** `Math.max` expects individual number arguments. Passing a whole array coerces it to a string `"1,2,3"`, which cannot be converted to a valid number, resulting in `NaN`. The spread operator (`...`) correctly unpacks it.

**60. `apply` to merge arrays**

```javascript
const arr1 = [1, 2];
const arr2 = [3, 4];
Array.prototype.push.apply(arr1, arr2);
console.log(arr1);

```

**Output:** `[1, 2, 3, 4]`
**Explanation:** This is a classic ES5 trick to push an entire array into another array. `apply` takes `arr2` and spreads its elements as individual arguments into `push`, mutating `arr1`.


**Output:** `42`, `42`, `[]`
**Explanation:** When you use `Object.defineProperty`, the boolean attributes `writable`, `enumerable`, and `configurable` all default to `false`. Therefore, the value cannot be overwritten (remains `42`), and it won't show up in `Object.keys()`.

**62. Deleting standard properties vs configured properties**

```javascript
const config = { a: 1 };
Object.defineProperty(config, "b", { value: 2, configurable: false });

delete config.a;
delete config.b;

console.log(config);

```

**Output:** `{ b: 2 }`
**Explanation:** Standard object literal properties are configurable by default, so `a` is deleted. Properties defined with `configurable: false` cannot be deleted.

**63. `delete` on the `arguments` object**

```javascript
function test(a, b) {
  delete arguments[0];
  console.log(a);
  console.log(arguments[0]);
}
test(10, 20);

```

**Output:** `10`, `undefined`
**Explanation:** Deleting an index from the `arguments` object severs the connection between the parameter and the `arguments` object. The parameter `a` retains its value (`10`), but `arguments[0]` is gone.

**64. Freezing deeply nested objects**

```javascript
const user = Object.freeze({
  prefs: { theme: "dark" }
});
Object.preventExtensions(user.prefs);

user.prefs.theme = "light";
user.prefs.font = "Arial";

console.log(user.prefs);

```

**Output:** `{ theme: "light" }`
**Explanation:** `Object.freeze` is shallow, so `prefs` is NOT frozen. We applied `preventExtensions` to `prefs`, which stops new properties (`font`) from being added, but still allows existing properties (`theme`) to be mutated.

**65. `delete` returns true for non-existent properties**

```javascript
const obj = { x: 1 };
console.log(delete obj.x);
console.log(delete obj.y);

```

**Output:** `true`, `true`
**Explanation:** The `delete` operator returns `true` if the operation was successful, which *includes* cases where the property didn't exist in the first place (because it successfully ensured the property is not there).

### **Part 13: Tricky Iterations & Function Passing**

**66. Mutating Arrays during `forEach**`

```javascript
const arr = [1, 2, 3, 4];
arr.forEach((val, index) => {
  if (val === 2) arr.shift();
  console.log(val);
});

```

**Output:** `1, 2, 4`
**Explanation:** `forEach` does not iterate over a snapshot; it iterates over the live array based on index.

* Index 0: Prints 1.
* Index 1: Prints 2. Removes first element (`1`). Array is now `[2, 3, 4]`.
* Index 2: The element at index 2 is now `4`. It skips `3` completely because `3` shifted into index 1, which has already been processed. Prints 4.

**67. Map with `parseInt**`

```javascript
const numbers = ["10", "10", "10"];
console.log(numbers.map(parseInt));

```

**Output:** `[10, NaN, 2]`
**Explanation:** `map` passes three arguments to its callback: `(value, index, array)`. `parseInt` takes two arguments: `(string, radix)`.

* `parseInt("10", 0)` -> 10.
* `parseInt("10", 1)` -> NaN (1 is an invalid radix).
* `parseInt("10", 2)` -> 2 (binary 10).

**68. Destructuring and References**

```javascript
let obj = { x: { y: 1 } };
let { x } = obj;
x.y = 2;
console.log(obj.x.y);

```

**Output:** `2`
**Explanation:** Destructuring an object extracts the reference to the nested object `x`, it does not clone it. Modifying the destructured `x` mutates the original `obj`.

**69. Call by Value vs Reference in Primitives**

```javascript
function change(str) {
  str = str + " World";
}
let greeting = "Hello";
change(greeting);
console.log(greeting);

```

**Output:** `"Hello"`
**Explanation:** Primitives (Strings, Numbers, Booleans) are passed by value. The parameter `str` gets a copy of `"Hello"`. Modifying `str` inside the function does not affect the global `greeting` variable.

**70. The Empty Array Truthiness**

```javascript
if ([]) {
  console.log([] == false);
  console.log([] === false);
}

```

**Output:** `true`, `false`
**Explanation:** An empty array `[]` is a truthy value, so the `if` block executes. However, in loose equality (`[] == false`), the array is coerced into a primitive (empty string `""`), which coerces to `false` (so `false == false` is true). Strict equality (`===`) checks types without coercion, so an Array is not equal to a Boolean.

### **Part 14: Type Coercion & Truthiness (The "Weird" Parts)**

**71. Relational Operator Coercion**

```javascript
console.log(1 < 2 < 3);
console.log(3 > 2 > 1);

```

**Output:** `true`, `false`
**Explanation:** Operators evaluate left-to-right.

* `1 < 2` evaluates to `true`. Then `true < 3` coerces `true` to `1`, and `1 < 3` is `true`.
* `3 > 2` evaluates to `true`. Then `true > 1` coerces `true` to `1`, and `1 > 1` is `false`.

**72. The Classic Banana**

```javascript
console.log("b" + "a" + + "a" + "a");

```

**Output:** `"baNaNa"`
**Explanation:** The unary plus operator `+ "a"` attempts to convert `"a"` to a number, which results in `NaN`. The expression becomes `"b" + "a" + NaN + "a"`, which concatenates into `"baNaNa"`.

**73. String vs Boolean Instantiation**

```javascript
console.log(!!String(false));
console.log(!!Boolean(false));

```

**Output:** `true`, `false`
**Explanation:** `String(false)` creates the string `"false"`. A non-empty string is truthy, so `!!` makes it `true`. `Boolean(false)` creates the boolean `false`, and `!!false` is `false`.

**74. The Null Relational Paradox**

```javascript
console.log(null == 0);
console.log(null > -1);
console.log(null < 1);
console.log(null >= 0);

```

**Output:** `false`, `true`, `true`, `true`
**Explanation:** Loose equality (`==`) strictly treats `null` as only equal to `undefined`. However, relational operators (`>`, `<`, `>=`) forcefully coerce `null` to the number `0`. So `0 >= 0` is `true`.

**75. `Object.is()` vs `===**`

```javascript
console.log(NaN === NaN);
console.log(Object.is(NaN, NaN));
console.log(-0 === 0);
console.log(Object.is(-0, 0));

```

**Output:** `false`, `true`, `true`, `false`
**Explanation:** `===` has two specific quirks: `NaN` is not equal to itself, and `-0` is considered equal to `0`. `Object.is()` fixes these quirks, returning strictly identical values.

### **Part 15: Advanced Hoisting & Execution Context**

**76. Variable vs Function Hoisting Collision**

```javascript
var a = 1;
function a() {}

console.log(typeof a);

```

**Output:** `"number"`
**Explanation:** Both the variable declaration and the function declaration are hoisted. Function declarations take priority during the creation phase, so `a` is initially a function. However, during the execution phase, the assignment `var a = 1` overwrites the function with a number.

**77. Function Expressions and Hoisting**

```javascript
console.log(typeof foo);
console.log(typeof bar);

var foo = function() {};
function bar() {}

```

**Output:** `"undefined"`, `"function"`
**Explanation:** Function declarations (`bar`) are fully hoisted, meaning their definition is available immediately. Function expressions assigned to variables (`foo`) only hoist the variable declaration (`var foo = undefined`), not the function assignment.

**78. Block-Scoped Functions**

```javascript
var foo = 1;
if (true) {
  function foo() {}
  foo = 2;
}
console.log(foo);

```

**Output:** `1` (in most modern browser environments)
**Explanation:** Function declarations inside blocks behave strangely. The block creates a local scoped `foo` function. Assigning `foo = 2` only affects the block-scoped `foo`. The global `foo` remains `1`. (Note: In strict mode, block-scoped functions are strictly locked to the block).

**79. The `arguments` Array-like Object**

```javascript
function checkArgs(a) {
  arguments[0] = 20;
  console.log(a);
}
checkArgs(10);

```

**Output:** `20`
**Explanation:** In non-strict mode, the `arguments` object is bidirectionally linked to the named parameters. Changing `arguments[0]` directly changes the parameter `a`. (In strict mode `"use strict"`, the output would be `10`).

**80. Method Invocation via Array Index (Context Loss)**

```javascript
const obj = {
  name: "Raj",
  sayHi() {
    console.log(this.name);
  }
};
const arr = [obj.sayHi, "Amit"];
arr[0]();

```

**Output:** `undefined`
**Explanation:** When you call `arr[0]()`, the `this` context becomes the object making the call—which is the array itself (`arr`). The array does not have a `name` property, so it returns `undefined`.

### **Part 16: Classes, `super`, and OOP**

**81. Returning Values from Constructors**

```javascript
class Person {
  constructor() {
    this.name = "Alice";
    return { name: "Bob" };
  }
}
const p = new Person();
console.log(p.name);

```

**Output:** `"Bob"`
**Explanation:** If a constructor explicitly returns an object, that object completely replaces the newly constructed instance (`this`). If it returns a primitive (like a string or number), the primitive is ignored and `this` is returned.

**82. The TDZ of `this` in Subclasses**

```javascript
class Parent {}
class Child extends Parent {
  constructor() {
    this.name = "Child";
    super();
  }
}
const c = new Child();

```

**Output:** `ReferenceError: Must call super constructor in derived class before accessing 'this'`
**Explanation:** In a derived class, you are not allowed to use the `this` keyword inside the constructor until *after* you have called `super()`.

**83. Class Methods vs Class Properties (Arrow Functions)**

```javascript
class Counter {
  count = 0;
  increment = () => this.count++;
  decrement() { this.count--; }
}
const c = new Counter();
console.log(c.hasOwnProperty("increment"));
console.log(c.hasOwnProperty("decrement"));

```

**Output:** `true`, `false`
**Explanation:** Standard class methods (`decrement`) are attached to the prototype (`Counter.prototype`). Arrow functions assigned as class properties (`increment`) are attached directly to every single **instance** as an own property.

**84. Static Methods and `this**`

```javascript
class Car {
  static type = "Vehicle";
  static getType() {
    return this.type;
  }
}
const myCar = new Car();
console.log(Car.getType());
console.log(myCar.getType());

```

**Output:** `"Vehicle"`, `TypeError: myCar.getType is not a function`
**Explanation:** Static methods belong to the class constructor itself, not the instances or the prototype. Therefore, `this` inside a static method refers to the class (`Car`), and the instance (`myCar`) cannot access static methods at all.

**85. Private Fields vs Object Keys**

```javascript
class Secret {
  #password = "12345";
  getPassword() {
    return this.#password;
  }
}
const s = new Secret();
console.log(Object.keys(s));
console.log(s.getPassword());

```

**Output:** `[]`, `"12345"`
**Explanation:** Private class fields (prefixed with `#`) are deeply encapsulated. They are non-enumerable, do not show up in `Object.keys()`, and cannot be accessed from outside the class.

### **Part 17: Generators & Iterators**

**86. Basic Generator Yielding**

```javascript
function* gen() {
  yield 1;
  yield 2;
  return 3;
}
const iterator = gen();
console.log(iterator.next().value);
console.log(iterator.next().value);
console.log(iterator.next().value);

```

**Output:** `1`, `2`, `3`
**Explanation:** Generators pause execution at each `yield`. The `next()` method resumes execution. The final `return` statement sets the final `value` and changes the `done` status to `true`.

**87. Passing Values into Generators**

```javascript
function* mathGen() {
  const x = yield 10;
  yield x * 2;
}
const iter = mathGen();
console.log(iter.next().value);
console.log(iter.next(5).value);

```

**Output:** `10`, `10`
**Explanation:**

* The first `next()` runs up to the first `yield` and returns `10`. The generator pauses.
* The second `next(5)` passes `5` *into* the generator, replacing the entire `yield 10` expression with `5`. So `x` becomes 5, and it yields `5 * 2`, which is `10`.

**88. Delegating Generators (`yield*`)**

```javascript
function* subGen() {
  yield "a";
  yield "b";
}
function* mainGen() {
  yield 1;
  yield* subGen();
  yield 2;
}
const it = mainGen();
console.log([...it]);

```

**Output:** `[1, "a", "b", 2]`
**Explanation:** The `yield*` operator delegates the yielding process to another generator or iterable, exhausting it entirely before continuing with the outer generator.

### **Part 18: Obscure Operators & Edge Cases**

**89. The Comma Operator**

```javascript
let x = (1, 2, 3);
console.log(x);

```

**Output:** `3`
**Explanation:** The comma operator evaluates each of its operands from left to right and returns the value of the very last operand.

**90. Comma Operator and Context Loss**

```javascript
const obj = {
  name: "Raj",
  sayHi() { return this.name; }
};
const result = (0, obj.sayHi)();
console.log(result);

```

**Output:** `undefined`
**Explanation:** `(0, obj.sayHi)` uses the comma operator. It evaluates `0`, then evaluates `obj.sayHi`, and returns the *unbound function reference*. When this unbound function is invoked with `()`, it runs in the global context, losing the `this` binding to `obj`.

**91. Array Coercion with Unary Plus**

```javascript
console.log(+[]);
console.log(+[2]);
console.log(+[2, 3]);

```

**Output:** `0`, `2`, `NaN`
**Explanation:** Unary `+` triggers numeric coercion.

* `[]` becomes `""`, which becomes `0`.
* `[2]` becomes `"2"`, which becomes `2`.
* `[2, 3]` becomes `"2,3"`, which cannot be a number, resulting in `NaN`.

**92. Short-Circuit Evaluation Priority**

```javascript
let a = 0;
let b = 1;
let c = 2;

console.log(a || b && c);

```

**Output:** `2`
**Explanation:** The Logical AND (`&&`) has higher precedence than Logical OR (`||`). First, `b && c` evaluates (`1 && 2` is `2`). Then, `a || 2` evaluates (`0 || 2` is `2`).

**93. The `in` Operator with Arrays**

```javascript
const arr = [10, 20, 30];
console.log(10 in arr);
console.log(1 in arr);

```

**Output:** `false`, `true`
**Explanation:** The `in` operator checks if a **key/index** exists in the object/array, not the value. There is no index `10` in the array. However, index `1` exists (it holds the value `20`).

**94. Mutating Array Prototype Methods**

```javascript
const arr = [1, 2, 3];
const reverse = arr.reverse;
reverse.call(arr);
console.log(arr);

```

**Output:** `[3, 2, 1]`
**Explanation:** `reverse()` mutates the array in place. By extracting the function reference and using `.call(arr)`, we pass the array back as the `this` context, allowing it to mutate the original array properly.

**95. Safely Checking Undeclared Variables**

```javascript
console.log(typeof undeclaredVar);
if (undeclaredVar) {
  console.log("Exists");
}

```

**Output:** `"undefined"`, then `ReferenceError: undeclaredVar is not defined`
**Explanation:** `typeof` is the only safe way to interact with a completely undeclared variable (it returns `"undefined"` without crashing). Attempting to read it directly in an `if` statement throws a `ReferenceError`.

**96. Symbols as Keys**

```javascript
const sym = Symbol("id");
const obj = { [sym]: 1, id: 2 };

console.log(Object.keys(obj));
console.log(obj[sym]);

```

**Output:** `["id"]`, `1`
**Explanation:** Properties keyed by Symbols are completely ignored by `Object.keys()`, `for...in` loops, and `JSON.stringify`. However, they can still be accessed directly via the Symbol reference.

**97. Reassigning Primitives Properties**

```javascript
let str = "Hello";
str.custom = "World";
console.log(str.custom);

```

**Output:** `undefined`
**Explanation:** When you try to add a property to a primitive string, JavaScript temporarily boxes it into a `String` object, assigns the property, and then immediately throws the object away. Therefore, `str.custom` is lost forever.

**98. The `void` Operator**

```javascript
function test() {
  return void (2 + 2);
}
console.log(test());

```

**Output:** `undefined`
**Explanation:** The `void` operator evaluates whatever expression follows it and then forces the return value to be `undefined`.

**99. Falsy Object Wrapper**

```javascript
const bool = new Boolean(false);
if (bool) {
  console.log("Truthy");
} else {
  console.log("Falsy");
}

```

**Output:** `"Truthy"`
**Explanation:** `new Boolean(false)` creates a Boolean *object*. In JavaScript, all objects are truthy when evaluated in a boolean context (like an `if` statement), regardless of their internal primitive value.

**100. Tagged Template Literals**

```javascript
function tag(strings, ...values) {
  console.log(strings[0]);
  console.log(values[0]);
}
const name = "Raj";
tag`Hello ${name}!`;

```

**Output:** `"Hello "`, `"Raj"`
**Explanation:** Tagged templates allow you to parse template literals with a function. The first argument is an array of the literal string segments (`["Hello ", "!"]`). The rest parameters (`...values`) contain the evaluated expressions (`"Raj"`).
