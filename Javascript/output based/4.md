Here is a deep-dive batch focused on **Arrays, Objects, Destructuring, and Reference Mutation**. These questions test your understanding of how JavaScript stores data in memory (by value vs. by reference) and how modern ES6 syntax interacts with that memory.

---

## 1. The Shallow Copy Trap (Spread Operator)

**Question:**

```javascript
const original = { a: 1, b: { c: 2 } };
const copy = { ...original };

copy.a = 10;
copy.b.c = 20;

console.log(original.a);
console.log(original.b.c);

```

**Output:**

```text
1
20

```

* **Explanation:** The spread operator (`...`) creates a **shallow copy** of an object. Top-level primitive values (like `a`) are copied by value, so changing `copy.a` does not affect `original.a`. However, nested objects (like `b`) are copied by reference. Both `original.b` and `copy.b` point to the exact same object in memory, so mutating `copy.b.c` also mutates `original.b.c`.

## 2. Reference Mutation vs. Reassignment in Functions

**Question:**

```javascript
function updateProfile(user) {
  user.age = 25;
  user = { name: "Bob", age: 30 };
  return user;
}

const myUser = { name: "Alice", age: 20 };
const updatedUser = updateProfile(myUser);

console.log(myUser.name, myUser.age);
console.log(updatedUser.name, updatedUser.age);

```

**Output:**

```text
Alice 25
Bob 30

```

* **Explanation:** JavaScript is "pass by value," but for objects, the "value" passed is the reference to the object.

1. `user.age = 25` mutates the original object in memory, changing Alice's age to 25.
2. `user = { name: "Bob", age: 30 }` reassigns the local `user` parameter to point to a completely **new** object in memory. This does *not* overwrite the original `myUser` object.
3. The function returns the new "Bob" object, which is stored in `updatedUser`.

## 3. Destructuring with Aliases and Defaults

**Question:**

```javascript
const settings = { theme: "dark", fontSize: 16 };

const { 
  theme: mode, 
  fontSize, 
  layout = "grid" 
} = settings;

console.log(mode);
console.log(layout);
console.log(settings.layout);

```

**Output:**

```text
dark
grid
undefined

```

* **Explanation:**
* `theme: mode` extracts the value of `theme` but renames the local variable to `mode`.
* `layout = "grid"` provides a default value during destructuring because `layout` doesn't exist on the `settings` object.
* **Crucially**, destructuring with a default value does *not* mutate the original object. Therefore, `settings.layout` remains `undefined`.

## 4. Array Destructuring and the Rest Operator

**Question:**

```javascript
const colors = ["red", "green", "blue", "yellow"];

const [first, , ...rest] = colors;

console.log(first);
console.log(rest.length);
console.log(rest[0]);

```

**Output:**

```text
red
2
blue

```

* **Explanation:** Array destructuring is order-dependent.
* `first` grabs index 0 (`"red"`).
* The empty comma `, ,` skips index 1 (`"green"`).
* The rest operator `...rest` gathers all remaining elements into a new array. It skips "green", so `rest` becomes `["blue", "yellow"]`. Therefore, its length is 2, and its 0th index is `"blue"`.

## 5. `const` Arrays and Reassignment

**Question:**

```javascript
const numbers = [1, 2];

numbers[2] = 3;
numbers.push(4);

try {
  numbers = [1, 2, 3, 4];
} catch (e) {
  console.log("Error caught!");
}

console.log(numbers);

```

**Output:**

```text
Error caught!
[ 1, 2, 3, 4 ]

```

* **Explanation:** Declaring an object or array with `const` does not make it immutable. It only prevents the variable identifier (`numbers`) from being reassigned to a new memory address. Mutating the array's contents via `numbers[2]` or `numbers.push()` is perfectly valid. The direct reassignment `numbers = [...]` throws a `TypeError`, which is caught by the `try...catch` block.

## 6. Object Keys as Strings

**Question:**

```javascript
const obj = { 1: "a", 2: "b", 3: "c" };
const set = new Set([1, 2, 3]);

console.log(obj.hasOwnProperty(1));
console.log(obj.hasOwnProperty("1"));
console.log(set.has(1));
console.log(set.has("1"));

```

**Output:**

```text
true
true
true
false

```

* **Explanation:** In standard JavaScript objects, all keys are implicitly converted to strings under the hood. So `obj[1]` and `obj["1"]` refer to the exact same property. However, modern structures like `Set` and `Map` maintain strict type equality (they do not coerce types). Therefore, `set.has(1)` is `true`, but `set.has("1")` is `false`.
