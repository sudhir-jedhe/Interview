React’s functional component model is incredibly powerful, but it relies heavily on closures and referential equality. If you don't perfectly understand how JavaScript memory works under the hood, React will punish you with infinite loops, stale data, and silent rendering failures.

Here is a masterclass batch of the most notorious **React anti-patterns and `useEffect` disasters**, and how to fix them.

---

### 1. The Infinite `useEffect` Loop (Referential Inequality)

❌ **The Bug:**
You pass an object or array as a dependency to `useEffect`. The effect runs, triggers a state update, the component re-renders, and the browser crashes from an infinite loop.

```javascript
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  // BUG: This object is created brand new on EVERY render
  const fetchOptions = { method: 'GET', headers: { token: "123" } };

  useEffect(() => {
    fetch(`/api/users/${userId}`, fetchOptions)
      .then(res => res.json())
      .then(data => setUser(data));
      
  // React sees fetchOptions is a NEW object memory reference every render. 
  // It runs the effect again, sets state again, loops forever.
  }, [userId, fetchOptions]); 

  return <div>{user?.name}</div>;
}

```

✅ **The Fix:**
Move static objects **outside** the component, or memoize them using `useMemo` so their memory reference stays perfectly stable across renders.

```javascript
// Fix 1: If it doesn't depend on component scope, move it outside!
const fetchOptions = { method: 'GET', headers: { token: "123" } };

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    fetch(`/api/users/${userId}`, fetchOptions)
      .then(res => res.json())
      .then(data => setUser(data));
  }, [userId]); // fetchOptions is completely removed from deps

  return <div>{user?.name}</div>;
}

```

### 2. The Stale Closure Trap

❌ **The Bug:**
You set up an event listener or an interval inside a `useEffect` that runs only once on mount. When the callback fires, it uses the state variable, but the state is permanently stuck at its initial value.

```javascript
function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const timerId = setInterval(() => {
      // BUG: 'count' is permanently locked at 0 in this closure!
      setCount(count + 1); 
    }, 1000);
    
    return () => clearInterval(timerId);
  }, []); // Empty dependency array

  return <div>{count}</div>;
}

```

✅ **The Fix:**
Use the **functional state updater** pattern. This bypasses the closure entirely by asking React to inject the most up-to-date state at the exact moment the update runs.

```javascript
function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const timerId = setInterval(() => {
      // FIX: prevCount is guaranteed to be accurate by React
      setCount(prevCount => prevCount + 1); 
    }, 1000);
    
    return () => clearInterval(timerId);
  }, []); 

  return <div>{count}</div>;
}

```

### 3. The Unnecessary `useEffect` (Derived State Anti-Pattern)

❌ **The Bug:**
You have a list of items, and you want to filter them when a search query changes. You create a second state variable and use `useEffect` to sync them. This causes a "double render"—the component renders once with the old filtered list, then immediately renders again with the new one, causing UI stutter.

```javascript
function ProductList({ products }) {
  const [search, setSearch] = useState("");
  const [filteredProducts, setFilteredProducts] = useState(products);

  // BUG: Anti-pattern. Causes unnecessary double-renders.
  useEffect(() => {
    setFilteredProducts(products.filter(p => p.name.includes(search)));
  }, [search, products]);

  return (
    // ... UI
  );
}

```

✅ **The Fix:**
If a value can be calculated from existing state or props, **calculate it directly during the render phase**. You do not need state, and you do not need `useEffect`.

```javascript
function ProductList({ products }) {
  const [search, setSearch] = useState("");

  // FIX: Derived state. Calculates naturally during render.
  // (Wrap in useMemo ONLY if the array is massive and math is heavy)
  const filteredProducts = products.filter(p => p.name.includes(search));

  return (
    // ... UI
  );
}

```

### 4. Direct State Mutation (The UI Won't Update)

❌ **The Bug:**
You have an array in state. You push a new item to it and call `setState`, but the UI refuses to update.

```javascript
function TodoList() {
  const [todos, setTodos] = useState(["Eat", "Sleep"]);

  const addTodo = (newTodo) => {
    // BUG: Mutating the existing array reference in memory
    todos.push(newTodo); 
    setTodos(todos); 
  };
  
  // ...
}

```

✅ **The Fix:**
React uses strict equality (`===`) to check if state changed. If you pass the exact same array reference back, React bails out of the render. You must create a **brand new array** in memory.

```javascript
function TodoList() {
  const [todos, setTodos] = useState(["Eat", "Sleep"]);

  const addTodo = (newTodo) => {
    // FIX: Spread operator creates a fresh array reference
    setTodos([...todos, newTodo]); 
  };
  
  // ...
}

```

### 5. The Fetch Race Condition (Missing Cleanup)

❌ **The Bug:**
The user clicks on "Profile 1", then immediately clicks "Profile 2". The network request for Profile 2 is fast and resolves first. Then, the slow request for Profile 1 resolves, overwriting the UI with Profile 1's data, even though the user is looking at Profile 2.

```javascript
function ProfileInfo({ userId }) {
  const [data, setData] = useState(null);

  useEffect(() => {
    // BUG: No cancellation. Whichever request finishes LAST wins.
    fetch(`/api/user/${userId}`)
      .then(res => res.json())
      .then(userData => setData(userData));
  }, [userId]);
  
  // ...
}

```

✅ **The Fix:**
Use an `AbortController` (or a simple boolean flag) in the `useEffect` cleanup function to ignore or cancel requests from previous, stale renders.

```javascript
function ProfileInfo({ userId }) {
  const [data, setData] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    fetch(`/api/user/${userId}`, { signal: controller.signal })
      .then(res => res.json())
      .then(userData => setData(userData))
      .catch(err => {
        if (err.name === 'AbortError') {
          console.log('Fetch aborted for stale render');
        }
      });

    // FIX: Cleanup runs when userId changes, cancelling the old fetch!
    return () => controller.abort();
  }, [userId]);
  
  // ...
}

```
