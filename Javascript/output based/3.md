Here is a deep-dive batch focused on **Closures, Lexical Scope, and the `this` keyword**. These concepts form the backbone of JavaScript's execution context and are notorious for tricking candidates.

---

## 1. The Context Loss (Implicit Binding)

**Question:**

```javascript
const user = {
  name: "Raj",
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

const sayHello = user.greet;
sayHello();

```

**Output:**

```text
Hello, undefined

```

* **Explanation:** When you call `user.greet()`, `this` is bound to the `user` object. However, when you assign `user.greet` to the variable `sayHello`, you are only copying the function reference. Calling `sayHello()` executes it as a regular function in the global scope. In the global object (or Window), `name` is undefined.

## 2. Arrow Functions vs. Regular Functions

**Question:**

```javascript
const profile = {
  name: "Priya",
  
  regularFunc: function() {
    const arrowFunc = () => {
      console.log(this.name);
    };
    arrowFunc();
  },
  
  arrowFuncProp: () => {
    console.log(this.name);
  }
};

profile.regularFunc();
profile.arrowFuncProp();

```

**Output:**

```text
Priya
undefined

```

* **Explanation:**

1. `regularFunc` is a standard method, so its `this` is the `profile` object. The `arrowFunc` inside it does not have its own `this`; it inherits it lexically from `regularFunc`. So it logs "Priya".
2. `arrowFuncProp` is an arrow function declared directly on the object. Arrow functions do not bind `this` to the object they are defined in. They inherit `this` from the outer scope where the object was created (the global scope), where `name` is undefined.

## 3. Lexical Scope and Hoisting

**Question:**

```javascript
var a = 10;

function testScope() {
  console.log(a);
  var a = 20;
}

testScope();

```

**Output:**

```text
undefined

```

* **Explanation:** Inside `testScope`, the declaration `var a` is hoisted to the top of the function scope, but its initialization (`= 20`) is not. This hoisted local variable shadows the global variable `a = 10`. When `console.log(a)` runs, the local `a` exists but hasn't been assigned a value yet, so it is `undefined`.

## 4. Closures in a Loop (The Classic `var` Trap)

**Question:**

```javascript
function createFunctions() {
  let funcs = [];
  for (var i = 0; i < 3; i++) {
    funcs.push(function() {
      console.log(i);
    });
  }
  return funcs;
}

const myFuncs = createFunctions();
myFuncs[0]();
myFuncs[1]();
myFuncs[2]();

```

**Output:**

```text
3
3
3

```

* **Explanation:** Because `var` is function-scoped (not block-scoped), there is only one shared variable `i` for the entire `createFunctions` scope. By the time the pushed functions are actually invoked, the loop has finished and `i` has reached `3`. Every closure references that exact same `i`. (Fix: use `let` instead of `var`).

## 5. `call()` and `bind()` on Arrow Functions

**Question:**

```javascript
const person = { name: "Anil" };

const regularGreet = function() { 
  console.log(this.name); 
};

const arrowGreet = () => { 
  console.log(this.name); 
};

regularGreet.call(person);
arrowGreet.call(person);

```

**Output:**

```text
Anil
undefined

```

* **Explanation:** `call`, `apply`, and `bind` are used to explicitly set the `this` context for a function. This works perfectly for `regularGreet`. However, arrow functions **permanently** lock in their `this` value based on their lexical scope at creation. You cannot override an arrow function's `this` using `call`, `apply`, or `bind`.

## 6. Live References in Closures

**Question:**

```javascript
let multiplier = 2;

function createMultiplier() {
  return function(value) {
    return value * multiplier;
  };
}

const double = createMultiplier();
console.log(double(5));

multiplier = 3;
console.log(double(5));

```

**Output:**

```text
10
15

```

* **Explanation:** Closures do not capture a static snapshot of a variable's value at the time they are created. Instead, they capture a **live reference** to the variable in memory. When the global `multiplier` is changed to `3`, the inner function sees the updated value the next time it is called.
