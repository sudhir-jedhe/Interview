Here is a specialized batch of output-based questions focusing on the **DOM, Event Propagation, and Browser APIs**. These questions test your understanding of how JavaScript interacts with the browser's rendering engine and event system.

---

### **1. Live vs. Static DOM Collections**

**Question:**
Assume the HTML starts with `<div class="box"></div>`. What is logged to the console?

```javascript
const liveNodes = document.getElementsByClassName('box');
const staticNodes = document.querySelectorAll('.box');

const newDiv = document.createElement('div');
newDiv.className = 'box';
document.body.appendChild(newDiv);

console.log(liveNodes.length);
console.log(staticNodes.length);

```

**Output:**

```text
2
1

```

* **Explanation:** `getElementsByClassName` (and `getElementsByTagName`) returns a **live `HTMLCollection**`. It automatically updates when the underlying document changes. `querySelectorAll` returns a**static `NodeList**`, meaning it captures a snapshot of the DOM at the exact moment it was called and does not update when new elements are added.

### **2. Moving Existing Nodes**

**Question:**
What will `console.log(parent.children.length)` output?

```javascript
const parent = document.createElement('div');
const child = document.createElement('p');

document.body.appendChild(parent);
parent.appendChild(child);

// Now, append the EXACT SAME child to the body instead
document.body.appendChild(child);

console.log(parent.children.length);

```

**Output:**

```text
0

```

* **Explanation:** A DOM node can only exist in one place in the document tree at a time. If you use `appendChild` (or `insertBefore`) on a node that already exists in the DOM, the browser **moves** it from its current parent to the new location. It does not clone it.

### **3. The `innerHTML` Security Check**

**Question:**
When this code runs, will the alert box pop up?

```javascript
const container = document.createElement('div');
document.body.appendChild(container);

container.innerHTML = "<script>alert('Hacked!');</script>";

```

**Output:**
*No alert is triggered.*

* **Explanation:** HTML5 specifies that `<script>` tags inserted via `innerHTML` should not execute. This is a built-in security measure to help mitigate Cross-Site Scripting (XSS) attacks. (However, malicious code can still execute via inline event handlers like `<img src="x" onerror="alert(1)">`).

### **4. Event Capturing vs. Bubbling Order**

**Question:**
Assume nested elements: `<div id="outer"><button id="inner">Click</button></div>`. What is the exact log order when the user clicks the `<button>`?

```javascript
const outer = document.getElementById('outer');
const inner = document.getElementById('inner');

outer.addEventListener('click', () => console.log('Outer Bubble'), false);
outer.addEventListener('click', () => console.log('Outer Capture'), true);

inner.addEventListener('click', () => console.log('Inner Bubble'), false);
inner.addEventListener('click', () => console.log('Inner Capture'), true);

```

**Output:**

```text
Outer Capture
Inner Bubble
Inner Capture

```

*(Note: In modern browsers, target phase events trigger in the order they were registered. Since 'Bubble' was registered before 'Capture' on the inner element, it fires first).*

* **Explanation:** The DOM event flow has three phases: Capture (top-down), Target (at the element), and Bubble (bottom-up).

1. **Capture Phase:** Starts at the window and goes down. `Outer Capture` fires.
2. **Target Phase:** Reaches the button. Listeners fire in the exact order they were attached. `Inner Bubble` was attached first, then `Inner Capture`.
3. **Bubble Phase:** Goes back up. `Outer Bubble` fires.

### **5. `stopPropagation` vs `stopImmediatePropagation**`

**Question:**
What logs when the user clicks the button?

```javascript
const btn = document.createElement('button');

btn.addEventListener('click', () => {
  console.log('Listener 1');
});

btn.addEventListener('click', (event) => {
  console.log('Listener 2');
  event.stopImmediatePropagation();
});

btn.addEventListener('click', () => {
  console.log('Listener 3');
});

document.body.addEventListener('click', () => {
  console.log('Body Listener');
});

btn.click();

```

**Output:**

```text
Listener 1
Listener 2

```

* **Explanation:**
* `event.stopPropagation()` stops the event from bubbling up to parents (like the `body`).
* `event.stopImmediatePropagation()` does that, **AND** it prevents any remaining listeners attached to the *exact same element* from firing. Because Listener 2 calls it, Listener 3 is blocked, and the Body listener is blocked.

### **6. Synchronous Layout Thrashing**

**Question:**
What will the user visually see on the screen? Will the box briefly appear red before turning blue?

```javascript
const box = document.createElement('div');
box.style.backgroundColor = 'red';
box.style.width = '100px';
box.style.height = '100px';
document.body.appendChild(box);

box.style.backgroundColor = 'blue';

```

**Output:**
*The box appears instantly blue. It is never visibly red.*

* **Explanation:** JavaScript execution blocks the browser's main thread rendering engine. The browser queues up DOM style changes and only calculates the layout and paints the screen *after* the current synchronous Call Stack is completely empty. The final state in the Call Stack is `blue`, so `red` is skipped entirely.

### **7. Microtasks and `MutationObserver**`

**Question:**
What is the order of the console logs?

```javascript
const p = document.createElement('p');
document.body.appendChild(p);

const observer = new MutationObserver(() => {
  console.log('Observer Fired');
});

observer.observe(p, { attributes: true });

console.log('Start');
p.setAttribute('data-id', '123');
console.log('End');

```

**Output:**

```text
Start
End
Observer Fired

```

* **Explanation:** `MutationObserver` callbacks are executed asynchronously as **Microtasks**. When `setAttribute` is called, the observer detects it and queues its callback in the Microtask queue. The Call Stack continues executing synchronous code (`console.log('End')`). Once the stack is empty, the Microtask queue is processed.

### **8. LocalStorage Type Coercion**

**Question:**

```javascript
localStorage.setItem('score', 100);
localStorage.setItem('user', { name: "Alice" });

console.log(typeof localStorage.getItem('score'));
console.log(localStorage.getItem('user'));

```

**Output:**

```text
"string"
"[object Object]"

```

* **Explanation:** The Web Storage API (`localStorage` and `sessionStorage`) can **only store strings**. If you pass a number, it implicitly converts to `"100"` (so `typeof` is `"string"`). If you pass an object, it implicitly calls `.toString()`, resulting in the useless string `"[object Object]"`. Always use `JSON.stringify()` before saving objects.

### **9. `event.target` vs `event.currentTarget**`

**Question:**
Assume you have `<ul id="list"><li>Item 1</li></ul>`. You click exactly on the text "Item 1". What logs?

```javascript
document.getElementById('list').addEventListener('click', function(e) {
  console.log(e.target.tagName);
  console.log(e.currentTarget.tagName);
});

```

**Output:**

```text
LI
UL

```

* **Explanation:**
* `event.target` is the most deeply nested element that triggered the event (the actual thing your mouse clicked on, which is the `<li>`).
* `event.currentTarget` is the element that the event listener is actively attached to (which is the `<ul>`). This is the foundation of **Event Delegation**.

### **10. Dynamically Injected Scripts**

**Question:**
Assume `script1.js` takes 3 seconds to download, and `script2.js` takes 1 second. Which script executes first?

```javascript
const s1 = document.createElement('script');
s1.src = 'script1.js';
document.body.appendChild(s1);

const s2 = document.createElement('script');
s2.src = 'script2.js';
document.body.appendChild(s2);

```

**Output:**
*`script2.js` executes first.*

* **Explanation:** When you dynamically create and append `<script>` tags using JavaScript, the browser automatically treats them as `async="true"`. This means they will execute the exact moment they finish downloading, regardless of the order they were inserted into the DOM. (To force insertion order, you must explicitly set `s1.async = false`).
