## 1. Scope & Accidental Globals

**Question:**

```javascript
function createVariables() {
  let a = b = 0;
  a++;
  return a;
}
createVariables();
console.log(typeof a);
console.log(typeof b);

```

**Output:**

```text
"undefined"
"number"

```

* **Explanation:** The statement `let a = b = 0` evaluates from right to left. It is equivalent to `b = 0` (creating a global variable `b` if not in strict mode) and then `let a = b` (creating a block-scoped variable `a`). Since `a` is block-scoped, it is `undefined` outside the function.

## 2. Object Keys & Type Coercion

**Question:**

```javascript
const a = {};
const b = { key: 'b' };
const c = { key: 'c' };

a[b] = 123;
a[c] = 456;

console.log(a[b]);

```

**Output:**

```text
456

```

* **Explanation:** Object keys must be strings or symbols. When you pass an object as a key, JavaScript implicitly converts it to a string, resulting in `"[object Object]"`. Both `b` and `c` become the exact same string key, so `a[c]` overwrites `a[b]`.

## 3. Hoisting & Function Overwriting

**Question:**

```javascript
var num = 8;
function num() {
  return 10;
}
console.log(typeof num);

```

**Output:**

```text
"number"

```

* **Explanation:** Both variable declarations and function declarations are hoisted. However, variable assignments happen at runtime. The function declaration `num` is hoisted first, but then the variable assignment `var num = 8` overwrites the function reference with a number.

## 4. Arrow Functions & Context (`this`)

**Question:**

```javascript
const shape = {
  radius: 10,
  diameter() {
    return this.radius * 2;
  },
  perimeter: () => 2 * Math.PI * this.radius
};

console.log(shape.diameter());
console.log(shape.perimeter());

```

**Output:**

```text
20
NaN

```

* **Explanation:** Regular functions (`diameter`) bind `this` to the object calling them (`shape`). Arrow functions (`perimeter`) do not have their own `this`; they inherit it from the surrounding lexical scope (the global window object here), where `radius` is undefined. `undefined * number` results in `NaN`.

## 5. Event Loop (Microtasks vs. Macrotasks)

**Question:**

```javascript
console.log(1);

setTimeout(() => console.log(2), 0);

Promise.resolve().then(() => console.log(3));

console.log(4);

```

**Output:**

```text
1
4
3
2

```

* **Explanation:** Synchronous code (1 and 4) executes first. Promises go to the **Microtask Queue** (3), which is always emptied before the **Macrotask Queue** (2) where `setTimeout` callbacks sit.

## 6. Array Length Mutation

**Question:**

```javascript
const arr = [1, 2, 3];
arr[10] = 11;
console.log(arr.length);
console.log(arr[5]);

```

**Output:**

```text
11
undefined

```

* **Explanation:** When you assign a value to an index far beyond the current length, JavaScript creates "empty slots" (sparse array) to bridge the gap. The length becomes the highest index + 1. Accessing an empty slot returns `undefined`.

## 7. Immediate Invoked Function Expressions (IIFE)

**Question:**

```javascript
let count = 0;
(function immediate() {
  if (count === 0) {
    let count = 1;
    console.log(count);
  }
  console.log(count);
})();

```

**Output:**

```text
1
0

```

* **Explanation:** The `if` block creates a new block scope for `let count = 1`, which shadows the outer `count`. The first `console.log` prints the block-scoped `1`. The second `console.log` is outside the `if` block, so it prints the globally scoped `0`.

## 8. Pass by Value vs. Pass by Reference

**Question:**

```javascript
function checkAge(data) {
  if (data === { age: 18 }) {
    console.log("You are an adult!");
  } else if (data == { age: 18 }) {
    console.log("You are still an adult.");
  } else {
    console.log("No match");
  }
}

checkAge({ age: 18 });

```

**Output:**

```text
No match

```

* **Explanation:** Objects are compared by reference, not by value. The object passed into the function `{ age: 18 }` occupies a different space in memory than the literal `{ age: 18 }` being used in the `if` conditions. Therefore, both strict (`===`) and loose (`==`) equality checks fail.

## 9. The `typeof` Quirks

**Question:**

```javascript
console.log(typeof typeof 1);

```

**Output:**

```text
"string"

```

* **Explanation:** `typeof 1` evaluates first and returns the string `"number"`. Then, `typeof "number"` evaluates, returning `"string"`.

## 10. Default Parameters & Arguments

**Question:**

```javascript
function multiply(x, y = 2, z = x + y) {
  console.log(x, y, z);
}

multiply(5);
multiply(5, 5);
multiply(5, undefined, 10);

```

**Output:**

```text
5 2 7
5 5 10
5 2 10

```

* **Explanation:** Default parameters are evaluated at call time. When `undefined` is passed, the default parameter kicks in. In the first call, `z = 5 + 2`. In the second, `z = 5 + 5`. In the third, `y` defaults to `2`, but `z` is explicitly provided as `10`.

## 11. Unary Plus Operator

**Question:**

```javascript
console.log(+true);
console.log(!"Lydia");

```

**Output:**

```text
1
false

```

* **Explanation:** The unary plus operator (`+`) attempts to convert an operand to a number (`true` becomes 1). The logical NOT operator (`!`) converts a value to a boolean and flips it. Non-empty strings are truthy, so `!"Lydia"` becomes `false`.

## 12. Deleting Properties

**Question:**

```javascript
const name = "Lydia";
age = 21;

console.log(delete name);
console.log(delete age);

```

**Output:**

```text
false
true

```

* **Explanation:** The `delete` operator returns a boolean indicating if an operation was successful. Variables declared with `const`, `let`, or `var` cannot be deleted from the global scope. However, `age = 21` creates a property on the global object (window) without a declaration keyword, making it configurable and deletable.
