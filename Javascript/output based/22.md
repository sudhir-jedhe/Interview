Asynchronous JavaScript is notoriously tricky. Promises and `async/await` were introduced to make our lives easier, but they brought along a whole new class of invisible bugs—silent failures, race conditions, and performance bottlenecks.

Here is a masterclass batch of the most common **Async/Await, Promise, and Race Condition bugs**, and exactly how to fix them.

---

### 1. The `try/catch` Return Trap

❌ **The Bug:**
You wrap an asynchronous function call in a `try/catch` block to handle network errors, but when the API fails, the application crashes anyway because the `catch` block is completely ignored.

```javascript
async function fetchUserData() {
  try {
    // BUG: Returning an un-awaited Promise escapes the try/catch!
    return fetch('/api/user/123'); 
  } catch (error) {
    console.error("Failed to fetch user:", error);
    return null;
  }
}

```

✅ **The Fix:**
You must `await` the Promise *before* returning it if you want the local `catch` block to handle its rejection.

```javascript
async function fetchUserData() {
  try {
    // FIX: Await the promise so the function pauses here
    return await fetch('/api/user/123'); 
  } catch (error) {
    console.error("Failed to fetch user:", error);
    return null;
  }
}

```

* **Why it works:** When you `return fetch(...)` without `await`, you are synchronously returning a pending Promise object to the caller. The `try` block succeeds immediately. When the network request eventually fails a second later, it throws an Unhandled Promise Rejection in the caller's scope, bypassing your `catch` entirely.

### 2. The Sequential Bottleneck (Fake Parallelism)

❌ **The Bug:**
You need to fetch a user's profile and their posts. You use `await` sequentially. The page takes 6 seconds to load, even though each request only takes 3 seconds.

```javascript
async function getDashboardData() {
  // BUG: Starts fetching profile. Waits 3 seconds...
  const profile = await fetch('/api/profile').then(r => r.json());
  
  // Starts fetching posts ONLY after profile finishes. Waits 3 seconds...
  const posts = await fetch('/api/posts').then(r => r.json()); 
  
  return { profile, posts }; // Total time: 6 seconds
}

```

✅ **The Fix:**
Trigger both network requests simultaneously, then `await` their collective resolution using `Promise.all`.

```javascript
async function getDashboardData() {
  // FIX: Fire both requests at the same time
  const profilePromise = fetch('/api/profile').then(r => r.json());
  const postsPromise = fetch('/api/posts').then(r => r.json());
  
  // Await them together
  const [profile, posts] = await Promise.all([profilePromise, postsPromise]);
  
  return { profile, posts }; // Total time: 3 seconds
}

```

* **Why it works:** Promises begin executing the exact moment they are created. By creating both promises before using `await`, they run in parallel. `Promise.all` waits for the slowest one to finish.

### 3. The Broken Promise Chain (Missing Returns)

❌ **The Bug:**
You chain multiple `.then()` blocks together. The first block modifies the data, but the second block receives `undefined` and crashes.

```javascript
fetch('/api/user')
  .then(res => res.json())
  .then(user => {
    // BUG: Forgot to return the result!
    formatUserData(user); 
  })
  .then(formattedUser => {
    console.log(formattedUser.name); // Crashes: Cannot read properties of undefined
  });

```

✅ **The Fix:**
Always explicitly `return` data if you want the next `.then()` in the chain to receive it.

```javascript
fetch('/api/user')
  .then(res => res.json())
  .then(user => {
    // FIX: Return the manipulated data
    return formatUserData(user); 
  })
  .then(formattedUser => {
    console.log(formattedUser.name); // Works perfectly
  });

```

### 4. The Autocomplete Race Condition (Overlapping Requests)

❌ **The Bug:**
You build an autocomplete search bar. The user types "A", which triggers a slow API call (takes 2s). The user immediately types "B" ("AB"), which triggers a fast API call (takes 0.5s). The UI displays the results for "AB", but 1.5 seconds later, the slow request for "A" finishes and overwrites the UI with outdated results.

```javascript
let searchResults = [];

async function handleSearch(query) {
  // BUG: If multiple searches are fired, the slowest one always wins, 
  // regardless of which one was requested last.
  const response = await fetch(`/api/search?q=${query}`);
  searchResults = await response.json();
  render(searchResults);
}

```

✅ **The Fix:**
Use an `AbortController` to cancel any pending requests the moment a new one is fired.

```javascript
let searchResults = [];
let abortController = null;

async function handleSearch(query) {
  // Cancel the previous request if it's still running
  if (abortController) {
    abortController.abort();
  }
  
  // Create a new controller for the current request
  abortController = new AbortController();
  
  try {
    const response = await fetch(`/api/search?q=${query}`, { 
      signal: abortController.signal 
    });
    searchResults = await response.json();
    render(searchResults);
  } catch (error) {
    if (error.name === 'AbortError') {
      console.log('Stale search request cancelled');
    } else {
      console.error('Search failed', error);
    }
  }
}

```

### 5. The `forEach` Async Mirage

❌ **The Bug:**
You need to process a list of files sequentially. You map over them with `forEach`, expecting the code to wait for all files to process before logging "All done!". Instead, "All done!" prints immediately, and the files process in random order.

```javascript
async function processFiles(files) {
  // BUG: forEach is synchronous. It fires these off and moves on instantly.
  files.forEach(async (file) => {
    await upload(file);
  });
  
  console.log("All done!"); // Prints immediately before uploads finish
}

```

✅ **The Fix:**
Use a `for...of` loop for strict sequential execution, or `Promise.all` + `.map()` for parallel execution.

```javascript
// FIX A: Sequential execution (Wait for file 1 before starting file 2)
async function processFilesSequentially(files) {
  for (const file of files) {
    await upload(file);
  }
  console.log("All done!");
}

// FIX B: Parallel execution (Upload all at once, wait for all to finish)
async function processFilesInParallel(files) {
  await Promise.all(files.map(file => upload(file)));
  console.log("All done!");
}

```
