### 1. The Asynchronous Loop Trap (Closures)

❌ **The Bug:**
You want to print 0, 1, 2 with a delay, but it prints 3, 3, 3.

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}

```

✅ **The Fix:**

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}

```

* **Why it works:** `var` is function-scoped, meaning all three timeouts share the exact same `i` variable (which is `3` by the time the timeouts run). `let` is block-scoped, creating a fresh, independent binding of `i` for every single iteration.

### 2. The Lost `this` Context

❌ **The Bug:**
Passing an object method as a callback strips its context, resulting in `undefined` or crashing.

```javascript
const user = {
  name: "Alice",
  greet() {
    console.log("Hi, " + this.name);
  }
};

setTimeout(user.greet, 1000); // Outputs: "Hi, undefined"

```

✅ **The Fix:**

```javascript
setTimeout(() => user.greet(), 1000);
// OR
setTimeout(user.greet.bind(user), 1000);

```

* **Why it works:** When you pass `user.greet` as a raw function reference, `setTimeout` executes it in the global context (where `name` doesn't exist). Wrapping it in an arrow function or using `.bind(user)` permanently locks the `this` context to the `user` object.

### 3. The `async/await` Array Map Disaster

❌ **The Bug:**
You map over an array of IDs to fetch data, but the function returns an array of pending Promises instead of the actual data.

```javascript
async function fetchAllUsers(userIds) {
  const users = userIds.map(async (id) => {
    const response = await fetch(`/api/users/${id}`);
    return response.json();
  });
  
  console.log(users); // [Promise { <pending> }, Promise { <pending> }]
}

```

✅ **The Fix:**

```javascript
async function fetchAllUsers(userIds) {
  const userPromises = userIds.map(async (id) => {
    const response = await fetch(`/api/users/${id}`);
    return response.json();
  });
  
  const users = await Promise.all(userPromises);
  console.log(users); // [{ id: 1, name: "Alice" }, ...]
}

```

* **Why it works:** Array methods like `.map()` are strictly synchronous. They do not pause for `await`. They immediately return the Promise created by the `async` callback. You must wrap the resulting array of Promises in `Promise.all()` to await their collective resolution.

### 4. The Accidental Array Mutation

❌ **The Bug:**
You sort an array to display a "Top 10" list, but it permanently ruins the original order of your main data source.

```javascript
const scores = [50, 10, 99, 45];
const topScores = scores.sort((a, b) => b - a);

console.log(scores); // [99, 50, 45, 10] - Original array is ruined!

```

✅ **The Fix:**

```javascript
const scores = [50, 10, 99, 45];
// Spread operator creates a shallow copy first
const topScores = [...scores].sort((a, b) => b - a); 

// Or in newer JS environments:
const topScores2 = scores.toSorted((a, b) => b - a); 

```

* **Why it works:** Unlike `.map()` or `.filter()`, the `.sort()`, `.reverse()`, and `.splice()` methods **mutate the array in place**. Always create a shallow copy first using the spread operator `[...]` before sorting, or use the modern non-mutating `.toSorted()` method.

### 5. The State Batching Trap (React)

❌ **The Bug:**
You try to increment a counter three times in one click, but it only increments once.

```javascript
const [count, setCount] = useState(0);

const handleTripleClick = () => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
};

```

✅ **The Fix:**

```javascript
const handleTripleClick = () => {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
};

```

* **Why it works:** React state updates are asynchronous and batched. In the buggy code, `count` is locked in a closure at `0`, so you are essentially calling `setCount(1)` three times. Passing an updater callback `(prev => prev + 1)` forces React to calculate the next state based on the most recent, pending state.

### 6. The Object Key Coercion Flaw

❌ **The Bug:**
You try to map DOM elements or objects to specific data, but every entry gets overwritten by the last one.

```javascript
const cache = {};
const node1 = document.getElementById('header');
const node2 = document.getElementById('footer');

cache[node1] = "Header Data";
cache[node2] = "Footer Data";

console.log(cache[node1]); // Outputs: "Footer Data" (Wait, what?)

```

✅ **The Fix:**

```javascript
const cache = new Map();
const node1 = document.getElementById('header');
const node2 = document.getElementById('footer');

cache.set(node1, "Header Data");
cache.set(node2, "Footer Data");

console.log(cache.get(node1)); // Outputs: "Header Data"

```

* **Why it works:** Standard JavaScript objects implicitly convert all keys to strings. Both `node1` and `node2` are coerced into the exact same string: `"[object HTMLDivElement]"`. A `Map` allows you to use actual object references as distinct keys.

### 7. The Optional Chaining "Half-Measure"

❌ **The Bug:**
You use optional chaining to prevent a crash, but it crashes anyway because you missed a level.

```javascript
const response = { data: null };

// You want to read response.data.user.id
const userId = response.data?.user.id; 
// Crashes: Cannot read properties of undefined (reading 'id')

```

✅ **The Fix:**

```javascript
const userId = response.data?.user?.id;

```

* **Why it works:** `response.data?.user` evaluates safely to `undefined`. However, the engine then attempts to read `.id` off of that `undefined` result. You must chain `?.` all the way down the potentially null path.
