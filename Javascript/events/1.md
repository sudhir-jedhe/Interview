To complete this mental model, here is how **`event.target` vs `event.currentTarget**` works in combination with **Event Bubbling & Capturing** and the **Event Delegation Pattern** in production JavaScript.

---

### The Complete Event Lifecycle: Capturing & Bubbling

When you click the `<button>` inside the `<div class="shop">` inside the `<div class="mall">`, the event doesn't just fire on the button—it travels through the DOM tree in **three distinct phases**:

```text
               1. CAPTURING PHASE (Window down to Target)
              ┌────────────────────────────────────────┐
              │  Window ──► Document ──► Mall ──► Shop │
              └───────────────────┬────────────────────┘
                                  │
                                  ▼
                       2. TARGET PHASE (Button)
                                  │
              ┌───────────────────┴────────────────────┐
              │  Shop ◄── Mall ◄── Document ◄── Window │
              └────────────────────────────────────────┘
               3. BUBBLING PHASE (Target up to Window)

```

1. **Capturing Phase (Trickling):** The event travels down from `window` $\rightarrow$ `document` $\rightarrow$ `mall` $\rightarrow$ `shop` until it reaches the `button`.
2. **Target Phase:** The event hits the exact clicked element (`button`).
3. **Bubbling Phase (Default):** The event bubbles back up from `button` $\rightarrow$ `shop` $\rightarrow$ `mall` $\rightarrow$ `document` $\rightarrow$ `window`.

---

### Real Code: Event Delegation Pattern

Because events bubble up from `target` to `currentTarget`, you don't need to attach individual event listeners to 1,000 buttons inside a shop. You attach **one listener to the parent container** (`currentTarget`) and inspect `e.target`.

#### HTML Structure

```html
<div class="mall">
  <div class="shop">
    <button class="btn" data-action="buy">Buy Item</button>
    <button class="btn" data-action="cart">Add to Cart</button>
    <button class="btn" data-action="wishlist">Add to Wishlist</button>
  </div>
</div>

```

#### Event Delegation JavaScript

```javascript
const shop = document.querySelector('.shop');

// Attach listener ONCE to the Shop (currentTarget)
shop.addEventListener('click', (event) => {
  // event.currentTarget IS ALWAYS .shop (where listener lives)
  // event.target IS WHICHEVER BUTTON WAS CLICKED
  
  const targetBtn = event.target.closest('button');

  // Guard clause: ignore clicks inside .shop that weren't on buttons
  if (!targetBtn || !shop.contains(targetBtn)) return;

  const action = targetBtn.dataset.action;

  switch (action) {
    case 'buy':
      console.log('Target:', event.target); // <button data-action="buy">
      console.log('CurrentTarget:', event.currentTarget); // <div class="shop">
      break;
    case 'cart':
      console.log('Added to cart');
      break;
    case 'wishlist':
      console.log('Saved to wishlist');
      break;
  }
});

```

### Stopping Event Propagation

If you want an event to handle something locally at the `button` level and **prevent it from bubbling up** to `.shop` or `.mall`, use `e.stopPropagation()`:

```javascript
const buyButton = document.querySelector('[data-action="buy"]');

buyButton.addEventListener('click', (e) => {
  e.stopPropagation(); // Prevents the click from bubbling up to .shop or .mall!
  console.log('Handled exclusively on the button!');
});

```

### Quick Reference Matrix

| Property                  | What it Represents                                               | Does it Change as Event Bubbles?                 |
| ------------------------- | ---------------------------------------------------------------- | ------------------------------------------------ |
| **`event.target`**        | The deepest element that triggered the initial click.            | **No** (Remains fixed to origin).                |
| **`event.currentTarget`** | The element currently executing its attached `addEventListener`. | **Yes** (Changes as event bubbles up DOM nodes). |
