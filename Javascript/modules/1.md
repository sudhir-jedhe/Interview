**Import Attributes** (formerly known as *Import Assertions*) are an ECMAScript feature that allows developers to pass explicit metadata alongside module import statements using the `with` keyword.

Their primary use case is importing non-JavaScript modules—such as **JSON modules** or **CSS module scripts**—safely without relying on file extensions or server content types alone.

---

## 1. Why Are Import Attributes Needed?

Historically, importing non-JavaScript files natively presented a significant **security vulnerability** (often referred to as an "unexpected execution" attack).

If a web application imported a file expecting data:

```javascript
// DANGEROUS without attributes:
import data from "./config.json";

```

If a malicious actor or compromised server served executable JavaScript code at `./config.json` with a `text/javascript` MIME type, the browser would execute that arbitrary JavaScript code instead of parsing it as static data.

**Import Attributes solve this by enforcing runtime verification:**
By specifying `with { type: "json" }`, you explicitly tell the JavaScript runtime to validate that the resource is parsed strictly as JSON. If the server returns anything other than valid JSON data, module loading fails immediately before any code can run.

---

## 2. Importing JSON Modules Syntax

### A. Static Import Syntax

Use the `with` keyword at the end of the `import` statement:

```javascript
// config.json
{
  "appName": "DevPortal",
  "version": "2.4.0",
  "features": {
    "darkMode": true,
    "maxUploadMb": 50
  }
}

```

```javascript
// main.js
import config from "./config.json" with { type: "json" };

console.log("App Name:", config.appName); // Output: DevPortal
console.log("Version:", config.version);   // Output: 2.4.0

```

> **Note:** JSON modules export data as their **default export**. Attempting to use named imports (`import { appName } from './config.json'`) throws a `SyntaxError`.

---

### B. Dynamic Import Syntax

For dynamic imports via `import()`, pass an options object containing the `with` attribute as the second parameter:

```javascript
async function loadConfiguration() {
  try {
    // Dynamic import with Import Attributes
    const module = await import("./config.json", {
      with: { type: "json" }
    });

    const config = module.default;
    console.log("Loaded dynamic config:", config);
  } catch (error) {
    console.error("Failed to load JSON module:", error);
  }
}

loadConfiguration();

```

---

### C. Re-exporting JSON Modules

You can re-export default JSON data directly from another ES module:

```javascript
// index.js
export { default as appConfig } from "./config.json" with { type: "json" };

```

---

## 3. Other Use Cases: CSS Module Scripts

Import attributes are not limited to JSON. Browsers also use them for loading **CSS Style Sheets** directly into JavaScript as `CSSStyleSheet` objects, which can be attached to the DOM or Shadow DOM:

```javascript
// Load CSS file as a constructable stylesheet
import sheet from "./styles.css" with { type: "css" };

// Apply styles directly to Document or Shadow Root
document.adoptedStyleSheets = [sheet];

```

---

## 4. `with` vs. Legacy `assert` Syntax

During the standardization process, this feature originally used the `assert` keyword (*Import Assertions*):

```javascript
// ❌ OLD / DEPRECATED SYNTAX (Import Assertions)
import data from "./data.json" assert { type: "json" };

// ✅ MODERN / STANDARD SYNTAX (Import Attributes)
import data from "./data.json" with { type: "json" };

```

### Why the change?

* **Assertions (`assert`):** Were purely checking/verifying the imported resource after fetch.
* **Attributes (`with`):** Allow runtime environments and bundlers to actively influence *how* the resource is requested, fetched, or transformed.

Explain how to use CSS Module Scripts and import attributes with Shadow DOM in Web Components with code examples

**CSS Module Scripts** combined with **Import Attributes** (`with { type: 'css' }`) allow you to import external CSS files directly into JavaScript as native **`CSSStyleSheet`** objects.

When paired with **Web Components** and **Shadow DOM**, this provides scoped, re-usable component styling without duplicate `<style>` tag overhead or CSS namespace collisions.

---

## 1. How It Works: `adoptedStyleSheets`

When you import a CSS file using `with { type: "css" }`, the browser parses the file once and exports a constructable `CSSStyleSheet` instance as the default export.

You can then pass this stylesheet to the **`adoptedStyleSheets`** array property on a **`Document`** or **`ShadowRoot`**.

```javascript
// Styles are parsed once into a shared stylesheet object
import sheet from "./styles.css" with { type: "css" };

// Attach to Shadow DOM root
shadowRoot.adoptedStyleSheets = [sheet];

```

### Key Performance Benefits

* **Zero Duplicate Parsing:** Even if you instantiate 1,000 instances of a custom Web Component, the browser parses the CSS file **only once** in memory.
* **No Inline `<style>` Overhead:** Eliminates DOM pollution and flash of unstyled content (FOUC).
* **Native Scope Isolation:** Shadow DOM prevents component styles from leaking out, and global styles from leaking in.

---

## 2. Complete Implementation Example

### Step 1: Create the Component Stylesheet (`user-card.css`)

```css
/* user-card.css */
:host {
  display: block;
  font-family: system-ui, sans-serif;
  border: 1px solid #e0e0e0;
  border-radius: 8px;
  padding: 16px;
  max-width: 300px;
  background-color: #f9f9f9;
}

h3 {
  margin: 0 0 8px 0;
  color: #2c3e50;
}

p {
  margin: 0;
  color: #666;
  font-size: 0.9rem;
}

button {
  margin-top: 12px;
  padding: 8px 12px;
  background-color: #0066cc;
  color: white;
  border: none;
  border-radius: 4px;
  cursor: pointer;
}

button:hover {
  background-color: #0052a3;
}

```

---

### Step 2: Define the Web Component (`UserCard.js`)

```javascript
// UserCard.js
import cardStyles from "./user-card.css" with { type: "css" };

class UserCard extends HTMLElement {
  constructor() {
    super();

    // 1. Attach Shadow DOM (Open mode)
    this.attachShadow({ mode: "open" });

    // 2. Adopt the imported stylesheet into the Shadow Root
    this.shadowRoot.adoptedStyleSheets = [cardStyles];
  }

  connectedCallback() {
    // 3. Render HTML template inside Shadow DOM
    const name = this.getAttribute("name") || "Anonymous";
    const role = this.getAttribute("role") || "Member";

    this.shadowRoot.innerHTML = `
      <h3>${name}</h3>
      <p>${role}</p>
      <button id="actionBtn">Connect</button>
    `;

    this.shadowRoot.querySelector("#actionBtn").addEventListener("click", () => {
      alert(`Connecting with ${name}...`);
    });
  }
}

// 4. Register Custom Element
customElements.define("user-card", UserCard);

```

---

### Step 3: Use in HTML (`index.html`)

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>CSS Module Scripts Demo</title>
  <script type="module" src="./UserCard.js"></script>
</head>
<body>

  <h2>Team Members</h2>
  
  <!-- Custom Web Components -->
  <user-card name="Alice Smith" role="Lead Developer"></user-card>
  <br>
  <user-card name="Bob Jones" role="UI Designer"></user-card>

</body>
</html>

```

## 3. Composing Multiple Stylesheets (Shared Themes + Local Styles)

Because `adoptedStyleSheets` takes an array, you can compose components using shared base design tokens or global stylesheets alongside component-specific CSS.

```javascript
import baseTheme from "./styles/base-theme.css" with { type: "css" };
import buttonStyles from "./components/button.css" with { type: "css" };

class CustomButton extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" });

    // Combine global theme styles with local component styles
    this.shadowRoot.adoptedStyleSheets = [baseTheme, buttonStyles];
  }
}

```

---

## 4. Updating Styles Dynamically at Runtime

Because the imported `cardStyles` is a mutable `CSSStyleSheet` instance, modifying it at runtime immediately updates **all component instances** sharing that sheet.

```javascript
import cardStyles from "./user-card.css" with { type: "css" };

// Function to toggle dark mode dynamically across all Web Component instances
function enableDarkMode() {
  // Append or insert new CSS rules into the constructed stylesheet
  cardStyles.insertRule(`
    :host {
      background-color: #1e1e1e;
      color: #ffffff;
      border-color: #333;
    }
  `, cardStyles.cssRules.length);
}

```

## 5. Browser Compatibility & Fallbacks

| Feature                                         | Browser Support                                    |
| ----------------------------------------------- | -------------------------------------------------- |
| **`adoptedStyleSheets`**                        | Chrome 73+, Edge 79+, Firefox 101+, Safari 16.4+   |
| **CSS Module Scripts (`with { type: 'css' }`)** | Chrome 123+, Edge 123+, Firefox 126+, Safari 17.2+ |

### Fallback for Older Browsers / Bundlers

If your target environment does not support CSS Module Scripts natively, use a constructable `CSSStyleSheet` manually or fallback to standard CSS text insertion:

```javascript
// Fallback if 'with { type: "css" }' is unsupported:
const sheet = new CSSStyleSheet();
sheet.replaceSync(`
  :host { display: block; padding: 16px; }
`);

this.shadowRoot.adoptedStyleSheets = [sheet];

```

Explain CSS Shadow Parts ::part and ::theme in Web Components with code examples

One of the core benefits of Web Components with Shadow DOM is **style encapsulation**—preventing outside CSS from accidentally breaking component styles. However, this encapsulation often made Web Components difficult to customize or theme from the outside.

To allow controlled customization without breaking encapsulation, CSS introduced the **`::part()`** pseudo-element.

---

## 1. What is `::part()`?

The **`::part()`** CSS pseudo-element allows a Web Component developer to expose specific elements inside its Shadow DOM for external styling.

* **Component Author:** Adds a `part="name"` attribute to internal HTML elements inside the Shadow DOM.
* **Component Consumer:** Uses `element-name::part(name)` in external CSS to style those exposed elements.

### What about `::theme()`?

> **Note on `::theme()`:** During early specification drafts, a proposed `::theme()` pseudo-element was discussed to allow deeply nested shadow tree customization. However, `::theme()` was **never standardized or implemented in browsers**. Today, deep theming across shadow boundaries is handled using **CSS Custom Properties (Variables)** or chained `::part()` forwardings.

---

## 2. Basic Example: Using `::part()`

### Step 1: Component Definition (`custom-card.js`)

Inside the component's Shadow DOM, mark elements you want consumers to style using the `part` attribute.

```javascript
class CustomCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });

    this.shadowRoot.innerHTML = `
      <style>
        :host {
          display: block;
          border: 1px solid #ccc;
          padding: 16px;
          border-radius: 8px;
        }
        /* Internal default styles */
        .card-header { font-size: 1.25rem; font-weight: bold; }
        .card-button { padding: 8px 16px; background: #0066cc; color: white; border: none; }
      </style>

      <!-- Exposing parts to the outside world using the part attribute -->
      <div part="header" class="card-header">
        <slot name="header">Default Header</slot>
      </div>

      <div part="body">
        <slot>Default body text goes here.</slot>
      </div>

      <button part="button primary-button" class="card-button">
        Click Me
      </button>
    `;
  }
}

customElements.define('custom-card', CustomCard);

```

---

### Step 2: External Customization (`styles.css` / Page HTML)

In your main page stylesheet (outside the Shadow DOM), use the `::part()` pseudo-element to target those exposed parts.

```css
/* Style the header part of all <custom-card> elements */
custom-card::part(header) {
  color: #d9534f;
  border-bottom: 2px solid #eee;
  padding-bottom: 8px;
}

/* Style the button part */
custom-card::part(button) {
  background-color: #28a745;
  border-radius: 20px;
  cursor: pointer;
}

/* ::part supports pseudo-classes like :hover or :focus */
custom-card::part(button):hover {
  background-color: #218838;
}

/* Elements can have multiple parts space-separated (part="button primary-button") */
custom-card::part(primary-button) {
  box-shadow: 0 4px 6px rgba(0, 0, 0, 0.1);
}

```

---

## 3. Forwarding Parts (`exportparts`)

When nesting Web Components inside other Web Components, outer components cannot directly see parts inside inner components by default.

To expose an inner component's part through an outer component, use the **`exportparts`** attribute.

```javascript
// Outer Component Definition
class UserCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });

    this.shadowRoot.innerHTML = `
      <div class="user-card">
        <h2>User Profile</h2>
        
        <!-- Forwarding 'button' part as 'action-button' to the outside page -->
        <custom-card exportparts="button: action-button, header"></custom-card>
      </div>
    `;
  }
}

customElements.define('user-card', UserCard);

```

### Page CSS targeting the forwarded part

```css
/* Style custom-card's button from OUTSIDE user-card */
user-card::part(action-button) {
  background-color: #6f42c1;
}

/* Forwarded without an explicit alias (header -> header) */
user-card::part(header) {
  font-family: monospace;
}

```

---

## 4. `::part()` Security & Design Rules

To maintain encapsulated boundaries, `::part()` enforces strict restrictions:

1. **Only Target Exists Directly:** You can **only** style the specific element marked with `part=""`. You cannot inspect or target child elements inside a part from the outside.

```css
/* ❌ INVALID: Cannot target children inside a part */
custom-card::part(header) span { color: red; }

/* ❌ INVALID: Cannot combine with pseudo-elements like ::after */
custom-card::part(button)::after { content: " →"; }

/* ✅ VALID: Styling properties directly on the part */
custom-card::part(header) { color: red; }

```

1. **Pseudo-classes ARE allowed:** You can combine `::part()` with pseudo-classes like `:hover`, `:focus`, `:active`, or `:disabled`.

```css
custom-card::part(button):disabled {
  opacity: 0.5;
  cursor: not-allowed;
}

```

---

## 5. Modern Theming: `::part()` vs. CSS Variables

For broad design system theming, combine **CSS Custom Properties** with **`::part()`**:

| Approach                        | Best Used For                                                                                          | Example                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| **CSS Custom Properties**       | Theme tokens (colors, fonts, radii, spacing) applied globally across the shadow boundary.              | `custom-card { --card-bg: #111; }`                     |
| **CSS Shadow Parts (`::part`)** | Complex component structural overrides (borders, layout, display, shadows, specific component states). | `custom-card::part(button) { border: 2px solid red; }` |

Explain Slot styling with ::slotted() in Web Components Shadow DOM with code examples
In Web Components with Shadow DOM, **slots** (`<slot>`) allow consumers to project their own HTML elements (called "slotted content" or "distributed nodes") into a component's shadow tree.

Because slotted elements reside in the **Light DOM** (the main document page) rather than inside the Shadow DOM itself, standard Shadow DOM CSS rules cannot style them. To style these projected nodes from inside a component's Shadow DOM, you must use the **`::slotted()`** CSS pseudo-element.

---

## 1. Syntax & Fundamental Rules

The `::slotted()` selector takes a **compound selector** as an argument representing the element projected into the slot.

```css
/* Styles any <p> element inserted into a default/unnamed slot */
::slotted(p) {
  color: #0066cc;
}

/* Styles an element with class "avatar" inserted into a named slot */
::slotted(.avatar) {
  border-radius: 50%;
}

```

### Essential Rules of `::slotted()`

1. **Top-Level Nodes Only:** `::slotted()` can **only** target direct children slotted into the `<slot>`. It cannot style nested descendants inside a slotted element.
2. **Outer Specificity Wins:** Styles applied from the main page (Light DOM) override `::slotted()` rules defined inside the Shadow DOM unless you use `!important`.
3. **Compound Selectors Only:** The argument must be a simple or compound selector (e.g., `h1`, `.card-title`, `p.intro`). You cannot pass combinator selectors like `::slotted(div p)` or `::slotted(ul > li)`.

---

## 2. Complete Code Example

Here is a full component demonstrating how to style slotted elements in both default (unnamed) and named slots.

### Step 1: Define the Component (`fancy-card.js`)

```javascript
class FancyCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" });

    this.shadowRoot.innerHTML = `
      <style>
        :host {
          display: block;
          border: 1px solid #e0e0e0;
          border-radius: 8px;
          padding: 16px;
          background-color: #fafafa;
          font-family: system-ui, sans-serif;
        }

        /* 1. Style top-level <h2> elements inside the 'title' slot */
        ::slotted(h2[slot="title"]) {
          margin-top: 0;
          color: #2c3e50;
          font-size: 1.5rem;
          border-bottom: 2px solid #0066cc;
          padding-bottom: 8px;
        }

        /* 2. Style any paragraph <p> inside the default (unnamed) slot */
        ::slotted(p) {
          color: #555;
          line-height: 1.6;
        }

        /* 3. Style images slotted anywhere with a specific class */
        ::slotted(img.hero-image) {
          width: 100%;
          height: auto;
          border-radius: 6px;
        }

        /* 4. Support pseudo-classes like :hover on slotted elements */
        ::slotted(a:hover) {
          text-decoration: underline;
          color: #004080;
        }
      </style>

      <div class="card-container">
        <!-- Named Slot for Title -->
        <slot name="title"></slot>
        
        <!-- Named Slot for Media -->
        <slot name="media"></slot>

        <!-- Default Slot for Main Content -->
        <slot></slot>
      </div>
    `;
  }
}

customElements.define("fancy-card", FancyCard);

```

---

### Step 2: Use in HTML Page (`index.html`)

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Slotted Styling Demo</title>
  <script type="module" src="./fancy-card.js"></script>
  <style>
    /* Main page CSS: This will override ::slotted() unless !important is used */
    .custom-p {
      font-weight: bold;
    }
  </style>
</head>
<body>

  <fancy-card>
    <!-- Projected into 'title' slot -->
    <h2 slot="title">Card Title Here</h2>

    <!-- Projected into 'media' slot -->
    <img slot="media" class="hero-image" src="https://via.placeholder.com/400x150" alt="Banner">

    <!-- Projected into default slot -->
    <p class="custom-p">This paragraph gets styled by ::slotted(p) inside the component.</p>
    
    <p>Multiple paragraphs can be slotted into the default slot!</p>
    
    <a href="#">Read more...</a>
  </fancy-card>

</body>
</html>

```

## 3. What `::slotted()` CANNOT Do (Common Gotchas)

### ❌ Gotcha 1: Descendant Selectors

You **cannot** style children or descendants inside a slotted element.

```css
/* ❌ DOES NOT WORK: Trying to style <span> nested inside a slotted <div> */
::slotted(div) span {
  color: red;
}

/* ❌ DOES NOT WORK: Combinators inside the parenthesis */
::slotted(div p) {
  color: red;
}

/* ✅ WORKS: Style the slotted <div> directly */
::slotted(div.content-box) {
  background-color: #fff;
}

```

### ❌ Gotcha 2: Text Nodes

`::slotted()` only targets **Element nodes**, not raw text nodes placed directly into a slot.

```html
<!-- Text node direct child won't match ::slotted(*) -->
<fancy-card>
  Raw un-wrapped text string here.
</fancy-card>

```

*To style text content reliably, wrap it in a container element like `<span>` or `<p>`.*

---

## 4. Styling Default Slot Fallback Content

If the consumer does **not** provide any content for a slot, the browser displays the default markup placed inside `<slot>...</slot>`.

To style this default fallback content (which lives inside the Shadow DOM), use standard CSS selectors rather than `::slotted()`.

```javascript
// Shadow DOM Markup
this.shadowRoot.innerHTML = `
  <style>
    /* Styles fallback text when NO content is slotted */
    .default-fallback {
      font-style: italic;
      color: #999;
    }

    /* Styles content provided BY THE CONSUMER */
    ::slotted(*) {
      font-weight: normal;
    }
  </style>

  <slot>
    <span class="default-fallback">No content was provided.</span>
  </slot>
`;

```
