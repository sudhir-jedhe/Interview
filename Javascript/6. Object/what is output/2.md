 ```js
  var text = 'outside';
function logIt(){
    console.log(text);
    var text = 'inside';
};
logIt();

```

The code will output **`undefined`**.

### Why this happens (Variable Hoisting)

In JavaScript, variable declarations using `var` are "hoisted" (moved) to the top of their containing scope during the compilation phase. However, **only the declaration is hoisted, not the initialization**.

Inside the `logIt` function, the code is interpreted by JavaScript as if it were written like this:

```js
var text = 'outside';

function logIt(){
    var text;          // Declaration is hoisted to the top of the function scope
    console.log(text); // 'text' exists locally, but its value is undefined
    text = 'inside';   // Assignment happens here
};

logIt();

```

Because the local `var text` is declared inside `logIt`, it shadow/overrides the global `text = 'outside'` variable within that function. At the moment `console.log(text)` runs, the local `text` variable exists, but has not yet been assigned a value.

---

### How to avoid this behavior

To prevent issues caused by hoisting, use `let` or `const` instead of `var`:

```js
let text = 'outside';

function logIt(){
    console.log(text); // ReferenceError: Cannot access 'text' before initialization
    let text = 'inside';
};

logIt();

```

With `let` or `const`, accessing the variable before its declaration causes a `ReferenceError` due to the **Temporal Dead Zone (TDZ)**, making bugs like this much easier to catch.

### Explanation

Unlike `var`, variables declared with `let` or `const` are **block-scoped** and enter a state called the **Temporal Dead Zone (TDZ)** from the start of the block until their declaration is encountered.

Here is how the JavaScript engine handles the code when using `let` or `const`:

```javascript
let text = 'outside';

function logIt() {
    // TDZ starts for local 'text' variable
    console.log(text); // ❌ Uncaught ReferenceError: Cannot access 'text' before initialization
    let text = 'inside'; // Declaration reached; TDZ ends here for 'text'
}

logIt();

```

### Key Takeaways

* **Hoisting still occurs:** The inner `let text` declaration is still hoisted to the top of the `logIt()` block, which is why it shadows the outer `'outside'` variable rather than logging it.
* **Accessing TDZ throws an error:** Because `let` and `const` are not initialized with `undefined` during hoisting (unlike `var`), accessing them before the actual declaration line throws a hard error instead of failing silently with `undefined`.
