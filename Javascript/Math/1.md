The **JavaScript `Math` object** is a built-in namespace object that provides mathematical constants and functions.

Unlike other built-in standard objects, `Math` is **not a constructor**. You cannot instantiate it with `new Math()` or call it as a function—all of its properties and methods are static.

---

## 1. Math Properties (Constants)

`Math` provides built-in constants for common mathematical values.

```javascript
// Example 1: Math.PI (Ratio of a circle's circumference to its diameter)
console.log(Math.PI); 
// Output: 3.141592653589793

// Example 2: Math.E (Euler's number) and Math.LN10 (Natural log of 10)
console.log(Math.E);    // Output: 2.718281828459045
console.log(Math.LN10); // Output: 2.302585092994046

// Example 3: Math.SQRT2 (Square root of 2)
console.log(Math.SQRT2); 
// Output: 1.4142135623730951

```

---

## 2. Rounding Methods

JavaScript offers four primary methods to round numbers depending on your needs.

```javascript
// Example 1: Math.round() - Rounds to nearest integer
console.log(Math.round(4.5)); // Output: 5
console.log(Math.round(4.4)); // Output: 4

// Example 2: Math.ceil() (Rounds UP) & Math.floor() (Rounds DOWN)
console.log(Math.ceil(4.1));  // Output: 5
console.log(Math.floor(4.9)); // Output: 4

// Example 3: Math.trunc() - Truncates fractional part (returns integer part)
console.log(Math.trunc(4.9));  // Output: 4
console.log(Math.trunc(-4.9)); // Output: -4

```

---

## 3. Power, Root, and Absolute Methods

```javascript
// Example 1: Math.pow(x, y) - Raises x to power y (equivalent to x ** y)
console.log(Math.pow(2, 3)); 
// Output: 8

// Example 2: Math.sqrt(x) & Math.cbrt(x) - Square and Cube roots
console.log(Math.sqrt(64)); // Output: 8

// Example 3: Math.abs(x) - Absolute (positive) value
```

## 4. Min, Max, and Random Methods

```javascript
// Example 1: Math.min() & Math.max()
console.log(Math.min(10, 20, 5, 30)); // Output: 5
console.log(Math.max(10, 20, 5, 30)); // Output: 30

// Example 2: Using Math.max with Spread Operator on Arrays

console.log(Math.max(...scores)); 
// Output: 95

// Example 3: Math.random() - Generates pseudo-random float between 0 (inclusive) and 1 (exclusive)
// Generate random integer between min (1) and max (10) inclusive:

  return Math.floor(Math.random() * (max - min + 1)) + min;
}
console.log(getRandomInt(1, 10)); 
// Output: Random integer between 1 and 10

```

In JavaScript, standard numbers are represented as **64-bit floating-point values** (IEEE 754 standard). This causes well-known precision issues with decimal arithmetic (like `0.1 + 0.2 !== 0.3`).

To handle numbers beyond IEEE 754 limits or perform exact integer calculations, ES2020 introduced **`BigInt`**.

Here is a breakdown of how floating-point precision works, how to fix its issues, and how to work with `BigInt`.

---

## 1. Understanding Floating-Point Precision Issues

JavaScript stores numbers in binary floating-point format. Certain base-10 decimals (like `0.1` or `0.2`) cannot be represented exactly in binary fractions and turn into repeating fractions, causing rounding errors.

```javascript
console.log(0.1 + 0.2); 
// Output: 0.30000000000000004

console.log(0.1 + 0.2 === 0.3); 
// Output: false

```

### How to Fix Floating-Point Issues

#### Method A: Convert Decimals to Integers (Cents Pattern)

Multiply by a factor of 10 to turn decimals into integers, perform operations, and divide back. This is the standard pattern for financial calculations.

```javascript
// Add $0.10 and $0.20 accurately by calculating in cents
const cents1 = 0.1 * 100;
const cents2 = 0.2 * 100;
const total = (cents1 + cents2) / 100;

console.log(total); // Output: 0.3

```

#### Method B: `toFixed()` or `toPrecision()`

Use `toFixed(n)` to round output for display purposes (note: `toFixed` returns a string).

```javascript
const sum = 0.1 + 0.2;
const formattedSum = Number(sum.toFixed(2));

console.log(formattedSum); // Output: 0.3

```

#### Method C: Using `Number.EPSILON`

`Number.EPSILON` represents the smallest difference between two representable numbers. Use it to perform safe equality comparisons.

```javascript
function numbersAreEqual(a, b) {
  return Math.abs(a - b) < Number.EPSILON;
}

console.log(numbersAreEqual(0.1 + 0.2, 0.3)); // Output: true

```

---

## 2. Working with `BigInt`

`BigInt` is a primitive data type used to represent **arbitrarily large integers** beyond the safe integer limit of standard numbers (`Number.MAX_SAFE_INTEGER`, which is $2^{53} - 1 = 9,007,199,254,740,991$).

### Creating a `BigInt`

Append `n` to an integer literal or call the `BigInt()` constructor function.

```javascript
// Example 1: BigInt literal
const big1 = 9007199254740995n;

// Example 2: Constructor from string
const big2 = BigInt("9007199254740995");

// Example 3: Exceeding Number limit accurately
const safeNum = Number.MAX_SAFE_INTEGER + 2; // Inaccurate floating point
const safeBig = BigInt(Number.MAX_SAFE_INTEGER) + 2n; // Accurate BigInt

console.log(safeNum); // Output: 9007199254740992 (Inaccurate)
console.log(safeBig); // Output: 9007199254740993n (Exact)

```

---

## 3. Mathematical Operations with `BigInt`

`BigInt` supports standard arithmetic operators (`+`, `-`, `*`, `/`, `%`, `**`), but **truncates fractional values** since it only represents integers.

```javascript
// Example 1: Basic arithmetic
const a = 100n;
const b = 3n;

console.log(a + b); // Output: 103n
console.log(a * b); // Output: 300n
console.log(a ** b); // Output: 1000000n

// Example 2: Integer division truncates decimals towards zero
console.log(5n / 2n); // Output: 2n (NOT 2.5n)

// Example 3: Modulo operator
console.log(5n % 2n); // Output: 1n

```

---

## 4. Key Rules and Pitfalls of `BigInt`

### Rule A: Cannot Mix `BigInt` and Standard `Number`

You cannot perform mathematical operations between `BigInt` and `Number` without explicit coercion. Doing so throws a `TypeError`.

```javascript
try {
  const result = 10n + 5; // Throws TypeError
} catch (err) {
  console.log(err.message); 
  // Output: "Cannot mix BigInt and other types, use explicit conversions"
}

// Correct approach: Cast explicitly
const validResult = 10n + BigInt(5);
console.log(validResult); // Output: 15n

```

### Rule B: Loose Comparison vs. Strict Comparison

`BigInt` and `Number` can be loosely equal (`==`), but not strictly equal (`===`).

```javascript
console.log(10n == 10);  // Output: true
console.log(10n === 10); // Output: false

```

### Rule C: JSON Serialization Error

`JSON.stringify()` cannot serialize `BigInt` out of the box and throws a `TypeError`. You must customize `.toJSON()` or convert it to a string first.

```javascript
const data = { id: 100n };

try {
  JSON.stringify(data);
} catch (err) {
  console.log(err.message); 
  // Output: "Do not know how to serialize a BigInt"
}

// Fix: Override prototype to stringify BigInt values
BigInt.prototype.toJSON = function () {
  return this.toString();
};

console.log(JSON.stringify(data)); 
// Output: '{"id":"100"}'

```

### 41. `Math.random()`

*Returns a pseudo-random floating-point number between `0` (inclusive) and `1` (exclusive).*

```javascript

// Example 2: Generate random integer between 1 and 100

  return Math.floor(Math.random() * (max - min + 1)) + min;
}
console.log(getRandomInt(1, 100)); // e.g., 73

// Example 3: Select random element from an array

const randomItem = items[Math.floor(Math.random() * items.length)];
console.log(randomItem); // e.g., "banana"

```
