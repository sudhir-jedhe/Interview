```js
console.log(1);
const promise = new Promise((resolve) => {
  console.log(2);
  resolve();
  console.log(3);
});
console.log(4);
```

The output of this code is:

```text
1
2
3
4

```

---

### Step-by-Step Explanation

1. **`console.log(1);`** runs synchronously on the call stack $\rightarrow$ prints **`1`**.
2. **`new Promise((resolve) => { ... })`**: The executor function passed into `new Promise` executes **synchronously and immediately** upon instantiation:

* **`console.log(2);`** runs synchronously $\rightarrow$ prints **`2`**.
* **`resolve();`** changes the internal promise state from `pending` to `fulfilled`. (If any `.then()` callbacks were attached, they would be queued into the microtask queue, but execution inside the current function continues).
* **`console.log(3);`** runs synchronously $\rightarrow$ prints **`3`**.

1. **`console.log(4);`** runs synchronously on the call stack $\rightarrow$ prints **`4`**.

Because there are no `.then()` or `.catch()` handlers registered in this code, no tasks need to be queued or executed on the microtask queue—everything runs in continuous synchronous order from top to bottom.

### Step-by-Step Event Loop Walkthrough

1. **Synchronous Execution (Call Stack):**

* `console.log(1)` runs $\rightarrow$ prints **`1`**.
* `setTimeout(...)` is invoked. The browser/Node runtime schedules the timer callback into the **Macrotask (Task) Queue**.
* `new Promise(...)` executor runs **synchronously**:
* `console.log(2)` runs $\rightarrow$ prints **`2`**.
* `resolve()` transitions the promise from `pending` to `fulfilled`.
* `console.log(3)` runs $\rightarrow$ prints **`3`**.

* `promise.then(...)` detects the promise is already fulfilled, so it enqueues its callback `() => console.log(5)` into the **Microtask Queue**.
* `console.log(4)` runs $\rightarrow$ prints **`4`**.

1. **Microtask Queue Drain:**

* Before the event loop touches any macrotask (timer, I/O), it **must completely empty the microtask queue**.
* The `.then` callback executes $\rightarrow$ prints **`5`**.

1. **Macrotask Queue Execution:**

* The call stack and microtask queue are now completely empty.
* The event loop picks up the oldest ready macrotask: the `setTimeout` callback.
* The callback executes $\rightarrow$ prints **`timeout`**.

### Priority Order Rule

$$\text{Synchronous Code} \longrightarrow \text{Microtask Queue } (\texttt{.then}, \texttt{queueMicrotask}) \longrightarrow \text{Macrotask Queue } (\texttt{setTimeout}, \texttt{setInterval})$$

### Where the Microtask Boundaries Are Placed

An `async` function executes **synchronously** until it encounters the `await` keyword. At the point of `await`, JavaScript splits the function in two:

```javascript
async function run() {
  // [SYNCHRONOUS PHASE]
  console.log(2);
  console.log(3);

  // ---------------- MICROTASK BOUNDARY ----------------
  await Promise.resolve(); 
  // Code pauses execution here. The rest of this function 
  // is registered as a callback on the microtask queue.
  // Control is yielded back to the caller (global execution context).
  // ----------------------------------------------------

  // [MICROTASK PHASE]
  console.log(5);
}

```

---

### Step-by-Step Execution Breakdown

1. **`console.log(1)`** executes synchronously on the call stack $\rightarrow$ prints **`1`**.
2. **`setTimeout(...)`** is delegated to browser/Node timer APIs; its callback is queued in the **Macrotask Queue**.
3. **`run()`** is invoked:

* It enters the function synchronously.
* `console.log(2)` runs $\rightarrow$ prints **`2`**.
* `console.log(3)` runs $\rightarrow$ prints **`3`**.
* Reaches `await Promise.resolve()`:
* `Promise.resolve()` evaluates immediately to a fulfilled promise.
* The engine creates a continuation (the remainder of `run()`) and schedules it into the **Microtask Queue** (identical to `.then(() => { console.log(5); })`).
* `run()` pauses and immediately returns an implicit pending promise to its caller.

1. **`console.log(4)`** runs synchronously on the call stack $\rightarrow$ prints **`4`**.
2. **Call Stack Empties:** The engine checks the microtask queue before picking up any macrotasks:

* It resumes `run()` right after the `await`.
* `console.log(5)` runs $\rightarrow$ prints **`5`**.

1. **Microtask Queue Empties:** The event loop advances to the macrotask queue:

* The `setTimeout` callback executes $\rightarrow$ prints **`timeout`**.
