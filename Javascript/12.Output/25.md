```js
const func1 = () => console.log(1);
func1();
func2();
function func2() {
  console.log(2);
}
func3();
var func3 = function func4() {
  console.log(3);
};```


This code outputs **`1`**, then **`2`**, and then throws an uncaught **`TypeError: func3 is not a function`**.

---

### Step-by-Step Execution Breakdown

1. **`const func1 = () => console.log(1);`**
`func1` is declared with `const` and assigned an arrow function. Calling `func1()` executes the function:
```text
1

```

1. **`func2();`**
Function declarations (`function func2() { ... }`) are fully hoisted along with their implementation to the top of the scope. Calling `func2()` before its definition succeeds:

```text
2

```

1. **`func3();`**
`func3` is declared using `var`:

* During the compilation/hoisting phase, `var func3;` is hoisted to the top and initialized to `undefined`.
* The assignment (`func3 = function func4() { ... }`) does **not** happen until the runtime reaches that line.
* Because line 7 attempts to execute `func3()` while its value is still `undefined`, the JavaScript engine throws an error:

```text
TypeError: func3 is not a function

```

1. **Line 8 (`var func3 = function func4() { ... }`) is never reached** due to the unhandled exception on line 7.

---

### Note on Named Function Expressions (`func4`)

Inside `var func3 = function func4() { ... }`:

* `func4` is a **Named Function Expression (NFE)**.
* Its identifier (`func4`) is scoped **only inside its own function body** (useful for recursion or stack traces). It is never accessible in the outer scope, so attempting to call `func4()` from outside would throw `ReferenceError: func4 is not defined`.

How does the behavior change if func3 is declared with let or const instead of var?

If `func3` is declared with `let` or `const` instead of `var`, calling it before its declaration throws a **`ReferenceError: Cannot access 'func3' before initialization`** instead of a `TypeError`.

```javascript
const func1 = () => console.log(1);
func1(); // 1

func2(); // 2
function func2() {
  console.log(2);
}

func3(); // ❌ ReferenceError: Cannot access 'func3' before initialization
const func3 = function func4() {
  console.log(3);
};

```

---

### Why the Error Changes

* **With `var` (Hoisted and Initialized):**
`var` declarations are hoisted and immediately initialized to `undefined`. When the runtime hits `func3()`, `func3` exists, but its value is `undefined`. Invoking `undefined()` produces:
`TypeError: func3 is not a function`
* **With `let` or `const` (Temporal Dead Zone):**
`let` and `const` declarations are also hoisted, but they remain **uninitialized** from the start of the block until execution physically evaluates the declaration line. This period is the **Temporal Dead Zone (TDZ)**. Any read or invocation attempt inside the TDZ throws:
`ReferenceError: Cannot access 'func3' before initialization`

---

### Comparison Summary

| Declaration Type       | Hoisted? | Initialized at Hoisting?         | Calling Before Declaration Line                              |
| ---------------------- | -------- | -------------------------------- | ------------------------------------------------------------ |
| `function declaration` | Yes      | Yes (bound to function body)     | Executes successfully                                        |
| `var func = ...`       | Yes      | Yes (initialized to `undefined`) | `TypeError: func is not a function`                          |
| `let func = ...`       | Yes      | No (resides in TDZ)              | `ReferenceError: Cannot access 'func' before initialization` |
| `const func = ...`     | Yes      | No (resides in TDZ)              | `ReferenceError: Cannot access 'func' before initialization` |
