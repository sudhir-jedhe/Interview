In JavaScript, a **primitive** (or primitive value) is the simplest form of data.

Primitives are fundamental building blocks that share two strict rules: they are **not objects** (meaning they have no properties or methods of their own), and they are **immutable** (their actual value cannot be altered once created).

There are **seven** primitive data types in modern JavaScript.

## The 7 Primitive Types

| Type            | Description                                                                               | Example                            |
| --------------- | ----------------------------------------------------------------------------------------- | ---------------------------------- |
| **`String`**    | Text data wrapped in quotes (single, double, or backticks).                               | `let name = "Alice";`              |
| **`Number`**    | Both integers and decimals. (Also includes special values like `NaN` and `Infinity`).     | `let score = 98.5;`                |
| **`Boolean`**   | A logical entity representing exactly one of two values: true or false.                   | `let isActive = true;`             |
| **`Undefined`** | The default value of a variable that has been declared but not assigned a value.          | `let age;` (value is `undefined`)  |
| **`Null`**      | The intentional, explicit absence of any object value.                                    | `let user = null;`                 |
| **`BigInt`**    | Used for mathematically massive numbers beyond the safe limit of standard Numbers.        | `let massive = 9007199254740991n;` |
| **`Symbol`**    | A unique, anonymous, and immutable identifier (mostly used for hidden object properties). | `let id = Symbol("id");`           |

---

## Key Characteristic: Immutability

It is very common to confuse variable reassignment with mutability.

When we say primitives are immutable, it means the **value itself** cannot be changed in memory. You can replace the entire value a variable holds, but you cannot alter the existing primitive.

```javascript
let greeting = "hello";

// This looks like we are changing the primitive string:
greeting[0] = "H"; 

// But strings are immutable primitives! The original value is untouched.
console.log(greeting); // Outputs: "hello"

// To "change" it, you must completely reassign the variable to a brand new primitive:
greeting = "Hello"; 

```

By contrast, **Objects** and **Arrays** are reference types, meaning they *are* mutable. You can change their internal properties without reassigning the whole variable (e.g., `myArray.push(5)`).

## The "Autoboxing" Exception (Wrapper Objects)

If primitives do not have methods or properties, you might wonder why this code works perfectly:

```javascript
let text = "javascript";
console.log(text.toUpperCase()); // Outputs: "JAVASCRIPT"
console.log(text.length);        // Outputs: 10

```

How does a primitive string have a `.toUpperCase()` method or a `.length` property?

When you try to access a property or method on a primitive string, number, or boolean, JavaScript performs a trick called **autoboxing**.

1. It temporarily wraps the primitive in a corresponding Object (like `new String("javascript")`).
2. It runs the method on that temporary object.
3. It immediately throws the temporary object away and returns the result, leaving your original primitive completely untouched.

## The `typeof null` Bug

There is a famous, decades-old bug in JavaScript regarding primitives. If you check the type of `null` using the `typeof` operator, it returns `"object"`.

```javascript
console.log(typeof null); // Outputs: "object"

```

Despite this output, **`null` is definitively a primitive type**, not an object. The `typeof` behavior is a historical mistake from the very first version of JavaScript that was never fixed because correcting it would break millions of existing websites that inadvertently rely on the bug.
