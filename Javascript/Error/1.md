## Understanding JavaScript Errors

When writing and executing JavaScript code, encountering errors is a normal part of the development process. They typically stem from three main sources: programmer coding mistakes, unexpected or incorrect user input, and unforeseen environmental factors (like network failures).

JavaScript defines several built-in error types to help identify what went wrong:

---

### Common JavaScript Error Types

* **Reference Errors:** Occurs when you attempt to use a variable that has not been declared or is out of scope.
* *Example:* `console.log(x);` when `x` is never defined.

* **Type Errors:** Occurs when an operation is performed on a value of the wrong data type, such as trying to call a non-existent method on a string or number, or modifying a constant value.
* *Example:* `let num = 5; num.toUpperCase();`

* **Range Errors:** Occurs when a value is outside the allowable range of values or arguments.
* *Example:* Setting an invalid array length or passing an out-of-range value to numeric methods like `Number.prototype.toPrecision()`.

* **URI Errors:** Occurs when global URI handling functions (like `encodeURI()` or `decodeURI()`) are used incorrectly.
* *Example:* Passing malformed URI characters to decoding functions.

* **Syntax Errors:** Occurs when the code contains invalid JavaScript syntax that the parser cannot understand. These prevent the script from running entirely.
* *Example:* Forgetting a closing parenthesis in a function call: `console.log("Hello";`

* **Eval Error (Deprecated):** Historically related to improper use of the global `eval()` function. Modern JavaScript engines rarely throw this, returning standard `TypeError` or `SyntaxError` instead.
* **Silent Errors:** Situations where the code fails to execute as intended or fails silently without throwing a traditional exception, often requiring strict mode (`"use strict";`) or careful debugging to catch.

---

### How to Handle JavaScript Errors

To prevent errors from crashing your application and to manage unexpected situations gracefully, JavaScript provides the `try...catch...finally` statement.

```javascript
try {
  // Code that may potentially throw an error
  let result = riskyOperation();
  console.log(result);
} catch (error) {
  // Code to handle the error
  console.error("An error occurred: " + error.message);
} finally {
  // Code that always executes, regardless of an error occurring or not
  cleanupResources();
}

```

* **`try`**: Wraps the block of code to be tested for errors while it's being executed.
* **`catch`**: Catches the error object thrown by the `try` block, allowing you to log it, display a user-friendly message, or take corrective action.
* **`finally`**: Executes cleanup tasks (like closing database connections or stopping spinners) whether the try block succeeded or failed.

You can also use the `throw` statement to create custom error messages tailored to your application's logic.

JavaScript errors are typically categorized into **Compile-time / Syntax errors** (syntax errors caught during parsing), **Runtime errors** (standard native errors thrown while executing code), and **Logical errors** (code runs without throwing errors but produces incorrect results).

Here are 5 concrete code examples for each primary type of JavaScript error.

---

## 1. Syntax Errors (`SyntaxError`)

Occur during code parsing when the code breaks the language rules. The code will fail to execute entirely.

```javascript
// Example 1: Missing closing bracket or parenthetical
if (true {
  console.log("Missing parenthesis");
}

// Example 2: Unexpected token / invalid variable name
const 123variable = "Invalid name";

// Example 3: Unmatched closing brace/bracket
function test() {
  console.log("Hello");
}}

// Example 4: Invalid destructuring assignment target
const { a, b } = null = 5;

// Example 5: Reserved keywords used as variable names
const class = "Biology";

```

---

## 2. Reference Errors (`ReferenceError`)

Occur at runtime when trying to access a variable or function that does not exist or has not been initialized yet.

```javascript
// Example 1: Accessing an undeclared variable
console.log(nonExistentVar);

// Example 2: Accessing let/const variable before initialization (Temporal Dead Zone)
console.log(myVar);
let myVar = 10;

// Example 3: Variable accessed outside its function scope
function setScore() {
  let score = 100;
}
console.log(score);

// Example 4: Typo in variable name
const userAge = 25;
console.log(userAges);

// Example 5: Calling a function that hasn't been defined
renderPage();

```

---

## 3. Type Errors (`TypeError`)

Occur when an operation cannot be performed because a value is not of the expected type.

```javascript
// Example 1: Calling a non-existent method on null/undefined
const obj = null;
obj.toString();

// Example 2: Invoking something that is not a function
const num = 42;
num();

// Example 3: Reassigning a `const` variable
const pi = 3.14;
pi = 3.14159;

// Example 4: Accessing properties on undefined
let user;
console.log(user.name);

// Example 5: Passing an invalid argument type to native methods
const name = "Alex";
name.toUpperCase().map(item => item); // .map is for arrays, not strings

```

---

## 4. Range Errors (`RangeError`)

Occur when a numeric variable or value falls outside its allowable range or limit.

```javascript
// Example 1: Infinite recursion causing stack overflow
function recursive() {
  recursive();
}
recursive();

// Example 2: Creating an array with invalid length
const arr = new Array(-1);

// Example 3: Invalid precision argument for toFixed()
const num = 12.34;
num.toFixed(101); // Precision must be between 0 and 100

// Example 4: Invalid code point passed to String.fromCharCode()
String.fromCharCode(0x110000); // Exceeds max valid code point (0x10FFFF)

// Example 5: Invalid date value in ISO format
new Date("invalid-date-string").toISOString();

```

---

## 5. URI Errors (`URIError`)

Occur when global URI encoding or decoding functions (`decodeURI()`, `decodeURIComponent()`, etc.) are passed an invalid URI format.

```javascript
// Example 1: Malformed percent-encoding sequence
decodeURI("%");

// Example 2: Incomplete hex sequence
decodeURIComponent("%A");

// Example 3: Invalid surrogate pair encoding
decodeURI("%E0%A0");

// Example 4: Invalid character sequence for URI decoding
decodeURIComponent("%G0%00");

// Example 5: Malformed URI component sequence
decodeURIComponent("https://example.com/%");

```

---

## 6. Logical Errors

Occur when the code runs completely fine without throwing any explicit JavaScript exception, but produces unexpected or incorrect output due to faulty logic.

```javascript
// Example 1: Off-by-one error in a loop (skips the last item)
const list = [10, 20, 30];
for (let i = 0; i < list.length - 1; i++) {
  console.log(list[i]); // Misses printing 30
}

// Example 2: Operator precedence mistake (intended: (a + b) / 2)
const avg = 10 + 20 / 2; // Returns 20 instead of 15

// Example 3: Assignment (`=`) instead of equality comparison (`===`)
let isLoggedIn = false;
if (isLoggedIn = true) { // Always evaluates to true and reassigns variable
  console.log("Welcome!");
}

// Example 4: Floating point arithmetic precision issue
const isPointThree = (0.1 + 0.2 === 0.3); // Evaluates to false (0.1 + 0.2 = 0.30000000000000004)

// Example 5: Array mutability bug (mutating original array instead of copying)
const original = [1, 2, 3];
const modified = original.reverse(); // Mutates 'original' in place unintentionally

```
