### 2. Production Service Worker (`sw.js`)

Implements a **Cache-First Strategy for static assets** and a **Network-First with Cache Fallback for API data**.

```javascript
const CACHE_NAME = 'pwa-cache-v1';
const STATIC_ASSETS = [
  '/',
  '/index.html',
  '/styles.css',
  '/main.js',
  '/icons/icon-192.png'
];

// 1. Install Event: Pre-cache core app shell
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => {
      console.log('[SW] Pre-caching static assets');
      return cache.addAll(STATIC_ASSETS);
    })
  );
  // Force active state immediately
  self.skipWaiting();
});

// 2. Activate Event: Clean up legacy caches
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames.map((cache) => {
          if (cache !== CACHE_NAME) {
            console.log('[SW] Clearing old cache:', cache);
            return caches.delete(cache);
          }
        })
      );
    })
  );
  self.clients.claim();
});

// 3. Fetch Event: Intercept network requests
self.addEventListener('fetch', (event) => {
  const { request } = event;

  // Strategy A: Network-first for API endpoints
  if (request.url.includes('/api/')) {
    event.respondWith(
      fetch(request)
        .then((response) => {
          const clonedResponse = response.clone();
          caches.open(CACHE_NAME).then((cache) => cache.put(request, clonedResponse));
          return response;
        })
        .catch(() => caches.match(request)) // Return cached fallback if offline
    );
    return;
  }

  // Strategy B: Cache-first with Network Fallback for static assets
  event.respondWith(
    caches.match(request).then((cachedResponse) => {
      if (cachedResponse) {
        return cachedResponse;
      }
      return fetch(request).then((networkResponse) => {
        if (!networkResponse || networkResponse.status !== 200 || networkResponse.type !== 'basic') {
          return networkResponse;
        }
        const clonedResponse = networkResponse.clone();
        caches.open(CACHE_NAME).then((cache) => cache.put(request, clonedResponse));
        return networkResponse;
      });
    })
  );
});

```

### 3. Registration & Install Prompt (React / JavaScript)

Register the Service Worker and intercept the `beforeinstallprompt` browser event to trigger your custom "Add to Home Screen" UI button.

```typescript
// hooks/usePWAInstall.ts
import { useState, useEffect } from 'react';

export function usePWAInstall() {
  const [deferredPrompt, setDeferredPrompt] = useState<any>(null);
  const [isInstallable, setIsInstallable] = useState(false);

  useEffect(() => {
    // Register Service Worker
    if ('serviceWorker' in navigator) {
      window.addEventListener('load', () => {
        navigator.serviceWorker
          .register('/sw.js')
          .then((reg) => console.log('[SW] Registered successfully:', reg.scope))
          .catch((err) => console.error('[SW] Registration failed:', err));
      });
    }

    // Capture install prompt
    const handleBeforeInstallPrompt = (e: Event) => {
      e.preventDefault();
      setDeferredPrompt(e);
      setIsInstallable(true);
    };

    window.addEventListener('beforeinstallprompt', handleBeforeInstallPrompt);

    return () => {
      window.removeEventListener('beforeinstallprompt', handleBeforeInstallPrompt);
    };
  }, []);

  const triggerInstall = async () => {
    if (!deferredPrompt) return;
    deferredPrompt.prompt();
    const { outcome } = await deferredPrompt.userChoice;
    console.log(`User response to install prompt: ${outcome}`);
    setDeferredPrompt(null);
    setIsInstallable(false);
  };

  return { isInstallable, triggerInstall };
}

```

### Key Architectural Caveats in Production

* **HTTPS Enforcement:** Service Workers require a secure context (`https://`), except on `localhost` during development.
* **iOS (Safari) Nuances:** Safari supports PWAs but ignores `beforeinstallprompt`. iOS users must manually tap **Share $\rightarrow$ Add to Home Screen**.
* **Cache Invalidation:** Always update `CACHE_NAME` (`v1` $\rightarrow$ `v2`) during deployments so the `activate` event purges stale files and updates the user's client.

Implementing **Web Push Notifications** in a Progressive Web App (PWA) requires three distinct actors working together:

1. **The Client (Browser & Service Worker):** Obtains notification permissions and subscribes the user to the browser's push service.
2. **The App Server (Backend):** Stores user subscriptions and triggers push notifications using **VAPID keys**.
3. **The Browser Push Service (Vendor Cloud):** (e.g., FCM for Chrome, APNs for Safari, Mozilla Push) Relays payload data from your server to the client device.

```text
 ┌────────────────┐          1. Subscribe           ┌─────────────────┐
 │                ├────────────────────────────────►│                 │
 │   PWA Client   │                                 │ Browser Push    │
 │ (ServiceWorker)│◄────────────────────────────────┤     Service     │
 └───────┬────────┘        2. PushSubscription      └────────▲────────┘
         │               (Endpoint & Encryption Keys)        │
         │                                                   │
         │ 3. Send Subscription Payload                      │ 4. Send Encrypted
         ▼                                                   │    Notification Payload
 ┌────────────────┐                                          │    signed with VAPID
 │   App Server   │──────────────────────────────────────────┘
 │  (Node.js/API) │
 └────────────────┘

```

### Step 1: Generate VAPID Keys on Your App Server

**VAPID (Voluntary Application Server Identification)** keys establish a secure cryptographic trust contract between your backend server and the browser's Push Service.

Install the standard `web-push` library in your Node.js backend to generate your public/private keypair once:


* **Public Key:** Exposed to the frontend client to authorize push subscriptions.
* **Private Key:** Kept secret on your backend server to sign outgoing notification requests.

### Step 2: Client Subscription Logic (Frontend)

To request subscription details from the browser, convert your Base64 URL-safe Public VAPID key into a `Uint8Array` format required by the Web Push API.

#### 1. VAPID Key Conversion Helper

```javascript
// utils/push.js
export function urlBase64ToUint8Array(base64String) {
  const padding = '='.repeat((4 - (base64String.length % 4)) % 4);
  const base64 = (base64String + padding).replace(/-/g, '+').replace(/_/g, '/');
  const rawData = window.atob(base64);
  const outputArray = new Uint8Array(rawData.length);

  for (let i = 0; i < rawData.length; ++i) {
    outputArray[i] = rawData.charCodeAt(i);
  }
  return outputArray;
}

```

#### 2. Requesting Permission & Subscribing

```javascript
// services/pushSubscription.js
import { urlBase64ToUint8Array } from '../utils/push';

const PUBLIC_VAPID_KEY = 'YOUR_GENERATED_PUBLIC_VAPID_KEY_HERE';

export async function subscribeUserToPush() {
  // 1. Verify Browser Support
  if (!('serviceWorker' in navigator) || !('PushManager' in window)) {
    throw new Error('Push messaging is not supported in this browser.');
  }

  // 2. Request User Notification Permission
  const permission = await Notification.requestPermission();
  if (permission !== 'granted') {
    throw new Error('Notification permission was denied by the user.');
  }

  // 3. Obtain Active Service Worker Registration
  const registration = await navigator.serviceWorker.ready;

  // 4. Subscribe to Browser Push Service using VAPID Public Key
  const convertedVapidKey = urlBase64ToUint8Array(PUBLIC_VAPID_KEY);
  const subscription = await registration.pushManager.subscribe({
    userVisibleOnly: true, // Guarantees a visible notification is always shown
    applicationServerKey: convertedVapidKey,
  });

  // 5. Send Subscription Object to Backend Database
  await saveSubscriptionToBackend(subscription);

  return subscription;
}

async function saveSubscriptionToBackend(subscription) {
  await fetch('/api/push/subscribe', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(subscription),
  });
}

```

### Step 3: Handling Push Events in the Service Worker (`sw.js`)

When a push event arrives from the Push Service, the Service Worker receives the payload (even if the browser tab is closed) and calls `showNotification()`.

```javascript
// sw.js

// 1. Listen for Incoming Push Event
self.addEventListener('push', (event) => {
  if (!event.data) {
    console.warn('[SW] Push event received without payload');
    return;
  }

  try {
    const data = event.data.json(); // Parse notification payload

    const options = {
      body: data.body || 'You have a new update.',
      icon: data.icon || '/icons/icon-192.png',
      badge: data.badge || '/icons/badge-72.png',
      vibrate: [100, 50, 100],
      data: {
        url: data.url || '/', // Deep link destination on tap
      },
      actions: [
        { action: 'open', title: 'View' },
        { action: 'close', title: 'Dismiss' },
      ],
    };

    // Keep SW alive until the notification is displayed
    event.waitUntil(
      self.registration.showNotification(data.title || 'New Notification', options)
    );
  } catch (err) {
    console.error('[SW] Error processing push payload:', err);
  }
});

// 2. Handle User Tap/Click on the Notification
self.addEventListener('notificationclick', (event) => {
  event.notification.close(); // Close the notification banner

  if (event.action === 'close') return;

  const targetUrl = event.notification.data.url;

  event.waitUntil(
    clients.matchAll({ type: 'window', includeUncontrolled: true }).then((windowClients) => {
      // If a tab with our app is already open, focus it
      for (let client of windowClients) {
        if (client.url === targetUrl && 'focus' in client) {
          return client.focus();
        }
      }
      // Otherwise, open a new window tab
      if (clients.openWindow) {
        return clients.openWindow(targetUrl);
      }
    })
  );
});

```

```javascript
  /*

    {

        p256dh: '...',
        auth: '...'
      }

    }
  }
```

### Production Considerations & Gotchas

1. **HTTPS Constraint:** Web Push APIs work strictly over secure contexts (`https://`). Local development is permitted on `http://localhost`.
2. **iOS Support Rules:** On iOS (Safari), Web Push is supported starting with iOS 16.4+, but **only if the PWA has been added to the Home Screen** by the user (`display: standalone`). It will fail in standard mobile Safari tabs.
3. **Handling Expired Subscriptions:** Always catch `410 Gone` HTTP status responses on your server during `sendNotification()`. This indicates the user unsubscribed or reset their browser permissions, so you must delete the stale subscription record from your database to prevent invalid network requests.

How do you implement the Background Sync API in a Service Worker to sync offline data when connectivity returns?

The **Background Sync API** allows web applications to defer server synchronization tasks until the user has a stable internet connection. Crucially, if the user fills out a form, submits data offline, and immediately closes the browser tab, the **Service Worker executes the sync task in the background** as soon as connectivity returns.

Here is a complete, production-grade implementation using `IndexedDB` for offline storage and a `Service Worker` with the `SyncManager` API.

---

### Architectural Flow

```text
  [ User Offline ] ──► Submit Form ──► Save Payload to IndexedDB
                                              │
                                              ▼
                                 Register Sync Event ('sync-orders')
                                              │
                                              ▼
  [ User Online / Tab Closed ] ──► Service Worker Receives 'sync' Event
                                              │
                                              ▼
                                 Fetch Payload from IndexedDB ──► POST to Server
                                              │
                                              ▼
                                 Clear IndexedDB Record on Success

```

### Step 1: Set Up IndexedDB Helper (`idb-helper.js`)

Because Service Workers run in a worker thread without access to `localStorage`, you must store offline payloads inside **IndexedDB**.

```javascript
// utils/idb-helper.js
const DB_NAME = 'OfflineAppDB';
const STORE_NAME = 'pendingOrders';

function openDB() {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open(DB_NAME, 1);

    request.onupgradeneeded = (event) => {
      const db = event.target.result;
      if (!db.objectStoreNames.contains(STORE_NAME)) {
        db.createObjectStore(STORE_NAME, { keyPath: 'id', autoIncrement: true });
      }
    };

    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
  });
}

export async function savePendingOrder(orderData) {
  const db = await openDB();
  return new Promise((resolve, reject) => {
    const tx = db.transaction(STORE_NAME, 'readwrite');
    const store = tx.objectStore(STORE_NAME);
    const request = store.add({ ...orderData, timestamp: Date.now() });

    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
  });
}

export async function getAllPendingOrders() {
  const db = await openDB();
  return new Promise((resolve, reject) => {
    const tx = db.transaction(STORE_NAME, 'readonly');
    const store = tx.objectStore(STORE_NAME);
    const request = store.getAll();

    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
  });
}

export async function deletePendingOrder(id) {
  const db = await openDB();
  return new Promise((resolve, reject) => {
    const tx = db.transaction(STORE_NAME, 'readwrite');
    const store = tx.objectStore(STORE_NAME);
    const request = store.delete(id);

    request.onsuccess = () => resolve();
    request.onerror = () => reject(request.error);
  });
}
```

### Step 2: Register Background Sync on Form Submission (Client)

When the user triggers an action (e.g., submitting a form), save the payload to IndexedDB and register a sync tag with the Service Worker.

```typescript
// services/orderService.js
import { savePendingOrder } from '../utils/idb-helper';

export async function submitOrder(orderPayload) {
  // Check if browser supports Service Workers and SyncManager
  if ('serviceWorker' in navigator && 'SyncManager' in window) {
    try {
      // 1. Save order to IndexedDB first
      await savePendingOrder(orderPayload);

      // 2. Obtain active Service Worker registration
      const registration = await navigator.serviceWorker.ready;

      // 3. Register a Sync tag with the SyncManager
      await registration.sync.register('sync-pending-orders');
      
      console.log('[App] Order saved offline. Background sync registered!');
      return { status: 'QUEUED_OFFLINE' };
    } catch (err) {
      console.warn('[App] Background sync registration failed; falling back to direct fetch.', err);
      return sendDirectFetch(orderPayload);
    }
  } else {
    // Fallback for browsers without SyncManager support (e.g., older Safari)
    return sendDirectFetch(orderPayload);
  }
}

async function sendDirectFetch(orderPayload) {
  const res = await fetch('/api/orders', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(orderPayload),
  });
  return res.json();
}
```

### Step 3: Handle the `sync` Event in the Service Worker (`sw.js`)

Inside the Service Worker, attach an event listener for `sync`. When connectivity returns, the browser fires this event, even if the user has navigated away or closed the tab.

```javascript
// sw.js
import { getAllPendingOrders, deletePendingOrder } from './utils/idb-helper.js';

self.addEventListener('sync', (event) => {
  // Check if the sync tag matches our registration
  if (event.tag === 'sync-pending-orders') {
    console.log('[SW] Network connectivity detected! Flushing offline queue...');
    
    // event.waitUntil keeps the Service Worker alive until the Promise resolves
    event.waitUntil(flushPendingOrders());
  }
});

async function flushPendingOrders() {
  const pendingOrders = await getAllPendingOrders();

  for (const order of pendingOrders) {
    try {
      const response = await fetch('/api/orders', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          items: order.items,
          total: order.total,
          timestamp: order.timestamp,
        }),
      });

      if (response.ok) {
        console.log(`[SW] Order #${order.id} synced successfully!`);
        // Remove item from IndexedDB once successfully processed on backend
        await deletePendingOrder(order.id);
      } else {
        console.error(`[SW] Server rejected order #${order.id}. Status: ${response.status}`);
      }
    } catch (error) {
      console.error(`[SW] Network error syncing order #${order.id}. Will retry later.`, error);
      
      // Throwing an error inside event.waitUntil signals to the browser 
      // that the sync failed. The browser will schedule an exponential backoff retry.
      throw error;
    }
  }
}

```

### Essential Gotchas & Best Practices

1. **Automatic Retries:** If your network call fails or throws an error inside `event.waitUntil()`, the browser automatically re-schedules the sync task using **exponential backoff** to attempt delivery on the next connection window.
2. **Browser Support:** Background Sync (`SyncManager`) is supported natively in Chrome, Edge, and Opera. For unsupported browsers (like Safari/Firefox), implement a fallback that listens to the `window.addEventListener('online', ...)` DOM event to flush IndexedDB when the window is active.
3. **Idempotency:** Because background retries might send the same payload twice if a network drop happens right after server processing, ensure your backend API handles duplicate requests gracefully using **idempotency keys** (`X-Idempotency-Key: <unique-order-id>`).
